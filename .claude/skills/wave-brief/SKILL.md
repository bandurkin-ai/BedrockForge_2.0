Составь и верни текст брифа (не запускай агента сам, если тебя не просили) для подшагов **$steps**, дорожка **$track**, агент **$agent**.

## Что собрать перед брифом
1. Строки подшагов `$steps` из `PROGRESS.md` («План этапа …»), строки «Пути», «Только оркестратор правит», «Один владелец файла».
2. Решения ADR этапа, на которые ссылаются подшаги (номера), и файлы spec этапа (`docs/spec/00-index.md`).
3. «Допущения» PROGRESS.md с записями прошлых подшагов этой дорожки и контракты соседних дорожек
   (интерфейсы функций, ответы API), если подшаг от них зависит.
4. Что уже сделано (коммиты, файлы) — одной строкой «Готово: …, не переписывай».

## Шаблон брифа
```
BedrockForge 2, /home/user/BedrockForge_2.0, ветка <ветка сессии>. Ты — дорожка $track этапа Э<N>.
Выполни подшаги $steps из PROGRESS.md «План этапа Э<N>» (прочитай эти строки, «Пути», «Только оркестратор правит»,
«Допущения» «Э<N> …»), по ADR <NNNN> (решения …) и ТЗ <файлы spec, разделы, тесты Т…>.
Готово: <что опирается>. Контракт: <интерфейсы / ответы, которых держаться>.

Правила:
- Ты в своём рабочем дереве (isolation: worktree) на своей ветке; правь только файлы своих подшагов.
  Файлы «только оркестратор» не трогай — нужные строки пришли точным текстом в отчёте.
- Коммит после каждого подшага: `git add <свои пути>`; `git commit -m "Э<N>: <подшаг> — …" -- <свои пути>`
  (никогда `git add -A`/`.`, `git stash`, `rebase` — их блокирует хук). Окончание сообщения коммита ровно:
  Co-Authored-By: <атрибуция из системного напоминания сессии>
  Claude-Session: <ссылка на сессию>
  Не пушь, PROGRESS.md не правь.
- Тесты — целевые: <команды pytest / vitest своих файлов>, ruff по своим файлам, `uv run mypy bf_core`,
  `npm run typecheck`. Полный набор не гоняй. Перед uv: `export UV_SYSTEM_CERTS=1; unset UV_NATIVE_TLS`.
- Правила CLAUDE.md: float64, NaN не в ноль, ошибки {code, message, hint} по-русски, файл ≤ ~600 строк,
  numba cache=True, только собственные окна, команда = запись реестра, фирменный стиль.
Отчёт ≤ <10–20> строк: коммиты, тесты, замеры критериев, строки для оркестратора, трактовки вне ТЗ, контракт для соседей.
```

## После отчёта агента (оркестратор)
- Ветка агента: `git merge --no-ff <ветка агента>` в ветку сессии (конфликты — только в файлах оркестратора).
- Строки оркестратора внести самому, целевые тесты, подшаг `[x]` с коммитами и трактовки — в «Допущения».
