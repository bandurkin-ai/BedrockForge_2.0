# Правила интерфейса (UI Rules)

Универсальный свод правил для React/TypeScript-интерфейсов. Не привязан к проекту: проектные особенности задаются в разделе «Профиль проекта». Документ написан так, чтобы работать и как обычный файл в `docs/`, и как навык Claude Code (`SKILL.md`).

Источник: переработка открытых наборов Vercel — `vercel-labs/agent-skills` (`react-best-practices`, `web-design-guidelines`), лицензия MIT. Правила перефразированы, отобраны и адаптированы; серверные (Next.js/RSC) и мобильные пункты вынесены в метки, чтобы не мешать десктопным проектам.

## Как использовать

| Сценарий | Действие |
|---|---|
| Писать новый UI-код | Следовать правилам разделов 1–9 и 11; профиль проекта (раздел 0) имеет приоритет |
| Ревью файлов | Пройти по разделам, выдать находки в формате раздела 12 |
| Рефакторинг производительности | Начать с разделов 6–8 (по убыванию влияния) |
| Спорный случай | Правило проекта (CLAUDE.md, ADR, бренд-гайд) выше этого документа |

### Установка для всех проектов в Claude Code

Скопировать файл как личный навык — он станет доступен в любом проекте и любой сессии на этой машине:

```bash
mkdir -p ~/.claude/skills/ui-rules
cp docs/UI_RULES.md ~/.claude/skills/ui-rules/SKILL.md
```

- Windows (PowerShell): `New-Item -ItemType Directory -Force $HOME\.claude\skills\ui-rules; Copy-Item docs\UI_RULES.md $HOME\.claude\skills\ui-rules\SKILL.md`
- Вызов: `/ui-rules <файл-или-шаблон>` либо автоматически по описанию в шапке файла.
- Для одного репозитория вместо `~/.claude/skills/` использовать `.claude/skills/ui-rules/SKILL.md` внутри репозитория.
- В облачных сессиях Claude Code `~/.claude` не сохраняется между контейнерами: там держать копию в `.claude/skills/` репозитория.

## 0. Профиль проекта

Перед применением определить параметры. Метки в таблицах ниже показывают, к какому профилю относится правило; без метки правило общее.

| Параметр | Варианты | Влияние |
|---|---|---|
| Платформа | `web` · `desktop` (Electron/Tauri) · `mobile` | Метки `[web]`, `[desktop]`, `[mobile]` |
| Рендеринг | `SPA` · `SSR` (Next.js и т. п.) | Метка `[ssr]` — применять только при SSR |
| Язык интерфейса | один язык · мультиязычный | Метка `[i18n]` — только при нескольких языках |
| Сеть | онлайн · офлайн | Метка `[online]` — только при наличии сети |
| Кавычки и регистр | задаются языком (ru: «ёлочки», регистр предложения; en: “curly”, Title Case) | Раздел 5 |

Запишите выбранный профиль в CLAUDE.md проекта одной строкой, например: `UI: desktop, SPA, один язык (ru), офлайн`.

## 1. Доступность

| ID | Правило |
|---|---|
| A1 | Кнопка только с иконкой имеет `aria-label` |
| A2 | Поле формы имеет `<label>` или `aria-label` |
| A3 | Действие — `<button>`; переход — `<a>`/`<Link>`. Не `<div onClick>` и не `<span onClick>` |
| A4 | Интерактивный элемент доступен с клавиатуры (Enter/Space/стрелки по ожидаемому поведению) |
| A5 | Изображение имеет `alt`; декоративное — `alt=""`; декоративная иконка — `aria-hidden="true"` |
| A6 | Асинхронные сообщения (тосты, валидация, прогресс, ошибки) озвучиваются: `aria-live="polite"` |
| A7 | Сначала семантический HTML (`button`, `a`, `label`, `table`), ARIA — только если семантики не хватает |
| A8 | Заголовки идут по порядку `h1`–`h6`; на длинных страницах есть «перейти к содержимому» |
| A9 | Якоря заголовков имеют `scroll-margin-top`, чтобы не прятаться под липкой шапкой |
| A10 | Значимые медиа имеют субтитры, расшифровку или описание; у медиаплеера работает клавиатура |
| A11 | Цвет не единственный носитель смысла (статус — ещё иконка или текст); контраст текста не ниже WCAG AA |

## 2. Фокус и клавиатура

| ID | Правило |
|---|---|
| F1 | У интерактивных элементов виден фокус (`:focus-visible` с кольцом/контуром) |
| F2 | Не убирать `outline: none` без равноценной замены |
| F3 | Использовать `:focus-visible`, а не `:focus` — без кольца при клике мышью |
| F4 | Составные контролы подсвечивать через `:focus-within` |
| F5 | Липкие шапки, подвалы и оверлеи не перекрывают сфокусированный элемент |
| F6 | Модальное окно: фокус внутрь при открытии, ловушка фокуса, Esc закрывает, фокус возвращается на вызвавший элемент |
| F7 | Горячие клавиши регистрируются в одном месте (реестр), не рассыпаны по компонентам; конфликты с системными и браузерными исключены |
| F8 | `autoFocus` — только на единственном главном поле и только на десктопе |

## 3. Формы

| ID | Правило |
|---|---|
| FM1 | Поля имеют осмысленные `name`; `autocomplete` задан там, где браузер может помочь |
| FM2 | Правильный `type` и `inputmode` (`email`, `tel`, `url`, `number`, `decimal`) |
| FM3 | Не блокировать вставку (`onPaste` + `preventDefault` запрещены) |
| FM4 | Подпись кликабельна (`htmlFor` или обёртка); у чекбоксов и радио подпись и контрол — одна область нажатия |
| FM5 | Отключить `spellCheck` у e-mail, кодов, логинов, идентификаторов |
| FM6 | Кнопка отправки доступна до начала запроса; во время запроса — индикатор и защита от двойного нажатия |
| FM7 | Ошибки — рядом с полем; при отправке фокус на первое поле с ошибкой |
| FM8 | Подсказка в поле показывает пример формата и оканчивается `…` |
| FM9 | `autocomplete="off"` на не-учётных полях, чтобы менеджеры паролей не срабатывали |
| FM10 | Несохранённые изменения: предупреждение при закрытии/уходе (`[web]` — `beforeunload` или guard роутера; `[desktop]` — собственное окно) |
| FM11 | Поле с `value` имеет `onChange` (или используется `defaultValue`) |
| FM12 | Предпочитать неуправляемые поля; управляемые должны быть дешёвыми на каждое нажатие |

## 4. Анимация

| ID | Правило |
|---|---|
| AN1 | Уважать `prefers-reduced-motion`: отключить или заменить упрощённым вариантом |
| AN2 | Анимировать только `transform` и `opacity` (дружественно к компоновщику) |
| AN3 | Не использовать `transition: all` — перечислять свойства |
| AN4 | Задавать правильный `transform-origin`; у SVG — `transform-box: fill-box` на обёртке `<g>` |
| AN5 | Анимации прерываемы вводом пользователя |
| AN6 | Автовоспроизведение дольше 5 с рядом с другим содержимым — с кнопками пауза/стоп/скрыть |
| AN7 | Декоративные циклы останавливаются при `prefers-reduced-motion` |
| AN8 | `[web]` Вместо анимированного GIF — `<video autoplay muted loop playsinline>` и статичная картинка-замена |

## 5. Типографика и тексты

| ID | Правило |
|---|---|
| T1 | `…` (один символ), а не `...`; состояния загрузки: «Загрузка…», «Сохранение…» |
| T2 | Кавычки по языку интерфейса: ru — «ёлочки» (вложенные „лапки“), en — “curly”; не прямые `"` |
| T3 | Неразрывные пробелы: между числом и единицей (`10 МБ`, `5 м`), в сочетаниях клавиш (`⌘ K`), в названиях бренда |
| T4 | Числовые столбцы и сравнения — `font-variant-numeric: tabular-nums` |
| T5 | Заголовкам — `text-wrap: balance` или `pretty` (без висячих слов) |
| T6 | Активный залог и обращение к пользователю на «вы»: «Установите программу», а не «Программа будет установлена» |
| T7 | Подписи кнопок конкретны: «Сохранить ключ», а не «Продолжить» |
| T8 | Сообщение об ошибке содержит причину и следующий шаг, а не только проблему |
| T9 | Числа цифрами: «8 файлов», а не «восемь файлов» |
| T10 | Регистр заголовков и кнопок по языку: ru — как в предложении; en — Title Case |

## 6. Перерисовки React (влияние: среднее — высокое)

| ID | Правило |
|---|---|
| R1 | Часто меняющиеся значения, которые не должны перерисовывать UI (позиция курсора, перетаскивание, камера, таймеры), держать в `useRef`, а не в состоянии |
| R2 | Не подписываться на состояние, которое нужно только в обработчиках (читать при событии) |
| R3 | Производные значения вычислять при рендере; не дублировать в `useEffect` + `setState` |
| R4 | Подписываться на производный булев признак, а не на сырое значение (`isEmpty`, а не весь массив) |
| R5 | Не объявлять компоненты внутри компонентов: состояние сбрасывается при каждом рендере |
| R6 | Тяжёлую работу выносить в мемоизированные компоненты (`memo`); непримитивные значения по умолчанию — на уровень модуля |
| R7 | Не оборачивать в `useMemo` простые примитивные выражения |
| R8 | В зависимостях эффектов — примитивы; независимые зависимости — в отдельные эффекты |
| R9 | `setX(prev => …)` вместо `setX(x + 1)` — стабильные колбэки без лишних зависимостей |
| R10 | Дорогую начальную инициализацию — функцией: `useState(() => compute())` |
| R11 | Логика реакции на действие пользователя — в обработчике события, не в эффекте |
| R12 | Несрочные обновления (фильтры, поиск по большим данным) — `startTransition`/`useDeferredValue`, ввод остаётся отзывчивым |
| R13 | Условный рендер `cond ? <A/> : null`, а не `n && <A/>` (иначе выведется `0`) |
| R14 | Статичный JSX выносить за пределы компонента |
| R15 | `useEffectEvent`-колбэки не включать в зависимости эффекта |
| R16 | Стабильные ссылки на обработчики для долгоживущих слушателей — через `ref` (паттерн useLatest) |

## 7. Данные, запросы и списки

| ID | Правило |
|---|---|
| D1 | Независимые запросы — параллельно (`Promise.all`), не последовательно |
| D2 | `await` ставить в ту ветку, где результат нужен; дешёвую синхронную проверку делать до ожидания |
| D3 | Запускать промис раньше, ждать позже (старт сразу, `await` перед использованием) |
| D4 | Дедуплицировать одинаковые запросы (общий кеш или библиотека запросов; новая зависимость — по правилам проекта) |
| D5 | Списки длиннее ~50 элементов — виртуализировать или `content-visibility: auto` |
| D6 | Не читать геометрию в рендере (`getBoundingClientRect`, `offsetHeight`, `scrollTop`); чтение и запись DOM группировать |
| D7 | Раскладку делать CSS (flex/grid), а не измерениями в JS |
| D8 | Данные в `localStorage` версионировать и держать минимальными; чтения кешировать |
| D9 | Глобальные слушатели (клавиши, resize) — один на тип событий, а не по одному на компонент |
| D10 | `[ssr]` Передавать клиентским компонентам минимум данных; не хранить изменяемое состояние запроса на уровне модуля |

## 8. Бандл и загрузка

| ID | Правило |
|---|---|
| B1 | Импортировать напрямую из файла, не через «бочки» (`index.ts` с реэкспортом) |
| B2 | Тяжёлые компоненты и модули — через `React.lazy`/`import()` |
| B3 | Модуль загружать только при включении функции (условный `import()`) |
| B4 | Предзагружать при наведении/фокусе на запускающий элемент |
| B5 | Пути импорта — статически анализируемые, без динамических конструкций с переменными |
| B6 | `[online]` Сторонние скрипты (аналитика, журналы) — после гидратации/загрузки |
| B7 | `[online]` `<link rel="preconnect">` для CDN, `preload` критичных шрифтов, `font-display: swap` |
| B8 | `[web]` У `<img>` явные `width`/`height`; ниже сгиба — `loading="lazy"`; критичные — `fetchpriority="high"` |

## 9. Горячие циклы JavaScript (влияние: низкое — среднее)

| ID | Правило |
|---|---|
| J1 | Повторные поиски по ключу — через `Map`/`Set`, а не `find`/`includes` в цикле |
| J2 | Несколько `filter`/`map` по одному массиву объединять в один проход; `flatMap` для «карта + фильтр» |
| J3 | Свойства объектов в цикле читать один раз в локальную переменную |
| J4 | Результаты чистых функций с повторяющимися входами — в кеш уровня модуля |
| J5 | RegExp создавать вне цикла |
| J6 | Ранний выход из функций |
| J7 | Минимум/максимум — одним циклом, а не сортировкой |
| J8 | Перед дорогим сравнением массивов проверять длину |
| J9 | `toSorted()`/`toReversed()` вместо мутирующих `sort()`/`reverse()` на данных из состояния |
| J10 | Некритичную работу — в `requestIdleCallback` |
| J11 | Изменение нескольких стилей — через класс или `cssText`, а не по одному свойству |

## 10. Контент и состояния

| ID | Правило |
|---|---|
| C1 | Текст в контейнерах обрабатывает длинные значения: `truncate`, `line-clamp`, `overflow-wrap: anywhere` |
| C2 | Дочерние элементы flex, где нужно усечение текста, имеют `min-width: 0` |
| C3 | Пустые состояния оформлены: не рендерить сломанный UI для пустой строки или массива |
| C4 | Пользовательский контент: рассчитывать на очень короткие, средние и очень длинные значения |
| C5 | Деструктивные действия — через подтверждение или отмену (undo); не выполнять сразу |
| C6 | Кнопки и ссылки имеют `hover`; `hover`/`active`/`focus` заметнее обычного состояния |
| C7 | Состояния загрузки, пустоты и ошибки предусмотрены для каждого экрана с данными |

## 11. Взаимодействие, тема, локаль

| ID | Правило |
|---|---|
| I1 | Перетаскивание, жесты и рисование имеют альтернативу кликом/тапом и клавиатурой, если не являются сутью действия |
| I2 | Во время перетаскивания отключать выделение текста; перетаскиваемому элементу — `inert` |
| I3 | `overscroll-behavior: contain` в модальных окнах, панелях, выпадающих списках |
| I4 | `[mobile]`/`[web]` `touch-action: manipulation` против задержки двойного тапа; `-webkit-tap-highlight-color` задан осознанно |
| I5 | `[mobile]` Полноэкранные раскладки учитывают `env(safe-area-inset-*)` |
| I6 | Не отключать масштабирование (`user-scalable=no`, `maximum-scale=1`) |
| I7 | Тёмная тема: `color-scheme: dark` на `<html>`; у нативного `<select>` явные `background-color` и `color` (Windows) |
| I8 | `[web]` `<meta name="theme-color">` совпадает с фоном страницы |
| I9 | Дата, время, числа, валюта — через `Intl.DateTimeFormat`/`Intl.NumberFormat` с локалью интерфейса (ru-RU: запятая и пробел-разделитель), не жёсткими форматами |
| I10 | `[i18n]` Язык определять по `navigator.languages`/`Accept-Language`, не по IP |
| I11 | Бренды, коды и идентификаторы — `translate="no"` |
| I12 | `[ssr]` Дата/время и значения из `window` не должны давать расхождение сервера и клиента; `suppressHydrationWarning` — только по необходимости |
| I13 | `[web]` Состояние (фильтры, вкладки, страница) отражается в URL; ссылки — настоящие `<a>` (Ctrl+клик, средняя кнопка) |

## 12. Чек-лист анти-паттернов (ревью)

Отмечать в ревью как нарушение:

- `<div>`/`<span>` с обработчиком клика вместо `<button>` (A3)
- Кнопка с иконкой без `aria-label` (A1); поле без подписи (A2)
- `outline: none` без замены фокуса (F2)
- `transition: all` (AN3); анимация без учёта `prefers-reduced-motion` (AN1)
- Блокировка вставки (FM3)
- `user-scalable=no` (I6)
- Жёсткие форматы даты и чисел (I9)
- Большой список без виртуализации (D5)
- Компонент, объявленный внутри компонента (R5)
- `useEffect` + `setState` для производного значения (R3)
- Частое событие (мышь, перетаскивание) в `useState` вместо `ref` (R1)
- Импорт из «бочки» в горячем пути (B1)
- `window.confirm`/`alert`/`prompt` (C5, F6): вместо них собственные окна (если проект это требует — обязательно)
- Жест без альтернативы (I1); `autoFocus` без обоснования (F8)

## 13. Формат отчёта ревью

Группировать по файлам, формат `файл:строка` (кликабельно в IDE), коротко, без вступлений. Объяснять только неочевидное. Указывать ID правила:

```text
## src/Toolbar.tsx

src/Toolbar.tsx:42 — A1: кнопка-иконка без aria-label
src/Toolbar.tsx:55 — AN3: transition: all → перечислить свойства
src/Toolbar.tsx:67 — R5: компонент объявлен внутри компонента

## src/Table.tsx

src/Table.tsx:12 — D5: 2000 строк без виртуализации
src/Table.tsx:34 — I9: жёсткий формат числа → Intl.NumberFormat('ru-RU')

## src/Panel.tsx

✓ без замечаний
```

Правило применения: если правило конфликтует с требованием проекта (бренд, ТЗ, ADR), побеждает проект; отступление фиксируется в профиле (раздел 0), а не молча.
