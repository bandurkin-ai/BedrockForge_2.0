# Форматы блочных моделей Datamine (.dm, .fbm) и Micromine (.DAT)

Разбор сделан по трём файлам из папки «Для BF» (одна и та же модель железорудного объекта, экспорт из Micromine). Все смещения байтовые, порядок байт little-endian, числа IEEE-754 double, если не сказано иное. Разбор проверен скриптом: значения во всех трёх файлах совпали построчно (169 070 блоков).

| Размер файла | 15 060 992 | 15 060 992 | 13 872 137 |
| Сигнатура | нет (страница-заголовок) | нет (страница-заголовок) | `THIS IS MICROMINE EXTENDED DATA FILE!` |
| Организация | страницы по 4096 байт | страницы по 4096 байт | XML-шапка 8192 байта + текстовый список полей + записи фикс. длины |
| Точность | extended (8-байтовые слова) | extended | double, ширина поля 8 |

## 1. Datamine .dm (extended precision)

### 1.1 Страницы

- Файл делится на страницы по 4096 байт = 512 слов double. Размер файла кратен 4096 (здесь 3677 страниц).
- Страница 0: заголовок и описание полей. Если полей больше, чем помещается (69 описателей), заголовок продолжается на следующих страницах; в этом файле хватило одной.
- Страницы 1…N-1: данные.

Признак extended precision: текстовые поля хранятся по 4 символа в каждом 8-байтовом слове, остальные 4 байта заполнены пробелами (`"блоч    "`, `"ная     "`). В single precision (старые .dm) слово 4 байта, страница 2048 байт, 4 символа на слово без добивки. Детектор формата: проверить байты 4..7 первой страницы (здесь пробелы `0x20`) и кратность размера файла 4096.

### 1.2 Заголовок (страница 0, слова по 8 байт)

| Слова | Смещение | Содержимое | В этом файле |
|---|---|---|---|
| 0–1 | 0x00 | имя файла, 8 симв. | `блочная ` (cp1251) |
| 2–3 | 0x10 | имя БД / доп. имя, 8 симв. | пробелы |
| 4–21 | 0x20 | описание, текст | `FILE EXPORTED BY MICROMINE … SYSTEM` |
| 22 | 0xB0 | служебное | 0.0 |
| 23 | 0xB8 | служебное | 2.0 |
| 24 | 0xC0 | дата (упакованная) | 456789.0 (заглушка Micromine) |
| 25 | 0xC8 | число полей | 20 |
| 26 | 0xD0 | номер последней страницы | 3677 |
| 27 | 0xD8 | число записей на последней странице | 20 |
| 28… | 0xE0 | описатели полей, по 7 слов | |

Слова 22–24 Micromine заполняет нестандартно; при чтении на них опираться не надо. Достаточно: число полей, последняя страница, записи на последней странице.

### 1.3 Описатель поля (7 слов = 56 байт)

| Слово | Содержимое |
|---|---|
| 0–1 | имя поля, 8 символов (по 4 в слове) |
| 2 | тип: `N` числовое, `A` текст (первый байт слова) |
| 3 | номер хранимого слова в записи (1…). **0 = поле-константа**, в записях его нет |
| 4 | номер слова внутри поля (для A-полей длиной больше 4 символов; у N всегда 1) |
| 5 | не используется |
| 6 | значение по умолчанию; для констант это и есть значение |

Поля файла .dm:

| Поле | Позиция | Default | Комментарий |
|---|---|---|---|
| IJK | 1 | 0 | индекс блока |
| XC, YC, ZC | 2, 3, 4 | 0 | центр блока |
| XINC, YINC, ZINC | 5, 6, 7 | 10 | размер блока (хранится явно) |
| Fe_m_pc | 8 | 0 | |
| Fe_o_pc | 9 | 0 | |
| 1 - Insi | 10 | 0 | |
| 1 Filter | 11 | 0 | |
| XMORIG, YMORIG, ZMORIG | 0 | 23436265.92 / 5988122.53 / -157.14 | константы |
| X0, Y0, Z0 | 0 | те же значения | дубли origin, только в .dm |
| NX, NY, NZ | 0 | 443 / 558 / 102 | константы |

### 1.4 Страницы данных

- Запись = число хранимых слов (здесь 11 × 8 = 88 байт), пишутся подряд от начала страницы.
- Записей на странице = floor(512 / 11) = 46, хвост страницы (6 слов) нули.
- Последняя страница содержит столько записей, сколько указано в слове 27 заголовка (20).
- Всего: (3677 − 1 − 1) × 46 + 20 = 169 070.
- A-поле длиной L символов занимает ceil(L/4) слов подряд, собирается по слову 4 описателя.

### 1.5 IJK

Проверено на данных:

```
I = floor((XC - XMORIG) / XINC)     # 0..NX-1
J = floor((YC - YMORIG) / YINC)
K = floor((ZC - ZMORIG) / ZINC)
IJK = (I * NY + J) * NZ + K         # Z меняется быстрее всех
```

Первый блок: I=0, J=10, K=61 → IJK = 10·102 + 61 = 1081. Записи отсортированы по IJK по возрастанию, пустые ячейки не пишутся. Для субблочных моделей Datamine добавляет поля XINC/YINC/ZINC меньше родительского блока и повторяющийся IJK; в этом файле такого нет, но парсер должен это допускать.

## 2. Datamine .fbm

Структура страниц и записей та же, что у .dm. Отличия:

- В заголовке сдвинуты служебные слова: слово 22 = 42.0, 23 = 2.0, 24 = 17 (число полей), 25 = 3677 (последняя страница), 26 = 20 (записей на последней), слово 27 содержит два float32 (42.0, 1.0). Похоже на маркер/версию «fast block model» (42). Для детекта .fbm удобно проверять расширение и слово 22 = 42.
- Полей 17: нет X0/Y0/Z0.
- NX/NY/NZ = 445 / 560 / 104, на 2 больше, чем в .dm, при том же origin. Индексы I, J, K блоков не сдвинуты, сетка добита с конца.
- Из-за другой сетки IJK пересчитан: первый блок IJK = 10·104 + 61 = 1101. Поэтому .fbm и .dm отличаются в ~538 тыс. байт, хотя координаты и атрибуты совпадают.
- Вывод для BF: при импорте IJK не брать как первичный ключ, а пересчитывать из XC/YC/ZC и origin; NX/NY/NZ из файла использовать только как размер индексной сетки.

## 3. Micromine .DAT (Extended Data File)

### 3.1 Общий вид

```
0x0000  "THIS IS MICROMINE EXTENDED DATA FILE!" 07 1A 01 0D 0A   (42 байта)
0x002A  XML-метаданные UTF-8 до </metadata>, дальше нули до 0x2000
0x2000  "10  VARIABLES\r\n"                    число полей текстом
        10 строк описания полей, каждая 19 байт с CRLF
0x20CD  записи: 10 × double + CRLF = 82 байта на запись
```

Контроль: (13 872 137 − 8397) / 82 = 169 070 ровно. Маркера конца файла нет.

### 3.2 XML-шапка

- Блок `meta-object type="title"`: заголовок и описание (пусто).
- `type="encoding"`: `codepage="BOCU-1"`. В этой кодировке записаны имена полей и текстовые значения.
- По одному `type="field-class"` на поле: `<field name="EAST"/><data field-class="Generic"/>`. Классы полей Micromine (Generic, East, North, RL, Hole ID и т.п.) задают роль поля; здесь всё Generic, роль координат определяется по имени.
- Атрибут `time-stamp="67452301efcdab89"` одинаков везде (константа-заглушка, не дата).
- Шапка занимает фиксированные 8192 байта; если XML длиннее, надо проверять, кратна ли граница 8192 (на одном файле не проверить).

### 3.3 Описание полей

Строка: `NNNNNNNNNN T WWW DDD\r\n`

| Позиция | Длина | Содержимое |
|---|---|---|
| 0 | 10 | имя (BOCU-1, добито пробелами) |
| 10 | 1 | тип: `R` real, `C` character, `N`/`L` и др. (встречен только R) |
| 11 | 3 | ширина в байтах (8 для double) |
| 14 | 3 | число знаков после запятой для отображения (3) |

Поля: EAST, NORTH, RL (центр), _EAST, _NORTH, _RL (размер блока), Fe_m_pc, Fe_o_pc, `1 - Insi`, `1 Filter`. Origin, NX/NY/NZ и IJK в файле нет: Micromine хранит блочную модель как обычную таблицу, параметры сетки лежат в отдельном файле или выводятся из данных.

### 3.4 BOCU-1 на практике

Имена в файле выглядят как мусор (`95 91 A3 A4` = `EAST`). Для ASCII декодирование простое: байт ≤ 0x20 берётся как есть, иначе `символ = 0x40 + (байт − 0x90)`, опорное значение после ASCII сбрасывается в 0x40. Для кириллицы и других диапазонов нужен полный BOCU-1 (ICU, `ucnv_open("BOCU-1")`; в Python штатного кодека нет, есть в PyICU). В BF лучше сразу подключить полноценный декодер: в русских проектах имена полей и коды пород часто кириллические.

### 3.5 Записи

- Фиксированная длина = сумма ширин + 2 (CRLF). Числа R8 хранятся как double LE.
- Для C-полей ожидаются байты BOCU-1 фиксированной ширины с добивкой (в этом файле нет, проверить на другом образце).
- Пустые значения в этой модели закодированы как -99 (90 блоков). В других файлах Micromine встречаются пустые поля и большие отрицательные коды; правило null лучше делать настраиваемым при импорте.

## 4. Что заложить в BedrockForge

- Внутренняя модель блока: центр (x, y, z), размер (dx, dy, dz), словарь атрибутов. IJK считать при импорте по формуле из 1.5 с заданным origin, а не читать из файла.
- Параметры сетки (origin, размер блока, NX/NY/NZ, поворот) держать отдельным объектом. Datamine их отдаёт через поля-константы, Micromine нет: восстанавливать как min(центр) − размер/2 и шаг по уникальным координатам, либо брать из сопутствующего файла.
- Читатель Datamine: детект single/extended по странице 0, разбор описателей, разделение на хранимые поля и константы, сбор A-полей по словам, учёт записей на последней странице.
- Читатель Micromine: проверка сигнатуры, XML-парсер шапки (кодировка, классы полей), разбор строк описания с позиции 0x2000, BOCU-1, записи фиксированной длины, отображение mm-типов на типы BF.
- Сопоставление имён: XC/YC/ZC ↔ EAST/NORTH/RL; XINC/YINC/ZINC ↔ _EAST/_NORTH/_RL. Имена атрибутов в обоих форматах до 8 символов (Datamine ограничение формата), поэтому в BF хранить исходное имя и отдельное полное «человеческое» имя.
- Тест-кейс на этих трёх файлах: 169 070 блоков, первый блок (23436270.92, 5988227.53, 457.86), Fe_m_pc = 9.4867, Fe_o_pc = 13.473, `1 - Insi` = 0.5024. Все три файла должны давать одинаковый набор блоков.
- Открытые вопросы (по одному образцу не закрыть): точный смысл слов 22–24 заголовка .dm и маркера 42 в .fbm; поведение .DAT с текстовыми полями и с XML длиннее 8 КБ; поворот модели (в этих файлах его нет).
