# Промт: новый интерфейс настройки отображения данных по скважинам в 3D

Этот файл — задание на реализацию. Сначала прочитай `docs/HANDOFF.md`, затем код, перечисленный в разделе 2.

## 1. Цель

Переделать форму настройки отображения данных по скважинам в окне 3D (содержания, литология, события) так, чтобы:

- одно отображение могло содержать **несколько полей сразу** (слои);
- любая настройка вида, шкалы, цвета, фильтра и подписей была доступна и понятна без справки;
- всё настроенное **сохранялось как стиль** и применялось к другим таблицам, полям и проектам;
- каждое изменение сразу было видно в сцене, а сохранялось только по кнопке (как сейчас).

Решения заказчика (не пересматривать):

| Вопрос | Решение |
|---|---|
| Охват | Все три формы: содержания, литология, события — единая панель и общая библиотека стилей |
| Применение стиля | По умолчанию копия; галочка «связать» делает стиль общим — правка обновляет все отображения, где он используется |
| Хранение | Библиотека в проекте + экспорт и импорт JSON-файлом |
| Первая версия | Несколько полей; редактор градаций на гистограмме; фильтр и урезка; радиус по значению и подписи значений |

Недостатки текущей формы, которые нужно устранить:

- одно поле на отображение;
- «Ширина колонки (90 — обычная)» — условные единицы без смысла для пользователя;
- вид графика спрятан в выпадающем списке, нет стороны, отступа, прозрачности;
- градации задаются только числами вслепую, без распределения данных и без авто-разбивки по квантилям;
- нет фильтра по борту, урезки ураганных, правил для пустых и отрицательных значений;
- нет подписей значений и радиуса по значению;
- раскраску можно сохранить, а вид, шкалу и остальное — нельзя;
- у литологии список обрезан на 60 значениях, нельзя скрыть породу или найти её поиском.

## 4. Устройство окна

Окно остаётся плавающим `ChartWindow`, но с изменяемой шириной (минимум 380 px, по умолчанию 420 px). Три зоны сверху вниз, нижняя полоса закреплена.

```
┌ Отображение · Скважины ────────────────────────── ⛶ ✕ ┐
│ Стиль: [ Au: борта 0.3 / 1 / 3      ▾] 🔗  [⋯]        │  ← полоса стиля
├────────────────────────────────────────────────────────┤
│ СЛОИ                                    [+ Добавить ▾] │
│ ⠿ 👁 ▮▮▯  AU, г/т    столбцы   справа            ⋯   │  ← выбранный
│ ⠿ 👁 ━━━  CU, %      лента     слева             ⋯   │
│ ⠿ 👁 ◆    Жилы       значки    на стволе         ⋯   │
├────────────────────────────────────────────────────────┤
│ ▾ Данные     Опробование · AU, г/т                     │
│ ▾ Вид        [▮▮][▟▙][╱╲][•••][◉][▌][Т]                │
│              сторона ◀ ▶   ширина ──●── 12 м           │
│ ▸ Шкала      0,1 – 20 · логарифмическая                │
│ ▾ Цвет       (один) (градации) (шкала) (по полю)       │
│              ┌ гистограмма с границами ┐                │
│ ▸ Фильтр     показывать ≥ 0,3                           │
│ ▸ Подписи    выключены                                  │
├────────────────────────────────────────────────────────┤
│ [Сохранить] [Отменить изменения]   Сохранено.     ↶ ↷ │
└────────────────────────────────────────────────────────┘
```

Общие правила:

- Разделы слоя — сворачиваемые. В свёрнутом виде заголовок показывает итог настройки одной строкой («0,1 – 20 · логарифмическая»). Состояние сворачивания запоминается в `localStorage`.
- Выбор из 2–7 вариантов — сегментированные кнопки с иконкой и подсказкой, а не выпадающий список.
- Числовые параметры — ползунок плюс поле с единицей (м, px, %). Никаких условных единиц в подписях.
- Числа принимаются с запятой и с точкой; показываются с запятой.
- Пустое поле границы шкалы означает «по данным», в подсказке поля — фактическое значение.
- У каждого элемента управления есть `title` с объяснением в одну фразу.
- Раздел, не применимый к выбранному виду, скрывается целиком, а не блокируется.
- Отмена и повтор (Ctrl+Z, Ctrl+Y) в пределах открытой формы; «Отменить изменения» возвращает к сохранённому.
- Тёмная и светлая тема, доступность: `aria-label` у всех полей, управление с клавиатуры, границы градаций двигаются стрелками.

## 5. Слои (несколько полей)

- Одно отображение = список слоёв = `settings.tracks[]`. Слой — одно поле одной таблицы.
- В одном отображении допускаются слои разных таблиц и разных форм (числа, текст, события). Параметр `form` у отображения остаётся только как подсказка, с какого набора полей начинать.
- Строка слоя: ручка перетаскивания (порядок = порядок колонок от ствола), глаз (скрыть, не удаляя), мини-образец вида и цвета, поле с единицей, вид, сторона, меню `⋯`.
- Меню слоя: дублировать, сохранить как стиль, применить стиль, применить к другим полям, удалить.
- «+ Добавить»: выпадающий список полей, сгруппированный по таблицам, с поиском; множественный выбор добавляет несколько слоёв сразу. Если для поля есть стиль по умолчанию (раздел 8), он применяется автоматически.
- Щелчок по строке выбирает слой, его настройки показываются ниже. Shift и Ctrl выбирают несколько слоёв: показываются только общие параметры, правка применяется ко всем выбранным.
- Кнопка «Разложить» расставляет слои без наложений: трубка на стволе, остальные по сторонам.
- Имя отображения по умолчанию собирается из слоёв: «AU · столбцы + CU · лента»; обновить `displayName`.

## 6. Настройки слоя

### 6.1. Данные

| Параметр | Описание |
|---|---|
| Таблица | С числом строк, как сейчас |
| Поле | С единицей; смена поля сохраняет вид и стиль, сбрасывает только то, что зависит от значений (цвета категорий) |
| Скважины | Все / только выбранные (список с поиском) — использует существующие `allHoles` и `holes` на уровне отображения |
| Интервал глубин | От – до, м — существующие `from` и `to` на уровне отображения |

### 6.2. Вид

Виды для числового поля:

| Вид | Что рисует | Свои параметры |
|---|---|---|
| Столбцы | Отдельный столбец на интервал | сторона, ширина, отступ, зазор |
| Ступени | Сомкнутый ступенчатый контур с заливкой | сторона, ширина, отступ, заливка |
| Линия | Ломаная по серединам интервалов | сторона, ширина, отступ, толщина линии, точки вкл/выкл |
| Точки | Символ на интервал | сторона, ширина, отступ, размер |
| Трубка | Цвет по стволу | радиус: постоянный, px, или по значению (от – до, px, логарифм) |
| Лента | Цветная полоса рядом со стволом | сторона, ширина, отступ |
| Текст | Только подпись значения | см. «Подписи» |

Виды для текстового поля: трубка, лента, текст. Для событий: значок.

Общие параметры вида:

| Параметр | Описание |
|---|---|
| Сторона | Слева / справа / в обе стороны (зеркально). Сторона задаётся относительно экрана, как сейчас у панелей |
| Ширина | В метрах сцены; рядом кнопка «авто» (значение `autoPanelWidth`). Заменяет «Ширина колонки (90 — обычная)» |
| Отступ от ствола | В метрах; по умолчанию авто (стопкой за предыдущим слоем) |
| Прозрачность | 0–100 % |
| Границы интервалов | Тонкие линии (существующий `boundaries`) |
| Разделение (split) | Порог: значения ниже порога рисуются в одну сторону, выше — в другую |

### 6.3. Шкала (длина столбца, положение линии, радиус)

| Параметр | Описание |
|---|---|
| От, до | Пусто — по данным. Кнопки быстрого выбора: «мин – макс», «P2 – P98», «0 – P99» |
| Логарифмическая | Переключатель; для полей-содержаний включена по умолчанию (существующая проверка `isGrade`) |
| Закреплена / по данным | «По данным» пересчитывает границы при обновлении таблицы (аналог Dynamic в Leapfrog) |
| Выше максимума | Обрезать по максимуму / обрезать и пометить (штрих на конце столбца) / рисовать как есть |

### 6.4. Цвет

Режим — сегментированные кнопки: **один цвет**, **градации**, **непрерывная шкала**, **по другому полю**.

**Один цвет:** палитра из недавних и цветов проекта плюс системный выбор цвета.

**Градации — редактор на гистограмме:**

```
 кол-во проб                              [лог X] [накопл.]
   ▂▅█▇▅▃▂▁▁
 ──┼────┼──────┼────────┼──   ← границы тянутся мышью
  0,1  0,3     1        3       двойной щелчок — новая граница
 👁 ■ < 0,3        12 480  55 %  [подпись]         ✕
 👁 ■ 0,3 – 1       6 120  27 %
 👁 ■ 1 – 3         2 950  13 %
 👁 ■ ≥ 3           1 113   5 %
 [+ класс] [Авто ▾] [Градиент ▾] [Вставить границы]
```

- Гистограмма строится по значениям поля во всём наборе (данные уже загружаются через `loadDownhole`). Переключатели: логарифмическая ось X, накопленное распределение, взвешивание по длине интервала.
- Столбцы гистограммы окрашены в цвет своего класса.
- Границы: перетаскивание мышью, стрелки на клавиатуре, точный ввод числа в строке класса. Двойной щелчок по гистограмме добавляет границу, Delete удаляет выбранную.
- Строка класса: глаз (скрыть класс в сцене), цвет, границы, число проб и доля, своя подпись, удалить.
- «Авто»: число классов и способ — квантили (равное число проб), равные интервалы, логарифмические, прогрессивная (≈33/27/20/13/6 %), двойная прогрессивная (≈50/25/12,5/6/3 %), круглые значения (текущий `defaultClasses`).
- «Вставить границы»: поле для списка «0,3 1 3 10» — быстрый ввод бортов.
- «Градиент»: готовые градиенты (серый → красный, синий → красный, viridis, turbo, «геохимия»: серый-синий-зелёный-жёлтый-красный-пурпурный), обратный порядок, «растянуть между выбранными» (аналог Colour Ramp: выделить два класса — промежуточные получают переходные цвета).
- Правило границы: значение, равное границе, относится к верхнему классу (как в `classColor`); показать это в подсказке.
- Число знаков в авто-подписях.
- Цвет для значений вне классов и пустых — отдельный образец «нет данных».

**Непрерывная шкала:** градиент из того же списка, обратный порядок, границы «от – до» (по умолчанию как в разделе «Шкала», можно отвязать), растяжка: линейная / логарифмическая / по квантилям. Та же гистограмма с полосой градиента под ней и двумя перетаскиваемыми границами.

**По другому полю:** выбрать поле той же таблицы (число или текст) и его раскраску. Пример: столбцы по AU, цвет по литологии.

**Текстовое поле (литология, категории событий):**

- список значений с поиском, числом интервалов и суммарной длиной по каждому; без ограничения в 60 строк (виртуальная прокрутка);
- глаз у значения — скрыть в сцене; порядок перетаскиванием — порядок в легенде;
- выделение нескольких (Shift, Ctrl) и общий цвет; «Случайные цвета»; «Цвета из градиента»;
- импорт соответствия «код — цвет» из CSV и из буфера обмена; экспорт туда же;
- объединение кодов в группу с общим цветом и подписью (вторая очередь, если не успеешь).

**События:** значок, размер (постоянный или по числовому полю), цвет — один / по значению поля; для текстового поля значок можно назначить каждому значению.

### 6.5. Фильтр и особые значения

| Параметр | Описание |
|---|---|
| Показывать | Все / значения ≥ X (борт) / диапазон от – до |
| Скрытые классы | Сводка по «глазам» из раздела «Цвет», с кнопкой «показать все» |
| Пустые значения | Пропуск / рисовать цветом «нет данных» |
| Ноль и отрицательные | Как есть / считать пустыми / заменить на значение (например, половина предела обнаружения) |
| Значения ≤ X считать пустыми | Для кодов вроде −999 |
| Условие по другому полю | Поле, оператор, значение (например, LITH = «кварц») — вторая очередь |

При логарифмической шкале ноль и отрицательные всегда прижимаются к минимуму шкалы; об этом пишет подсказка.

### 6.6. Подписи

| Параметр | Описание |
|---|---|
| Включить | Переключатель |
| Шаблон | Текст со вставками полей: `{AU} г/т`, кнопка «Вставить поле» (любые поля той же таблицы, глубины `{from}`, `{to}`, длина `{len}`) |
| Число знаков | 0–4 или «как в данных» |
| Только для значений ≥ X | Чтобы подписывать только рудные интервалы |
| Размер, px | |
| Цвет | Как у класса / свой |
| Положение | У столбца снаружи / у ствола |
| Плотность | Не больше N подписей в кадре; при нехватке бюджета (`MAX_LABELS`) оставлять самые высокие значения |

## 7. Полоса стиля и библиотека

Три уровня сохраняемого:

| Уровень | Что содержит | К чему применяется |
|---|---|---|
| Раскраска | Градации, или градиент с границами, или цвета категорий | К разделу «Цвет» любого слоя подходящего типа |
| Стиль слоя | Всё из раздела 6, кроме таблицы и поля; раскраска внутри или ссылкой | К любому слою того же типа данных (число, текст, событие) |
| Шаблон отображения | Список слоёв с именами полей | К любой таблице или набору: поля сопоставляются по имени |

Полоса стиля вверху окна работает с шаблоном отображения; в меню слоя и в разделе «Цвет» — такие же элементы для стиля слоя и раскраски.

Элементы полосы:

- выпадающий список: галерея с мини-образцами, поиск, группы «Встроенные», «Проект», отметка «изменён» у текущего;
- значок связи 🔗: выключен — копия, включён — связан;
- меню `⋯`: сохранить, сохранить как…, переименовать, сделать стилем по умолчанию для поля, применить к…, где используется, экспорт в файл, импорт из файла, удалить.

Поведение:

| Действие | Результат |
|---|---|
| Выбрать стиль | Настройки копируются в слой или отображение; в полосе остаётся имя источника |
| Изменить настройку у копии | Рядом с именем появляется «изменён»; доступны «Обновить стиль» и «Сохранить как новый» |
| Включить связь | Слой перестаёт хранить свои настройки и берёт их из стиля |
| Изменить настройку у связанного | Над разделами полоса-предупреждение: «Связан со стилем „X“ — используется в N отображениях» и два действия: «Изменить стиль (обновит N)» и «Отвязать и изменить только здесь» |
| Сохранить связанный стиль | Все отображения, где он используется, перестраиваются в сцене сразу |
| Удалить стиль, который используется | Предупреждение со списком; связанные слои получают копию настроек и отвязываются |
| Применить к… | Окно со списком наборов, таблиц и полей (флажки, поиск): создать новые отображения или заменить стиль в существующих; выбор «копией» или «связать» |
| Применить шаблон к другой таблице | Поля сопоставляются по имени без учёта регистра; для несопоставленных — таблица «слой → поле» с выбором или пропуском |
| Где используется | Список отображений с переходом к каждому |

Стиль по умолчанию для поля:

- у стиля слоя есть список имён полей (`AU`, `AU_PPM`, шаблон с `*`), для которых он применяется автоматически при добавлении слоя;
- так раскраска и вид, один раз настроенные для AU, сами появляются в любой другой таблице проекта с полем AU;
- при автоматическом применении форма показывает заметку «Применён стиль „X“ (по умолчанию для AU)» с кнопкой «сбросить».

Встроенные стили (только чтение, можно скопировать): «Столбцы, один цвет», «Столбцы по градациям», «Ступени с заливкой», «Линия», «Трубка по шкале», «Лента по градациям», «Литология: трубка с подписями», «События: значки».

Файл стилей:

- расширение `.bfstyle.json`; содержимое: `{ "format": "bedrockforge-styles", "version": 1, "styles": [...] }`;
- экспорт: один стиль, выбранные или вся библиотека проекта; связанные раскраски вкладываются;
- импорт: проверка формата и версии, таблица конфликтов по имени (заменить / оставить оба / пропустить), итоговая сводка;
- неизвестные поля в файле не теряются при повторном экспорте.

## 8. Модель данных

Все новые поля необязательны; старые сохранённые отображения должны открываться без миграции данных (`withDefaults`).

Расширение `Track` (`web/src/charts/stripLog.ts`):

```ts
type TrackType = "line" | "bars" | "steps" | "points" | "color" | "text" | "color_text" | "event";

interface Track {
  // ...existing fields
  visible?: boolean;                       // default true
  side?: "left" | "right" | "both";
  widthM?: number;                         // metres; unset: derived from `width` as now
  offsetM?: number;                        // metres; unset: stacked automatically
  opacity?: number;                        // 0..1
  split?: number | null;
  dynamic?: boolean;                       // scale bounds follow the data
  over?: "clip" | "mark" | "asis";         // values above the scale maximum
  radius?: { by: "fixed" | "value"; min: number; max: number; log: boolean };
  colorBy?: "single" | "classes" | "scale" | "field";
  colorField?: string;
  gradient?: { name: string; reverse: boolean; stretch: "linear" | "log" | "quantile"; min: string; max: string };
  noDataColor?: string;
  hidden?: string[];                       // hidden categories
  catOrder?: string[];
  filter?: { mode: "all" | "min" | "range"; min?: number; max?: number;
             empty: "skip" | "nodata"; nonPositive: "asis" | "empty" | { replace: number }; emptyBelow?: number };
  label?: { on: boolean; template: string; decimals: number | null; min?: number; size: number;
            color: "class" | string; place: "outside" | "trace"; limit?: number };
  style?: { id: number; name: string; linked: boolean; modified?: boolean };
  palette?: { id: number; name: string; linked: boolean };
}

interface ColorClass { from: number | null; color: string; label?: string; hidden?: boolean }
```

- `StripLogSettings` получает `template?: { id; name; linked; modified? }`.
- Связанный слой хранит в `settings` только ссылку и привязку к данным (`table`, `field`, `id`); настройки подставляются из стиля перед построением геометрии. Сделай одну функцию `resolveTracks(settings, styles)` и вызывай её и в сцене, и в форме.
- 2D-колонка (`StripLogChart`) должна продолжать работать: новые виды `steps` и `points` либо поддержи, либо рисуй как `bars` и `line`.

Сервер:

- новая таблица `style`: `id`, `project_id`, `name`, `level` (`palette` | `layer` | `display`), `data_kind` (`number` | `text` | `event` | `mixed`), `body` JSONB, `default_for` JSONB (список имён полей), `builtin` нет в базе (встроенные живут в коде фронта), `created_at`, `updated_at`; уникальность (`project_id`, `level`, `name`);
- миграция `0010_styles`: создать таблицу, перенести строки `palette` как `level = "palette"`; `downgrade` возвращает обратно;
- маршруты `api/app/routers/styles.py`:

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/projects/{id}/styles?level=` | Список |
| PUT | `/api/projects/{id}/styles` | Создать или заменить по (`level`, `name`) |
| PATCH | `/api/styles/{id}` | Переименовать, изменить `body`, `default_for` |
| DELETE | `/api/styles/{id}` | Удалить; отвязку слоёв делает клиент перед удалением |
| GET | `/api/styles/{id}/usage` | Отображения проекта, где стиль связан или был источником |
| GET | `/api/projects/{id}/styles/export?ids=` | Файл `.bfstyle.json` |
| POST | `/api/projects/{id}/styles/import` | Тело файла + решения по конфликтам |

- проверка `body` на сервере: границы классов возрастают, цвета `#rrggbb`, не больше 40 классов (перенеси правила из `palettes.py`), размер `body` ограничен;
- старые маршруты `/palettes` удалить после перевода формы (они используются только в `DownholeForm.tsx`); проверь это поиском перед удалением;
- если добавляешь таблицу с файлами — см. `OWNERS` в `app/storage/gc.py`; у `style` файлов нет, добавлять не нужно.

## 9. Геометрия и сцена

Изменения в `web/src/viz/downholeGeometry.ts`:

- сторона, ширина в метрах, отступ, зеркальный вид, разделение по порогу;
- виды `steps` и `points`;
- урезка выше максимума с пометкой;
- радиус трубки по значению;
- фильтр и особые значения применяются до построения; скрытые классы и категории не строятся;
- прозрачность слоя;
- подписи значений по шаблону с бюджетом и приоритетом высоких значений;
- `stackOf` учитывает сторону и явный отступ.

Сцена и легенда (`SceneView.tsx`):

- легенда показывает слои отображения, для градаций — классы с числом проб;
- щелчок по записи легенды открывает форму на этом слое;
- глаз в легенде скрывает класс или категорию (то же, что глаз в форме) — можно во вторую очередь.

Производительность:

- набор на скриншоте — 22 663 пробы; целевое время перестроения после правки настройки — до 100 мс на 50 тыс. интервалов;
- правки, не меняющие геометрию (цвет класса, прозрачность), обновляют только цвета буфера;
- гистограмма считается один раз на поле и кэшируется; перетаскивание границы не пересчитывает её;
- предпросмотр во время перетаскивания — через `requestAnimationFrame`, без запросов к серверу.

## 12. Проверка

Тесты (vitest, рядом с существующими `stripLog.test.ts`, `downholeGeometry.test.ts`):

- `withDefaults` и `resolveTracks`: старые настройки без новых полей; связанный слой; слой со ссылкой на удалённый стиль;
- `classify.ts`: каждый способ на равномерных, логнормальных, вырожденных (все значения равны, одно значение, пусто) данных; границы возрастают и не повторяются;
- геометрия: сторона, зеркальный вид, отступ, урезка, фильтр по борту, скрытый класс, радиус по значению, бюджет подписей;
- сопоставление полей по имени при применении шаблона;
- формат файла: экспорт → импорт даёт то же самое; неизвестная версия отклоняется с понятным сообщением.

Тесты сервера (pytest, рядом с `api/tests/test_intervals.py`): маршруты `styles`, проверка `body`, уникальность, миграция `0010` вверх и вниз с данными `palette`, список использований, импорт с конфликтами.

Ручная проверка в приложении (демо-проект, лента → «Демо-проект»):

- [ ] старое отображение «AU · столбцы» открывается и выглядит как раньше;

- [ ] стиль по умолчанию для AU сам применяется при добавлении слоя AU в другой таблице;
