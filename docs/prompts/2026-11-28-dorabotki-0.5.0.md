> Для сессии «Комбайн по сборке ГГИС 2.0» (основная ветка разработки BedrockForge 2.0).
> Составлен 2026-11-28 по замечаниям владельца продукта. Код при составлении не проверялся:
> места в проекте, затронутые модули и объём работ уточняются на этапе ТЗ/ADR.

## Задача

Внести перечисленные ниже доработки и исправления в ТЗ (`docs/TZ`, `docs/spec`), план вех/этапов
и `PROGRESS.md`, затем реализовать по этапам. Правила проекта из `CLAUDE.md` обязательны:

- тексты для пользователя — по-русски; идентификаторы и комментарии — по-английски;
- каждая команда — запись в реестре (лента, Ctrl+K, клавиши, ассистент);
- только собственные окна, никаких `window.confirm/prompt/alert/open`;
- ошибки — `{code, message, hint}` по-русски с подсказкой; пропуски не превращать в ноль;
- новые зависимости — только через ADR (ADR 0001), лицензии MIT/BSD/Apache-2.0/MPL-2.0/ISC/PSF,
  проверка `tools/ci/check_licenses_py.py` и `tools/ci/check_licenses_npm.mjs`;
- файл ≤ ~600 строк; координаты float64.

Для каждого пункта в ТЗ: требование, место в интерфейсе, критерии готовности, затронутые модули
(`ui/`, `core/`, `app/`), этап/веха, приоритет. Конфликт с принятым решением — новый ADR,
а не переписывание старого.

Справочный репозиторий `bandurkin-ai/BedrockForge` (BF1) использовать **только** для пунктов,
где на него есть прямая ссылка (31, 40). Код переносить, а не писать заново
(см. `docs/spec/pril-e-…md`).

## Часть А. Ошибки версии 0.5.0 (приоритет — исправить первыми)

В журналах версия указана как 0.3.0 (интерфейс и ядро) — это и есть 0.5.0.
Проект тестирования: «Удокан», данные в `C:\Users\bandu\Yandex.Disk\Месторождения\Удокан\…`.

### А1. Импорт скважин: Micromine `.DAT` не распознаётся
- Файл `…\БД\DH_collars.DAT`.
- `POST /drillholes/import/inspect` → 422 `unsupported`: «Формат файла «.dat» не поддерживается
  или содержимое не похоже на таблицу», при этом подсказка перечисляет Micromine .DAT как поддерживаемый.
- Другие `.DAT` из той же папки (`collar_ser.DAT`, `assay_ser.DAT`, `ERR Core *.DAT`) читаются
  как «Micromine DAT (ibm-5347_P100-1998)», cp1251.
- Сделать: разобрать структуру проблемного файла (заголовок, версия формата, кодировка),
  сделать детектор устойчивым к вариантам Micromine DAT; при отказе — сообщать конкретную причину
  (какая строка/поле не разобраны), а не общее «не поддерживается».

### А2. Импорт скважин: интервальные таблицы определяются как устья
- `…\БД\ERR Core assay 03_10_10.DAT`: поля `Hole-ID, Sample, From, To, Length, Cu_%, Ag_G/T, …, X, Y, Z`.
  `/drillholes/import/check` вернул `kind: collar`, mapping `td ← Length`, 86 ошибок `duplicate_hole_id`.
- `assay_ser.DAT` с теми же полями (без X/Y/Z) определён верно — `kind: assay`.
- Гипотеза: при наличии X/Y/Z устья имеют приоритет над `From/To`.
- Сделать: **убрать** автоназначение типа таблицы, если он не соответствует разделу, в который
  идёт импорт; показывать определённый тип и причину несовпадения; предлагать выбор
  (импортировать в нужный раздел / сменить тип / отменить). `From`+`To` должны иметь приоритет
  над X/Y/Z при определении интервальной таблицы.

### А3. Диалог выбора файлов: кнопка «Добавить файлы» не запоминает папку
- При импорте нескольких файлов повторное нажатие «Добавить файлы» открывает диалог не в той
  папке, где был выбран предыдущий файл.
- Сделать: в пределах одного диалога/мастера открывать системный диалог в последней выбранной папке
  (см. также Б22).

### А4. Окна выбора цветов — быстрый выбор
- Добавить палитру: 10 стандартных цветов + 5 плашек последних пользовательских цветов.

### А5. Дерево данных — пакетное изменение свойств
- Выбор нескольких однотипных элементов мышью с Shift/Ctrl; изменение свойств применяется ко всем.

### А6. Импорт блочных моделей Micromine: `blocks_unaligned` на модели с субблоками
- `…\БМ\Геомет+1;2 Участок_Январь_2026.DAT`, 1 012 620 ячеек, 330 МБ, cp1251.
- Роли: `X,Y,Z` + `_X,_Y,_Z` (dx,dy,dz). Ошибка: 626 791 блок «не по подъячейкам 2^L».
  Родитель взят автоматически «по самому большому блоку: 10 × 10 × 10».
- Сделать: корректный импорт субблочных моделей Micromine (не обязательно октодерево; субблоки
  произвольного дробления). Если модель всё же не ложится в сетку — не отказывать целиком,
  а предложить: задать родителя/начало сетки вручную, импортировать как неструктурированную
  модель (список блоков с размерами), либо отменить.

### А7. Импорт блочных моделей Micromine: `broken` — заголовок в неверной кодировке
- `…\БМ\западный 1.DAT`, 546 МБ. Ошибка: «Строка описания поля не читается: «Òèï ðóäû  C255  0»».
- Текст — кириллица («Тип руды»), прочитанная как latin-1; файлы проекта cp1251.
- Сделать: определять кодировку заголовка DAT так же, как для тела; разбирать описание поля
  `<имя> <тип><ширина> <десятичных>` с именем, содержащим пробелы; при отказе — подсказка
  с выбором кодировки.

### А8. Редактор полилиний: кнопки общих функций не переключают режим
- Во время создания/редактирования полилинии нажатие «Провести разрез» не переключает инструмент:
  полилиния остаётся активной, вместо разреза рисуется полилиния.
- Сделать: кнопка завершает (или отменяет) текущую полилинию и переключает инструмент.
  Проверить все кнопки редактора на переключение к общим функциям в процессе редактирования
  (выбор, разрез, масштаб, отмена и т. п.).
