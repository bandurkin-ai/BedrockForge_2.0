# Промт: создание и редактирование стрингов (линий) и каркасов

Этот файл — задание на реализацию. Сначала прочитай `docs/HANDOFF.md`, `docs/ROADMAP.md` (этапы 24 и 25, разделы 2.3 и 8) и `docs/CHECKLIST.md` (модули «Линии и поверхности» и «Каркасы: построение»), затем код из раздела 3.

## 1. Цель

Сейчас BedrockForge только показывает линии и каркасы, загруженные из файлов. Геолог не может ничего нарисовать или исправить: чтобы оконтурить рудное тело на разрезах и получить из контуров каркас, ему приходится уходить в Micromine.

Нужно закрыть этот цикл внутри приложения:

1. нарисовать и поправить стринги в плане и на разрезе с привязкой к данным;
2. построить из стрингов поверхность или замкнутое тело;
3. проверить, исправить и скомбинировать каркасы (булевы операции, обрезка);
4. получить объём, которому можно доверять.

Ориентир по набору инструментов и по привычкам пользователя — Micromine (редактор стрингов, «Каркас → Создать», «Каркас → Булевы операции», «ЦМР»). Копировать его интерфейс не нужно: у нас одно 3D-окно, лента и палитра команд, инструменты должны встать в них.

| Упрощение | `api/app/geo/meshes.py` (`simplify`, pyfqmr) | Используется для уровней детализации |
| Чтение форматов | `api/app/formats/lines.py`, `wireframes.py`, `dxf_stream.py`; описание — `docs/FORMATS.md` | Записи в файлы нет |
| Эндпоинты | `api/app/routers/datasets.py` | Для линий и каркасов — загрузка, геометрия, `PATCH` имени и цвета, удаление |
| Фоновые задания | `api/app/jobs/` | Прогресс, журнал, отмена, повтор |
| Сцена | `web/src/viz/scene3d.ts` (`GeoScene`), `SceneView.tsx`, `geometry.ts` (`SectionLine`), `geometryLoader.ts`, `geometry.worker.ts` | `pickPoint` уже даёт точку на плоскости вида (план или вертикальная плоскость) — им рисуется линия разреза; `pickBlock` — пример запроса по клику |
| Дерево и свойства | `web/src/shell/DataTree.tsx`, `PropertiesPanel.tsx` | |
| Команды | `web/src/shell/registry.ts`, `ribbonConfig.ts` | Команда в реестре сразу доступна ленте, палитре, Claude и MCP |
| Журнал правок таблиц | `DataEdit`, `api/app/routers/datatables.py`, миграция 0013 | Образец для истории и отмены |

Что важно понимать про существующее устройство:

- **Показ идёт в float32 относительно `origin` объекта**, точные координаты — float64 в хранилище. Редактор обязан работать с точными координатами проекта: из сцены берётся только положение курсора, а вершины читаются и записываются в float64. Иначе после нескольких правок контуры «поплывут» на сантиметры.
- **Каждый объект стоит в сцене в своём начале.** Привязка между объектами считается в координатах проекта, а не в координатах сцены.
- **При включённом отсечении `pickPoint` должен давать точку в плоскости разреза** (середина окна «от / до»), а не в плоскости через центр вида: контур, нарисованный на разрезе, обязан лежать в плоскости этого разреза.
- Новая таблица с файлами хранилища добавляется в `OWNERS` (`app/storage/gc.py`), иначе очистка удалит её файлы.

## 5. Часть A. Редактор стрингов

### 5.1. Режим правки

- Правка включается на слое линий (дерево → правая кнопка → «Редактировать», лента «Моделирование», команда реестра). Активный слой один; остальные объекты видны и служат целями привязки.
- Новый слой создаётся пустым («+» у группы «Линии» → «Новый слой»): имя, цвет, код стринга.
- Пока есть несохранённые изменения, это видно в дереве и в строке состояния; уход из режима или закрытие вкладки спрашивает, сохранить ли.
- Инструменты работают в любом положении вида: в плане точки ложатся на заданный уровень Z, при включённом отсечении — в плоскость разреза, при привязке — в точку объекта (её Z берётся от объекта).

### 5.2. Инструменты

| Группа | Инструменты |
|---|---|
| Создание | Новая линия · новый полигон (замкнутый) · точка · продолжить линию с любого конца · замкнуть / разомкнуть |
| Вершины | Переместить · вставить на сегменте · удалить · ввести координаты с клавиатуры (X Y Z либо азимут, расстояние и угол наклона от предыдущей вершины) |
| Линии | Переместить · копировать · удалить · разорвать в вершине · соединить две линии · развернуть направление · сдвиг по Z · копия со смещением (для полигона — наружу или внутрь) |
| Форма | Проредить с допуском (Дуглас–Пекер) · сгустить с шагом · сгладить |
| Выбор | Щелчок, рамка, Shift — добавить; выбранные линии и вершины подсвечены; `Esc` — снять |
| Атрибуты | Код стринга, имя, свои поля линии (те же, что приходят из STR); перенос линии в другой слой |

Инструмент, которого нет в таблице, но без которого неудобно работать (например, повтор последнего), добавляй по своему усмотрению и перечисли в отчёте.

### 5.3. Привязка

| Цель | Что даёт |
|---|---|
| Вершина линии, середина и ближайшая точка сегмента | Стыковка контуров |
| Вершина и ребро каркаса | Опора на готовые тела |
| Линия сечения каркаса на текущем разрезе | Оконтуривание по существующей модели |
| Устье, точка траектории, границы интервала по стволу | Контур строго по границам проб — главный сценарий на разрезе |
| Узел координатной сетки | Ровные построения |

- Цели включаются и выключаются по отдельности; радиус привязки задаётся в пикселях экрана.
- Перед щелчком курсор показывает, к чему он привяжется (значок и подпись цели).
- На разрезе привязка к данным скважин **проецирует точку в плоскость разреза** или оставляет её истинное положение — переключатель, по умолчанию проекция (контуры одного разреза лежат в одной плоскости, это нужно для сшивки).
- Поиск целей не должен замедлять движение курсора на сцене с 10 тыс. скважин и каркасом в 10 млн треугольников: нужен пространственный индекс и поиск только среди видимого.

### 5.4. Свойства и измерения

- У линии: число вершин, длина (3D и в плане), замкнутость; у полигона — площадь в его собственной плоскости и в плане, периметр.
- У слоя — сумма. Значения пересчитываются при правке.

### 5.5. Сохранение и история

- `PUT` геометрии слоя: вершины float64, начала линий, замкнутость, атрибуты. Сервер пересчитывает `extent`, `stats`, копию для показа.
- Каждое сохранение — запись в журнале версий слоя (кто, когда, сколько линий и вершин было и стало, ссылки на прежние массивы). «Вернуть версию» делает её текущей новой записью, ничего не стирая.
- Одновременная правка одного слоя с двух вкладок: второе сохранение не должно молча затирать первое (проверка версии, понятное сообщение).

## 6. Части B–E. Поверхности и каркасы

Общие правила для всех операций:

- запуск — из контекстного меню выбранных объектов, с ленты и командой реестра; параметры — в собственном диалоге приложения (`web/src/shell/dialogs.tsx`), не в браузерном;
- расчёт — фоновое задание с прогрессом и отменой; результат — новый каркас или слой линий в той же папке дерева, с именем по шаблону («A − B», «ЦМР: слой»), дальше обычный путь `add_wireframe` → `queue_derive`;
- в `stats` результата записываются: операция, исходные объекты, параметры, допуски — чтобы результат можно было воспроизвести;
- до расчёта проверяются предусловия (например, оба тела замкнуты); при нарушении задание не запускается, а пользователь видит, что именно не так и какой инструмент это исправит.

### 6.1. Часть B. Поверхности

| Функция | Требования |
|---|---|
| ЦМР из точек и линий | Триангуляция Делоне в плане; линии участвуют как структурные (рёбра триангуляции их не пересекают); граница — выпуклая оболочка или заданный полигон; отбрасывание треугольников длиннее заданного ребра; совпадающие в плане точки с разным Z — сообщение, а не тихий выбор |
| Изолинии | Сечение поверхности горизонтальными плоскостями с шагом; результат — слой линий с атрибутом отметки; основные и дополнительные горизонтали — разные коды |
| Объём между поверхностями | Объём выемки и насыпи между двумя поверхностями в пределах общего контура или заданного полигона; отдельно — объём между поверхностью и уровнем |

### 6.2. Часть C. Каркас из контуров

Это главный рабочий сценарий блока: геолог нарисовал контуры рудного тела на серии разрезов и хочет получить тело.

| Функция | Требования |
|---|---|
| Сшивка двух контуров | Два замкнутых стринга на соседних разрезах → полоса треугольников между ними без перекрутов и самопересечений; контуры с разным числом вершин и разной формы |
| Серия контуров | Выбрать несколько контуров — сшить по порядку разрезов в одно тело |
| Тай-линии | Пользователь указывает пары соответствующих вершин; сшивка обязана их соблюдать. Нужны там, где автоматический подбор соответствия даёт перекрут |
| Разветвления | Один контур на одном разрезе — два и более на соседнем |
| Замыкание торцов | Плоская крышка · выклинивание в точку · выклинивание в линию · продолжение на заданное расстояние (доля расстояния между разрезами) |
| Выдавливание | Полигон → тело на заданное расстояние по нормали или по вектору (для тел по одному разрезу и для слоёв) |
| Ручная правка | Удалить выбранные треугольники · добавить треугольник по трём вершинам — чтобы дошить место, с которым автоматика не справилась |

Результат серии с замкнутыми торцами — замкнутое тело, проходящее проверки этапа 10. Если это не так, задание сообщает, между какими контурами проблема.

### 6.3. Часть D. Правка каркасов

| Функция | Требования |
|---|---|
| Исправление | Сшить совпадающие вершины (с допуском) · удалить вырожденные и повторные треугольники · согласовать и развернуть нормали наружу · закрыть отверстия (открытые контуры рёбер) · убрать неманифолдные рёбра. Каждое исправление включается отдельно; отчёт «было → стало» по каждой проверке этапа 10 |
| Самопересечения | Устранить, если выбранная библиотека это умеет надёжно; иначе показать пересекающиеся треугольники в сцене и оставить исправление пользователю (ручная правка из 6.2) |
| Упрощение и сглаживание | Упрощение до числа треугольников или до допуска по отклонению; сглаживание без усадки объёма; в отчёте — изменение объёма и наибольшее отклонение от исходной поверхности |
| Объединение и разделение | Несколько каркасов → один объект · один каркас → отдельные связные части |

### 6.4. Часть E. Операции с каркасами

| Функция | Требования |
|---|---|
| Объединение, пересечение, вычитание | Для замкнутых тел; результат замкнут; объёмы сходятся: V(A∪B) = V(A) + V(B) − V(A∩B) в пределах записанного допуска |
| Обрезка поверхностью | Тело режется незамкнутой поверхностью (ЦМР, разлом) на части «выше» и «ниже»; пользователь выбирает, какую оставить, или получает обе |
| Обрезка плоскостью и полигоном | Плоскость разреза или уровень; полигон в плане (границы лицензии, карьера) |
| Пересечение как линии | Линия пересечения двух каркасов → слой линий |

## 7. Алгоритмы и библиотеки

Выбор за тобой. Ограничения:

- **Лицензия** должна допускать коммерческое использование без раскрытия кода. В частности, Triangle Шевчука для коммерческого использования не подходит — для триангуляции с ограничениями нужна другая реализация.
- **Булевы операции не писать с нуля.** Нужна библиотека с гарантией манифольдного результата и устойчивостью к почти совпадающим граням (типичный случай: два тела, построенные от общего контура). Проверь на таких данных до того, как строить на ней остальное; если кандидат не проходит — скажи об этом и предложи замену, не маскируй обходными путями.
- Зависимость добавляется в `api/pyproject.toml` с версией; сборка образа Docker (`docker compose build`) должна проходить.
- Тяжёлые ядра уже принято писать на numba (см. самопересечения этапа 10) — это допустимый путь для сшивки и привязки.
- Обрезка незамкнутой поверхностью обычно сводится к булевой операции с телом, построенным от этой поверхности до уровня ниже модели. Это допустимо, если результат проходит тесты раздела 9.

## 8. Модель данных и API

Нужно спроектировать (и оформить обратимой миграцией):

- версии слоя линий и журнал сохранений (раздел 5.5);
- связь «результат ← операция ← исходные объекты» (достаточно `stats` результата, отдельная таблица — на твоё усмотрение);
- тай-линии: хранить ли их как служебный слой линий или в параметрах операции — реши и обоснуй; пользователь должен иметь возможность перестроить тело после правки контуров, не расставляя их заново.

Эндпоинты продолжают существующий стиль `routers/datasets.py`. Точные массивы вершин передаются двоично, не JSON (как `/api/blobs/{sha}`).

Экспорт (часть F): слой линий → Micromine STR и DXF; каркас → DXF и OBJ. Проверка «импорт → экспорт → импорт» без потери точности (совпадение координат float64 для STR в пределах точности текстового формата, записать допуск).

## 9. Проверка

Правило завершения этапа — `ROADMAP.md`, раздел 8. Для этого блока обязательно:

**Тесты точности (pytest, синтетика с известным ответом):**

| Что | Эталон |
|---|---|
| Площадь и длина полигона | Аналитически, в том числе для наклонного полигона |
| Сшивка двух одинаковых контуров | Призма: объём = площадь × расстояние |
| Сшивка с выклиниванием в точку | Пирамида: объём = площадь × высота / 3 |
| Сшивка контуров разной формы и с разным числом вершин | Замкнуто, нет самопересечений, объём в ожидаемых границах |
| Разветвление и тай-линии | Замкнуто; тай-линии присутствуют рёбрами результата |
| ЦМР | Плоскость и аналитическая поверхность: отклонение в узлах — ноль; структурная линия — ребро результата |
| Объём между поверхностями | Две плоскости над прямоугольником |
| Булевы операции | Кубы со сдвигом (точный ответ), сфера и куб (допуск по дискретизации), тела с общей гранью, тождество объёмов из 6.4 |
| Обрезка | Сумма объёмов частей = объём исходного тела |
| Исправление | Каркас с внесёнными дефектами каждого вида → все проверки этапа 10 пройдены, объём сохранён |
| Правка и сохранение слоя | Координаты после цикла «сохранить → прочитать» совпадают побитно; возврат версии восстанавливает массивы |

Допуск каждого теста записан в самом тесте и в `ROADMAP.md` 2.3.

Бюджетов для этих операций в `ROADMAP.md` 2.2 пока нет: измерь, предложи значения и внеси их туда.
