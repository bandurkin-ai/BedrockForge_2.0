# ADR 0024. Оценка содержаний: IDW, SK, OK, IK, поиск, проверка; SGS, SIS, ко-SGS (Э18, Э18б)

**Статус:** предложен 2026-11-25 (architect, opus); решения 1–22 — ниже. Вопросы № 76–87 не блокируют работу: до ответа действует «По умолчанию».
- **Исполняет:** ТЗ 8.8 (Т8.8-1…15; CHECKLIST № 320–329, 333, 334), 7.35 Д-21 (`kb2d`, `declus` ≤ 1e−9), Д-23 (Т18б-С1…С4), 8.0, 10.5.
- **Опирается на:** ADR 0001, 0002, 0012, 0014, 0018, 0022 (`rotation`, `variogram.model.Model`, `trend.matrix`, `object_refs(role="trend")`), 0023 (`Model`, `FieldsWriter`, `restrict`, `calc`, `filter`, `source.op = estimate`). Их не пересматривает.

## Варианты
| Вопрос | Варианты | Выбор и причина |
|---|---|---|
| Ядро оценки | А) порция 2¹⁶ целей → `cKDTree.query` пакетом → ядро numba `nogil` (отбор, система, LU, выходы); потоки над порциями (`composites/strips`); Б) всё на numba со своим поиском по суперблокам (GSLIB); В) numpy: пакетный `linalg.solve` | **А.** ТЗ называет cKDTree и LU numba. Порции не зависят от числа потоков, поэтому результат побитный. Б — лишние ≈ 600 строк без выигрыша по ТЗ; В — переменное n, BLAS-потоки, нет правила главного элемента 1e−12·C(0) |
| Хранение параметров | А) объекты `estimation` (строка) и `estimation_plan`; Б) JSON в `meta` модели; В) один объект плана со строками внутри | **А.** ТЗ: «строка — объект с повторным запуском»; дерево, `.bfggis` и `object_refs` работают как есть |
| Модель вариограммы в строке | А) копия `Model.as_dict()` + id и sha; Б) только ссылка | **А.** Расчёт воспроизводим; правка модели делает строку «устарел» (как тренд, ADR 0022 §10) |
| Реализации SGS | А) объект `simulation` + blob Parquet f4/u1; Б) N полей модели; В) только кеш | **А.** 20 полей на переменную засоряют модель; ТЗ: «реализации SGS — в проекте». Постобработка пишет поля через `FieldsWriter` |
| Где живёт модуль | А) `geostat/estimate/*`, `geostat/simulation/*`, роутер `geostat/router.py`; Б) пакет `estimation` | **А** (ADR 0022: «Э18 — туда же, один роутер») |
| Где считается | А) предпросмотр блока — синхронно в слоте HEAVY (≤ 100 мс), остальное — заданиями; Б) всё заданиями | **А** (8.0.2; эллипсоид поиска и KNA в 3D у блока) |

## Решение
**1. Состав.**
- Ядро `geostat/estimate/`: `spec` (параметры, умолчания, диапазоны, 422), `samples`, `cov`, `search`, `krige`, `methods` (NN, IDW), `indicator`, `kernel` (порция → проходы → метод), `store`, `job`, `xval`, `kna`, `checks`, `routes`, `routes_check`, `warm`.
- Э18б `geostat/simulation/`: `path`, `nodes`, `sgs`, `sis`, `cosgs`, `post`, `store`, `job`, `routes`, `warm`.
- ui: `modules/estimation/*`, `modules/simulation/*` (Э18б).
- Каждый файл ≤ 600 строк.

**2. Схема данных** (миграции нет; роли blobs `xval`, `real` — в `db/schema.py`):
```
objects(kind="estimation").meta v1  — «Параметры оценки», раздел дерева «Геостатистика → Параметры оценки»
  model_id; target {domain_field (cat|number модели), label, filter_id?|rules?}; sub: parent|own; disc [nx,ny,nz]
  samples {set_id, table, field, unit, domain {table, field, values[]}, soft {domains[], dist}, topcut {field}|{value}|null, weights}
  method {kind: nn|idw|sk|ok|ik, power, mean {mode: declus|value, value?}, ik {thresholds[], models: per|median, class_means}}
  variogram {model_id, snapshot, sha} | ik: [{t, model_id, snapshot, sha}]; trend_id?
  search {ang1..3, r1..r3, from: model|trend|manual, passes ≤5 [{factor, n_min, n_max, n_hole, n_oct, k_oct, n_holes_min}]}
  outputs {prefix, fields [EST KV NS NH AD DMIN PASS SLOPE KE LAGR SNW NOCT | P1..PK ETYPE]}
  origin [x,y,z] (центр охвата всех проб строки); inputs {table name_key/token/rev, trajectories, variogram sha, model shas}; algo "est-1"; versions; last_run {at, job, counts, by_pass[], singular, merged}
objects(kind="estimation_plan").meta v1 {model_id, items: [estimation_id…]}  — порядок = порядок строк
object_refs(src=estimation → trend, role="trend"), (→ filter, role="filter"); blob роли xval (Parquet таблицы проверки)
Э18б: objects(kind="simulation").meta {model_id, kind: sgs|sis|cosgs, estimation-подобные параметры, seed, n_real, secondary {field, rho}, nodes, inputs}
      blob роли real: Parquet, строки — цели (P, D) по порядку модели: p u64, dom i2, r001…rN (f4; SIS-категории u1)
Поля модели: EST f8 (role grade, unit пробы); KV, SLOPE, KE, LAGR, SNW, AD, DMIN f4; NS, NH i2; PASS, NOCT i1; P_k, ETYPE f4/f8
  source {op: estimate, params {estimation_ids}, inputs [sha], algo, versions}. Не оценено, вне ограничителя, вне домена — NaN/null, не 0
```

**3. Пробы и домены (`samples.py`).**
- Чтение: `stats/source.read`; положение — середина интервала (`midpoints`); домен — `domain_at`; урезка — поле `*_CUT` или порог min(z, T); веса — `DECL_W`, если поле есть.
- Пропуски не участвуют и считаются (`counts`).
- Пробы одного домена с совпадающими координатами (≤ 1e−6 м) усредняются; число — в журнал.
- Канонический порядок: lexsort (X, Y, Z, значение). «Номер пробы» в правилах равенства — позиция в этом порядке (№ 76).
- Опорная точка `origin` — центр охвата всех проб строки. Она хранится в строке и не меняется при перекрёстной проверке.
- Домены: метка блока ↔ значения домена проб (по умолчанию по совпадению имён, правка в мастере).
- Граница жёсткая; мягкая — пробы из S при евклидовом расстоянии до центра блока ≤ d_м (№ 79).

**4. Поиск (`search.py`).**
- Пространство, где эллипсоид — шар: diag(1, r1/r2, r1/r3)·R_s. Одно дерево на строку плана (D ∪ S); проходы — то же пространство, радиус × factor.
- Кандидаты: пакет порции 2¹⁶; k_c = max(4·n_max, 64). Повтор с k_c × 4, если после ограничений проб < n_max и k_c-е расстояние < r1. Повтор и тогда, когда отобранная проба равна k_c-му расстоянию.
- Отбор по (h_s, номер): n_скв, октанты в осях эллипсоида (n_окт, k_окт), n_скв_min.
- Блок оценивается первым проходом, где ограничения выполнены. Главный элемент < 1e−12·C(0) — переход к следующему проходу и запись в журнал.

**5. Кригинг (`cov.py`, `krige.py`).**
- Структуры передаются массивами. C и C* по 8.8.2; C̄_VV считается один раз на размер блока и кешируется.
- Точки дискретизации — в локальных осях модели с поворотом R_z(φ).
- LU с выбором главного элемента (n ≤ 129). SK, OK; выходы λ, μ, KV, SLOPE (для SK = 1), KE, SNW.
- numba `cache=True, nogil=True`, без `prange` и `fastmath`; BLAS нет.

**6. Методы.**
- NN — равенства по номеру.
- IDW — h_s; при h < 1e−9·r1 — среднее совпадающих проб (BF `idw`).
- SK — m: декластерированное среднее домена или заданное.
- IK — пороги; модель на порог или медианная; поправка порядка GSLIB (обрезка [0; 1], среднее поправок вверх и вниз); поля P_k и ETYPE, m_k — декластерированные средние классов.

**7. Субблоки и запись (`job.py`).**
- `sub: parent` — оценка в центре P с дискретизацией P, все строки (P, D) получают её. `own` — дискретизация по размеру субблока, C̄_VV по размерам.
- Проход по модели порциями: K порций считаются потоками, пишутся по порядку (очередь ограничена). Один `FieldsWriter` на задание (`replace=True` после подтверждения).
- Строки плана с одним префиксом сливаются в одни поля. Повторный запуск строки переписывает только строки её домена, остальные значения поля переносятся из текущего (№ 77).
- Стадии: «Пробы», «Поиск и кригинг: проход k», «Запись». Отмена между порциями; сбой ничего не оставляет.
- «Устарел» — `inputs` против текущих; «Перестроить» — задание.

**8. Проверка.**
- `xval.py` — то же ядро с маской исключения (проба или скважина, по умолчанию скважина) и той же `origin`. Таблица в blob `xval`; сводка: средняя ошибка, СКО, MAE, r, наклон, среднее (ошибка²/KV).
- `kna.py` — тестовые блоки щелчком или три автоматически (квантили 0,9/0,5/0,1 числа проб в r1). Перебор по одному параметру: n_max 4…64 шагом 4, радиусы ×0,5…×2 шагом 0,25, дискретизация 1…5, размер ×0,5/×1/×2 (№ 80). Рекомендация — наименьший n_max с SLOPE ≥ 0,95·max; автоматически не применяется.
- `checks.py` — глобальная статистика: композиты наивно и декластерированно, NN на лету без записи, оценка с весом объёма; норма ≤ 5 %; C̄_VV против дисперсии оценок. Q-Q — `qq_samples`.
- Swath — заготовка окна Э13: ряд `blocks` с фильтром домена и ряд `samples` с весом `DECL_W` или без, `within: blocks`.

**9. Э18б (Д-23).**
- **SGS:** `nscore` с весами → путь по целям (P, D) родителей регулярной модели в локальной сетке. `variable_grid` → 422 (№ 83).
- **Случайные числа:** `PCG64(SeedSequence(seed).spawn(N)[r])`.
- **Условие:** SK со средним 0 по пробам (n_max 24) и узлам (12). Узлы — спиральный шаблон смещений сетки, отсортированный по C (GSLIB).
- **Обратное преобразование:** `stats/transforms.backtr`.
- **Потоки:** реализации параллельно, каждая последовательно.
- **SIS:** индикаторный SK/OK на порог; поправка порядка; выборка с хвостами `backtr`; категории по p_k.
- **Ко-SGS:** марковская модель 1, система n + 1; ρ задаётся или считается по колокированным нормальным оценкам. ρ = 0 — путь SGS побитно; |ρ| = 1 — значение вторичной без системы.
- **Постобработка** (`simulate.post`): `stats/local.local_*` → поля MEAN, STD, P10/P50/P90, PROB>t.

**10. Команды** (вкладка «Геостатистика»; лента и дерево — оркестратор):
- «Оценка» — `estimate.open` (мастер), `estimate.plan`, `estimate.ellipsoid`;
- «Проверка» — `estimate.xval`, `estimate.kna`, `estimate.swath`, `estimate.global`, `estimate.qq`;
- «Моделирование» — `simulate.sgs` (+ `secondary`), `simulate.sis`, `estimate.open {method: "ik"}` («Индикаторы»).
- Плюс `estimate.run`, `estimate.delete`, `simulate.post`.
- Признаки: confirm — у `run` (при замене полей), `delete`, `post`. Без параметров команда открывает окно. «Только просмотр» — 423.
