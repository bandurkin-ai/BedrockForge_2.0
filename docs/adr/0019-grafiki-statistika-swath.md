# ADR 0019. Графики и статистика; swath в плавающем окне с вращаемым коробом (Э13)

**Статус:** Принят 2026-11-21 (проект — architect, fable / xhigh; решения 1–24 приняты оркестратором по разрешению 1 мастер-промта; вопросы № 25–33 — заказчику, до ответа — «По умолчанию»). Исполняет ТЗ 7.25–7.30, 8.3 (Т8.3-1…3; № 224–228, 237 из 7.34), 7.35 Д-01 (ответ № 8), 7.0.12, 7.0.13. Опирается на ADR 0003 (таблица `charts`), 0007 (график — `objects(chart)` + `charts`; ключ вида `swaths`), 0008 (Д-01: окно, ручки, расчёт в системе короба), 0016 (серии разрезов как плоскости выборки), 0017 (регулярные блочные модели), 0018 (`stats/weighted.py`, `DECL_W`, `charts/column/`, кривые урезки, `stats.open {analysis: "declus"}`) и не пересматривает их. Решения 1–24 — в конце; вопросы заказчику № 25–33 — отдельной таблицей, блокирующих нет: до ответа действует столбец «По умолчанию».

## Контекст

## Варианты

| Вопрос | Варианты | Выбор и причина |
|---|---|---|
| Где хранится swath | А) `objects(kind="chart", parent_id=NULL)` + `charts(kind="swath")`; Б) `objects(kind="swath")` + `meta`, свой CRUD (как виды, ADR 0008); В) таблица `swaths` (миграция 0008) | **А.** Один механизм «график с настройками, расчёт по текущим данным»: тот же API `/charts`, версия и 409, `auto_name`, автосохранение окна, `archive/spec.py`. Б — второй CRUD и второе автосохранение ради того же; В — миграция без запросов по полям (ADR 0003 §3) |
| Где считается | А) синхронно в процессе API (пул потоков, кеш колонок); Б) задания `quick` с опросом; В) в интерфейсе по выгруженным колонкам | **А.** Цели — ≤ 2 с; задание добавляет запуск исполнителя и опрос, окно теряет отклик «правка → график»; В не держит 5 млн проб в окне и дублирует расчёты. Тяжёлых расчётов одновременно ≤ 2 (решение 5) |
| Чем рисовать | А) свой SVG (как отображения по стволу и кривые урезки) + canvas для облака точек; Б) библиотека графиков (новая зависимость — ADR 0001); В) всё на canvas | **А.** Окна BF — SVG и переносятся; экспорт SVG и PNG × 2 уже есть (`charts/striplog/export.ts`); зависимость не нужна. Canvas — только точки рассеяния и тернарной (до 200 тыс.) |
| Ручки Д-01 | А) в главном 3D: кольцо и две дуги у выбранного swath; Б) мини-3D в окне и ручка поворота в плане (BF HEAD); В) только числа | **А** — текст Д-01 и ADR 0008. Из Б берётся математика, не мини-окно |
| Ряд блочной модели | А) плотные центры и размеры (BF): 20 млн × 3 × 8 Б = 480 МБ и матричное умножение; Б) ядро по `idx`: t = a[i] + b[j] + c[k] | **Б.** BF2 хранит номера ячеек; память — только колонки значения и веса, ядро — один проход |
| Связь выделения (№ 237) | А) выделение — список id строк таблицы в ядре (жетон) → слой отрезков в 3D и фильтр таблицы; Б) подсветка только скважин; В) выбор проб рамкой в 3D | **А** в объёме решения 16; Б не выполняет Т8.3-3 («ровно выбранные пробы»); В — нет выбора интервалов в 3D, отдельная работа (вопрос № 26) |

### 2. Хранение: `charts`, ключ вида `swaths`, `.bfggis`

| Что | Решение |
|---|---|
| График набора | `objects(kind="chart", parent_id=<набор>)` + строка `charts`; виды: `histogram`, `qq`, `dendrogram`, `scatter`, `box`, `probplot`, `contact`, `ternary`, `domains` (и прежний `striplog`). Миграции нет, `db/schema.py` не меняется |
| Swath | `objects(kind="chart", parent_id=NULL)` + `charts(kind="swath")` — объект проекта, строка раздела «Аудит и статистика»; не больше 200 на проект |
| `settings` | JSON `v: 1`, ≤ 64 КБ (`striplog` — прежние 256 КБ). Ядро проверяет вид, версию, размер, списки (рядов ≤ 12, полей дендрограммы ≤ 100, скважин ≤ 10 000; поправка 13.37: 64 КБ вмещают ≈ 5–6 тыс. имён по 8–10 символов — предел 64 КБ сохраняется, длинный список получает своё сообщение до проверки размера) и идентификаторы; форму остальных полей ведёт интерфейс (`withDefaults`, как у `striplog`). Таблица — `name_key`, поля — имена (ссылка переживает замену таблицы и `.bfggis`, ADR 0007); чужие объекты — id: `y_set_id`, `series[].set_id`, `series[].model_id` |
| Имя | Создаётся с `auto_name = true`; имя строит интерфейс из настроек («Гистограмма · AU · по длине», «Q-Q · AU · логнормальное», «Swath plot · X · 25 м»), занятое — « (2)». `PUT {settings, auto_name: "<имя>"}` переименовывает, пока флаг стоит; `PUT {name}` снимает флаг навсегда (Т7.28-2) |
| Когда сохраняется | Сразу при открытии командой (7.28): гистограмма, Q-Q, дендрограмма, графики 8.3 (вопрос № 33) и swath. Правка настроек — `PUT` с задержкой 400 мс и `expected_version`; 409 — окно берёт серверные настройки. Проект «только просмотр» — окно считает и рисует, не сохраняя (пометка в заголовке) |
| Данные | Не хранятся: расчёт по текущим данным при каждом открытии и после события `drillholes.changed` / `objects.changed` источника (Т7.28-1, Т7.30-5) |
| Ключ вида `swaths` | `[{swath: <id>, visible: bool}]` ≤ 50 — swath, показанные в 3D; нормализация, `drop_missing`, `ids_in`, `map_ids` — `viewstate/keys.py`; входит в сохранённые виды (ADR 0008) |
| `.bfggis` | `charts` уже в `archive/spec.py`; `archive/chart_remap.py` перенумеровывает id наборов и моделей внутри `settings` (`swath`, `qq`, `scatter`); объекта в архиве нет — `null` с сохранённым именем (ряд — «источник удалён»). Тест цикла — 10.5 п. 5 |
| Удаление источника | Набор — его графики уходят каскадом (`parent_id`); набор или модель ряда swath — swath остаётся, ряд помечен. `object_refs` не заводятся (как у видов: иначе удаление модели давало бы 422) |

### 3. Источник данных, кеши, где считается

| Что | Решение |
|---|---|
| Чтение таблицы | `stats/source.py` поверх `composites/source.read`: поле (компонент, числовой атрибут, `length` — длина интервала), вес, домен (текст → коды), список скважин, id строк; второе поле другой таблицы — по ключу пробы (скважина, FROM, TO), несовпавшие строки считаются; середины интервалов на траектории (`interval_positions`) — для swath, вкладки «Статистика» и подсветки в 3D |
| Домены | Текстовое поле той же таблицы или другой интервальной таблицы набора (код — по середине пробы, ядро `overlay` Э12); каркасы — через «Кодировать каркасами» Э12 (вопрос № 32) |
| Кеш | Память процесса API, LRU: колонки таблиц — по (таблица, `token`, `rev`, поле), ≤ 512 МБ (13.35: было 256 МБ — на 5 млн строк строки таблицы занимают 120 МБ, поле — 40 МБ, середины интервалов — 120 МБ: десять полей дендрограммы, swath по пробам и рассеяние двух таблиц в 256 МБ не помещались и читались заново при каждом пересчёте; `length` не хранится); колонки моделей — `stats/blocks_cache.py` по (SHA-256 ячеек, колонка), ≤ 600 МБ (`idx` — uint32 при < 2³² ячеек). Правка данных меняет `rev` или SHA — промах и пересчёт; закрытие проекта очищает кеш |
| Где считается | Процесс API, пул потоков, ядра импортируются лениво (не до BF-READY; ADR 0018, решение 26); одновременно ≤ 2 тяжёлых расчётов (семафор), окно показывает «Расчёт…» и отбрасывает обогнанный ответ. Заданий `jobs` у Э13 нет |
| Пропуски | Строки без значения, без веса или с весом ≤ 0 не участвуют и считаются: `counts {rows, missing, bad_weight, negative, zero_excluded, bottom_capped, bottom_excluded, capped, top_excluded, used}` — видны в окне. Пропуск нулём не становится |

### 4. Формулы и допуски

| График | Формулы | Допуск в тестах |
|---|---|---|
| Отбор (общий для всех графиков, `stats/select.py`) | Порядок BF: пропуски и вес → значения < 0 (оставить, исключить, \|c\| / 2) → нули (исключить по галочке) → отсечка снизу (по умолчанию «исключить») → сверху (по умолчанию «заменить» — урезка); статистика — после отсечек. Вес: нет, длина, поле, длина × поле | Счётчики — точно |
| Описательная статистика | m = Σ w·c / Σ w; дисперсия генеральная Σ w·(c − m)² / Σ w; CV = σ / m; асимметрия Σ w·(c − m)³ / (Σ w·σ³); процентили — GSLIB: значение в середине накопленного веса P_i = (C_i − w_i / 2) / W, между — линейно, вне — крайние (без весов — Hazen); P5, 10, 25, 50, 75, 90, 95, 97,5, 99; геометрическое среднее, среднее и дисперсия ln — по c > 0. С весом и без — рядом | 1e−12 отн. против прямого счёта; Т7.25-1 — 1e−12 |
| Гистограмма | Бины [a; b), последний закрыт; линейные или равные в log10; авто — «круглая» ширина при ≈ √n бинов в пределах 10…60, либо ширина, либо число; «от — до»; ≤ 1000 бинов; Y — доля %, Σ весов, число; накопленная кривая с учётом значений ниже диапазона | Σ по бинам + вне диапазона = итог, 1e−12 |
| Q-Q с распределением | Проба в P = (C − w / 2) / W против μ + σ·Φ⁻¹(P) (логнормальное — по ln, взвешенные μ и σ); PPCC = r(Φ⁻¹(P), значение или ln); > 2000 точек — интерполяция в 2000 равных шагов вероятности между первой и последней, крайние значения остаются | Т7.26-1: PPCC ≥ 0,999 (логнормальная выборка 10 000, фиксированное зерно); Т7.26-3 — точно |
| Q-Q двух выборок | Квантили сторон при p_k = k / (n + 1), n = 99 по умолчанию; D Колмогорова–Смирнова = max \|F_x − F_y\| взвешенных распределений; таблица X / Y / отношение | Т7.26-2: D = 0, X = Y точно |
| Дендрограмма | r — взвешенный Пирсон или Спирмен (Пирсон средних рангов), по ln при `log`; пропуски — попарно (общих строк ≥ 3) или полные строки; расстояние 1 − r или 1 − \|r\|; связь `average` (UPGMA), `complete`, `single`, `weighted` — `scipy.cluster.hierarchy`; Ward не предлагается и отклоняется ядром; порог `cut` — группы (`fcluster`, расстояние) | Т7.27-1: высота слияния ≤ 1e−12 |
| Рассеяние | МНК: b = cov / σ²_x, a = ȳ − b·x̄; RMA: b = sign(r)·σ_y / σ_x; взвешенная — те же формулы с весами; r Пирсона и Спирмена; лог-оси — по log10 (значения ≤ 0 считаются и не участвуют); > 200 000 точек — плотность 100 × 100 ячеек в координатах осей | Т8.3-1: a, b — 1e−12 |
| Ящики с усами | По доменам: Q1, медиана, Q3 — `weighted_percentiles`; усы — крайние значения в [Q1 − 1,5·IQR; Q3 + 1,5·IQR]; выбросы — точки, до 5000 на график (сверх — прореживание, крайние остаются, число показано); среднее, n; лог-шкала — по логарифмам | Т8.3-1: квартили — 1e−12 |
| Лог-вероятностный | x — содержание (log), y = Φ⁻¹(P), P = (C − w / 2) / W; домены — отдельными линиями; до 2000 точек на домен, крайние остаются | Логнормальная выборка — прямая, r ≥ 0,999 |
| Контактный анализ | Контакт — граница смежных участков доменов A и B вдоль ствола (зазор ≤ 1e−6 м; через пропуск опробования контакта нет); проба относится к контакту по своему участку: сторона A — расстояние середины d < 0, B — d > 0, \|d\| ≤ D (20 м); шаг b (1 м): номер ⌊d / b⌋; по шагу — среднее с весом длины и n; проба дальше соседнего контакта своего участка не берётся дважды. Вариант «до каркаса» — контакт в точке пересечения ствола с каркасом (`geo/intersect.hole_crossings`), сторона — снаружи / внутри | Т8.3-2 — точно |
| Тернарная | (a, b, c) / (a + b + c); строки с пропуском или суммой ≤ 0 считаются и не рисуются | 1e−12 |
| По доменам | n, длина, взвешенное среднее, декластерированное среднее (по полю `DECL_W`, если оно есть; иначе пусто с подсказкой), медиана, σ, CV, min, max, P10, P50, P90 | Σ n = итог; среднее — 1e−12 |
| Нормальные оценки, бутстрап, декластеризация | GSLIB `nscore` / `backtr` (перенос BF), бутстрап с возвратом (зерно задаётся; среднее, медиана, σ, CV, P10, P90; интервал 2,5–97,5 %), ячейки и полигоны — ядра Э12 | 1e−6 отн. против эталона GeostatsPy `tests/data/ref/geostatspy` (10.2); `backtr(nscore(x)) = x` — 1e−12 |

### 5. Swath: система короба, полосы, ряды

| Что | Решение |
|---|---|
| Углы | Азимут A — 0…360° от севера по часовой; наклон D — −90…+90°, отрицательный — ось полос идёт вниз (как у скважин BF2); поворот R — −180…+180° вокруг оси полос (вопрос № 29) |
| Оси | u₀ = (sin A, cos A, 0), h = (cos A, −sin A, 0), z = (0, 0, 1); **u = cos D·u₀ + sin D·z** (ось полос: поперёк полос, ось графика); n = −sin D·u₀ + cos D·z; **v = cos R·h + sin R·n**; **w = −sin R·h + cos R·n**. X = (90; 0; 0), Y = (0; 0; 0), Z = (A; +90; 0). sin и cos углов, кратных 90°, — точные 0 и ±1 |
| Обратно (оси → углы) | D = asin u_z; при \|u_z\| < 1 − 1e−12: A = atan2(u_x, u_y), R = atan2(v·n, v·h); иначе (ось вертикальна) R = 0, A = atan2(−v_y, v_x) |
| Полоса | t = p·u; k = ⌊(t − start) / width⌋; дальняя граница последней полосы принадлежит ей; допуск 1e−9·max(1, \|start\|, width); блок и проба (середина интервала) относятся к полосе по центру |
| Ширина | Заданная: полос > 2000 → 422 `too_many_swaths` (Т7.30-1). По умолчанию: есть ряд-модель — b·⌈span / (50·b)⌉, где b — сторона родительского блока первой модели по оси модели, ближайшей к u (max \|u_i\|; при равенстве — большая; переменный шаг OMF — медиана шагов оси); без моделей — «круглое» (1; 2; 2,5; 5 × 10ⁿ) не меньше span / 25 (Т7.30-4) |
| Привязка | Граница полос проходит через `anchor` (координата вдоль u); без неё первая полоса начинается у кубоида |
| Кубоид | По габаритам ячеек рядов-моделей в системе короба (полуразмер ячейки вдоль оси e — Σ \|e_i\|·размер_i / 2); без моделей — по серединам проб; вдоль u — до целых полос. Параметр `limits` (границы вручную) ядро принимает сразу; ручки граней — вопрос № 28 |
| Ряды | До 12 в любом сочетании (13-й → 422 `too_many_series` и отказ окна — Т7.30-1): `blocks {model_id, field, weight: volume / tonnage / none, density?, filter {field, labels}?}` или `samples {set_id, table, field, weight: none / length / field / length_field, weight_field?, negatives, top_cut?, within: box / blocks, within_series?}` + цвет, «линия», «столбики» |
| Ряд-модель | Центр ячейки `idx` → (i, j, k); t = a[i] + b[j] + c[k] — три одномерных массива проекций (плотных центров нет); вес — объём dx·dy·dz, тоннаж (объём × плотность) или 1; отбор — значения категориального поля (Д-02 на Э17 добавит `filter_id`). Ядро numba `cache=True, nogil=True` по группам строк Parquet; потоки над группами, суммы — попарные в порядке групп: побитно при 1, 2, 4, 8 потоках |
| Ряд-пробы | Вес и отбор — `stats/select.py`; «внутри блоков ряда k» (с его отбором): точка → (i, j, k) → `idx` → двоичный поиск среди занятых ячеек ряда (Т7.30-2) |
| Ответ | По рядам: среднее, число, вес по полосам (пустая полоса — пусто, не 0); итог по всем полосам (в легенду); отклонение от первого ряда, %; счётчики отброшенного; примечания («полоса уже блока — часть полос пуста») |
| Диапазон | `range [с; по]` — строится часть полос, в 3D остальные приглушены; на расчёт не влияет |
| Серия разрезов (ADR 0016) | «Взять из серии…»: ось полос — нормаль плоскостей серии (азимут, наклон), ширина — шаг Δ, привязка — s₀ − Δ / 2 (разрез — в середине полосы); серия планов — направление Z. Желательно |

Правила: команда графика без обязательных параметров открывает окно с параметрами по умолчанию (первый компонент активного набора), с параметрами — открывает окно с ними; в обоих случаях график сразу сохраняется (7.28). Создание графика и правка его настроек — без confirm (новый объект, данные проб не меняются — как новая таблица в ADR 0018 п. 10); удаление — confirm. Ассистенту команда возвращает короткий текст: имя и id графика, число проб, среднее, медиану, CV (swath — итоги рядов). `stats.swath` без `swath_id` создаёт swath по умолчанию (ряды: первая модель и активный набор) и открывает окно; с `swath_id` — меняет настройки и открывает окно (поворот мышью вызывает её же). Недоступность — с причиной: «Нет активного набора скважин», «В наборе нет таблиц проб», «Нужно 2 и больше компонента», «В проекте нет наборов скважин и блочных моделей».

## Последствия

- Новое: расчёты `stats/*` (18 модулей), API `/stats`, 10 новых видов `charts` без миграции, ключ вида `swaths`, `archive/chart_remap`, модули `modules/{charts,stats,swath}`, `ui/src/charts/*`, `viz/swath/*`, слой выделения проб; вкладка нижней панели `swath` удалена, «Статистика» — рабочая; плавающие окна помнят положение и размер.
- Э14 (QAQC) берёт рамку `ChartWindow`, оси, рассеяние и Q-Q двух выборок (дубликаты); Э15 — контактный анализ и столбец проб; Э16 — вкладку «Статистика» (вариограммы, карты, `local`), `stats/tab.py` (точки, предел 20 000), нормальные оценки и веса; Э17 — ряд-модель swath для субблоков, `filter_id` (Д-02), «содержание–тоннаж» на `ChartWindow`; Э22 — печать графиков (SVG); Э23 — команды `chart.*`, `stats.*` для ассистента.
- В ТЗ (docx v1.1): номера приёмок Т7.25-1…Т7.30-6 и ТД01-1…7; ответы № 25–33 — в 7.35 (новый подпункт), после ответа владельца.
- Схема БД не меняется; `.bfggis` прежних версий читается без изменений (новые виды `charts` — только в новых проектах).
- Отступление от п. 4 (контактный анализ, 13.7, «Допущения» PROGRESS): номер шага — ⌊|d| / b⌋ на каждой стороне, а не ⌊d / b⌋: шаг k стороны держит пробы с k·b ≤ |d| < (k + 1)·b. При ⌊d / b⌋ сторона A (d < 0) сдвигалась бы на шаг относительно B, и запрос «B, A» не был бы зеркалом «A, B»; с модулем стороны зеркальны побитно (`stats/contact.py`). Середина в 1e−6 м от границы шага относится к шагу, который там начинается; при D, не кратном b, крайний шаг короче.
- Отбор рассеяния (13.36): отсечки `bottom_cut`/`bottom_mode`, `top_cut`/`top_mode` — общие с другими графиками (п. 4) и применяются к обеим осям одной парой значений после нулей; пара, задетая отсечкой «исключить» по любой оси, не рисуется, «заменить» урезает только задетое значение.
