# ADR 0022. Вариография, эллипсоид анизотропии, тренды (Э16)

**Статус:** Предложен 2026-11-21 (проект — architect, fable / xhigh; решения 1–27 — в конце; вопросы заказчику № 52–61 неблокирующие, до ответа — «По умолчанию»). Исполняет ТЗ 8.6 (Т8.6-1…8; CHECKLIST № 314, 315, 318, 319), 7.29 (анализы `variogram`, `map`, `local`), 7.35 Д-14, Д-15 (глобальный тренд), Д-21 (эталоны `gamv`, `vmodel`, `varmapv`), 8.0, 10.5. Опирается на ADR 0001 (версии), 0002 (задания, blobs), 0003 (таблицы наборов), 0008 (раздел «Тренды», вкладка «Настройки проекта»), 0012 (эталоны), 0014 (потоки над ядрами `nogil`), 0018 (композиты, `DECL_W`), 0019 (вкладка «Статистика», `stats/source`, рамка графиков, ручки короба Д-01), 0021 (`/intercepts/orientation/plane`). Их не пересматривает.

## Контекст

- ТЗ 8.6: направленные 3D-вариограммы по определениям GSLIB gamv, вдоль скважин, веер и роза дальностей, карта в произвольной плоскости, четыре типа (полувариограмма, коррелограмма, парная относительная, нормальные оценки), модель «самородок + до 3 структур» со своими углами и дальностями, автоподбор, обратное преобразование модели нормальных оценок (Эрмит), эллипсоид в 3D, хранение и обмен JSON / GSLIB, цели времени 8.6.4, тесты 8.6.5. ТЗ 7.29: на вкладке «Статистика» — `variogram`, `map`, `local` в плане, не больше 20 000 интервалов, без хранения. Д-14: окно «Вариография · ‹поле›» и эллипсоид с ручками «как в Leapfrog», отклик ≤ 50 мс, предпросмотр ≤ 1 с. Д-15: объект `trend` (глобальный — Э16, структурный — Э19). ТЗ 8.0.2: задание, атомарность, параметры + версия алгоритма + SHA-256 входов, «устарел», побитно при 1, 2, 4, 8 потоках, первая компиляция ядер ≤ 30 с.

### 2. Данные расчёта (`points.py`)

| Что | Решение |
|---|---|
| Точки | Интервал любой интервальной таблицы набора (пробы, композиты) с числом в поле и положением: середина интервала на траектории, X, Y, Z (`stats/source.midpoints`); строки без значения и без положения не участвуют и считаются (`counts {rows, missing, no_position, used}`) — пропуск не ноль |
| Домен | Значения текстового или числового поля той же или другой интервальной таблицы (по середине пробы, `stats/source.domain_at`), список значений; не задан — все точки. Каркасы — через «Кодировать каркасами» (Э12) |
| Веса | Числовое поле (по умолчанию `DECL_W`, если есть): для таблицы нормальных оценок и Var(Z); в суммы по парам не входят (как GSLIB) |
| σ² | Дисперсия значений точек расчёта (делитель n, как BF `v.var()`); для нормальных оценок порог равен 1 |
| Преобразование | `none` или `nscore`: таблица `stats/transforms.nscore` с весами; оценки точек — переменная расчёта |
| Опорная точка | Центр охвата точек вычитается до расчёта (8.0.1) |
| Умолчания | Лаг L = 5 × медиана длин интервалов точек (2 значащие цифры); 15 лагов; допуск лага L / 2; допуски азимута и погружения 22,5°; полосы 3L и 2L; порог пар 30; вдоль скважин — лаг = медиане длин; веер — 12 направлений; карта — 41 × 41, ячейка L. Диапазоны — 8.6.4; вне диапазона — 422 `bad_param {param}` |
| Предел | Отдельного предела числа точек нет; при оценке перебора больше 2·10⁹ пар — случайная выборка точек (п. 4). Вкладка «Статистика» — прежние 20 000 |

### 3. Экспериментальная вариограмма: определения (`pairs.py`, `experimental.py`)

| Что | Решение |
|---|---|
| Направление | Азимут Az ∈ [0°; 360°), погружение p ∈ [−90°; 90°] (вниз положительное, ang2 = −p), допуски азимута и погружения (0°; 90°], полосы горизонтальная и вертикальная (> 0 или ∞); u = (cos p·sin Az, cos p·cos Az, −sin p) |
| Пара | Неупорядоченная (i < j); Δ = r_j − r_i, h — длина Δ, d_xy — длина горизонтальной части. Проверки GSLIB gamv по порядку: abs(Δx·sin Az + Δy·cos Az) / d_xy ≥ cos(допуска азимута) − 1e−12 (d_xy < 1e−20 — проходит); abs(sin Az·Δy − cos Az·Δx) ≤ горизонтальной полосы; d_xy берётся со знаком проекции на азимут; abs(d_xy·cos p − Δz·sin p) / h ≥ cos(допуска погружения) − 1e−12; abs(cos p·Δz + sin p·d_xy) ≤ вертикальной полосы. Допуск ≥ 90° — проверка не делается; оба ≥ 90° — всенаправленная |
| Лаг | k = 1…nlag, центр k·L, окно abs(h − k·L) ≤ допуска (границы включены, как BF: при допуске L / 2 пара на границе входит в оба лага); лага с центром 0 и самопар нет (BF). h̄_k — среднее расстояние пар лага |
| Что копится | За один проход по переменной: N, Σh, Σ(z_i − z_j)², Σz_хв, Σz_гол, Σz_хв², Σz_гол², Σz_хв·z_гол, Σ((z_i − z_j) / ((z_i + z_j) / 2))² и число таких пар. Хвост и голова — по знаку проекции Δ на u; у всенаправленной пара учитывается в обе стороны |
| Типы | Полувариограмма γ = Σ(z_i − z_j)² / (2N); коррелограмма ρ = (Σz_хв·z_гол / N − m_хв·m_гол) / (σ_хв·σ_гол), на графике 1 − ρ (σ = 0 — пусто); парная относительная — пары с z_i + z_j ≤ 0 не участвуют и считаются; нормальные оценки — полувариограмма переменной Y. Смена типа в окне не требует нового расчёта |
| Порог пар | Точка с N меньше порога отдаётся с признаком «мало пар»: на графике — полым знаком, в подбор не входит; лаг без пар — пусто (не ноль) |
| Допуски точности | Т8.6-1: γ 1e−12, N точно; Т8.6-2: прямой перебор NumPy в тестах — N точно, γ, 1 − ρ, парная относительная 1e−12; Д-21 `gamv`: 1e−9, N точно |

### 4. Ядро, полосы, потоки, выборка

| Что | Решение |
|---|---|
| Сетка | Ячейки со стороной c = h_max / m, h_max = (nlag + 0,5)·L; m = 1 — как в ТЗ; m = 2…4 — с таблицей смещений ячеек: для каждого смещения — список направлений, которые могут принять пару (полосы и допуски против коробки смещения); смещение без направлений не перебирается. Отсечение результата не меняет; m выбирается по замеру подшага 16.2 |
| Порядок | Точки сортируются по (ключ ячейки, номер строки); пара проверяется один раз — из ячейки с меньшим ключом |
| Полосы | Не больше 256 полос подряд идущих ячеек с примерно равным числом проверок пар; у полосы свои накопители [направление × лаг]; разбиение зависит только от данных и параметров |
| Суммы | В полосе — компенсированные (Нёймайер), между полосами — попарно в порядке полос; счётчики — int64 |
| numba | `from bf_core.jit import njit`, `cache=True, nogil=True`, без `prange` и `fastmath`; потоки — пул над полосами (`composites/strips`). Результат побитно одинаков при 1, 2, 4, 8 потоках |
| Оценка пар и выборка | Оценка — число проверок пар по счётчикам ячеек (верхняя граница перебора). Больше 2·10⁹ — случайная выборка n′ = ⌊n·√(2·10⁹ / оценка)⌋ точек без возврата, `Generator(PCG64(seed))`, зерно 12345 — параметр; в ответе `sampled {n, of, seed}`, в окне — строка «Расчёт по выборке n′ из n проб» |
| Отмена, ход | Между полосами; стадии «Чтение таблицы», «Траектории», «Нормальные оценки», «Пары: оси», «Пары: вдоль скважин», «Запись» |
| Память | Точки 200 тыс. — десятки МБ; накопители ≤ 256 полос × 72 направления × 100 лагов × 10 чисел ≈ 150 МБ в худшем случае; цель ≤ 2 ГБ |

### 5. Вдоль скважин, веер, роза, карта (`downhole.py`, `fan.py`, `varmap.py`)

| Что | Решение |
|---|---|
| Вдоль скважин | Пары одной скважины, расстояние — abs разности глубин середин интервалов; лаги и окно — как п. 3, без направления; скважины — полосами; считается по всем точкам (выборка п. 4 на неё не действует). Назначение — самородок (Т8.6-7) |
| Плоскость | Задаётся тремя углами (ang1–ang3): оси плоскости — a1 и a2 модели, нормаль — a3; по умолчанию горизонтальная. Данные переводятся в систему плоскости, дальше — определения п. 3 (азимут — угол в плоскости от a1 к a2, «погружение» — выход из плоскости) |
| Веер | N направлений (4–72, по умолчанию 12) через 180° / N в плоскости; допуск в плоскости по умолчанию 90° / N (соседние не перекрываются), выход из плоскости — допуск погружения и вертикальная полоса окна |
| Роза дальностей | Для направления — первое расстояние, где γ̂ ≥ q·σ² (q = 1, параметр 0,5–1,2): линейная интерполяция между точками с N ≥ порога; уровень не достигнут — пусто с пометкой «> h_max» |
| Карта | (2n_u + 1) × (2n_v + 1) ячеек (по умолчанию 41 × 41, ячейка L; до 201 × 201), номер ячейки — округление сдвига к ближайшей (BF); пара учитывается в ячейке и в симметричной; самопары — в центральной (как BF и GSLIB); пары дальше толщины слоя от плоскости (по умолчанию 2L; ∞ — проекция) не участвуют; ячейка с N < порога (по умолчанию 5) — пусто. Правило `trunc` — только для сверки с `varmapv` |
| Щелчок по карте, лучу веера | Задаёт направление большой оси в плоскости: ang1–ang3 пересчитываются так, что плоскость не меняется |
| Допуски точности | Д-21 `varmap` (правило `trunc`, строки эталона перевёрнуты по Y): N точно, γ 1e−9; перенесённые тесты карты BF — как в BF |

### 6. Модель и анизотропия (`rotation.py`, `model.py`; зеркало — `ui/src/viz/ellipsoid/frame.ts`, `modules/variography/model.ts`)

| Что | Решение |
|---|---|
| Углы | ang1 ∈ [0°; 360°), ang2 ∈ [−90°; 90°], ang3 ∈ (−180°; 180°]; в интерфейсе — «азимут», «погружение» p = −ang2, «поворот» ang3. Матрица — 8.6.3 дословно; sin и cos углов, кратных 90°, точные (`sections/geometry.sin_cos_deg`, как у короба swath): оси при нулевых углах равны (0; 1; 0), (−1; 0; 0), (0; 0; 1) точно |
| Обратное преобразование | u₁, u₂, u₃ — строки R (оси a1, a2, a3). ang1 = atan2(u₁x, u₁y) mod 360; ang2 = asin(u₁z); ang3 = atan2(R₂₃, R₃₃). Большая ось вертикальна (abs(u₁z) > 1 − 1e−12): ang1 остаётся прежним (окно хранит три числа, а не матрицу), ang3 — из u₂ |
| Вторая запись углов | «Падение / азимут падения / склонение» плоскости осей a1–a2: α, Aп — по нормали u₃ (правила ADR 0021 п. 2), склонение — угол в плоскости от линии простирания до u₁, [0°; 180°); функции пересчёта в обе стороны — в `rotation.py` и `frame.ts`; показ в окне — вопрос № 53 |
| Структуры | 0–3: сферическая, экспоненциальная, гауссова; c ≥ 0; дальности a1, a2, a3 > 0; свои ang1–ang3; флажок «общие оси» — углы всех структур равны углам первой. Практическая дальность (BF) |
| Расчёт | h_r = √((u₁·Δ / a1)² + (u₂·Δ / a2)² + (u₃·Δ / a3)²) — то же, что запись 8.6.3; γ и C — 8.6.3; γ(0) = 0 |
| 2D-модель вкладки | Частный случай: ang1 = `azi`, ang2 = ang3 = 0, a1 = `hmaj`, a2 = a3 = `hmin` |
| Допуски | Т8.6-3, Т8.6-4 — 1e−12; `vmodel` — 1e−9; зеркало TypeScript против фикстур ядра — 1e−12 (`core/tests/data/variography/{frames.json, model_curves.json}`) |

### 7. Подбор (`fit.py`)

| Что | Решение |
|---|---|
| Входы | Точки осей с N ≥ порога: (h̄, γ̂, N, направление); углы закреплены (оси модели — направления расчёта); типы структур задаёт пользователь |
| Невязка | r = √w·(γ̂ − γ(h̄·u_d)) / σ²; w = N / h̄ (по умолчанию), N или N / γ² (γ — модели предыдущего прохода, три прохода) |
| Неизвестные | Общий порог S ∈ [0; 1,2·σ²] (для нормальных оценок S = 1 закреплён); доли f ∈ [0; 1]: C0 = S·f₀, c₁ = S·(1 − f₀)·f₁, …, последней структуре — остаток; дальность — доля t ∈ [0; 1] логарифмического отрезка [L / 2; 2·h_max], у структуры s по каждой оси t_s = t_(s−1) + (1 − t_(s−1))·v_s, v ∈ [0; 1] — дальности не убывают от структуры к структуре (вложенность). Любой параметр можно закрепить |
| Решатель | `scipy.optimize.least_squares` (trf), аналитический якобиан, xtol = ftol = gtol = 1e−12; 8 стартов: 2 доли самородка × 4 масштаба дальностей; лучший по невязке, при равенстве — первый по сетке |
| Начальный C0 | Экстраполяция к h = 0 первых трёх точек вариограммы вдоль скважин (≥ 0); флажок «закрепить самородок». В сумму невязки вариограмма вдоль скважин не входит (у неё нет одного направления) |
| Ответ | Параметры, взвешенная сумма квадратов, число точек, предупреждения («дальность на границе 2·h_max», «точек меньше, чем неизвестных», «ось без точек»); структуры — по возрастанию a1 |
| Т8.6-5 | Модель теста: дальности не короче трёх лагов по каждой оси и вложены, структуры одного типа — с разными вкладами; восстановление 1e−4 отн. |

### 8. Нормальные оценки и обратное преобразование (`hermite.py`)

| Что | Решение |
|---|---|
| Прямое | Таблица `nscore` с весами; модель подбирается в единицах Y (порог 1) |
| Обратное | 8.6.3 дословно: Φ_Z — интерполяция таблицы с хвостами `backtr`; φ_n — `numpy.polynomial.hermite_e.hermegauss(200)`, n = 0…30; C_Z = Σ φ_n²·ρ_Y^n; кривые γ_Z по трём осям (100 расстояний до полутора наибольших дальностей) аппроксимируются моделью тех же типов через `fit.py` (равные веса) |
| Ответ | Модель в единицах Z, доля Σφ_n² / Var(Z), предупреждение при доле < 0,95, невязка аппроксимации; хранится в модели (`back`) |
| Допуски | Т8.6-6: 1e−6 отн. аналитически, ≤ 2 % по выборке 10⁵ |

### 9. Эллипсоид и ручки (Д-14; `viz/ellipsoid/*`, `modules/variography/{scene.ts, handles.ts}`)

| Что | Решение |
|---|---|
| Что показано | Эллипсоид выбранной структуры (по умолчанию — с наибольшей a1): полупрозрачная поверхность и три главных сечения; остальные структуры — тонкими контурами; «подвижная плоскость» — диск осей a1–a2; пробы предпросмотра не дальше толщины слоя от диска — точками по значению. Центр — центр охвата точек расчёта или точка «Поставить эллипсоид здесь»; на модель не влияет. Показанные в 3D эллипсоиды моделей и трендов — ключ вида `ellipsoids` (`[{object, visible}]`, по образцу `swaths`) |
| Геометрия | Единичная сфера с матрицей «масштаб a1, a2, a3 × поворот»: правка меняет только матрицу; float32 от целого начала слоя (`viz/origin.ts`) |
| Ручки | Кольцо азимута — горизонтальная окружность через центр, угол ang1; дуга погружения — полуокружность в вертикальной плоскости большой оси, −90°…90°; дуга поворота — окружность вокруг большой оси у её конца, угол ang3; концы осей — три узла на осях a1, a2, a3 |
| Перетаскивание | Луч курсора ∩ плоскость ручки → угол; шаг 1°, с `Shift` 5°; конец оси — ближайшая к лучу точка оси → дальность (3 значащие цифры, не меньше L / 2; с `Ctrl` — все три дальности в одном отношении). Меняется только свой параметр; при «общих осях» поворачиваются все структуры |
| Указатель | `viz/core/handleChain.ts`: цепочка обработчиков ручек (короб swath, эллипсоид модели, эллипсоид тренда), первым — окно в фокусе; попадание 8 px, иначе указатель уходит сцене |
| Синхронность | Одно хранилище модели окна (`modules/variography/state.ts`): ручки, таблица и графики пишут в него и читают из него; кривые и эллипсоид — в том же кадре, без запроса к ядру (метки `performance`: `vario:edit` → `vario:drawn`, цель ≤ 50 мс) |
| Экспериментальные точки | Движение — пауза 200 мс → `POST /variography/preview` по выборке ≤ 20 000 точек (≤ 1 с; обогнанные ответы отбрасываются); отпускание — задание `variography.experimental`, предыдущее отменяется |
| Цвета | Ручки — Cobalt, под курсором и в перетаскивании — Copper Orange (как Д-01); эллипсоид — цвет модели из палитры |
| Допуски | ТД14-1: ручки ↔ углы на фикстурах `frames.json` 1e−9, туда-обратно без потерь |

### 11. Вкладка «Статистика» (7.29)

| Анализ | Решение |
|---|---|
| `variogram` | Точки вкладки (план, ≤ 20 000); всенаправленная или 4 направления (0°, 45°, 90°, 135°, допуск 22,5°) на ядре п. 4 при z = 0 и допуске погружения 90°; модель «самородок + до 4 структур» в форме BF (`it, cc, hmaj, hmin, azi`), кривая модели — и без данных (`/stats/tab/variogram-model`); число пар в лагах; кнопка «Открыть в окне „Вариография“» |

| Хранение | Нет (7.29); расчёт синхронный, слот HEAVY |

### 16. Крайние случаи

| Случай | Поведение |
|---|---|
| Меньше 2 точек; все значения равны | 422 `too_few_values`; `no_spread` |
| Пропуски, нет траектории | Точка не участвует и считается; γ лага без пар — пусто |
| Вертикальное направление (p = ±90°) | Азимут не проверяется; вертикальная полоса — радиус цилиндра вокруг направления (следует из формул п. 3) |
| Большая ось вертикальна | Кольцо азимута и дуга поворота вращают одно и то же: ang1 сохраняется, меняется ang3 |
| Совпадающие точки (h = 0) | В лаг попадают только при допуске лага, равном L (окно первого лага начинается с 0); на азимут не проверяются (как BF) |
| Отрицательные и нулевые значения | Парная относительная: пары с z_i + z_j ≤ 0 пропускаются, счёт — в ответе и предупреждение |
| Пар больше 2·10⁹ | Выборка точек с сообщением (п. 4) |
| Порог модели больше 1,2·σ² | Вручную — допускается с предупреждением; подбор держит границу |
| a2 > a1, структура с c = 0 | Допускаются; названия осей — по номеру |
| Доля Эрмита < 0,95 | Предупреждение; модель Z отдаётся |
| Набор или таблица модели удалены | Модель остаётся («источник удалён»), «Перестроить» недоступно |
| Удаление тренда со ссылками | 409 `in_use`, список потребителей |

### 17. Что Э16 не берёт

Эллипсоид поиска и выбор модели или тренда в мастере оценки (Э18); структурный тренд, выбор тренда в мастере RBF и проверка «RBF с трендом = RBF с той же A» (Э19); индикаторные вариограммы (Э18б, Д-23 — тем же ядром); кросс-вариограммы, облако вариограммы, мадограмма; конус вместо допусков GSLIB (№ 52); печать (Э22); изменения демо-проекта, `viz/Scene.ts`, `viz/swath/*`, миграции; новые зависимости.

## Последствия

- Новое: пакет `geostat` (поворот, вариография, тренды), ядра 3D-вариограмм, виды объектов `variogram_model` и `trend`, задания `variography.*`, API `/geostat`, три анализа вкладки «Статистика», вкладка ленты «Геостатистика», группа «Настройки проекта → Геостатистика», разделы дерева «Геостатистика» и «Тренды», `viz/ellipsoid`, ключ вида `ellipsoids`, цепочка обработчиков ручек, модули `modules/{variography, trends}`, графики `charts/variogram`. Схема БД не меняется, миграций нет; `.bfggis` прежних версий читается без изменений; lock-файлы не меняются.
- ТЗ 7.29 закрыт полностью: пометки «Появится на этапе Э16» сняты. Веха В4 получает «вариограмму с моделью и эллипсоидом» (раздел 11 ТЗ).
- Э18 берёт `variogram/model.py` (γ и C модели), `rotation.py`, `trend.matrix`, список моделей и трендов для мастера оценки, эллипсоид поиска на слое `viz/ellipsoid`; IDW вкладки (`stats/local.py`) остаётся плановым, анизотропный — свой. Э18б — индикаторные вариограммы тем же ядром (новое преобразование). Э19 — `kind: "structural"` тренда, выбор тренда в мастере RBF, ссылки `object_refs(role = "trend")`, проверка «RBF с трендом = RBF с той же A», тренд как источник ориентировки (ADR 0021). Э22 — печать графиков вариограмм. Э23 — команды `variography.*`, `trend.*` для ассистента.
- В ТЗ (docx): ответы № 52–61 — в 7.35 новым подпунктом после ответа владельца; номера приёмок ТД14-1…5 и ТД15-1…5. CHECKLIST: № 314, 315, 318, 319 — ✅ после Э16.
