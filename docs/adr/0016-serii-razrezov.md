| Вопрос | Варианты | Выбор и причина |
|---|---|---|

Б — миграция и архив ради JSON в 2–200 КБ; В не даёт объекта в дереве и нескольких серий |

В — не float64 и не точная геометрия |

## Решение

### 1. Модель серии — объект `objects(kind = "section_series")`

| Поле `meta` (`v: 1`) | Содержание | Проверка (422 `bad_series` с подсказкой) |
|---|---|---|
| `number` | Номер серии в проекте (1, 2, …; следующий = наибольший + 1), не меняется, переносится `.bfggis` как есть; пишется в `SECTION_SET` контуров | Уникален |
| `type` | `vertical`, `plan`, `inclined`, `polyline` | — |
| `p1` [x, y, z]; `p2` [x, y] или `az` | P1; P2 (азимут A — от P1 к P2) или азимут, [0°; 360°) | P2 ≠ P1 (> 1e−6 м) |
| `phi` | Наклон плоскости φ: 90° — вертикальная, `plan` — без φ (v̂ = (0, 0, −1)) | 0–90° |
| `s0`, `s1`, `step` | Пределы и шаг Δ вдоль v̂; план: `p1.z` = верхняя отметка, `s1` = верх − низ | Δ 0,01–10 000 м; K ≤ 5 000 |
| `towards`, `away` | w_к, w_от | 0,01–10 000 м |
| `overrides` | `{"k": {towards, away}}` — свои окна разрезов | k < K; ≤ 5 000 |
| `template` | Шаблон имён или `null` (по умолчанию 8.1.2) | п. 2 |
| `polyline`, `corridor` | Ломаная P0…Pm в плане (≤ 1 000 точек), ширина коридора (25 м) | Звенья > 1e−6 м |
| `shadow` | `none`, `prev` (по умолчанию), `next`, `both` | — |
| `contour_layer` | Слой контуров серии или `null`; перенумеровывается `.bfggis` | Слой есть |
| `layout` | Шаблон макета печати — `null` до Э22 | — |

Ломаный разрез — серия из одного разреза (K = 1); «Из линии разреза», «Через скважину» и «Серия из одного разреза» создают вертикальную серию с s0 = s1 = 0. Изменение параметров — `PATCH` с `expected_version` (409 `version_conflict`); имена и O_k не хранятся — вычисляются. Удаление серии контуров не трогает (их атрибуты остаются).

### 2. Геометрия (ядро — `sections/geometry.py`, `polyline.py`, `names.py`; окно — `viz/section/plane.ts`, `series.ts`)

| Что | Правило |
|---|---|
| Оси | ŝ = (sin A, cos A, 0); v̂ = (−cos A·sin φ, sin A·sin φ, −cos φ); ŵ = ŝ × v̂; sin и cos точные на кратных 90° (как `sinCosDeg` / `_sin_cos`); план: v̂ = (0, 0, −1), ŵ при A = 90° — север |
| Разрезы | K = floor((s1 − s0)/Δ + 1e−9) + 1; s_k = s0 + k·Δ (умножением, без накопления); O_k = P1 + s_k·v̂; k = 0…K−1, в интерфейсе и в атрибутах — номер k + 1 (как `{k}`) |
| Координаты | u = (p − P1)·ŝ, w = (p − P1)·ŵ, t = (p − O_k)·v̂ — разность с P1 первой (UTM без потери); у вертикального w = Z |
| Окно | −w_к ≤ t < w_от со своими окнами разреза; разрез точки при общих окнах — кандидат floor((τ − s0 + w_к)/Δ), затем проверка тем же неравенством, что у окна, с поправкой ±1 — граница t = w_от уходит в следующий побитно (Т8.1-2) |
| Ломаный | Сегмент — ближайший в плане (при равенстве — меньший номер), если расстояние ≤ коридора; u = длина предыдущих сегментов + u на сегменте; в 3D — текущий сегмент: две грани коридора и две биссектрисы изломов (выпуклая область — 4 плоскости) |
| Имена | Подмножество формата Python: поля только `{k}` (с 1), `{s}`, `{X}`, `{Y}`, `{Z}` (координаты O_k) и спецификация формата числа; без обращения к атрибутам и индексам, без `!r` — разбор `string.Formatter().parse`, иначе 422 (произвольный `str.format` дал бы доступ к атрибутам объектов). По умолчанию: A = 90° или 270° — `{Y:.0f}N`, A = 0° или 180° — `{X:.0f}E`, план — `{Z:.0f}`, иначе `{s:+.0f}`; повтор имени — 422 «добавьте {k}» |
| Эталоны | `core/tests/data/sections/series_cases.json` — входы и ответы (оси, K, O_k, (u, w, t), разрез точки, сегмент и u ломаного); читают `test_section_geometry.py` и `ui/test/viz-section-plane.test.ts` (как `tests/data/ground/profiles.json`) |

### 4. Окно: плоскость, отсечение, вид, навигация

| Что | Решение |
|---|---|
| Плоскость | `SectionPlane {origin, s, v, w, towards, away, u?: [u0, u1], seg?}` — общий вид разреза; `SectionLine` 7.14 приводится к ней (φ = 90°, побитно те же плоскости). Разрез выносится из `Scene.ts` в `viz/section/rig.ts`; `Scene.setSectionPlane(plane, clip)` |
| Отсечение | `SharedClip` — плоскости ±v̂ (и пределы u) в пространстве показа с преувеличением; `inWindow(x, y, z)`; ломаный — 4 плоскости текущего сегмента |
| Ключ вида | `section {line, clip, series}`, `series` — `{id, k, seg}` или `null`: при активной серии показывается её разрез, `line` хранит последнюю свободную линию; `map_ids` и `drop_missing` знают серию; старые ключи читаются без изменений. Запись при частых `]` — не чаще раза в 300 мс (последняя — всегда) |
| «Зафиксировать вид» (`L`) | Ортокамера по v̂, верх — ŵ; вращение выключено (мышь и гизмо), сдвиг и масштаб работают; смена разреза переносит камеру и цель на (s_k′ − s_k)·v̂ — точка с теми же (u, w) остаётся на месте экрана (Т8.1-6) |
| Навигация | `]` / `[` — k ± 1, у ломаного — сегмент, без серии — сдвиг на ширину окна (`section.step`, как в BF); край — k не меняется, сообщение в строке состояния; `Home` / `End` / `Ctrl+G` (имя или номер с подсказками) — при фокусе 3D-окна, не в полях ввода |
| Свободный разрез | `S`, `section.set`, «Через скважину», «Авто-разрез» снимают активную серию (серия остаётся в проекте) |
| Строка состояния | «Серия «Профили» · разрез 3 из 12 · 5050N» |
| Лента «Разрезы» | «Серия»: Менеджер серий, Новая серия, Из линии разреза, Через скважину; «Навигация»: Первый, Предыдущий, Следующий, Последний, Перейти; «Вид»: Зафиксировать вид, Отсечение, Тень; «Оцифровка»: Контур на разрезе, Каркас по серии; «Печать»: Печать серии (Э22, недоступна с причиной) |
| Дерево | Раздел «Серии разрезов»: серии, под серией — разрезы (до 1 000 строк, далее «Перейти…»); щелчок по разрезу — переход; меню: сделать активной, копировать, переименовать, удалить |
| Менеджер серий | Список (создать, копировать, удалить, сделать активной), параметры, таблица разрезов (номер, имя, s, свои окна — правятся), линии серии на мини-плане |
| Команды | `series.new`, `series.manager`, `series.from_line`, `series.through_hole`, `series.activate {series_id, k?}`, `series.first`, `series.prev`, `series.next`, `series.last`, `series.goto {name или number}`, `series.lock`, `series.shadow {mode}`, `series.digitize`, `series.stitch`, `series.print` (Э22); изменяющие проект (`series.create {params}`, `series.delete`, `series.stitch` с запуском) — с подтверждением для ассистента |

### 5. Что показывается при отсечении

| Объект | Как | Кто |
|---|---|---|
| Скважины, отображения по стволу, линии, точки | Части в окне — плоскости отсечения (как 7.14) | Окно |
| Каркасы | Точная линия сечения плоскостью t = 0 (float64, ядро, пакет разреза); галочка «часть каркаса в окне» — сам каркас с плоскостями отсечения | Ядро + окно |
| Блоки | Срез 8.7.6 или блоки в окне — Э17 (решение 11) | — |
| Растры | Как 7.14 / BF: вертикальный — подложка, остальное поверх | Окно |
| Выбор и привязка | Вне окна не выбираются и не цели: `pick` с плоскостями окна, `snap?plane=`, цели линий других слоёв — `inWindow(x, y, z)` | Ядро + окно |
| Тень | Контуры разрезов k − 1 / k + 1 (по положению, п. 7) серым пунктиром, без отсечения, не выбираются, не цели привязки | Ядро отдаёт, окно рисует |

### 6. Сечения каркасов: упреждение и фоновый кеш

| Что | Решение |
|---|---|
| Окно | На смену k — пакет разреза k (устаревший запрос отменяется, линии старого разреза уходят сразу), затем по простою k ± 1, k ± 2; в памяти — до 5 разрезов. При активации серии и по `objects.changed` каркасов — `POST …/cache` |
| Ядро, запрос | Есть файл кеша — срез по k (mmap); нет — расчёт по кешу геометрии `exact.py` (затронутые части, ≤ 1 с на 10 млн — ТЗ 5.3) |
| Задание `sections.cache` | Все разрезы при K ≤ 500, иначе k ± 50 вокруг текущего; на каркас — файл `cache/sections/<ключ серии>/<ключ каркаса>.bfa` (линии всех разрезов и смещения по k), запись во временный и атомарный перенос; `quick` до 2 млн треугольников, иначе `heavy`; одно задание на серию (новое заменяет идущее); окно узнаёт о готовности обычным событием задания (`jobs/scheduler.py` — 598 строк — не меняется) |
| Ключ и очистка | Ключ серии — SHA-256 параметров геометрии (без имён, окон и тени); ключ каркаса — `MeshState.cache_key`; производные, не входят в `.bfggis`; предел 2 ГБ на проект, старые каталоги удаляются по LRU при открытии проекта |

### 7. Оцифровка на разрезе

| Что | Решение |
|---|---|
| Плоскость | t = 0 разреза k (ломаный — текущего сегмента): пересечение луча курсора с плоскостью во float64 на CPU от O_k и одна поправка p −= ((p − O_k)·v̂)·v̂ — ≤ 1e−9 м на UTM (Т8.1-3); при привязке — проекция цели вдоль v̂, переключатель «оставить 3D». `edit/drawPlane.ts` (из `session.ts`) |
| Слой | `contour_layer` серии; нет — новый слой «Контуры <серия>» в файле «Серии разрезов» (`lines.new_layer`) |
| Атрибуты | Новые линии получают `SECTION_SET` (номер серии), `SECTION` (k + 1), `SECTION_NAME` через `new_attrs` PUT геометрии (ADR 0015); в STR и DXF уходят обычными атрибутами |
| Принадлежность | Контур — на разрезе k, если все его вершины с Z в окне k (одно правило в ядре и окне, по эталонам п. 2); фильтр «текущий разрез / все»: линии вне окна видны, но не выбираются и не правятся (`edit/lock.ts`) |
| Переход во время правки | Плоскость рисования следует за k; несохранённое не теряется (сеанс один) |

### 8. «Каркас по серии» (операция `stitch_series`)

| Шаг | Решение |
|---|---|
| Контуры | Замкнутые линии выбранных слоёв (по умолчанию — слоя контуров серии), лежащие в окнах разрезов (п. 7); вершины дальше 1e−3 м от плоскости t = 0 — предупреждение с именем разреза и номером линии; незамкнутые и вне окон — пропуск со счётом |
| Автосвязи | Соседние разрезы k и k + 1: проекции на плоскость разреза (u, w) перекрываются (пересечение рёбер или вложение; numba, float64 от центра пары, точные знаки ориентации) — связь; иначе расстояние между центрами ≤ Δ — связь. 1 → N, N → 1 — разветвление; N : M в одной связной паре разрезов — отказ «разделите связи» с именами разрезов |
| Таблица | Окно показывает пары разрезов, линии связей в 3D; щелчок по контуру связывает или развязывает его с выбранным; связи — пары (слой, `lid`) в параметрах операции |
| Сшивка | `stitch_contours(…, normal=v̂, groups=разрез контура, links=…)` — без новых параметров поведение прежнее побитно (тесты Э9). Торцы на концах каждого тела: по умолчанию `extend` на Δ/2 и плоская крышка; `flat` — крышка на крайнем разрезе; `point` / `line` — выклинивание на Δ/2 |
| Тела | Связная группа контуров — отдельный каркас «<серия> — тело N»; галочка «одним каркасом» (части без сшивки вершин) |
| Задание | `geometry.operation {op: "stitch_series"}` — очередь, отмена, одна транзакция, `meta.built` (серия по номеру и версии, слои и `lid`), «Перестроить» — по ADR 0015; провал проверки — каркас не создаётся, ошибка называет разрезы («между 5050N и 5075N: самопересечение») |
| Отчёт | По телу: объём, треугольники, замкнутость, проверки; число пропущенных контуров |

## Последствия

- Э13 (swath) и Э15 (рудные пересечения) получают разрезы серии как плоскости выборки; Э17 — плоскость для среза блоков; Э22 — серии, (u, w) и пакет сечений для листов и пакетной печати; Э23 (ассистент) — `series.*` с подтверждением изменяющих проект.
- Схема БД не меняется: новый вид объекта `section_series`, ключ вида `section.series`; производные — `cache/sections/`.
- Плоскость разреза в 3D-окне становится общей (наклонная, план, сегмент); `SectionLine` 7.14 — частный случай с прежними плоскостями побитно.
- Не входит: печать и листы (Э22), срез блоков (Э17), параллельные серии ломаных разрезов, связи через пустой разрез, автоматическое исправление самопересечений тела.
