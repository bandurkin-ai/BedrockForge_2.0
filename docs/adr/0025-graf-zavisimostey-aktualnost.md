# ADR 0025. Граф зависимостей и актуальность расчётных объектов (Д-35)

**Статус:** Предложен 2026-11-25 как ADR 0023, перенумерован в 0025 (номер 0023 занят ADR блочных моделей Э17; Э17 слит без Д-35 — реализация в Э18, план 18.Г). Исходно: предложен 2026-11-25 (оркестратор, по разбору промпта владельца о рабочих процессах Leapfrog Geo / Edge; 7.35 Д-35). Принять в подшаге 17.0 вместе с проектом Э17 (architect может уточнить пути и имена, не меняя решений 1–12). Вопросы № 88–90 — ответ владельца 2026-11-25: «По умолчанию» (закрыты).

## Контекст

- ТЗ 8.0.2: «Расчётный объект хранит параметры, версию алгоритма, SHA-256 входов… При смене входов объект помечается „устарел“; „Перестроить“ повторяет расчёт». 8.9.3 — то же для неявных моделей (хеши участков).
- Сейчас «устарел» реализован по модулям и только по **прямым** входам:

| Где | Что сравнивается | Транзитивно |
|---|---|---|
| `composites/results.py` (`_reason`) | токен и `rev` таблиц, `version` набора скважин, `cache_key` каркасов | нет |
| `composites/routes_ore.py` (`stale_reason`) | то же + `ALGO` правил | нет |
| `qaqc/service.py` | `rev` таблицы-источника | нет |
| `geostat/variogram/store.py` (`stale_reason`) | свои входы модели | нет |
| `intercepts/*`, `stats/source.py` | свои входы | нет |

- Э17–Э20 добавляют цепочку длиной 4–6: таблица проб → композиты → модель вариограммы → оценка (поле блочной модели) → отчёт по ресурсам; плюс домены из каркасов и неявных моделей (Э19). При правке инклинометрии отчёт по ресурсам сейчас остался бы «актуальным».
- `object_refs` (схема `db/schema.py`) — связи между `objects` с `ON DELETE RESTRICT` у цели; результаты наборов скважин (`dh_results`) и таблицы (`dh_tables`) — не строки `objects`.

## Варианты

| Вопрос | Варианты | Выбор и причина |
|---|---|---|
| Как вычислять актуальность | А) **pull**: при чтении — сравнить сохранённые отпечатки входов с текущими, рекурсивно; Б) **push**: при каждой записи помечать зависимых в таблице; В) только прямые входы (как сейчас) | **А.** Писателей много (импорт, редактор таблиц, траектории, каркасы, ассистент); push требует не забыть пометку в каждом и ломается при импорте `.bfggis` и откате. Pull уже применяется во всех модулях — расширяется, а не заменяется. В не выполняет 8.0.2 для цепочек |
| Где хранить рёбра | А) `object_refs`; Б) только `meta.inputs` (JSON); В) новая таблица `lineage` + `meta.inputs` | **В.** `object_refs` с RESTRICT запрещает удалить источник — а нужно «источник удалён» у зависимого; узлы не только `objects`. `meta.inputs` — источник истины для сравнения; `lineage` — обратный индекс для «Зависимые» и «Влияние изменения» (без него — полный перебор `meta`) |
| Отпечаток узла | А) хеш содержимого всегда; Б) дешёвый токен состояния (токен + `rev`, `version`, `cache_key`), для расчётных — SHA-256 результата | **Б.** Пересчитывать хеш 20 млн блоков при каждом показе дерева нельзя; токены уже есть и используются в `_reason` |

## Решения

| № | Решение |
|---|---|
| 1 | Модуль `bf_core/lineage/`: `graph.py` (обход, причины), `providers.py` (реестр поставщиков по виду узла), `router.py` (`/lineage/*`), `store.py` (таблица `lineage`). Регистрация поставщиков — явным импортом в `lineage/providers.py` (как обработчики заданий, 17) |
| 2 | Узел — пара `(kind, id)`; виды: `dh_set`, `dh_table`, `dh_result`, `wireframe`, `object:<kind>` (модель вариограммы, тренд, неявная модель, блочная модель, поле блочной модели `bm_field`, параметры оценки, отчёт по ресурсам, QAQC-отчёт и т. д.). Поле блочной модели — отдельный узел: оценка пишет поле, а не модель целиком |
| 3 | Поставщик вида — `fingerprint(conn, id) -> str \| None` (None — узла нет) и, для расчётных, `inputs(conn, id) -> list[InputRef]`. Источники: токен состояния (`table_token`+`rev`, `version`, `cache_key`); расчётные — `sha256` записанного результата + номер `ALGO` |
| 4 | При записи результата задание сохраняет `meta.inputs = [{kind, id, fp, name}]` (имя — для причины после удаления) и строки `lineage(dst_kind, dst_id, src_kind, src_id)`; это общий помощник `lineage.record(conn, dst, inputs)` в той же транзакции, что и перенос результата (8.0.2, атомарно) |
| 5 | Состояние узла: **«актуален»** — все входы есть, их текущий `fp` равен сохранённому и каждый вход актуален; **«устарел»** — иначе, причина — первая найденная по цепочке («устарела модель вариограммы „Au_D1“ ← изменена таблица „assay“»); **«источник удалён»**; **«закреплён»** (решение 8); **«считается»** — `state = building`. Обход — в глубину с памятью на запрос; цикл невозможен (вход создаётся раньше результата), но обход проверяет его и отвечает ошибкой `lineage_cycle` |
| 6 | Существующие проверки (`results._reason`, `routes_ore.stale_reason`, `qaqc`, `variogram/store`) **не переписываются**: адаптер вида вызывает их как проверку прямых входов, граф добавляет транзитивную часть. Ответы API, где уже есть `stale`/`reason`, сохраняют формат; `reason` может стать цепочкой |
| 7 | «Влияние изменения» `lineage.impact {kind, id}`: транзитивные зависимые по таблице `lineage` с числом по видам и списком; окно (собственное, не `confirm`) показывается перед заменой, удалением или правкой источника, **только если зависимые есть** (№ 64); изменение не блокируется |
| 8 | «Закрепить» (`lineage.pin`): закреплённый объект не помечается «устарел», в дереве — «закреплён (входы изменились)» с причиной; нужен для сравнения версий (Д-37) и выпущенных отчётов. Закреплённый вход для зависимых считается актуальным (№ 62) |
| 9 | «Перестроить с зависимыми» (`lineage.rebuild`): устаревшие узлы цепочки в топологическом порядке, по одному заданию на узел (очередь `heavy`, 6.7), с сохранёнными параметрами; отмена — останавливает оставшиеся; ошибка узла — зависимые не запускаются, остаются «устарел». Автоматического перестроения нет (№ 63) |
| 10 | Интерфейс: значок состояния в дереве (общий компонент для всех видов, вместо модульных), подсказка — причина; «Свойства» → «Происхождение» (входы, их `fp`, дата, ссылки) и «Зависимые». Состояния — запросом `lineage.status {ids}` пачкой при раскрытии раздела дерева |
| 11 | `.bfggis` (7.4): таблица `lineage` экспортируется; идентификаторы перенумеровывает существующая `ops/provenance.remap_objects` (одна строка подключения); `fp` при переносе не меняются — проект после импорта сохраняет состояния |
| 12 | Миграция БД проекта — одна: таблица `lineage` (индексы по `dst` и `src`); старые результаты без `meta.inputs` в формате графа — актуальность по прежней прямой проверке, транзитивная часть для них пуста (без миграции данных) |

## Производительность

| Операция | Цель |
|---|---|
| `lineage.status` для 2000 узлов, глубина 6 | ≤ 50 мс (сценарий `bench/scenarios/lineage_status.py`, бюджет в `budgets.json`) |
| `lineage.impact` для источника с 500 зависимыми | ≤ 30 мс |
| `lineage.record` в задании | ≤ 5 мс, не зависит от размера результата |

## Проверки

| Тест | Ожидание |
|---|---|
| ТД35-1 | Цепочка таблица → композиты → модель вариограммы → поле оценки → отчёт: правка одного значения таблицы — все четыре «устарел», причина отчёта называет таблицу; остальные объекты проекта — «актуален» |
| ТД35-2 | Правка, вернувшая прежнее состояние (тот же токен и `rev` невозможны — проверяется на каркасе с тем же `cache_key`): «актуален» |
| ТД35-3 | Удаление таблицы: зависимые — «источник удалён», имя таблицы в причине |
| ТД35-4 | Закреплённая модель вариограммы: она и зависимые от неё — не «устарел»; снятие закрепления — «устарел» |
| ТД35-5 | `lineage.rebuild` цепочки — после заданий все «актуален»; отмена на втором узле — третий и четвёртый не запускались; результат перестроения побитно равен расчёту с нуля |
| ТД35-6 | `.bfggis` туда-обратно: состояния и цепочки причин совпадают; старый проект без `lineage` открывается, состояния — по прямым проверкам |
| ТД35-7 | Существующие тесты «устарел» Э12–Э16 проходят без изменений |

## Последствия

- Каждое новое расчётное задание Э17–Э22 обязано вызвать `lineage.record`; проверка в `tests/test_structure.py`: виды объектов с `meta.algo` без поставщика в `lineage/providers.py` — ошибка.
- Модульные значки «устарел» в дереве заменяются общим компонентом (Э17); поведение для пользователя то же, плюс транзитивность.
- Риск: длинная цепочка и большой проект — показ дерева медленнее. Меры: память на запрос, пачка `lineage.status`, замер в bench.
