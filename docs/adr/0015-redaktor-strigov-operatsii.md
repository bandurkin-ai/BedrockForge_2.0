# ADR 0015. Редактор стрингов и версии слоя; операции с линиями и каркасами; «Перестроить» (Э9)

**Статус:** Предложен, 2026-11-19 (проект — architect, fable / xhigh; принимает оркестратор; «Решения 1–13 (предложение)» в конце — на подтверждение владельцем и оркестратором). Не пересматриваются: ADR 0002 (очереди `heavy` / `quick`, `spawn`, неизменяемые blobs), 0003 (схема, 409 по версии, таблица `line_layer_versions` — Э9), 0004 (части ≤ 64 тыс. треугольников, LOD), 0007 (BFA1, ETag, `Scene.addLayer`), 0011 (линии в blobs, задание `model.dtm`), 0013 (проверки, `POST /pick`, сечение; «Исправить» — Э9), 0014 (облака не правятся; параллельность — полосы и `nogil`, без `prange`).

## Варианты

| Вопрос | Варианты | Выбор и причина |
|---|---|---|
| Номер версии и защита от затирания | А) `objects.version`; Б) свой счётчик `line_layers.rev` + журнал, сохранение несёт базовую версию; В) пометка «слой занят» на время правки | **Б.** Журнал получает номера 1…N без дыр (приёмка «возврат к версии 1 → версия N+1»), смена цвета не отклоняет сохранение. В оставляет «вечно занятый» слой после сбоя окна и не нужна при одном пользователе |
| Хранение версий | А) версия = ссылки на неизменяемые blobs слоя (полная копия геометрии на сохранение); Б) дельты между версиями; В) геометрия в JSON строки журнала | **А.** Возврат и «версия 1 из импорта» не пишут файлов; сборщик blobs и `.bfggis` работают как с любым владельцем; читатели не меняются. Б — свой формат и чтение цепочки; В — 1 млн вершин в JSON |
| Тело сохранения | А) слой целиком в JSON; Б) слой целиком в BFA1; В) BFA1: порядок линий со ссылкой на исходную (`src`) + координаты только изменённых и новых | **В.** Закрывает находку 2, правка одной линии в слое 1 млн вершин — килобайты; атрибуты линии переносятся по `src`. А теряет побитность на вершине замыкания |
| Рабочая копия | А) перенос BF: линия — массив `[x, y, z]`, неизменяемые операции с общими нетронутыми линиями, `History`; Б) типизированные массивы на слой | **А.** 2 874 строки с 1 863 строками тестов переносятся как есть; 1 млн вершин — ~64 МБ и ~10 мс на перебор. Б — переписывание операций и тестов ради слоёв, которые целиком не правят |
| Ссылка операции на линии | А) позиция в слое; Б) устойчивый номер линии `lid`; В) копия координат контуров в записи операции | **Б.** «Перестроить после правки контура» берёт те же контуры при любых вставках и удалениях. В повторяет старую геометрию — противоречит 7.23 |
| Очередь операций | А) всё в `quick` (буква 7.23); Б) `quick` до порога входа, крупные — `heavy` | **Б** (решение 1). Исправление каркаса 10 млн треугольников — минуты; единственный быстрый исполнитель на это время закрыт для остальных операций и отчётов |
| Предпросмотр «Собрать из контуров» | А) синхронный запрос в процессе API с пределами; Б) скрытое задание `quick` с файлом результата; В) сшивка на TypeScript в окне | **А.** Как `POST /pick` и сечение: ядра `nogil`, прогреты быстрым исполнителем, вход ограничен. Б — запасной (риски); В — второй экземпляр алгоритма |
| Уровни детализации по запросу (долг) | А) часть отдаётся целиком, уровни строит задание `wireframe.lod`; Б) грубая кластеризация вершин в процессе API; В) уровни строит каждое задание, создающее каркас | **А.** Точные границы частей — без щелей, код показа не меняется; бюджет кадра уже умеет «сверх бюджета». Б — новый код упрощения в процессе API; В не закрывает проект без кеша (импорт `.bfggis`, копия папки) |
| Мелкие каркасы (долг) | А) общий blob порции, как `lines/pack.py`; Б) один `fsync` на порцию; В) геометрия мелких каркасов в SQLite | **А.** Решение Э7 для 2 000 слоёв (14,9 → 3,0 с) с готовым форматом и ролью `pack:<n>`. Б оставляет 3 файла и 4 строки на каркас; В нарушает ADR 0002 |

## Решение

### 1. Версии слоя и журнал (миграция `0006_e9_line_versions`)

| Что | Решение |
|---|---|
| `line_layer_versions` | `id`, `layer_id` → `objects.id` (CASCADE), `version` 1…N (уникально с `layer_id`), `action` (`import`, `create`, `save`, `restore`, `move`, `operation`), `note` ≤ 255, `author`, `created_at`, `line_count`, `point_count`, `prev_line_count`, `prev_point_count`, `stats` (длина 3D и в плане, площадь, число замкнутых, `flat`, `extent`, `origin`, `attr_schema`) |
| Файлы версии | `blob_owners(owner_kind = "line_version", owner_id = id строки)` с ролями слоя (`xyz`, `offsets`, `closed`, `seq`, `lid`, `attrs`, `vattrs` либо `pack:<n>`). `BLOB_OWNER_KINDS += line_version`, `BLOB_ROLES += lid` |
| `line_layers` | `rev` Integer NOT NULL, по умолчанию 1 — номер текущей версии журнала; `next_lid` Integer NULL (пусто — число линий) |
| Версия 1 | Строка журнала создаётся при первом сохранении или возврате — из текущих владельцев слоя (`import`, `create` или `operation`); у слоя без правок журнал показывает одну расчётную строку. Импорт 2 000 слоёв строк не пишет |
| Сохранение | Вне транзакции: сборка массивов (нетронутые линии — срезами blobs базовой версии, изменённые — из тела), `LineSet.validate`, временные файлы. В транзакции: `UPDATE line_layers SET rev = rev + 1 … WHERE object_id = :id AND rev = :base`; 0 строк → 409 `layer_changed` (текущая версия, автор, время), временные файлы удаляются, в БД ничего не меняется. Иначе владельцы слоя заменяются, пишется строка журнала N+1, `objects.version + 1`, счётчики и охват |
| Перенос при сохранении | Атрибуты линии — по `src`; новая линия — пустые; `new_attrs` задаёт значения (инструмент `tie` ставит `ROLE = TIE`; колонки нет — добавляется в схему). `vattrs` и `seq`: у нетронутой линии — как были; в изменённой вершина с побитно прежними координатами сохраняет строку и `seq`, перемещённая и новая — пустые поля и новые `seq`. `lid`: прежний по `src`, новой линии — `next_lid` |
| Возврат к версии | `POST …/versions/{k}/restore {expected_version}`: тот же путь без записи файлов — версия N+1 с blobs версии k (`restore`, «Возврат к версии k»); ничего не стирается |
| Перенос в другой слой | `lines.move_selected`: один запрос, одна транзакция — тело сохранения слоя-источника без линий и их геометрия; ядро дописывает линии к текущей геометрии приёмника; проверяются `rev` обоих слоёв, оба получают версию (`move`) |
| Удаление, архив | Строки журнала уходят каскадом, владельцы `line_version` снимаются явно (как `drop_import_owners`). `.bfggis`: `Table("line_layer_versions", renumber=True)`, `layer_id → objects`, владелец `line_version → line_layer_versions` |
| Чего нет | Автоматической очистки журнала (решение 3); правки облаков (`meta.cloud` → 422 `not_editable`, ADR 0014) |

### 2. API (`/api/v1`; ошибки `{code, message, hint}`; проект только для чтения — 423)

| Запрос | Назначение |
|---|---|
| `POST /lines/layers {name, file_id?, color?}` | `lines.new_layer`: пустой слой в новом `line_file` (`meta.format = "editor"`) или в указанном файле; название — код стринга в STR; занято — «имя (2)» |
| `GET /lines/layers/{id}/geometry[?lines=]` | BFA1 `linegeom`: заголовок `{layer_id, version, lines, points, ties}`, массивы `xyz <f8`, `offsets <u4`, `closed u1`, `lid <u4`; ETag по blobs. Служит редактору, привязке к другим слоям и измерению выбранной линии |
| `PUT /lines/layers/{id}/geometry` | Тело BFA1: заголовок `{base_version, note, new_attrs}`, массивы `src <i4` (`lid` исходной линии, −1 — новая), `touched u1`, `count <u4`, `closed u1` — по линии в новом порядке; `xyz <f8` — только изменённые и новые линии в виде хранения (замкнутая повторяет первую вершину). Ответ — слой и версия; 409 `layer_changed`; 422 `bad_geometry` |
| `GET /lines/layers/{id}/versions`, `POST …/versions/{k}/restore`, `POST /lines/layers/{id}/move-lines` | Журнал (версия, когда, кто, действие, линии и вершины «было → стало», заметка), возврат, перенос |
| `GET /viz/sets/{id}/snap?section=…` или `?bbox=…` | BFA1 `snap` (п. 4) |
| `GET /operations`, `POST /operations {op, params, name, folder?}` | Список операций; предусловия → 422, иначе задание `geometry.operation` (п. 6) |
| `POST /wireframes/{id}/rebuild`, `POST /lines/layers/{id}/rebuild` | `model.rebuild` для каркаса и для слоя-результата |
| `POST /geometry/stitch/preview` | Предпросмотр «Собрать из контуров» (п. 6) |

### 3. Рабочая копия (`ui/src/edit/` — чистый TypeScript; тест запрещает импорты three и react)

| Модуль (строк в BF) | Содержание |
|---|---|
| `model.ts` (238) | `EditLayer {lines, nextId}`, `EditLine {id, points: [x, y, z][], closed, attrs, src}`, `Selection`, `History` (шаг, живое перетаскивание `replace` → `commit`, отмена и повтор; ≤ 200 шагов и ≤ 256 МБ заменённых линий) |
| `io.ts` (58) | Хранение ↔ рабочая копия: у замкнутой линии повтор первой вершины снимается и возвращается; «изменена» = объект линии не тот, что загружен |
| `ops.ts`, `offset.ts` (580) | Добавить линию и точку, замкнуть и разомкнуть, сдвинуть вершины и линии, вставить и удалить вершину, копия на вектор, разорвать в вершине, соединить две, развернуть, копия со смещением (митра), проредить (Дуглас–Пекер), сгустить, сгладить, забрать и вложить линии (перенос) |
| `coords.ts` (148) | Плоскость и луч; `X Y Z` и `X Y`; `@азимут расстояние [наклон]` (азимут от севера по часовой, наклон от горизонта, вверх — плюс); `@@dX dY [dZ]`; запятая и точка |
| `measure.ts` (243) | Вершины, длина 3D и в плане, периметр, площадь полигона в его плоскости (вектор Ньюэлла) и в плане; суммы по слою — с несохранёнными правками |
| `snap.ts`, `snapIndex.ts` (713), `pick.ts` (153) | Цели привязки, экранный индекс, попадание по вершинам и отрезкам, рамка |
| `session.ts`, `tools.ts` (741) | Сеанс: инструменты `select`, `line`, `polygon`, `point`, `tie`, `insert`; выбор, клавиши, привязка; сцена даёт только события указателя и луч курсора |

Правила: числа float64 не округляются и не сужаются; операция — чистая функция «слой → новый слой», без изменений возвращает тот же объект (шага истории нет); вершина без высоты (NaN) остаётся без высоты, в 3D-длину и площадь не входит, нулём не становится; предел правки — слой до 1 млн вершин (решение 4). Куда ложится точка: в плане — на `Z` панели; при отсечении — в вертикальную плоскость середины окна разреза; при привязке — в точку цели либо в её проекцию на плоскость разреза (переключатель).

### 4. Привязка: что считает ядро, что окно

| Цель | Точные координаты (float64) | Кто |
|---|---|---|
| Вершина, середина, ближайшая точка сегмента — рабочая копия | Рабочая копия | Окно |
| То же — другие видимые слои линий | `GET /lines/layers/{id}/geometry`, кеш по версии; слой > 500 тыс. вершин и облака в привязке не участвуют (строка в панели привязки) | Ядро отдаёт, окно ищет |
| Вершина и ребро каркаса | `POST /wireframes/pick` (Э8): точный треугольник под курсором → ближайшая вершина, ближайшая к лучу точка ребра; запросы с паузой 30 мс, устаревшие отменяются | Ядро — треугольник, окно — выбор |
| Сечение каркаса на разрезе | `GET /viz/wireframes/{id}/section` (Э8, `xyz <f8`) | Ядро |
| Устье, траектория, границы интервалов | `GET /viz/sets/{id}/snap`: `collars <f8`, `trace <f8` + `trace_offsets` (ломаная с допуском 1 см к дуге, как пути ADR 0007), `bounds <f8` + `bound_hole`, `bound_depth` — позиции «от» и «до» всех интервальных таблиц и проб по десуртингу ядра. Отбор скважин по окну разреза или охвату вида; ≤ 5 000 скважин и ≤ 2 млн точек, иначе `truncated` и только устья; ETag по версии набора, ревизиям таблиц и окну | Ядро |
| Узел сетки | `gridSnap(точка, шаг, плоскость)` | Окно |

Окно: экранный индекс целей (равномерная сетка по окну вида, сортировка подсчётом в типизированные массивы, пересборка после движения камеры или смены источника), приоритет видов цели, радиус в пикселях, включение целей по отдельности, проекция целей скважин и каркасов в плоскость разреза, подпись у курсора.

### 5. Редактор в 3D-окне и интерфейс

| Что | Решение |
|---|---|
| Ввод | `viz/core/toolInput.ts`: при активном инструменте события указателя (нажатие, движение, отпускание, щелчок, двойной щелчок, правая кнопка без перетаскивания, `Shift`, `Ctrl`) сначала получает сеанс; взял — камера не двигается (на время перетаскивания вершины и рамки `controls.enabled = false`). `Scene.setTool(handler)`, `Scene.cursorRay(px, py)` — луч в координатах проекта float64 (с обратным преувеличением Z). Обработка указателя выносится из `Scene.ts` |
| Слой правки | `viz/edit/overlay.ts` (`SceneLayer`, ключ `edit`): линии рабочей копии одним буфером с диапазонами по линиям (изменённая линия переписывается на месте); метки вершин — у выбранных и ближайших к курсору линий (≤ 20 тыс.); нить, рамка, значок и подпись цели, тай-линии штрихом; float32 от целого начала (`viz/origin.ts`), поверх глубины. ### 6. Операции: задание, запись, «Перестроить»

| Что | Решение |
|---|---|
| Задание | `geometry.operation {op, params, name, folder, rebuild_of}` (`ops/job.py`); очередь `quick` при входе ≤ 2 млн треугольников, иначе `heavy` (решение 1); `max_attempts = 1`; память — по треугольникам входа. Прогресс и отмена — между шагами и порциями ядер numba; вызов manifold3d — через `ExecutionContext`, если 9.11 подтвердит отмену, иначе неделим |
| Предусловия | `ops/registry.py::precheck` — в запросе (422 до постановки) и повторно в задании: объекты есть и готовы, вид, замкнутость по `wireframes.stats`. Пример: `{code: "wireframe_open", message: "Каркас «Тело 2» не замкнут: открытых рёбер — 14.", hint: "Запустите «Исправить каркас» и повторите."}`; окно показывает кнопку «Исправить каркас» |
| Результат | Новый объект (или несколько) в папке первого исходного; имя — из операции и исходных, занято — «(2)». Каркасы — `stage_wireframe` / `commit_wireframe`; линии — `line_file` (`meta.format = "operation"`) со слоями. Одна транзакция в конце: отмена и сбой не оставляют ни объектов, ни временных файлов; исходные читаются и не меняются |
| Запись операции | `objects.meta.built = {kind: "operation", op, title, algo, params, sources: [{role, kind, id, name, version, lines}], tolerances, report, at, rebuild_of}` у каждого объекта результата; у ЦТМ — прежняя запись `kind: "dtm"`. Связь с исходными — номера в записи, **не** `object_refs`: `RESTRICT` запретил бы удалять контуры после построения тела. `.bfggis` перенумеровывает номера (`remap_built` обобщается в `ops/provenance.py`); удалённый исходный теряет номер, имя остаётся |
| Линии в параметрах | `contours[].lines`, `polygon.line`, `boundary.line` — устойчивые номера `lid`; `lines: null` — все линии слоя. У слоя без правок `lid` = позиция |
| «Перестроить» | Операция и параметры из `built` на текущих исходных → обычное задание с `rebuild_of`; тай-линии читаются из слоёв заново (те же линии по `lid` и метке `ROLE = TIE`); результат — новый объект, старый не меняется. Исходный удалён или линии нет → 422 с именем. ЦТМ — задание `model.dtm` с `built.params` |
| После операции | Окно ставит `wireframe.check` на каркасы результата (как мастер импорта); показ до готовности уровней — п. 8 |
| Предпросмотр | `POST /geometry/stitch/preview {contours, ties, start_cap, end_cap}` — координаты из рабочей копии (контуры могут быть не сохранены); ≤ 500 контуров и ≤ 50 тыс. вершин, иначе 422 «создайте каркас операцией»; ответ BFA1 `mesh` (float32 от целого начала) и `{triangles, closed, volume, warnings}`; ничего не хранится |
| Команды | `model.operation {op, params, name}` (confirm), `model.rebuild {wireframe_id или layer_id}` (confirm); 13 диалогов `model.*` — одно окно по схеме полей (`modules/model/opForms.ts`); «Собрать из контуров» и «Править треугольники» — панели в режиме правки |

Сшивка (`stitch`):

| Шаг | Решение |
|---|---|
| Нормаль и разрезы | Общая нормаль — среднее нормалей плоскостей контуров (вектор Ньюэлла); контуры группируются в разрезы по положению вдоль неё (допуск — десятая медианного шага, не меньше 1e−6 м) и поворачиваются против часовой стрелки; вершины контуров идут в результат первыми, побитно |
| Пары контуров | На соседних разрезах — назначение по центрам (`linear_sum_assignment`); 1 : 1 — лента, 1 : N — разветвление |
| Соответствие вершин | Кратчайший путь в графе Фукса–Кедема–Юзелтона: узел (i, j) — ребро a_i–b_j, шаг вдоль любого контура добавляет треугольник ценой длины нового ребра. Длины берутся после приведения контуров к общему центру и размеру (сопоставление по форме, а не по положению). Лучшее начало ищется точно: кратчайшие пути разных начал не пересекаются, поиск делится пополам — O(n·m·log m). Путь один раз обходит оба контура — лента без перекрута |
| Тай-линии | Линия из двух вершин с атрибутом `ROLE = TIE` (инструмент `tie`) либо без метки, оба конца которой стоят на вершинах контуров (≤ 1e−3 м). Тай-линия закрепляет узел пути: поиск идёт отдельно между соседними тай-линиями, каждая становится ребром результата |
| Разветвление | Родительский контур режется одной прямой хордой между группами дочерних; каждая часть сшивается со своим дочерним контуром как замкнутая. Две трубы проходят рёбра хорды в противоположных направлениях — получается манифолд. Концы хорды вставляются в родительский контур во всех его употреблениях (лента с другой стороны, крышка); внутренние точки хорды сдвигаются на четверть пути к дочерним (седло). Ветви, не разделимые прямой, — отказ с номерами разрезов и линиями (помогают тай-линии или промежуточный контур) |
| Торцы | `none`; `flat` — крышка earcut в плоскости наилучшего приближения; `point` — вершина за центром контура на `cap_distance` × шаг разрезов; `line` — гребень; `extend` — копия контура на `cap_distance` × шаг и плоская крышка |
| Проверки | Замкнутость и ориентация наружу — всегда; самопересечения — `geo/checks.py` с точным подтверждением пар; найдены — отказ с парой разрезов |
| Ограничения (ТЗ) | Контур повёрнут не больше чем на 60° от плоскости разрезов; хорда одна и прямая; самопересечения не исправляются; оболочки нет (решение 8) |

## Последствия

- Э10 (серии разрезов) получает редактор, привязку к сечениям и `stitch` по контурам серий; Э11 (OMF, экспорт проекта) — писателей без изменений, журнал версий и запись операций уже в `.bfggis`; Э15 — линии пересечения и обрезку; Э17 — замкнутые тела после «Исправить» для кодирования блоков; Э19 — булевы и обрезку для неявных тел; Э23 (ассистент) — `lines.add_line`, `model.operation`, `model.rebuild` с подтверждением.
- Схема: миграция 0006 (таблица `line_layer_versions`, две колонки `line_layers`), владелец blobs `line_version`, роль `lid`; у каркасов появляется роль `pack:<n>`.
- Процесс API больше не вызывает pyfqmr; правило на будущее: расчёт дольше ~100 мс или с холодной компиляцией — только в исполнителе.
- Не входит: оболочка тела, автоматическое исправление самопересечений, полигон обрезки с отверстиями, правка облаков точек и значений атрибутов, очистка журнала версий, совместная правка одного слоя (на сервере — отказ второму сохранившему).
- В отчёт вехи: оценка 5–6 окон; решения 1, 2, 5, 10; «побитно» у изменённой замкнутой линии — вершина замыкания равна первой (у нетронутой — как в файле).
