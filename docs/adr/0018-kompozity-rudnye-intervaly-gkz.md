|---|---|---|

### 2. Хранение результатов, «устарел», «Перестроить»

| Что | Решение |
|---|---|
| Таблица-результат | `dh_tables` вида `interval`; содержания — колонки роли `component` с единицами источника. Имя: «Композиты 2 м», «Композиты по доменам», «Композиты по уступам 10 м», «‹Таблица› — коды», «‹Таблица› — координаты», «Объединение: …», «Рудные интервалы»; занято — « (2)»; «Заменить» — подмена одноимённой (`swap_in`). Колонки композитов — по ТЗ 8.2.3: LENGTH, X, Y, Z, поля источника, DENSITY, SAMPLED_LEN, N_SAMPLES, DOMAIN, FLAG |
| `dh_results` (миграция `0007_e12_dh_results`, обратимая) | `id`, `set_id` → `objects` CASCADE, `table_id` → `dh_tables` CASCADE (NULL — «Анализ кондиций»), `op` (`length`, `domain`, `bench`, `coding`, `merge`, `coords`, `topcut`, `equivalent`, `declus`, `ore`, `conditions`), `name`, `params` JSON (числа, с которыми считало ядро), `inputs` JSON, `sha256`, `algo` (версия алгоритма операции), `report` JSON (сводка «до/после», пороги и отчёт урезки по доменам, сводка Д-26, варианты кондиций, ручные правки, версии numpy и numba, секунды), `job_id`, `created_at` |
| `inputs` | Таблицы — `name_key` + `rev` + поля; набор — `objects.version` (устья и инклинометрия → X, Y, Z, уступы, кодирование); каркасы — ключ геометрии (`MeshState.cache_key`) + имя. Идентификаторов в JSON нет — `.bfggis` ничего не пересчитывает |
| «Устарел» | Вычисляется при чтении списка: текущие `rev`, версия набора и ключи геометрии ≠ записанным → `stale {reason}` («изменена таблица „Пробы“», «каркас удалён»). Обработчики правок не трогаются. Своя запись полей обработкой сдвигает отметку `rev` у остальных свежих результатов этой таблицы в той же транзакции, кроме тех, чьи входные поля перезаписаны |
| SHA-256 входов | В задании: байты выбранных колонок, FROM, TO, имён скважин, станций траекторий, ключей геометрии и параметров. «Перестроить» с тем же хешем и `algo` расчёт не повторяет — снимает «устарел» |
| Атомарность | Таблица `building` под id задания → одна итоговая транзакция: подмена, колонки на месте, `dh_results`, отметки `rev`; отмена и сбой — `drop_building`, ничего не остаётся. После транзакции задание кладёт снимок `cache\tables\<id>-<rev>.parquet` из своих массивов (таблица открывается без расшифровки векторов) |
| Поля на месте | `sink.write_columns`: все колонки операции одним проходом по `dh_rows`, `rev` + 1, одна запись журнала правок `column` («Отменить» скрывает колонки), событие `drillholes.changed`. Повтор операции перезаписывает свои колонки |
| Дерево и «Свойства» | У набора — строки «Обработка проб»: результаты с пометкой «устарел»; меню: «Открыть таблицу», «Параметры…» (окно с прежними значениями), «Перестроить», «Свойства» (источник, параметры, хеш, версия, время, сводка), «Удалить» (у полей на месте — убирает колонки). `GET /drillholes/sets/{id}/tables` отдаёт `origin {result_id, op, stale}` |
| `.bfggis` | `archive/spec.py`: `dh_results` (`set_id` → `objects`, `table_id` → `dh_tables`, `job_id` → NULL); тест цикла (10.5 п. 5) |

### 3. Что создаёт таблицу, что пишет поля

| Операция | Результат |
|---|---|
| Композиты (по длине, доменам, уступам); кодирование каркасами (с делением и без); объединение таблиц; координаты проб; рудные интервалы | Новая таблица набора + `dh_results`. Исходная таблица не переписывается |
| Урезка | Поля `<F>_CUT`, `<F>_CUT_F` в таблице источника + результат «Урезка · ‹F›» с отчётом и порогами по доменам |
| Эквивалент металла; декластеризация | Поле (имя задаёт пользователь, по умолчанию `<F1>EQ`); поле `DECL_W` + отчёт (кривая «размер → среднее», лучший размер) |
| Рудные интервалы | Таблица + поля `ORE_ID` (номер интервала в скважине, 1…k — не зависит от порядка скважин), `ORE_CLS` в таблице проб |
| Анализ кондиций | Результат без таблицы: варианты в `report`, окно-таблица, экспорт XLSX / CSV |

### 4. Общий движок интервалов (`composites/intervals.py`, `strips.py`)

| Часть | Решение |
|---|---|
| Представление | «Линии»: строки, упорядоченные по (скважина, FROM), и начала скважин (как `Snapshot.hole_index()`); текст — коды int32 (`pandas.factorize`), пусто — −1. Строки с TO ≤ FROM и перекрытия с предыдущей пробой не участвуют и считаются в журнале задания (не молча) |
| Ядра | `overlay` (границы двух наборов интервалов → подынтервалы с номерами покрывающих строк; N таблиц — свёрткой), `runs` (непрерывные участки по коду или порогу), `targets` (границы композитов), `aggregate` (Σ l·w·g / Σ l·w, ρ, L_оп, N, NaN не участвует и не становится нулём), `mode_by_length`; суммы — попарные, в порядке проб (8.0.1) |
| Кто пользуется | Композиты (участки доменов → `targets` → `aggregate`), объединение (`overlay`), кодирование (`overlay` проб с участками внутри тел), координаты, урезка (перцентили по доменам с весом длины), Д-26 (линии опробования, элементарные интервалы — `runs`, M, MC, C) |
| Источник и запись | `source.py` — только выбранные колонки: из снимка Parquet, иначе узким чтением `dh_rows`; траектории — `drillholes.trajectory`. `sink.py` — запись таблицы порциями, колонки на месте, итоговая транзакция |

### 5. numba, потоки, точность

| Что | Решение |
|---|---|
| Ядра | `from bf_core.jit import njit`; `cache=True, nogil=True`; без `fastmath`, `parallel`, `prange`; одни и те же типы аргументов (float64, int64, int32) — по одной специализации |
| Потоки | Полосы по 4096 скважин, границы не зависят от числа потоков; два прохода «счёт → смещения → заполнение», полоса пишет только свой участок; итоговые суммы — в одном потоке. Потоков — min(8, ядра / исполнители `heavy`) (как `ground.classify`). Результат побитно одинаков при 1, 2, 4, 8 потоках — тесты, в том числе `-m windows` |
| Сравнения Д-26 | C ≥ Сб, M ≤ Мпп, M ≥ Мрт, MC ≥ МС, C ≥ Смин — с относительным допуском 1e−9 в сторону равенства («равенство — руда», M = Мпп — присоединение); M, MC — прямые суммы по фрагменту, не разности накопленных |
| Первая компиляция | Шаг `composites` прогрева исполнителей (`ops/warm.py` → `composites/warm.py`: все ядра на наборе из 3 скважин); цель ≤ 30 с (8.0.2) |
| Память | Колонки float64, текст — коды; запись порциями по 50 тыс. строк; оценка для планировщика — строки × (поля + 6) × 8 Б × 3 |

### 6. Композиты, кодирование, объединение, координаты

| Операция | Решение |
|---|---|
| По длине | Алгоритм 8.2.2 дословно: участок [a; b] домена, отсчёт от a / устья / кровли первой пробы, «равные» и «остаток» (f_min; присоединить, отбросить, n0 = 0 — в журнал), p_min → NaN и FLAG «мало проб», вес по плотности, непробованное — NaN / 0 / число |
| По доменам | Источник кода: поле той же или другой интервальной таблицы (`runs` + `overlay`) либо каркасы (участки п. «Кодирование» без промежуточной таблицы); композит не пересекает смену кода |
| По уступам | Глубины Z = Z_j — ядро на дугах минимальной кривизны (`_pieces` и уточнение по `Trajectories.positions`, как `geo/intersect`), допуск 1e−6 м; Z_верх по умолчанию — максимум Z устьев, округлённый вверх до H; X, Y, Z — середина по длине; FLAG «пологая» |
| Кодирование каркасами | `geo/intersect.py`: `MeshTarget.from_stats` → `hole_crossings` → `inside_intervals`, по одному каркасу в памяти. Это строже записи ТЗ «хорды ≤ 1 м»: куски в 1 мм от дуги, глубина — по дуге (ADR 0013); код не переписывается. Только замкнутые тела (`stats.closed`), иначе 422 `wireframe_open` с подсказкой «Проверьте и исправьте каркас». Ствол без пересечений с телом: устье проверяется вертикальным отрезком от верха охвата тела теми же ядрами (сумма знаков) — внутри → интервал [0; длина]. Перекрытие тел — приоритет по порядку списка. С делением — пробы режутся в точках входа и выхода, значения копируются в части; без деления — код по середине и `INSIDE_FRAC` |
| Объединение таблиц | `overlay` всех выбранных таблиц; колонки — с именем таблицы при совпадении имён; нет покрытия — NaN / пусто |
| Координаты проб | Копия таблицы + XB, YB, ZB, XM, YM, ZM, XE, YE, ZE (`Trajectories.interval_positions`); скважина без траектории — NaN и запись в журнале |

### 7. Урезка, эквивалент, декластеризация

| Операция | Решение |
|---|---|
| Урезка | T — число или перцентиль P с весом длины (`weighted_percentiles`, правило BF) по доменам; `<F>_CUT = min(g, T)`, `<F>_CUT_F`; NaN остаётся NaN. Отчёт по домену — 8.2.2. Порог автоматически не применяется: «Применить» — отдельное действие с порогами из окна |
| Анализ урезки | Синхронно, `POST /composites/topcut/analysis`: одна сортировка и накопленные суммы на домен → кривые «порог → среднее, CV, потеря металла, число урезанных» для P 90…99,9 %, доли металла по децилям и процентилям верхнего дециля с пометками (40 % / 10 %, пороги — параметры), квантили для лог-вероятностной кривой. В окне Э12 — простые SVG-кривые; график 8.3 целиком — Э13 |
| Эквивалент | Формула 8.2.2; k — по единице поля (г/т и $/унц — 1/31,1034768; % и $/т — 0,01; ppm = г/т; ppb — ×0,001); компонент NaN → Eq = NaN («считать нулём» — только явной галочкой) |
| Декластеризация | Перенос BF: ячейки в плане, полигоны (`cKDTree`). 3D — GSLIB declus: ячейка (cs, cs·anisy, cs·anisz), `noff` сдвигов, критерий min / max; начало и сдвиги по X, Y — как в BF (Т8.2-11). Без матрицы «размеры × точки»: средние по размерам → лучший → веса вторым проходом; размеры — по потокам. Точки — середины интервалов; нет координат или значения — вес NaN; Σ весов = n |
