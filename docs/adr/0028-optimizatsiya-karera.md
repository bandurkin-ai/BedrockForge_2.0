### 2. Экономика блока (8.11.2)
| № | Решение |
|---|---|
| 3 | Параметры (`spec`): модель; элементы e (поле содержания, единица → k_e: г/т — 1/31,1034768 унц/г, ppm = г/т, ppb — 10⁻³ г/т, % — 0,01 т/т (цена за т металла); цена P_e, сбыт S_e на единицу металла, роялти roy_e ∈ [0; 1)); плотность (поле или число > 0, `default_density` для пропусков, № 118); породы (решение 4): для каждой — c_p, извлечение rec_e(r), c_mр, «только пустая», «воздух»; c_m0, Z_ref (по умолчанию — верх сетки), H_гл = 10 м, c_гл = 0; RF (список или {от, до, шаг}: 0,30…1,50 шаг 0,05; 0,01–5; ≤ 200); углы (решение 6); рельеф и ограничитель (решение 5); K (авто / 1–20); допуск угла 2,5° (0,5–10); календарь Q_р, Q_гм, r = 8 % (0–50 %); префикс полей (№ 120); решатель `auto` / `hpf` / `ortools` |
| 4 | Тип породы r_b: А) категорийное поле (каждая подпись — тип; «(пусто)» — отдельный тип) или Б) правила: упорядоченный список {имя, дерево `filters/schema`}, первое с f > 0, иначе «прочие». «Запустить» недоступна, пока у каждого встреченного типа не заданы c_p и rec_e всех элементов (или «только пустая» / «воздух»), у каждого элемента — P_e, и c_m0: `POST /pit/validate` → `{ready, missing [{param, message}]}` — один источник для кнопки и для 422 `pit_not_ready` при запуске |
| 5 | t_b = V_b·FRAC_b·f_b·ρ_b (`geometry.row_volumes`); f_b = доля дерева `restrict.combine`(ограничитель, лист `surface {id: рельеф, side: below, by: frac}`); f_b = 0 или тип «воздух» — «воздух»: вне графа, не пустая (Т8.11-9). Без рельефа f_b = доля ограничителя (без него — 1) |
| 6 | Формулы ТЗ дословно (`econ_kernels`, numba `cache=True`, float64): R_b = Σ_e t_b·g_e,b·k_e·rec_e(r_b)·(RF·P_e − S_e)·(1 − roy_e); C_m = t_b·(c_m0 + c_гл·max(0; (Z_ref − z_b)/H_гл)) (z_b — центр блока); C_p = t_b·(c_p(r_b) + c_mр(r_b)); v_b = max(R_b − C_p; 0) − C_m; руда при R_b − C_p > 0 (RF = 1 — поле ORE); «только пустая» → R_b = 0. g_e = NaN: элемент выручки не даёт, тоннаж и число блоков — в «Контроль» (№ 117), никогда не 0 в полях и средних. ρ = NaN без `default_density` — 422 `pit_density_missing {blocks}` |
| 7 | Субблоки (№ 119): узел графа — родитель; v_родителя = Σ v строк (решение руда/пустая — по строке), t и металл — суммы; родитель — «воздух», если все строки — «воздух». Пустые ячейки разреженной модели ниже рельефа — пустая порода типа «(пусто)» с `default_density` (№ 118), выше рельефа или без рельефа — «воздух»; число и объём — в «Контроль» |
| 8 | Целые для решателя: q = max(0,01; Σ abs(v_b)/10¹⁶), v'_b = round(v_b/q) (int64; Σ abs(v') ≤ 10¹⁶ + N < 2⁶³ — «бесконечность» = Σ_(v'>0) v' + 1); ошибка цели ≤ N·q/2 — в `meta.objective_error` и в окне. Граничное содержание (Т8.11-7) по каждой паре (тип, элемент) при RF = 1 и прочих элементах 0: g_гр = (c_p + c_mр)/(k_e·rec_e·(P_e − S_e)·(1 − roy_e)) — без затрат на добычу (№ 123); P_e ≤ S_e — «нет», не ∞ |

| 12 | Контроль угла: R(M), M = 2K — достижимые замыканием шаблона на M уровней (поиск в ширину по смещениям); ρ(az) = max_(o ∈ R(M), уровень M) o·û(az); φ_эфф(az) = atan(M·dz/ρ(az)) через 1°; max и среднее abs(φ_эфф − φ) по домену; > допуска — предупреждение «Ошибка угла X° больше допуска: увеличьте K» (не отказ). Задание `pit.check` отдаёт смещения, K, ошибки и φ_эфф(az) для окна; приёмка — Т8.11-6 и числа прототипа ТЗ (45°, кубы, K = 8: 17 смещений, 1,44°) |

### 4. Максимальное замыкание (8.11.3)
| № | Решение |
|---|---|
| 13 | Граф (`graph`): узлы — родители не «воздух» внутри охвата; плотный индекс int32 по **обрезанному охвату** узлов (−1 — нет узла), `nx·ny·nz` охвата ≤ 2³¹ − 1 и память индекса ≤ 1 ГБ, узлов ≤ 10 млн — иначе 422 `pit_too_large` «укрупните модель регуляризацией». Предшественник за пределами сетки или «воздух» — нет дуги (свободно). Предобработка: оставить объединение конусов над блоками с v > 0 при RF_max — подъём по уровням снизу вверх (`needed[k] |= dilate(needed[k − m], шаблон уровня m)`), numba `prange` по столбцам уровня (логическое ИЛИ — побитно при любых потоках) |
| 14 | HPF (`hpf_kernels`, numba `cache=True, nogil=True`, однопоточный): псевдопоток Хохбаум для замыкания, нормализованное дерево, правило наименьшей метки; дуги не хранятся — соседи узла строятся из шаблона и плотного индекса; поток — только у рёбер дерева (у дуг вне дерева 0 — `assert` в отладочной сборке `BF_PIT_DEBUG=1`). Ядро работает порциями операций и возвращает состояние: между порциями — отмена, прогресс, контроль памяти. Ответ — **наименьшее** оптимальное замыкание: достижимые из s в остаточной сети (поиск в ширину по шаблону + рёбрам дерева с потоком). Режим «явные дуги» — то же ядро над CSR предшественников (`explicit`, MineLib); `flow_ref` — OR-Tools SimpleMaxFlow (явные дуги порциями, `get_source_side_min_cut` = наименьшее замыкание); scipy — только тесты. Оба решателя за одним интерфейсом `solve(graph, v') → mined bool[узлы]`; `solver: auto` — HPF |
| 15 | **Ранняя точка замера (подшаг 21.6):** синтетика 1 млн узлов (эллипсоидальное тело, логнормальные содержания, ρ 2,7, 45°, K = 8, кубы 10 м), одно решение RF_max на полном графе: время и пик памяти HPF и OR-Tools, равенство значения и набора блоков; прогноз 25 оболочек и 5 млн. Критерии: (а) HPF ≤ 20 с и ≤ 0,8 ГБ на 4 потоках ВМ и = OR-Tools → HPF основной; (б) HPF > 20 с → по порядку: тёплый старт по RF (вариант В «Оболочки»), глобальная перенумерация меток / порядок обработки сильных корней, затем OR-Tools основной ≤ 1 млн, HPF > 1 млн с исключением 5 млн в «Допущения»; (в) HPF ≠ OR-Tools после второй попытки Sonnet → Opus (CLAUDE.md «Эскалация»), до исправления — OR-Tools основной (интерфейс тот же — волны 4–5 не ждут). Выбор пишет оркестратор в «Допущения» до волны 4 |
| 16 | Детерминизм (Т8.11-9): решатель однопоточный, порядок узлов — по P; параллельны только экономика (по строкам), конусы (по столбцам уровня) и запись полей — без сумм между потоками; наименьшее оптимальное замыкание единственно, поэтому PIT побитно одинаково при 1–8 потоках и у HPF и OR-Tools. Суммы отчёта — Neumaier в порядке строк |

### 5. Оболочки, отчёт, календарь (8.11.3–8.11.4)
| № | Решение |
|---|---|
| 17 | Оболочки (`shells`): RF по возрастанию; C(RF_max) на графе решения 13; C(RF_min) — на C(RF_max); внутри (RF_a; RF_b) граф = C(RF_b) \ C(RF_a): узлы C(RF_a) стягиваются в s (вынуты), вне C(RF_b) — исключены; интервалы делятся пополам рекурсивно. Вложенность C(RF_k) ⊆ C(RF_(k+1)) — по построению и проверкой (Т8.11-5: ни одного вынутого без вынутого предшественника — проверка по шаблону после каждого решения; нарушение — 500 `pit_internal` с журналом, не результат) |
| 18 | Отчёт (`report`) по приращениям ΔC_k = C_k \ C_(k−1) при базовой цене (RF = 1, руда — ORE): руда и пустая (т), коэффициент вскрыши W/O (O = 0 — пусто), по элементам — среднее содержание руды (по тоннажу блоков со значением), металл в руде и извлекаемый, выручка, затраты на добычу, переработку, сбыт, роялти, CF = выручка − затраты; накопленные по C_k. Худший случай для n: C_n по уровням модели сверху вниз (уступ = уровень k, № 122); лучший — ΔC_1 … ΔC_n |
| 19 | Календарь (`npv`, ТЗ дословно): τ_i = max(O_i/Q_р; (O_i + W_i)/Q_гм) (Q_гм пусто — без ограничения; Q_р обязателен для NPV), t_i = Σ_(j<i) τ_j, NPV = Σ CF_i·((1 + r)^(−t_i) − (1 + r)^(−(t_i + τ_i)))/(τ_i·ln(1 + r)), τ_i = 0 → CF_i·(1 + r)^(−t_i); r = 0 — предел (CF_i). NPV лучшего и худшего случаев для каждого n. Календарь — показ: не вход графа и не часть отпечатка, пересчёт синхронно из `data` (Т8.11-8) |
