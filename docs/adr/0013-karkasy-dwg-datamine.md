# ADR 0013. Каркасы: форматы, проверки, точный выбор и сечение; DWG, Datamine (Э8)

**Статус:** Принято, 2026-11-18 (проект — architect, fable / xhigh; принято оркестратором с решениями на подтверждение: пересечения стволов с каркасами — в Э8, «Исправить» — Э9, TRIDB «побитно» = BLOB геометрии байт в байт и равные строки, части по 64 000, `seq` — в `wireframes/source.py`; Д-22 «облака точек» — подэтап Э7.1 после Э8). Не пересматриваются: ADR 0003 (схема), 0004 (части ≤ 64 тыс. треугольников, LOD, точный выбор в ядре), 0007 (BFA1, `/viz/sets/{id}/intersections`), 0009 (DWG — вариант А; Datamine — свой читатель), 0010 (писатели для Д-17), 0011 (основа каркасов и ЦТМ сделаны в Э7).

## Контекст

- ТЗ 7.21, 9.4, 9.5, 9.12 (TRIDB — импорт и **экспорт**; Surpac DTM — пара STR + DTM, импорт и экспорт; DXF-каркасы; OBJ, STL — в обе стороны), 5.3 (бюджеты), 5.4 (побитно; объём 1e−9), раздел 11 (Э8: «импорт, проверки, исправление, объём, LOD, BVH, точное сечение», 2–3 окна); 7.35: Д-13 (DWG — обязательно; каркасы и стринги Datamine — желательно, образцов нет, вопрос № 4), Д-17 (писатели каркасов, DWG).
- Сделано в Э7 (ADR 0011): хранение (`wireframes/store.py`: blobs `xyz <f8`, `tri <i4` в Z-порядке), части и LOD (`geo/meshes.py`, `viz/meshes.py`), слой 3D и грубый выбор (`ui/src/viz/mesh/*`), «Построить ЦТМ», дерево, «Свойства» (имя, цвет, атрибуты). `mesh_stats` уже считает площадь, объём, замкнутость, ориентацию, вырожденные, открытые и неманифолдные рёбра.
- Нет: читателей и писателей каркасов (`.tridb .obj .stl .dtm .dwg` — в `LATER`, сетки DXF только считаются), проверок нормалей и самопересечений, `POST /pick`, линий сечения, пересечений стволов с каркасами (ADR 0007 и CHECKLIST 7.14, 7.15 отсылают к Э8), экспорта (`wireframe.export`, `model.self_intersections` — `stage: "Э8"`).
- В BF есть: `formats/wireframes.py` (TRIDB, DXF, OBJ, STL — 510 строк), `dxf_stream.py::read_dxf_meshes`, `export.py::write_dxf_mesh`, `write_obj`, `geo/checks.py` (262), `section.py` (112), `pick.py` (118), `intersect.py::MeshTarget`; тесты `test_wireframes_stage10.py`, `test_intersect.py`. Нет в BF: запись TRIDB, STL, Surpac DTM, DWG, Datamine.
- Проверено при проектировании. Оба TRIDB из `tests/data/real` (66 каркасов / 3 590 треугольников и 55 / 128 994): BLOB версии 5, только блоки 1–4; `mesh_stats` Э7 расходится с `Volume` файла не больше чем на 1,4e−13 (отн.), с `SurfaceArea` — на 2,9e−16; пользовательские атрибуты — только `Type = 0`, все 605 значений — пустой текст; `DatabaseInformation` и `DisplayProperties` пусты. В ezdxf 1.4.5 `odafc.convert()` не поднимает ошибку, когда конвертер не создал файл (`UnknownODAFCError(...)` без `raise`), и отдаёт конвертеру всю папку исходного файла с фильтром по имени.
- ADR 0012: на Э8 ничего не назначено. Д-22 (фильтр «земли», LAS) записан на Э7 и не сделан — в Э8 не входит (см. «Последствия»).
- Расхождение ТЗ: 7.21 — «части по 32 768»; действует ADR 0004 (64 000) — в отчёт вехи.

## Варианты

| Вопрос | Варианты | Выбор и причина |
|---|---|---|
| Состав Э8 после переноса основы в Э7 | А) форматы (чтение и запись), проверки, точный выбор, сечение, пересечения стволов, экспорт; «Исправить» и остальные операции 7.23 — Э9; Б) А + «Исправить» (перенос `repair.py`, 1 603 строки); В) только форматы | **А.** 7.23 относит «Исправить» к Э9 вместе с общими правилами операций (результат — новый объект, запись операции, «Перестроить»), которых до Э9 нет. В Э8 остаётся то, без чего не работают читатели: точная сшивка совпадающих вершин. В не закрывает 5.3 (сечение, клик) и ADR 0007 |
| Исходный порядок треугольников | А) `tri` в Z-порядке + необязательный blob `seq <u4 M` (номер треугольника в файле); Б) `tri` в порядке файла + перестановка для показа; В) порядок не хранить | **А.** Части остаются отрезками подряд идущих треугольников (ADR 0004), 4 байта на треугольник, роль `seq` уже в `BLOB_ROLES`, ключи кеша LOD не меняются. Б ломает части, В — побитный экспорт (5.4) |
| Файл с несколькими каркасами | А) каждый каркас — отдельный объект, папка дерева = имя файла, строка `import_log` на каркас (общий исходник по SHA-256); Б) родитель `objects(kind="wireframe_file")` | **А.** Без нового вида объекта, без правок архива и дерева; каркас свободно переносится в «ЦТМ» и удаляется. Б тянет зависимость «файл → ЦТМ в другом разделе» |
| Когда строить LOD и проверки | А) импорт делает каркас `ready` с площадью, объёмом и рёбрами, затем задание `wireframe.check` («Проверка и копии для показа»); Б) всё внутри импорта (как `model.dtm`) | **А.** Так написано в 7.21; бюджет импорта 60 с на 10 млн не зависит от pyfqmr и самопересечений; «Проверить» — то же задание. До его конца части строятся по первому запросу (как сейчас) |
| Плоские наклонные участки (долг Э7) | А) предпроход: свёртка рёбер у вершин с компланарным окружением к соседней исходной вершине с проверкой переворота, затем pyfqmr; Б) поворот части в её плоскость перед pyfqmr; В) кластеризация вершин по сетке | **А**, запасной — В. Новых вершин нет — отклонение от плоскости 0 (сейчас до 0,2 ячейки); граница части не трогается. Б не гарантирует результат (шум округления остаётся), В может склеить близкие листы |
| Вызов ODA File Converter | А) `ezdxf.addons.odafc.convert()` из своей временной папки, отмена — штатное завершение исполнителя после `CANCEL_GRACE_S`; Б) свой `subprocess` по командной строке конвертера; В) `odafc.readfile` (документ ezdxf целиком в памяти) | **А.** Буква ADR 0009; В нарушает потоковость 9.12. Б — запасной путь дополнением ADR 0009, если на Windows встретятся зависания |

## Решение

### 1. Состав Э8

| Входит | Не входит (этап) |
|---|---|
| Чтение: TRIDB, DXF (POLYFACE, polygon mesh, 3DFACE, MESH), OBJ, STL, Surpac DTM + STR, DWG (через ODA), Datamine `.dm` (каркасы `*tr` + `*pt`, стринги) | OMF-поверхности (Э11); блочные модели Datamine (Э17, на общем читателе таблиц из Э8); двоичные Surpac, Vulcan (после образцов) |
| Запись: TRIDB, DXF (polyface), DWG, OBJ, STL, Surpac DTM + STR; задание `export.wireframes` | Окно «Экспорт проекта» и реестр писателей (Э11, ADR 0010) — писатели Э8 имеют одну сигнатуру |
| Проверки: при загрузке — площадь, объём, замкнутость, ориентация, открытые и неманифолдные рёбра, вырожденные; задание — согласованность нормалей, самопересечения, LOD; «Проверить»; показ самопересечений красным | «Исправить», «Упростить», «Сгладить», «В один объект», «На части», булевы, обрезка, линии пересечения, изолинии, «Объём» между поверхностями, сшивка, «Перестроить» (Э9) |
| Точный выбор треугольника (`POST /pick`), линии сечения каркасов в режиме отсечения, пересечения стволов с каркасами (ADR 0007) | Серии разрезов (Э10 — на том же сечении); рудные пересечения (Э15) |
| Долги Э7: плоские участки LOD, `seq`, тяжёлая сцена `perf3d` | Д-22 (облака точек) |

### 2. Форматы (`core/bf_core/formats/`; правила 9.12; каркас файла читается по одному, состав — без удержания геометрии в памяти)

| Формат | Чтение | Запись | Основа |
|---|---|---|---|
| Micromine TRIDB | SQLite только для чтения; BLOB частями (`blobopen`); имя, цвет BGR, атрибуты (`ValueText/Integer/Real`; пустой текст — пусто), `GeometryProperties` вида «ключ–значение»; сверка N, M, охвата; атрибуты точек и треугольников — предупреждение | DDL и UTF-16LE как в образцах; BLOB версии 5 (`zeroblob` + запись частями), треугольники в порядке `seq`; `Volume`, `SurfaceArea`, охват; GUID и строки исходника — из `meta.source`. Числовые атрибуты пишутся текстом (`Type = 0`) с предупреждением, пока нет образца с другим кодом | Перенос `read_tridb*`; запись — новая |
| DXF | Сетки собираются в том же проходе, что и линии (`DxfStream`); каркас на слой; невидимые рёбра (отрицательные номера), четырёхугольник → 2 треугольника; двоичный и битый — ezdxf | Polyface, как пишет Micromine; на сущность ≤ 32 767 вершин (предел AutoCAD), больше — несколько сущностей слоя; `repr`, CRLF, ACI | `read_dxf_meshes`, `write_dxf_mesh` |
| OBJ | `v`, `f` (`v`, `v/vt`, `v/vt/vn`, `v//vn`, отрицательные); каркас на `o`/`g`; многоугольник — веером | `repr`, `o` на каркас | `read_obj`, `write_obj`; числа — `_numkernel.py` |
| STL | Двоичный (по размеру 84 + 50·n, а не по слову `solid`) и текстовый; float32 → float64 без изменения; `meta.source.precision = "float32"` и предупреждение при координатах > 1e5 | Двоичный (с тем же предупреждением) или текстовый с `repr` | `read_stl`; запись — новая |
| Surpac DTM | Пара `.dtm` + `.str`: номера точек — по порядку записей STR (`seq` читателя Э7); `OBJECT`/`TRISOLATION` → каркасы | Пара файлов | По справке Surpac; образца нет |
| DWG | `formats/dwg.py`: копия в свою временную папку под именем из ASCII → `odafc.convert` в DXF R2018 → проверка, что файл создан → читатель DXF (линии, точки, текст, каркасы). В хранилище идёт исходный DWG | Наш DXF → `odafc.convert` (версия по выбору, по умолчанию R2013) | ADR 0009 |
| Datamine `.dm` | `formats/datamine.py` — таблица (страницы 4096 / 2048, описатели, константы, A-поля; cp1251). Вид — по полям: `PID1…PID3` — треугольники, `PID, XP, YP, ZP` — точки, `PTN, PVALUE, XP, YP, ZP` — стринги, `XC, XINC` — «блочная модель — этап Э17». Пара `tr` + `pt` — по имени или из той же папки; деление на каркасы — по выбранному полю (по умолчанию нет) | — | `blockmodels-dm-fbm-dat.md`; имена полей — по справке Studio, **до образцов читатель помечен «предварительно»** |

Совпадающие вершины сшиваются **точно** (равные float64, −0.0 = 0.0): геометрия не меняется, цикл остаётся побитным; сшивка с допуском — «Исправить» (Э9). «Побитно» (5.4): координаты и порядок после цикла «импорт → экспорт → импорт» равны бит в бит, повторный экспорт равен первому; для TRIDB (контейнер SQLite) — BLOB геометрии байт в байт и равные строки таблиц, не файл целиком.

### 3. Хранение — без миграций

| Что | Где |
|---|---|
| Порядок файла | Blob `seq <u4 M` владельца `object` (роль есть); нет blob — порядок хранения. Новый код — `wireframes/source.py` (`store.py` уже 598 строк) |
| Сведения исходника | `objects.meta.source`: формат, имя в файле, слой, точность, для TRIDB — GUID, строка `GeneralInformation`, свойства, определения атрибутов |
| Атрибуты файла | `wireframes.attrs` (как у пользователя) |
| Проверки | `wireframes.stats.checks`: состояние, конфликты нормалей, число пар и треугольников самопересечений, до 200 точек, время. Список треугольников для показа — `cache\mesh\<ключ>\checks.bfa` (восстанавливается заданием) |
| Исходный файл | `import_log` на каркас, владелец `import`; папка дерева = имя файла, если каркасов больше одного |

### 4. Геометрия (`core/bf_core/geo/`, numba `cache=True`)

| Модуль | Решение |
|---|---|
| `checks.py` | Перенос: конфликты ориентации (направленные рёбра), самопересечения по сетке ячеек; добавляется список треугольников (≤ 200 тыс.). Компланарные наложения не находятся — сказано в «Свойствах» |
| `flat.py` | Предпроход плоских участков (вариант А); `viz/meshes.py::ALGO = 2` — старые кеши LOD не используются |
| `section.py` | Перенос `plane_section`: читаются только части, чьи габариты задевает плоскость; цепочки — numba |
| `pick.py` | Перенос `ray_pick`: луч float64 → габариты частей → треугольники задетых частей; ответ — вершины, площадь, угол и азимут падения. Индекс ядра — таблица частей; three-mesh-bvh в окне (ADR 0004) включается, только если замер клика на 10 млн > 50 мс |
| `intersect.py` | Перенос `MeshTarget`: ствол × треугольники, глубина до 1 мм |

### 5. API и задания (`/api/v1`; ошибки `{code, message, hint}`)

| Запрос / задание | Назначение |
|---|---|
| `import.objects` (расширение), `POST /import/objects/inspect` | Каркасы в составе: имя, треугольники, вершины, цвет, атрибуты, предупреждения; DXF и DWG дают линии и каркасы сразу; отмена не оставляет объектов; затем `wireframe.check` на файл |
| Задание `wireframe.check {wireframe_ids}` (`heavy`), `POST /wireframes/{id}/check` | LOD всех частей → нормали → самопересечения; `objects.changed` |
| `GET /viz/wireframes/{id}/checks` | BFA1 `mesh` треугольников самопересечений (для красного слоя) |
| `POST /pick {origin, direction, wireframe_ids, clip}` | Точный треугольник; `clip` — плоскости окна разреза |
| `GET /viz/wireframes/{id}/section?point&normal` | BFA1 `section`: `xyz <f8` (абсолютные), `offsets`, `closed`; ETag по геометрии и плоскости |
| `GET /viz/sets/{id}/intersections?wireframes=` | Контракт ADR 0007 |
| Задание `export.wireframes {wireframe_ids, format, options}` | tridb, dxf, dwg, obj, stl, dtm; запись во временный файл и переименование; 409 `files_exist` → своё окно; `export_log` |
| `GET/PUT /tools/oda` | Путь к конвертеру (хранит интерфейс, как число исполнителей), автопоиск `C:\Program Files\ODA\ODAFileConverter*\`, признак «найден» |

### 6. Интерфейс и команды

| Что | Решение |
|---|---|
| Мастер «Импорт файлов» | Каркасы в составе; `wireframes.upload` («Главная › Загрузка › Каркасы»), «+» у «Каркасов»; Datamine — поле деления и пометка «предварительно»; DWG без конвертера — текст ADR 0009 и кнопка «Настройка» |
| «Настройка › Внешние программы» | Путь к ODA File Converter, «Найти», «Проверить», как установить |
| «Свойства» каркаса | Площадь, объём, замкнутость, открытые и неманифолдные рёбра, вырожденные, нормали, самопересечения, «Проверить», источник («координаты float32»), треугольник по клику |
| 3D | Точный выбор после грубого; красный слой самопересечений; линии сечения каркасов при отсечении (цвет каркаса, отмена устаревших запросов); метки ◆ пересечений (слой Э6 получает данные) |
| Команды | Включаются `wireframes.upload`, `wireframe.export` (форматы tridb, dxf, dwg, obj, stl, dtm; без формата — окно), `model.self_intersections`; новая `wireframe.check` («Моделирование › Правка каркасов › Проверить») |
| Демо | 2–3 замкнутых рудных тела и открытый разлом (`demo/geo.py`) |

### 7. Зависимости

Новых пакетов нет: ezdxf 1.4.5 (`odafc`), numba, pyfqmr, sqlite3 (стандартная библиотека), three-mesh-bvh — в стеке. ODA File Converter — программа пользователя, не распространяется и не входит в lock-файлы и проверки лицензий.

## Риски

| Риск | Мера |
|---|---|
| Нет образцов Datamine (каркасы, стринги), текстового Surpac DTM, DWG с сетками | Читатели по описанию с синтетикой; Datamine — «предварительно» в мастере и CHECKLIST; готовность формата — после образцов (ADR 0009) |
| TRIDB, записанный BF2, не откроется в Micromine; коды типов атрибутов кроме 0 неизвестны | DDL и значения — как в образцах; ручная проверка владельцем (CHECKLIST); числа — текстом |
| 10 млн треугольников: LOD и самопересечения дольше ожидаемого | Отдельное задание; замер в 8.19 до интерфейса; запасной путь — кластеризация для LOD |
| Сшивка 30 млн углов (3DFACE, STL на 10 млн) не уложится в 2 ГБ | Сшивка порциями по хешу с проверкой равенства; замер памяти |
| ODA: зависание, окно, кириллица и чужие файлы в папке, тихий отказ | Своя временная папка, имя ASCII, проверка результата, прогресс «ждём конвертер», отмена через завершение исполнителя; ручная проверка на Windows |
| Отображённые в память blobs на Windows мешают удалению каркаса | Отображение на время запроса или короткий кеш со сбросом при удалении |
| Объём: 30 подшагов при 2–3 окнах ТЗ | Порядок «TRIDB → импорт → остальное»; Datamine и Surpac DTM — последними среди форматов |
