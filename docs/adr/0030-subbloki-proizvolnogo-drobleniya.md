# ADR 0030. Субблочные модели произвольного дробления и импорт неструктурированной модели (Э27, Д-45 А6)

**Статус:** предложен 2026-11-28 (architect, opus; подшаг 27.3). Решения 1–18 — в конце. Вопросы № 159–164 не блокируют работу: до ответа действует «По умолчанию».
- **Исполняет:** ТЗ 7.31 («Субблоки — как есть (центр, размер) + родительская сетка»), 8.7.2, 7.35 Д-45 (замечание заказчика А6 к выпуску 0.5.0), 8.0, 10.5.
- **Опирается на:** ADR 0017 (P = i + nx·(j + ny·k)), 0023 (meta v2, `GridV2`, `geometry`, проверки, показ, регуляризация), 0024 (оценка `sub: parent|own`), 0027 (отчёт), 0028 (граф по родителям). Их не пересматривает, кроме перечисленного ниже.
- **Заменяет явно:** ADR 0023 решение 5 («субблоки 2^L; невыровненные — отказ со строками») и строку §4 «Нельзя представить» — решениями 1, 7, 8 этого ADR; «По умолчанию» вопроса № 63 («отказ по 8.7.2») — решением 1 (ответ заказчика — замечание А6). ADR 0023 решение 6 (поворот только вокруг Z, проверка трёх центров) остаётся; меняется только допуск проверки (решение 4). В ADR 0028 находка 2 «субблоки `div` (2^L)» читается как «`div` 1…128» — граф по родителям не меняется.

## Гипотезы причины 626 791 отказа

| Гипотеза | Оценка | Как видно в диагностике | Что исправляет |
|---|---|---|---|
| (а) Дробление не 2^L: 10/5 = 2 м, 10/3 = 3,333 м, смесь 2 и 5 | **Наиболее вероятна.** Все отказы — «не по подъячейкам», ни одного «через границу» и «за сеткой»; `_div_of` вернул 128; заказчик сам пишет «произвольное дробление» | Гистограмма размеров по осям: 10; 2; 3,333…; найденные дроби 1/5, 1/3; «деление по X — 5» | Решения 1–2: `div` = НОК знаменателей ≤ 128 |
| (б) Неверное начало сетки | Сама по себе маловероятна: начало берётся по моде остатков целых 10-метровых блоков, они легли. Вариант — модель склеена из двух участков с разным началом («1;2») | Остатки нижних граней по модулю родителя: две моды со сравнимыми долями | Выбор «список блоков» или сетка вручную (решения 7–8) |
| (в) Родитель не 10 (20 × 20 × 10 без целых родителей 20) | Одна даёт «через границу родителя» — их 0; в паре с (а) (20/3 = 6,667) возможна | Кандидаты родителя k·max (k = 1…4) с долей выровненных | Решение 3: перебор кандидатов, первый со 100 % берётся сам |
| (г) Округление при записи | f8 (R) — точно; N с 2–3 знаками усиливает (а) (3,33 вместо 3,333…); f4 (F) на координатах 10⁶–10⁷ ошибается на 0,06–1 м — сломал бы и целых родителей, маловероятна | Тип и ширина столбцов X…_Z, «квант» столбца, наибольшее отклонение | Решение 4: допуск по типу столбца |
| (д) Субблоки произвольной высоты (Z по поверхности или каркасу «точно») | Возможна для части модели | По оси сотни различных размеров, дроби не находятся | Только «список блоков» (решение 8) |

## Варианты

| Вопрос | Варианты | Выбор и причина |
|---|---|---|
| Субблоки произвольного дробления | А) целое `div` 1…128 по оси (НОК дробей), формат прежний; Б) рациональная решётка внутри родителя — список разрезов по оси (как `tensors` внутри P); В) хранить у каждой строки float64 центр и размер | **А.** Формат, индексы, ключи и ядра не меняются (находки 3–5); Б меняет `geometry`, оболочку, срез, регуляризацию; В — все 58 потребителей |
| Модель, не ложащаяся ни в какую решётку | А) отказ (как 0.5.0); Б) «только выровненные» (потеря объёма); В) неструктурированная модель «список блоков» с ограниченным набором операций и регуляризацией в сетку | **В** (требование заказчика); Б — вопрос № 161 |
| Где список блоков | А) тот же `kind = "block_model"`, meta v3 `layout: "list"`, запрет в `Model.open` по умолчанию; Б) новый вид объекта `block_list` | **А.** Дерево, папка «Блочные модели», фильтры, `.bfggis`, менеджер данных, окно модели — как есть; опасные операции закрыты одним местом |
| Когда выбирать | А) автоматически переходить на список; Б) 422 с вариантами в мастере, выбор пользователя | **Б** (требование заказчика: «предложить»); автоматически — только кандидат сетки со 100 % выровненных |

## Решения

### 1. Деление родителя `div` (`schema.py`)
- `SubblockSpec.of`: любое целое 1…128 по оси (было: степень двойки). `bad_div`: «Деление на субблоки по X — 200: нужно целое от 1 до 128». Формат `cells` (`sx…wz` uint8), `KEY_SHIFT` = 21 (7 бит на ось, s ≤ 127), порядок (P, sz, sy, sx) — без изменений; meta остаётся v2.
- `SubblockSpec.levels` → `None`, если хоть одно `div` не 2^L; `public_meta.grid.levels` → `null`; UI («Свойства», окно заполнения) пишет «деление 5 × 5 × 3» без «уровней».
- Прототип и новое заполнение (8.7.3) — по-прежнему 2^L (`of_levels`). «Кодировать с дроблением» на модели с делением 3/5 делит по целым подъячейкам (w // 2; w − w // 2) — неравные половины, решётка модели сохраняется (вопрос № 163).
- 0.5.0 и раньше открывают модель с `div` не 2^L отказом 422 `subblock_div` — явным, без порчи.

### 2. Вывод решётки (`grid_infer.py` + новый `grid_lattice.py`)
- Первый проход дополнительно собирает различные нижние грани блоков по осям (округление до 1e−9 м; ≤ 1 млн значений на ось, больше — признак «нет решётки»).
- По оси: значения v = размеры ∪ остатки (низ − O) mod d. Для каждого v — наименьший знаменатель q ≤ 128, при котором |v·q/d − round(v·q/d)|·d/q ≤ tol (перебор q векторно: ≤ 128 × 8192); `div` = НОК всех q; НОК > 128 или v без q — ось «не ложится». Степень двойки получается как частный случай; прежний выбор 2^L — подмножество.
- Проверка `rows_of` (второй проход) — та же, с `div` и `tol` из решения 4.

### 3. Кандидаты родителя и начала (автоматически)
- По каждой оси независимо: родитель d ∈ {подсказка | max, 2·max, 3·max, 4·max}, начало ∈ {3 моды остатков низов целых блоков} × сдвиги j·max (j < k). Для оси берётся первый кандидат (по порядку: подсказка, max, 2·max…), при котором все блоки оси ложатся без «через границу» и «за сеткой». Не подсказанный выбор — предупреждение журнала («Размер родителя по X взят 20 м: блоки 6,667 м пересекали границу родителя 10 м»).
- Ни один кандидат не даёт 100 % по оси — 422 (решение 6) с лучшими кандидатами и их долями.

### 4. Допуск привязки
- `tol` по оси = max(1e−6 м, квант столбцов центра и размера): N с d знаками — 0,5·10^−d; F (f4) — ulp(max |v|); R, CSV — 1e−6 м. Мастер может задать `grid.tol` (м, 0 < tol ≤ ¼ подъячейки, иначе 422 `bad_param {param: "grid.tol"}`).
- Центры модели всегда вычисляются из (P, s, w); блоки, сдвинутые больше 1e−6 м, считаются: предупреждение «Центры уточнены до сетки: 412 300 блоков, наибольший сдвиг 0,0033 м»; `source.params` {tol, shifted, max_shift}. Проверка трёх центров (ADR 0023 решение 6) — с этим же `tol`.

### 5. Диагностика (`grid_diag.py`, новый)
- Считается только при отказе, по выборке ≤ 200 000 строк (равный шаг по строкам — побитно повторяемо): в мастере — по прочитанной части, в задании — из spool. Добавляет ≤ 1 с на 1 млн блоков; тело ответа ≤ 16 КБ.
- `diag`: `{rows, sample, columns: {x: "R 8", dx: "N 10.2", …}, axes: [{axis, parent, sizes [{v, n}] ≤ 12, distinct, fractions [{v, q}] ≤ 12, div | null, residues [{v, n}] ≤ 5, quantum, fit}], candidates [{size, corner, div, tol, aligned, crosses, off_grid}] ≤ 5, causes [код], text [строки по-русски]}`.
- Коды причин: `div_too_fine` (НОК > 128), `off_lattice` (размеры без дроби — гипотеза д), `two_origins` (две моды остатков ≥ 10 % каждая — гипотеза б), `rounded` (квант столбца > 1e−6 м — гипотеза г), `crosses_parent` (гипотеза в), `off_grid` (блоки за началом). `text` — готовые фразы для мастера: «По Z 412 различных высот, общего деления нет — субблоки произвольного размера».

### 7. Мастер (`ui/src/modules/blocks/import/*`)
- Шаг «Блоки» при `blocks_unaligned` показывает панель «Модель не ложится в сетку» (своё окно шага, без `window.confirm`): таблица по осям (размеры, деление, смещения, тип столбца), кандидаты с долей выровненных, три кнопки по `choices`.
- «Задать сетку вручную» — заполняет существующие поля (начало, размер, число ячеек, `div` 1…128, поворот) лучшим кандидатом, добавляет поле «Допуск, м»; повторная проверка (`inspect`) после правки. «Импортировать списком блоков» — `blocks.layout = "list"`, повторная проверка (сводка «Список блоков: N, охват …»). «Не импортировать» — снимает файл из пакета, остальные файлы идут.
- Задание с отказом: в итоге импорта — «Открыть мастер с выбором» для файла (те же `choices`).
- Опции: `options[путь].blocks.layout`: `"grid"` (по умолчанию) | `"list"`; `blocks.grid.tol`. Контракт — `docs/progress/e17-api.md` §5 (правит К3).

### 8. Неструктурированная модель «список блоков»
- **Объект:** `kind = "block_model"`, meta **v3** `{"layout": "list", grid: охватывающая сетка (corner, counts, size = родитель-кандидат или max размер, rotation из мастера, div [1, 1, 1]), rows, parents (занятых ячеек центров), sub: false, fields, checks, source, warnings}`. v1/v2 — `layout: "grid"` по умолчанию.
- **Файл `cells`:** `idx` u64 = P ячейки охватывающей сетки, где лежит центр (порядок и группы строк по слоям k — как у v2), `cx cy cz` f8 — центр в локальных осях (q), `dx dy dz` f8 — размер, затем поля. Порядок (idx, cz, cy, cx).
- **Проверки:** дубликаты — те же центр и размер (остаётся первая); перекрытия — попарно с блоками ячеек центра ± 1 (размер блока ≤ шагу охватывающей сетки), `method: "boxes"`; объём Σ Π d·FRAC.
- **`Model`:** `Model.open(..., layout=("grid",))` по умолчанию; список блоков открывают только модули, которые явно передали `"list"`; прочие → 422 `block_list_unsupported` «Операция «…» недоступна для модели-списка блоков» + подсказка «Регуляризуйте модель: Блочные модели → Регуляризация». `p()` — idx, `subs()` → `None`, `centres/local/boxes/volume` — из `cx…dz`.
- **Дерево и «Свойства»:** значок и подпись «список блоков», в «Свойствах» — «Структура: список блоков (без сетки субблоков)»; команды, требующие сетки, недоступны с подсказкой (предикат `enabled` в реестре команд модуля).

| Доступно | Недоступно (422, «регуляризуйте») |
|---|---|
| Показ: 6 граней на блок, совпадающие встречные грани скрыты, без слияния; больше лимита граней — упрощение по ячейкам центров 2^ℓ («упрощено»); выбор блока по точке | Срез плоскостью (текстура, растр, многоугольники) — вопрос № 160 |
| Фильтры и быстрый ограничитель: условия по полям — как есть; каркас и поверхность — по центру (доля 0/1, вопрос № 162) | Оценка содержаний и моделирование (ADR 0024), подсчёт ресурсов (ADR 0027), оптимизация карьера (ADR 0028), swath по субблокам |
| Калькулятор, плотность, категории (правила; без мажоритарного фильтра) | Заполнение и кодирование каркасами, сравнение моделей, мажоритарный фильтр |
| Отчёт «Содержание–тоннаж» (объём Π d·FRAC) | Экспорт OMF |
| Экспорт DAT, CSV (центр O + R·q, размер как в файле), Parquet | — |
| **Регуляризация** в регулярную модель тех же осей: точные перекрытия боксов по осям, суммы объёма, тоннажа, металла сохраняются 1e−9 — путь «оценка в сетку» | — |

### 9. Что не меняется
P, порядок строк, файлы полей `fld:`, BFA1, LOD по родителям, регуляризация моделей с сеткой, повороты (только Z), миграции БД, зависимости, lock-файлы.

## Последствия
- Модели Micromine и Datamine с целым дроблением родителя (2, 3, 5, их произведения ≤ 128) импортируются как обычные субблочные; все операции Э17–Э21 работают без изменений ядер.
- Модель, не ложащаяся ни в какую решётку, импортируется по выбору пользователя списком блоков; в сетку — регуляризацией.
- 422 `blocks_unaligned` называет причину (размеры, деления, смещения, тип столбцов, кандидаты) — заказчик видит её без файла у разработчика.
- Схема БД, зависимости, lock-файлы не меняются; meta v3 — только у списка блоков.
