# ADR 0017. OMF v1, экспорт объектов проекта по типам, менеджер данных (Э11)

**Статус:** Предложен 2026-11-19 (architect, opus / xhigh: лимит Fable до 2026-11-24). Исполняет ADR 0010 (принят, не пересматривается), ТЗ 7.24, 9.8, Д-17, Д-20, Д-21 (ADR 0012). Решения 1–15 — в конце.

## Контекст

- ТЗ 7.24 (импорт мастером; каждый объём — блочная модель; ≈ 100 байт на блок, 20 млн ячеек — пик ≈ 2 ГБ; нехватка памяти — понятная ошибка, 2 попытки; экспорт каркасов, линий, регулярных моделей заданием `export.omf`; `omf.export {dataset_ids, filename}`), 9.8 (устройство v1, соответствие элементов, своя реализация), 5.3 (импорт блочной модели 20 млн × 20 атрибутов ≤ 8 мин, ≤ 4 ГБ), 5.x S4 (OMF — потоково с пределом памяти, «бомбы» отклоняются), 7.4 (`.bfggis` — без изменений), Д-17 / Д-20 (ADR 0010), Д-21 (образцы `tests/data/ext/omf`, счётчики `expected/test_file.v1.json`), 10.5, 17.2–17.3.
- Находки при проектировании:

| № | Находка | Следствие |
|---|---|---|

## Варианты

| Вопрос | Варианты | Выбор и причина |
|---|---|---|
| Чтение и запись OMF v1 | А) библиотека `omf` 1.x; Б) форк omf-python 2.0.0a0; В) своя реализация — перенос BF | **В.** А не ставится на Python 3.12 / numpy 2; Б пишет не v1; В — готовый код с тестами, только numpy + zlib |
| Где регулярная модель Э11 | А) `objects(kind="block_model")`, сетка в `meta`, ячейки — Parquet в blob `cells`, без миграции; Б) миграция 0007 и таблица `block_models` сейчас; В) хранить только исходный OMF | **А.** ТЗ 7.24 требует модель на объём и цикл «экспорт → импорт»; Б решает за Э17 (субблоки, проверки 7.31); В — не модель (нет полей, свойств, выбора при экспорте) |
| Объём 20 млн ячеек | А) как BF — плотные массивы в памяти (≈ 100 Б/блок, пик ≈ 2 ГБ); Б) поток: поле распаковывается один раз во временный memmap, маска занятости, номера занятых ячеек, Parquet группами по 10⁶ строк | **Б.** Пик ≈ 0,5 ГБ; отмена между порциями 16 МиБ; цена — временный диск n × 8 Б × полей (20 млн × 20 = 3,2 ГБ, проверяется заранее) |
| Атомарность экспорта по типам | А) временная папка → перенос файлов по одному в выбранную; Б) временная папка → **одно** переименование в новую «‹Проект› — экспорт ГГГГ-ММ-ДД»; В) `.part` у каждого файла | **Б.** Нет «половины набора» после сбоя и вопросов о перезаписи; А и В оставляют часть файлов |
| Строки менеджера данных | А) списки модулей в окне; Б) один каталог ядра (ADR 0010) | **Б**; размер — по `blob_owners` |

## Решение

### 1. Файл OMF v1 (`formats/omf_file.py`)

| Часть | Решение |
|---|---|
| Заголовок | Сигнатура, версия `OMF-v0.9.0` (иная — `omf_version`), UUID, смещение JSON (uint64 LE) |
| Пределы (S4) | Смещение JSON ∈ [60; размер); JSON ≤ 256 МиБ, объектов ≤ 10⁶; блок `{start, length, dtype}` — внутри [60; JSON), dtype из списка BF; распаковка `zlib.decompressobj` порциями ≤ 16 МиБ (`max_length`): известный размер (данные объёма — n × размер элемента) должен совпасть, иначе ≤ 1 032 × сжатого (предел deflate) и ≤ 2³¹ элементов; PNG текстур не распаковываются |
| Ошибки `{code, message, hint}` | `omf_damaged` («Файл повреждён»), `omf2_not_supported` («OMF 2 (ZIP) не поддерживается» — «Сохраните в OMF 1: в Leapfrog — OMF 0.9»), `omf_version`, `omf_too_large`, `out_of_memory`, `disk_full` |
| Состав для мастера | Только по JSON, без блоков: элементы, типы, размеры, данные, что не загрузится и почему |

### 2. Импорт (`formats/omf_read.py`, `formats/omf_volume.py`; задание `import.objects`, формат `omf`)

| OMF v1 | BF2 | Не переносится (журнал задания и `meta.warnings`) |
|---|---|---|
| `SurfaceElement` (треугольники; грид — 2 треуг. на ячейку, `origin + u·axis_u + v·axis_v + offset_w·(axis_u × axis_v)`) | Каркас; все поверхности файла — в папке дерева по имени файла (как TRIDB, ADR 0013) | Данные на вершинах и гранях, текстуры |
| `LineSetElement` | Один файл линий, слой на элемент; смежные сегменты склеиваются, возврат в первую вершину — замкнута (хранится с повтором, 17.3.12) | Данные на вершинах; данные сегментов, постоянные вдоль линии, — атрибуты линии |
| `VolumeElement` | Блочная модель (п. 3); оси — перестановка и знаки X, Y, Z (допуск 1e−9), иначе «модель повёрнута» — не загружается | Данные на узлах, повёрнутые модели |
| `ScalarData`; `MappedData` (первая легенда), `StringData`, `DateTimeData` | Число; категория (коды int32, подписи) | Цвета легенды |
| `PointSetElement`, `ImageTexture` | — (решение 3) | Целиком |
| `origin` проекта и элемента; `color` | Прибавляются во float64; `#rrggbb` | — |
| Описание проекта «Система координат: …», элемента «BedrockForge: ЦТМ» (пишет BF2) | СК объектов; признак ЦТМ (решение 8); иначе — без СК, запись в журнале | — |

- Порядок ячеек и узлов — Фортран (u быстрее всех); тест 2 × 3 × 4 и переставленных осей переносится из BF.
- Объём: поля по одному — распаковка порциями → временный memmap `cache/import/<задание>/` → маска «есть значение» (`isfinite`, код ≥ 0); без полей — все ячейки (предупреждение). Номер ячейки BF2 `idx = i + nx·(j + ny·k)` по +X, +Y, +Z; при перестановке или минусе осей — пересчёт и сортировка. Parquet группами по 10⁶ строк (`idx` + поля), статистика полей. memmap закрываются явно до удаления (17.2.6). Память ≈ n Б (маска) + 16 Б × занятых (номера, перестановка) + порция; диск — n × 8 Б × полей (проверка → `disk_full`). Предел — 200 млн ячеек.
- `MemoryError` → `out_of_memory` («Не хватило памяти на модель N ячеек» — «Закройте другие программы или разделите модель»); у импорта 2 попытки (`jobs/registry.py`). Отмена или сбой — ничего (`building` под id задания); исходный файл — один blob у всех созданных объектов (как 8.15).

### 3. Регулярная блочная модель Э11 (`blocks/`)

| Что | Решение |
|---|---|
| Объект | `objects(kind="block_model")`: имя, папка, `extent`, `crs` |
| `meta` (`v: 1`) | `grid {corner [x, y, z] f64, counts [nx, ny, nz], size [dx, dy, dz]` или `tensors {x, y, z}` (переменный шаг OMF), `order: "F"}`, `cells` (занятых), `fields [{name, kind: number / category, unit, labels?, stats}]`, `source {format, file, element}`, `warnings` |
| Файлы | Blob `cells` (новая роль `BLOB_ROLES`): Parquet zstd, группы по 10⁶ строк, `idx uint64` по возрастанию + поля (f64; категории — int32, −1 — пусто) |
| API | `GET /blocks`, `GET /blocks/{id}` (сетка, поля, статистика); переименование, папка, удаление — общие (`object.*`, каталог); событие `objects.changed {kind: "block_model"}` |
| Окно | Раздел «Блочные модели»: строка, меню «Свойства», «Экспорт OMF…», «Переименовать», «Удалить»; «Свойства» — сетка, ячейки, поля с единицами и статистикой, источник; «Показать в 3D» недоступна: «Показ блочных моделей — этап Э17» (решение 2) |
| `.bfggis` | Общий механизм объектов и blobs; тест цикла (10.5 п. 5) |
| Э17 | Добавляет субблоки, таблицу `block_models` (миграция заполняет её из `meta.grid`), показ, DAT/CSV, проверки 7.31; хранение регулярных ячеек не переписывает |

Схема БД не меняется.

### 4. Экспорт OMF (задание `export.omf`; `formats/omf_write.py`, `exporting/omf_job.py`)

| Что | Решение |
|---|---|
| Выбор | Каркасы и ЦТМ, файлы линий, регулярные модели; > 100 млн ячеек — недоступны с причиной; слои точек не пишутся (предупреждение); субблочных в Э11 нет |
| Каркас | `SurfaceElement`: вершины `<f8` без смещения (`origin` = 0 — координаты побитно), треугольники `<i8`, цвет; ЦТМ — «BedrockForge: ЦТМ» в описании |
| Линии | `LineSetElement` на слой: замкнутая — сегмент к первой вершине; атрибуты линии — на сегментах (`ScalarData`; текст — `MappedData` с легендой); линии с вершинами без Z не пишутся (предупреждение; пропуск не становится 0, 17.3.2) |
| Модель | `VolumeElement`: `origin` = угол, оси +X, +Y, +Z, тензоры; поля плотно порциями 4·10⁶ ячеек по отсортированному `idx` (пусто — NaN, у категорий −1); единица — «Единицы: g/t» в описании |
| Проект | Имя проекта, `units: "m"`, описание «Система координат: ‹имя› (EPSG:…)» |
| Файл | `‹имя›.omf.part` → `os.replace`; отмена — нет файла; файл есть — 409 `files_exist` (своё окно «Заменить?»); `export_log` |
| API | `GET /omf/exportable` (объекты, доступность, причина), `POST /omf/export {wireframe_ids, line_file_ids, block_model_ids, path, overwrite?}` → задание (`heavy`, оценка памяти) |
| Окно | «Экспорт OMF» (перенос `OmfExportDialog`): три списка с галочками, «Сохранить как…», ход, «Показать в папке»; «Экспорт OMF…» в меню дерева каркасов, линий, моделей |
| Ассистент | `omf.export {dataset_ids, filename}`: с `dataset_ids` — confirm и сразу задание в `Документы\BedrockForge\Экспорт\‹filename›.omf` (решение 9), без — окно |
| Сверка | Leapfrog в CI нет: разовая `omf.load` + `validate()` omf-python 1.0.1 во временном Python 3.11 (вне `core/uv.lock`, как GeostatsPy в Д-21) — в отчёт; Leapfrog 2026.1 — ручная проверка (CHECKLIST) |

### 6. Менеджер данных (Д-20; исполнение ADR 0010 §2)

Кеш numba привязан к процессору (`magic_tuple`: имя и признаки CPU) — заполнять с `NUMBA_CPU_NAME=generic` и при сборке, и в программе (ядра медленнее на 0–30 % без AVX2); +4–8 мин каждой сборки Windows (228 ядер `cache=True`), +10–30 МБ установщика, 1–2 подшага; прогрев в исполнителях (10.11) уже прячет большую часть | Решение 12 |
