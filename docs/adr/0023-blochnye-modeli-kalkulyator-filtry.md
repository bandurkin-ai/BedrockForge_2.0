**Статус:** предложен 2026-11-24 (architect, opus); решения 1–24 — в конце. Вопросы № 62–71 не блокируют работу: до ответа действует «По умолчанию».
Исполняет ТЗ 7.31, 8.7 (Т8.7-1…10; CHECKLIST 21, 31, 301–310, 335), 7.35 Д-02 и Д-13 (блоки DM/FBM), 8.0, 5.3, 6.8, 10.5.

## Варианты

| Вопрос | Варианты | Выбор и причина |
|---|---|---|
| Описание модели | А) `objects.meta` v2 без миграции; Б) таблица `block_models` и миграция 0008 (план ADR 0003) | **А.** SQL-запросов по сетке нет; `meta` лежит в project.sqlite (8.7.2 «в SQLite»); Б — миграция, PostgreSQL и архивы без новой функции |
| Порядок строк | А) P по возрастанию, затем (sz, sy, sx); Б) Мортон родителя; В) Мортон в файле и отсортированная копия в кеше | **А.** Принято ADR 0017; на нём стоят Э11 и Э13. Все операции Э17 — полный проход по колонкам в памяти (20 млн × 4 поля ≈ 0,7 ГБ). Группы строк по P — это слои k, отбор по Z сохраняется |
| Файлы полей | А) один файл, переписывается каждым расчётом; Б) файл на поле или группу полей одного расчёта; `cells` — геометрия и поля импорта | **Б** (8.7.2); поля импорта пишутся с геометрией одним проходом, как в Э11 |
| Субблоки | А) 2^L (8.7.2); Б) любой делитель ≤ 128 | **А.** Хранятся делители d = 2^L, поэтому Б потом не меняет формат (№ 63) |
| Калькулятор | А) расширить `ast`-движок Э4; Б) свой рекурсивный спуск → дерево → numexpr или numpy | **Б** (8.7.4; Т8.7-6 требует синтаксическую ошибку без выполнения и позицию) |
| Оболочка | А) перенос BF по блокам; Б) по граням с правилами BF, слияние в прямоугольники, LOD | **Б** (Т8.7-9, лимит граней 6.8) |
| Отрисовка | А) треугольники; Б) экземпляры прямоугольников + легенда в 1D-текстуре | **Б.** 24 байта на грань; смена палитры не пересылает геометрию (6.8) |
| Выбор блока | А) three-mesh-bvh по 10 млн треугольников; Б) индекс плоскостей граней в воркере + блок по точке в ядре (float64) | **Б.** Синхронный `pick`; после слияния грань покрывает много блоков, блок находит ядро |
| Срез | А) многоугольники; Б) текстура значений (регулярная модель) или растр подъячеек ≤ 4096² | **Б** для показа (8.7.6); многоугольники — ядро и API для печати Э22 |
| Фильтр Д-02 | А) `objects(kind="filter")`; Б) JSON в настройках проекта | **А.** Дерево, `.bfggis`, `object_refs`, «Где используется» работают как есть |
| Где считается | А) дольше 1 с — задание, показ — синхронно в слоте HEAVY с отменой обогнанных; Б) всё заданиями | **А** (8.0.2; цели показа ≤ 3 с / ≤ 1 с / ≤ 100 мс) |
| Потоки | А) `prange`; Б) полосы столбцов или строк, потоки над ядрами `nogil` (ADR 0014) | **Б.** Результат побитно одинаков при 1, 2, 4, 8 потоках |

### 2. Схема данных

```
objects(kind="block_model").meta  v2  (v1 читается как v2: rotation 0, div [1,1,1], все поля в "cells")
grid   corner [x,y,z] f64 = O (угол модели, минимум локальных координат, в осях проекта); counts [nx,ny,nz], nx·ny·nz ≤ 2·10⁹;
       size [dx,dy,dz] | tensors {x,y,z} (переменный шаг OMF: показ, фильтр, отчёт, экспорт; субблоки, заполнение,
       регуляризация → 422 variable_grid); rotation φ° ∈ (−180; 180]; div [2^Lx, 2^Ly, 2^Lz], L ≤ 7; order "F"
rows   строк файла (родители + субблоки); parents — занятых родителей; sub — есть ли субблоки
fields [{name, kind: number|category, dtype: f8|f4|i4|i2|i1|cat, unit, description, role: grade|density|frac|code|class|null,
         labels?, stats, file: "cells"|"fld:<key8>", source {op: import|calc|fill|code|density|classify|regularize|estimate,
         params, inputs [sha256], algo, versions, at}}]
checks {at, duplicates, overlaps {n, method: exact|volume}, empty [], constant [], volume, examples ≤ 20}
groups [{rows, k0, k1}]  — группы строк по 2²⁰ (охват по k); min/max полей — статистика Parquet
source, warnings, inputs {wireframes|model: [{id, sha}]}, algo        (у fill/code/regularize; «устарел» = inputs ≠ текущим)
```

| Файл | Содержимое |
|---|---|
| blob `cells` | Parquet zstd, группы по 2²⁰ строк: `idx u64` (P), при `sub` ещё `sx sy sz wx wy wz u8` (смещение и размер в подъячейках), затем поля импорта |
| blob `fld:<key>` | Parquet в том же порядке строк: одно поле или группа одного расчёта; неизменяем; замена поля = новый файл, прежний уходит при сборке мусора |
| Порядок, пропуски | Строки по (P, sz, sy, sx) строго по возрастанию. Пусто: f8/f4 — NaN; целые и `cat` — null Parquet (int16 + словарь ≤ 32 767 подписей); `cat` v1 (int32, −1) читается |
| Объём строки | Π(w_a·d_a / div_a) · FRAC, если у модели есть поле с `role: frac`; родитель без субблоков — `s = 0`, `w = div` |
| `cache\blocks\<sha>\` | `.npy` (memmap), доли каркасов для ограничителей, оболочки; производные — удаляются без потерь |

### 3. Геометрия и поворот (`geometry.py`)

| Что | Решение |
|---|---|
| Формула | p = O + R_z(φ)·q (8.7.2 дословно); q центра субблока = ((i + (sx + wx/2)/div_x)·dx, …); sin и cos углов, кратных 90°, — точные (`sin_cos_deg`). Поворот вокруг X/Y → 422 «поворот вокруг X/Y в v1 не поддерживается» |
| Соглашения | Datamine: XMORIG/YMORIG/ZMORIG, NX/NY/NZ, XINC… — константы файла; IJK из файла не берётся, пересчитывается (ADR 0009); поворот ANGLE1 + ROTAXIS1 = 3 (по справке Studio, «предварительно»); центры — в осях проекта или модели, выбирает мастер. Micromine: O, φ и размер родителя — из мастера, из строки сетки CSV или выводятся (min(центр) − размер/2, шаг по уникальным центрам, начало кратно размеру) |
| Проверка соглашения | Центры трёх строк (первая, средняя, последняя) совпадают с вычисленными ≤ 1e−6 м, иначе 422 `rotation_mismatch {rows, dist}` с подсказкой |
| Допуск | Т8.7-4: 1e−9 м |

### 4. Импорт (7.31, Д-13; задание внутри `import.objects`)

| Что | Решение |
|---|---|
| Форматы | Micromine DAT (типы C, N, R; cp1251 и BOCU-1; заголовок 4096 или 8192 байта), CSV Micromine (3 строки: имена, типы, сетка `x0, dx, …, CENTRE\|CORNER`), обычный CSV, OMF v1 (регулярные, поворот Z), Datamine `.dm`/`.fbm` |
| Распознавание | DAT — по подписи и полям центра и размера (иначе это таблица скважин), CSV — по заголовку, DM — `DmHeader.kind == block_model`; роли — `blocks_roles` (имена BF, правка в мастере) |
| Поток | Порции → ключ (P, s) → временные memmap полей в `cache\import\<job>\` → argsort ключей → `CellsWriter` группами 2²⁰ строк. Память ≈ 16 Б × строк + порция; диск проверяется заранее (`disk_full`) |
| Пусто | Коды пустого настраиваются в мастере (по умолчанию для DAT и DM −99 предлагается, если встречается); пусто — NaN или null, никогда не 0 |
| Нельзя представить | Блок за началом сетки, субблок через границу родителя, субблок не по подъячейкам 2^L → отказ задания: 422 `blocks_unaligned {count, rows ≤ 20}` (8.7.2) |
| Хранимые находки | Дубликаты (остаётся первая строка, число — в находках), перекрытия (строки остаются), пустые и постоянные поля, объём → `meta.checks` |

### 5. Проверки (7.31; `checks.py`)

Все проверки — порциями.
- Перекрытия считаются точно на сетке наименьшего блока, когда в родителе ≤ 6·10⁷ подъячеек (как BF), иначе — по сумме объёмов в родительской ячейке (`method: volume`).
- Т8.7-5: сумма объёмов субблоков родителя ≤ его объёма (1e−12 отн.), субблоки не перекрываются.
- «Проверить» (`blocks.check`) пересчитывает `meta.checks`.

### 6. Прототип, заполнение и кодирование каркасами (8.7.3; `prototype.py`, `fill/*`)

| Что | Решение |
|---|---|
| Прототип | Охват выбранных объектов (`objects.extent`) + отступ; начало кратно размеру блока; φ, L по осям. Результат — модель с 0 строк, флажок «Все родители заняты» (№ 66). В окне: nx·ny·nz, объём на диске, рамка с сеткой в 3D |
| Шаги 1–6 | Дословно 8.7.3. Каркасы проходят `check_stats` и переводятся в локальные оси (−O, R_z(−φ)). Граничные родители — тест параллелепипед–треугольник по разделяющим осям с индексом по ячейкам XY. Остальные — по чётности пересечений вертикального луча через центр столбца, лучи смещены на (√2·1e−6, √3·1e−6)·размер подъячейки. Граничные делятся по уровням по осям, где уровень не исчерпан; подъячейка относится к телу по центру; FRAC — доля m³ центров подсетки; потомки с одним кодом и FRAC ∈ {0; 1} сливаются в родителя рекурсивно |
| Несколько каркасов | Точка принадлежит телу с наибольшим приоритетом. CODE (категория по именам тел) и FRAC — доля точек в теле этого кода. Режимы: «внутри», «снаружи» (код «вне»), «оба» |
| Потоки, память | Полосы столбцов XY, накопители у полосы; побитно при 1, 2, 4, 8 потоках; ≤ 3 ГБ (списки пересечений только у столбцов, которые задевает тело) |
| Результат | Заполнение создаёт новую модель (`source.op: fill`, `inputs` — sha каркасов). «Кодировать каркасами»: «по центру» — новые поля той же модели; «с дроблением» — новая модель «‹имя› (кодирование)», поля родителя наследуются потомками. «Устарел» → «Перестроить» (задание) |

### 7. Калькулятор (8.7.4; `calc/*`, `calc_job.py`)

| Что | Решение |
|---|---|
| Грамматика | Дословно 8.7.4. Поле — имя или `[имя с пробелами]`; строки — в одинарных кавычках; ≤ 4000 символов; глубина ≤ 64. Ошибка: 422 `expr_syntax {pos, message}` по-русски. `__import__('os')` — синтаксическая ошибка, без выполнения |
| Пропуски | Арифметика с NaN → NaN; сравнение с NaN → ложь; логика двузначная (НЕ от ложного — истина, поэтому обратный фильтр = дополнение, как в приёмке 7.31); IF: если в операндах условия есть NaN, результат NaN (отметка NaN тянется по поддереву условия) |
| Категории | Сравнение с текстом — по подписи; с числом — по числовому значению подписи; `IN ('A', 'B')` |
| Вычисление | Дерево → строка numexpr (если все узлы поддержаны) или numpy, порциями по 2²⁰ строк; результат numexpr равен numpy побитно |
| Выход | Тип f8 (по умолчанию), f4, i4/i2/i1 (NaN → null), `cat` (из строковых IF). Вне ограничителя — «оставить» или NaN. Существующее поле — замена с подтверждением (№ 69). `source` = выражение + sha входных файлов → «устарел» |

### 8. Ограничители и библиотека фильтров (8.7.5, Д-02; `restrict.py`, `filters/*`)

```
objects(kind="filter").meta v1: {v, rules: Node, text (каноническая запись), fields [имена], note}
Node = {op: and|or|not, items: [Node]} | {expr: "<8.7.4>"} | {cond: {field, op: = <> > >= < <= empty notempty in, value|values}}
     | {wireframe: {id, side: inside|outside, by: frac|centre, m: 4}} | {surface: {id, side: above|below, by: centre|frac}}
object_refs(src=filter, dst=wireframe, role="filter_src");  потребители → object_refs(src=…, dst=filter, role="filter")
```

| Что | Решение |
|---|---|
| Доля f ∈ [0; 1] | `expr`, `cond` — 0 или 1. Каркас «по доле» — ядра 8.7.3, кеш по (sha строк, sha каркаса, m); «по центру» — чётность. Поверхность: z поверхности в центре блока в плане (`dz_kernels`), доля ниже = clip((z_пов − z_низ)/dz; 0; 1), выше = 1 − доля; нет поверхности — 0 и предупреждение. И — произведение, ИЛИ — максимум, НЕ — 1 − f, «обратный» — 1 − f |
| Применение | Показ, экспорт, калькулятор, swath: блок проходит при f > 0. Отчёт: вес f (№ 65) |
| Ошибки | Модели не хватает поля → 422 `filter_field_missing {field, model}` с подсказкой. Удаление используемого фильтра → 422 `filter_in_use {usage}`: `object_refs` + сохранённые виды (`block_styles`). PUT без `expected_version` или с чужой → 409 |
| «Проверить на модели» | `{passed, total, weight}` |
| `.bfggis` | `filters/remap.py` перенумеровывает id каркасов в `rules`; каркаса нет в архиве → лист недоступен с причиной |

### 9. Плотность, категории, регуляризация (8.7.5)

| Функция | Решение |
|---|---|
| Плотность | Постоянная, поле, таблица «домен → плотность», формула (`calc`). Нет значения → значение домена по умолчанию и DENS_SRC = 1 (i1). Выход — поле `role: density` |
| Категории | Правила по порядку, первое выполненное задаёт CLASS (`cat`); каркас категории переопределяет правило. Мажоритарный фильтр 3×3×3 по родителям, n итераций (по умолчанию 0), побитно. Блок без оценки (поле оценки — параметр) категории не получает. Схемы JORC и ГКЗ (A, B, C1, C2) — справочник проекта в `settings` (№ 68) |
| Регуляризация | Новая регулярная модель в тех же осях: начало кратно новому шагу, φ прежний. Перекрытия — точные (произведение перекрытий по осям). Содержания — по объёму или по тоннажу; категории — мода по объёму и поля долей `P_<КОД>`; FRAC — доля покрытого объёма. Объём, тоннаж и металл сохраняются (суммы Нёймайера в полосе, попарно между полосами). Т8.7-7: 1e−9 |

### 10. Отчёт «Содержание–тоннаж» (7.31; перенос BF `report.py`)

- Тоннаж = объём × FRAC × f × плотность (поле или константа); содержания взвешены по тоннажу блоков, где они есть; `missing_tonnes` — в ответе.
- Металл: г/т и ppm → тыс. унц (31,1034768 г), % → т, ppb → г/1000. Борт — «≥» (как BF).
- По умолчанию плотность — меняющееся поле `SG`; постоянное `DENSITY` = 2,6 пропускается. Содержания по умолчанию — поля `*_CUT`.
- Отбор по категориям и фильтру, группы по полю, кривая содержание–тоннаж, CSV. Борт 0 даёт полный тоннаж.

### 11. Показ (8.7.6, 6.8)

| Что | Решение |
|---|---|
| Оболочка (ядро) | Грань видна, если сосед за ней не «полный и прошедший». Сосед за границей родителя — родитель, целиком занятый прошедшими блоками (правило BF); грань внутри родителя скрыта, если родитель полный и прошедший; иначе грань показывается (лишнее рисуется, видимое не теряется). Занятость: битовая карта при nx·ny·nz ≤ 5·10⁸, иначе поиск по P |
| Класс грани | Шкала — 256 корзин [от; до] (лог. — по выбору); градации — номер класса; категории — код; пусто — 0xFFFF. Копланарные соседние грани одного класса сливаются в прямоугольники: сортировка (ось, сторона, плоскость, класс, v, u), прогоны по u, затем по v. Т8.7-9 |
| LOD | Граней больше лимита (5·10⁶, настройка 0,5–10·10⁶) → родители 2×2×2, 4×4×4…: среднее по объёму, для категорий — мода; в ответе `simplified` и пометка «упрощено» |
| BFA1 `blocks` | Заголовок {origin (целый центр модели, локальные оси), rotation, faces, simplified, classes, bins}; массивы: `c f4×3` (центр грани от origin), `h f4×2`, `a u1` (ось·2 + сторона), `k u2` (класс). Цвет — по 1D-текстуре легенды; смена цветов не пересылает геометрию, смена поля, границ шкалы или классов — новый запрос |
| Отрисовка | Экземпляры прямоугольников; рёбра — в фрагментном шейдере (цвет, толщина px); непрозрачность; матрица модели = O + R_z(φ); float32 от целого начала (`viz/origin.ts`) |
| Выбор | Воркер строит индекс граней по плоскостям (ось → отсортированные плоскости → корзины 2D); синхронный `pick` даёт точку и нормаль; `POST /viz/blocks/{id}/at` (float64, шаг −ε·нормаль внутрь) → строка, P, субблок, центр, размер, поля |
| Срез | Регулярная модель — текстура значений f32 на плоскости (пиксель — проекция ячейки, NaN — прозрачно) + палитра; с субблоками — растр на сетке подъячеек ≤ 4096². «Срез на разрезе»: при отсечении разреза — подложка под скважины. Многоугольники сечения — ядро и `POST /blocks/{id}/slice/polygons` (печать Э22) |
| Настройки | Окно «Блочная модель · ‹модель›»: быстрый ограничитель («поле — оператор — значение», И/Или, обратный), список фильтров библиотеки, раскраска (шкала, градации на гистограмме, категории с цветами и флажками, «Взять раскраску», «Сохранить…» в `styles`), «Оболочка / Все блоки», срез, рёбра, непрозрачность. Применяется сразу; хранится в виде проекта `block_styles[<id>]` |

### 12. Экспорт (8.7.7)

- Отбор по фильтру и полям; задание `blocks.export`. Файл есть → 409 `files_exist`, путь в папке проекта → 422 `bad_path` (как Э16).
