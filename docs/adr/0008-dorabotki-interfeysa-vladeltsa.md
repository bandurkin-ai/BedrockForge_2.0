# ADR 0008. Доработки интерфейса владельца продукта и подэтап Э6.1

**Статус:** Принято, 2026-11-17 (ответы владельца на вопросы ТЗ 7.35.6: № 5–8, 12; см. «Ответы владельца»).

## Ответы владельца (2026-11-17)

| № | Ответ | Что учтено в ADR |
|---|---|---|
| 5 | «пока просто Bandurkin Mikhail» | «О производителе»: производитель «Bandurkin Mikhail», без контактов и ссылок; 17.4.1 не меняется |
| 6 | «Да» — везде | «Аудит и статистика»: раздел дерева, узел набора, вкладка нижней панели, группа ленты; id `audit` прежний |
| 7 | «только кнопки на панели» | Переменные `--tool-*` — только для кнопок и значков; поля и подписи прежние |
| 8 | «во всех плоскостях» | Короб swath: азимут, наклон, поворот (ручки и числа); расчёт в системе короба |
| 12 | «как хочешь» | Решение исполнителя: вариант Б — Э6.1 первым этапом В3, после приёмки В2 |

## Контекст

- Владелец продукта прислал доработки к выпуску 0.2.0 (ТЗ 7.35, Д-01…Д-20). Часть из них меняет принятый текст ТЗ (7.0.3, 7.0.4, 7.0.14, 7.1, 7.20, 7.30, 17.4.3) и ADR 0007 §2 — по правилу 17.1.4 такие изменения оформляются ADR, а не правкой spec.
- Сейчас: лента — `ui/src/shell/ribbonConfig.ts` (на «Главной» группы «Вид» и «Разрез» повторяют вкладку «Вид»; «Вписать» есть только на «Главной»); палитра `Ctrl+K` ищет только по кнопкам ленты (`paletteSearch.ts`); дерево — `DataTree.tsx` (щелчок по заголовку раздела сворачивает его), `SetsTree.tsx`, `DisplaysTree.tsx`; разделы — `workspace.ts` (`TREE_SECTIONS`, `normalizeOrder` дописывает новые разделы в конец); вкладка `ribbonTab` проверяется выражением `^[a-z]{1,16}$`; «Задания» — `modules/jobs`, в ядре нет удаления заданий (`jobs/router.py`); заголовок — `Header.tsx`; панель 3D — `modules/scene/Toolbar.tsx` (кнопки 28×26 px); ключ вида `hidden` — не больше 2000 ключей (ADR 0007 §2).

## Решение

### 1. Изменения принятого текста

| ТЗ / ADR | Было | Становится | Д |
|---|---|---|---|
| 7.0.3 «Нижняя панель», 7.30 «Интерфейс», 7.0.12 | Вкладка «Swath plot», 3D на виду | Плавающее немодальное окно «Swath plot · \<название\>»; вкладки нет; короб в 3D вращается ручками во всех плоскостях (азимут, наклон, поворот) | Д-01 |
| 7.0.3 «Лента», 8.0.3 | «Главная», «Вид», «Моделирование», «Анализ», «Claude» + вкладки раздела 8 | + «Настройки проекта» (id `projsettings`) перед «Claude» | Д-02, Д-10, Д-15, Д-20 |
| 7.0.3 «Заголовок» | Проект, поиск, тема, Claude | + значок «О производителе» справа от темы | Д-12 |
| 7.0.4 «Главная / Вид», «Главная / Разрез»; 7.0.14 «все кнопки 7.0.4» | Есть | Удалены; «Вписать» `F` — в «Вид › Поворот вида»; клавиши прежние. 7.0.14 проверяет состав 7.0.4 с поправками этого ADR | Д-05, Д-08 |
| 7.0.4 «Моделирование / Поверхности» | «ЦМР» (`model.dtm`) | «Построить ЦТМ»; «ЦМР» и «ЦМП» в интерфейсе не употребляются | Д-07 |
| 7.1 «Функции», 17.4.3 | Шестерёнка — настройки показа в строке | У строк ЦТМ шестерёнки нет (щелчок по строке и меню «Настройки ЦТМ…» — 7.20); у остальных — как было | Д-07 |

| 7.1 «Разделы сворачиваются» | Способ не задан (сейчас — щелчок по заголовку) | Только стрелкой; щелчок по имени — выбор (уточнение, не конфликт) | Д-03 |
| 7.0.10, ADR 0007 §2 | Камера в проекте не хранится; `hidden` ≤ 2000 ключей | Сохранённые виды — объекты `view`; новый ключ `hide_all` | Д-04, Д-09 |
| 11.1 | После В2 — Э7 | В3 начинается подэтапом Э6.1 | — |

### 2. Технические решения

| Тема | Решение |
|---|---|
| Строка дерева | Один компонент `TreeRow` (`shell/TreeRow.tsx`): стрелка — единственный элемент с `aria-expanded`; имя — `onClick` выбор, `onDoubleClick` действие по умолчанию; клавиатура WAI-ARIA tree — в чистом `shell/tree.ts`. Используют `DataTree`, `SetsTree`, `DisplaysTree`, позже менеджер данных |
| Порядок разделов | `normalizeOrder`: раздел `views`, которого нет в сохранённом порядке, вставляется **первым**, остальные новые — в конец |
| «Очистить окно» | Ключ вида `hide_all` = `{on, shown: [ключи ≤ 2000]}`. `scene.clear` → `hide_all {on: true, shown: []}` и `hidden: []`, отображения `visible = false`, выбор снят. Пока `on`, галочка добавляет или убирает ключ в `shown`; новый объект после импорта попадает в `shown` (17.4.7). Нормализация — в ядре (`viewstate/keys.py`) и в интерфейсе; старый проект без ключа — `on: false` |
| Сохранённые виды | `objects(kind="view", meta = {v: 1, camera {position, target, up: float64[3], zoom, ortho, fov}, keys {scene, section, hidden, hide_all, displays, swaths}})`, без новой таблицы (ADR 0003 §3: «objects + meta»), `meta` ≤ 512 КБ, ≤ 200 видов. API `/api/v1/views`: `GET`, `POST`, `PUT /{id}` (`expected_version`, 409), `DELETE /{id}`, `POST /{id}/apply` — все ключи одной транзакцией, ответ — новые значения ключей. Камера применяется в интерфейсе. `.bfggis`: `archive/view_remap.py` перенумеровывает id и в `meta` объектов `view`; ссылки через `object_refs` не заводятся (иначе удаление набора, попавшего в вид, давало бы 422) |
| Задания | `POST /api/v1/jobs/clear {statuses: ["done", "cancelled"] + "failed" по флажку}` → `{removed}`; одна транзакция `DELETE … job_log` + `jobs` для проекта и `instance.sqlite`; `running`/`queued` не трогаются; проект «только чтение» → 423 |
| Панель 3D | Ответ № 7: крупнее только кнопки и их значки — `--tool-w: 42px; --tool-h: 39px; --tool-icon: 24px` в `tokens.css`; `Icon size` из переменной. Поля «От», «До», «Аз.» и подписи — прежние размеры, выравнивание по центру строки; высота строки растёт до 39 px, раскладка `flex-wrap` пересчитывается |
| «О производителе» | `shell/About.tsx` — якорная плашка в общем слое окон (17.4.1), тексты — `shell/about.ts`: «Bandurkin Mikhail» (ответ № 5); контактов и ссылок нет — не выдумывать, 17.4.1 не меняется |
| Вкладка «Настройки проекта» | id `projsettings` (проходит `^[a-z]{1,16}$`); на Э6.1 — группа «Обслуживание» (`jobs.clear_finished`); дубли кнопок других вкладок не добавляются (замечание владельца о дублях) |
| Swath (Э13) | Окно — общий компонент плавающих окон (7.0.12); `BottomTab` теряет `swath`, сохранённое значение нормализуется к `table`; ручки — `viz/swath/handle.ts` (кольцо азимута, дуги наклона и поворота; ответ № 8), углы — также числами в окне; математика (матрица поворота, система короба) — чистый модуль, ядро считает swath в повёрнутой системе (`dip`, `roll` — в `stats.swath`) |

## Варианты

| Вариант | Плюсы | Минусы | Выбор |
|---|---|---|---|
| А. PR «Замечания В2» до приёмки, выпуск 0.2.1 | Владелец видит правки сразу | Задерживает приёмку В2; Д-09 и ядро заданий — не «замечания», а новые функции | Если владелец вернёт В2 со списком |
| **Б. Подэтап Э6.1 в начале В3** | Механизм 11.2 «принято с замечаниями»; код Э1/Э6 свежий; отдельный PR | Э7 начинается на 1–1,5 окна позже | **Выбрано** (ответ № 12 «как хочешь» — решение исполнителя) |
| В. Раздать правки по Э7 | Без нового этапа | PR Э7 смешивает 3D-оболочку и линии; ревью тяжелее | Нет |
| Видимость: снять все галочки списком `hidden` | Без нового ключа | > 2000 объектов не помещаются (ADR 0007 §2) | Нет |
| Виды: своя таблица `views` | Запросы по полям | Миграция без нужды; ADR 0003 советует `objects + meta` | Нет |

## Риски

| Риск | Мера |
|---|---|
| Пользователь не найдёт `T/X/Y/F/S/C` без «Главной» | Подсказки кнопок «Вида» с клавишами; руководство; поиск `Ctrl+K` по «Вписать» находит кнопку на «Виде» (E2E есть) |
| `hide_all` расходится в ядре и интерфейсе | Общие фикстуры нормализации (`core/tests/data/view/*.json`) для pytest и vitest, как у стилей (ADR 0007 §3) |
| Применение вида ссылается на удалённые объекты | Нормализация отбрасывает ненайденные id (как `hidden`); тест |
| Крупные кнопки ломают панель при 1024 px | `flex-wrap`, ≤ 2 строк — E2E на 1024 px |
| Контакты производителя появятся позже | Плашка без строк контактов; добавление — правка `about.ts` (и 17.4.1, если нужны ссылки) |
| Строка панели 3D выросла из-за кнопок | Выравнивание по центру; E2E: поля прежнего размера, ≤ 2 строк при 1024 px |
| Удаление заданий во время записи исполнителем | Удаляются только `done/cancelled/failed`; планировщик их не трогает; `BEGIN IMMEDIATE` |
