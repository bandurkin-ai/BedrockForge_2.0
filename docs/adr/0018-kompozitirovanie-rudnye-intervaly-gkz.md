# ADR 0018. Композитирование и подготовка проб; рудные интервалы по методике ГКЗ (Э12)

**Статус:** Предложен 2026-11-20 (architect, opus / xhigh: лимит Fable до 2026-11-24). Решения 1–20 — предложение; владельцу на подтверждение — 3, 4, 5, 10, 11, 12, 16, 17, 18, 20 и бюджеты с пометкой «предл.» («Замеры»); остальные — оркестратору. Исполняет ТЗ 8.0, 8.2, Д-26 (7.35) с ответами владельца № 17–24 (7.35.10). Не пересматриваются: ADR 0002 (очереди `heavy` / `quick`, `spawn`), 0003 (вектор `num`, 409, Alembic), 0007 (отображения по стволу; таблица — по `name_key`), 0013 (`geo/intersect.py`), 0014 (параллельность — полосы и `nogil`, без `prange`).

## Контекст

## Варианты

| Вопрос | Варианты | Выбор и причина |
|---|---|---|
| Где параметры и происхождение расчёта | А) колонка `dh_tables.derived` (JSON); Б) таблица `dh_derived` (миграция 0007); В) `objects(kind="dh_result")` + `object_refs` | **Б.** У одной таблицы бывает несколько расчётов (композиты + урезка + эквивалент); у полей в чужой таблице нет своей таблицы-результата; список по набору и каскады — внешними ключами. В — дубль таблицы как объекта, `object_refs` не ссылается на `dh_tables` |
| Поля проб ORE_ID, ORE_CLS, AU_CUT, DECL_W | А) настоящие колонки исходной таблицы, запись порциями со скрытыми колонками; Б) «виртуальные» колонки из blob расчёта, подмешиваемые в снимок и `viz/log.py`; В) таблица-спутник | **А.** ТЗ: «поля … в исходной таблице»; Б трогает все читатели `dh_rows` (снимок, отображения, экспорт); В удваивает 5 млн строк |
| «Устарел» | А) только версии (как аудит); Б) отпечаток входов при каждом запросе; В) версии — быстрый путь, при их сдвиге — отпечаток SHA-256 использованных входов с памятью | **В.** А помечает устаревшим после записи своих же полей; Б — 1–2 с на каждый список |
| Протокол оконтуривания | А) файл (Parquet в blobs); Б) расчёт по запросу тем же ядром у свежего результата | **Б.** Детерминированно, совпадает с таблицей по построению; нет владельцев blobs и пересчёта id в `.bfggis` |
| Предпросмотр | А) синхронный запрос к ядру API (одна скважина); Б) задание `quick` | **А.** Одна скважина — миллисекунды; ядра грузятся из кеша numba (прогрев — решение 14) |

## Решение

### 1. Модули

Ядро — `core/bf_core/composites/` (8.2 и Д-26; роутер `composites/router.py` включает `prep_router.py`, `ore_router.py`), перенос BF — `core/bf_core/stats/` (`declustering.py`, `percentiles.py`; Э13 переносит остальное `stats/*` рядом). Интерфейс — `ui/src/modules/composites/`. Тесты — `core/tests/composites/`, `core/tests/stats/`.

### 2. Результат: таблица набора + запись `dh_derived` (миграция `0007_e12_derived.py`, обратимая)

| Колонка | Смысл |
|---|---|
| `id`; `set_id` → `objects` CASCADE | Набор |
| `kind` | `composite_length`, `composite_domain`, `composite_bench`, `code_wireframes`, `merge_tables`, `sample_coords`, `topcut`, `equivalent`, `declus`, `ore_intervals`, `conditions` |
| `table_id` → `dh_tables` CASCADE (NULL у `conditions`) | Таблица-результат или таблица, получившая поля |
| `source_table_id` → `dh_tables` SET NULL | Исходная; NULL — «исходная таблица удалена» |
| `columns` (JSON) | id колонок, добавленных расчётом |
| `params` (JSON) | Параметры команды в каноническом виде (ключи по алфавиту); id таблиц и каркасов внутри пересчитывает `.bfggis` |
| `algo` `{name, version}`, `libs`, `seed` | Версия растёт, когда меняется результат; numpy, numba, Python, bf-core; зерно (8.0.2; сейчас не используется) |
| `inputs` `{sha256, parts}`, `versions` | Отпечаток входов (решение 6); версия набора, `[rev, created_at]` таблиц, `objects.version` каркасов |
| `summary` (JSON) | Сводка «до/после», отчёт урезки, сводка рудных интервалов, таблица анализа кондиций |
| `job_id`, `author`, `created_at`, `updated_at` | — |

Индексы `(set_id)`, `(table_id)`. Новая таблица-результат — обычная `dh_tables` вида `interval` (ТЗ 8.0.3: «композиты, урезка и пересечения — таблицы набора»). `.bfggis`: `dh_derived` в TABLES после `dh_columns`, REFS для трёх ключей, `params` — `archive/derived_remap.py`. Роли и владельцы blobs не меняются.

| Координаты проб | Новая «‹Таблица› — координаты» | X_FROM, Y_FROM, Z_FROM, X_MID…, X_TO… + исходные поля (по выбору, по умолчанию все) |

| Эквивалент металла | Поле | AUEQ (имя правится) |
| Декластеризация | Поле | DECL_W (сумма = n); метод и выбранный размер ячейки — `summary` |

### 4. Таблица «Рудные интервалы ‹поле› ‹Сб›» (Д-26, результат (1)–(5))

- Поля: LENGTH, M (мощность расчёта), поле расчёта и прочие числовые (средневзвешенные по l), MC, CLASS (`ore`, `subgrade`, `waste_in`, `interlayer`, `waste`, `frame`), BASIS (`thickness` / `mc`), N_SAMPLES, WASTE_LEN, **NESTED**, ORE_ID, MODE, MANUAL, FLAG («пропуск как порода»), X, Y, Z (середина), LABEL «8,0 м @ 2,84 г/т (МС 22,7)» (M и MC — 1 знак, C — 2, единица — у поля).
- Основные строки (NESTED = 0: `ore`, `subgrade`, `interlayer`, `waste`) покрывают линию опробования без перекрытий — это и даёт Т8.2-19 «Σ M по классам = длине линии». Вложенные (NESTED = 1): `waste_in` — безрудные фрагменты внутри `ore`; `frame` — обрамление Мпп с обеих сторон `ore` (обрезается краем линии и соседним `ore`), с C.
- Поля проб в исходной таблице: ORE_ID (номер `ore` по порядку «скважина, FROM»), ORE_CLS (`ore` / `subgrade` / `waste_in` / `interlayer` / `waste`; пусто — проба вне линий опробования). Переключатель «Записать классы в пробы» (по умолчанию вкл.), имена правятся; занятое обычной колонкой имя — «_2».
- Сводка (`summary`): число интервалов, Σ M, средняя M, среднее C = Σ MC / Σ M, Σ MC, пропущенные скважины. Протокол — решение 16.

### 5. Имена, замена, перестроение

- Имя — по умолчанию (п. 3–4), правится в окне; занято обычной таблицей — 409 `name_taken` («Таблица с таким именем уже есть» — «Выберите другое имя»); своя расчётная того же вида — своё окно «Заменить?».
- Расчётные таблицы — только для чтения: правка ячеек, «+ Строка», удаление строк и инструменты Э4 недоступны с причиной «Расчётная таблица: измените исходные данные и нажмите «Перестроить»»; исключения — операции «Обработки проб» (урезка, эквивалент, декластеризация на композитах) и ручная правка рудных интервалов (решение 17).
- «Перестроить» (`composite.rebuild`) — те же параметры → новая таблица (`building`) → в том же задании заново считаются зависимые поля этой таблицы (урезка, эквивалент, DECL_W — в порядке создания) → итоговая транзакция: записи `dh_derived` переводятся на новую таблицу, старая заменяется (`swap_in`); отображения остаются (находка 3). Скважины с ручной правкой — своё окно «Перестроить всё / оставить их интервалы».
- Удаление таблицы «Рудные интервалы» предлагает удалить и ORE_ID, ORE_CLS в пробах (галочка, по умолчанию вкл.).

### 6. «Устарел» (`composites/derived.py`)

- `status → fresh | stale | source_missing` + причина по-русски («изменены пробы: AU», «изменена инклинометрия», «каркас «Тело 1» изменён», «исходная таблица удалена»).
- Быстрый путь: `versions` совпали — `fresh`. Сдвинулись — пересчёт отпечатка SHA-256: (а) имена скважин, FROM, TO и **использованные** поля (содержание, плотность, мощность, домен) строк в порядке «скважина, FROM, id»; (б) устья и инклинометрия набора — если расчёт берёт XYZ (композиты, уступы, кодирование, координаты); (в) SHA-256 blobs `xyz`, `tri` каркасов и приоритеты; (г) канонические `params`; (д) `algo.version`. Результат запоминается в `cache\derived\‹id›-‹хеш versions›.json`.
- Добавление колонки (свои ORE_*, AU_CUT, вычисляемое поле) или правка неиспользуемого поля двигает `rev`, но не отпечаток — `fresh` (в отличие от аудита). Сам не пересчитывается: «(устарел)» в дереве, «Свойствах», заголовке окна; «Перестроить».

### 7. Поля в существующей таблице (`drillholes/columns_bulk.py`)

Колонки создаются скрытыми (`deleted = true`, слот не виден — ADR 0003) → значения пишутся порциями по 100 тыс. строк, каждая — `BEGIN IMMEDIATE` → чтение `num` / `txt` → дописывание слота → запись → фиксация (правка пользователя между чтением и записью не теряется) → `tick` → итоговая транзакция открывает колонки, `rev + 1`, пишет `dh_derived` (при перестроении прежние колонки расчёта скрываются). Отмена и сбой — колонки остаются скрытыми, пользователь ничего не видит; уплотнение слотов — существующей командой. ORE_ID — число (`num`), ORE_CLS — текст (`txt`).

### 8. Задания (`composites/jobs.py`, `composites/ore_jobs.py`; `HANDLER_MODULES` — оркестратор)

| Вид | Очередь | Стадии (прогресс с названием) |
|---|---|---|
| `composite.run` (op: length, domain, bench, code, merge, coords, topcut, equivalent, declus) | heavy | «Чтение проб», «Траектории», «Каркасы», «Расчёт», «Запись таблицы» / «Запись полей» |
| `composite.ore_intervals`; `composite.conditions` | heavy | «Чтение», «Оконтуривание», «Запись», «Поля проб»; «Вариант k из N» |
| `composite.rebuild` | heavy | как у операции + «Зависимые поля» |
| `composite.protocol_export` | heavy | «Протокол: скважина k из N», «Запись файла» |

- Оценка памяти: строки × (полей + 8) × 8 Б × 2,5 (+ каркасы: 24 Б × вершин + 12 Б × треугольников + дерево); попыток 3.
- Отмена — между полосами скважин (≤ 1 с) и порциями записи; таблица-результат — `building` + `drop_building`, поля — скрытые (п. 7): прерванное задание не оставляет ничего.
- Чтение (`composites/inputs.py`): снимок Parquet (`SnapshotCache`), если он есть для текущего `rev`, иначе прямое чтение нужных слотов порциями; текст — только если поле выбрано.
- Скважины с пересекающимися пробами пропускаются: журнал (до 20 имён), число в сводке и в окне; все пропущены — ошибка `samples_overlap` («Пробы пересекаются» — «Запустите аудит и исправьте интервалы»). Прочие ошибки `{code, message, hint}`: `no_samples`, `field_not_number`, `wireframe_not_closed` («Каркас не замкнут» — «Проверьте и исправьте каркас»), `name_taken`, `out_of_memory`.

Кнопка 8.2.3 «Объединить таблицы» — с подсказкой «Общие подынтервалы нескольких таблиц со значениями покрывающих интервалов»; у `table.append` (Э4) название меняется на «Добавить строки из таблицы» (id тот же), чтобы палитра не показывала два одинаковых. Клавиш нет (7.35.4); палитра `Ctrl+K` — по кнопкам; ассистент — из реестра (JSON-схема `params`). ### 11. Окна (`modules/composites/`; только собственные окна)

### 15. Точность и пропуски

- float64 везде; суммы — в порядке проб; C(A) и MC(A) — прямой суммой по фрагменту, не разностью накопленных сумм (иначе 1e−12 не держится); итоги по миллионам — `np.sum` (попарно) в фиксированном порядке.
- Сравнение итогов с порогами (C с Сб и Смин, M с Мрт и Мпп, MC с МС) — с допуском τ = 1e−9·max(1, |порог|) (0,1 + 0,2 м ≠ 0,3 м во float64); проба с порогом — точно (g = Сб — руда).
- NaN не становится нулём: композиты — непробованное NaN (0 или значение — явным параметром), L_оп < p_min·L → NaN + FLAG; Д-26 — разрыв по умолчанию, «порода до L_н» — явно, g = 0 с FLAG; эквивалент — NaN, если нет хоть одного компонента; урезка — NaN остаётся NaN.
- Глубины пересечения с уровнями уступов — на дугах минимальной кривизны до 1e−9 м; X, Y, Z — `Trajectories` во float64.
- Порядок — «скважина (`name_key`), FROM, id строки»; никакой зависимости от порядка словарей и множеств.
