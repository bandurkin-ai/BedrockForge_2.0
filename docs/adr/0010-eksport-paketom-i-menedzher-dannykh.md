# ADR 0010. Экспорт проекта по типам объектов и менеджер данных (Д-17, Д-20)

**Статус:** Принято, 2026-11-17 (ответы владельца на вопросы ТЗ 7.35.6 № 10–11); реализация — Э11 (В3), писатели растут с этапами типов объектов.

## Ответы владельца (2026-11-17)

| № | Ответ | Что учтено |
|---|---|---|
| 10 | «нет, экспорт каждого файла в выбранный соответствующий формат — блочные модели в dat или csv, каркасы в dxf или dwg, скважины в csv или xlsx и т.д. просто одним махом экспортировать все данные из проекта для работы в другом ПО» | Решение переписано: экспорт всех объектов по типам в выбранные форматы; пакет-папка/ZIP, `manifest.json`, «Паспорт проекта PDF» — не требуются; PDF-печать — Э22 отдельно |
| 11 | «обязательно» | Менеджер данных (Д-20) — «обязательно», в готовности Э11 |

## Контекст

- ТЗ 7.4: «Экспорт проекта» — `.bfggis` (перенос в BF2); остаётся отдельной командой. Владелец (Д-17): одним действием выгрузить все данные проекта в форматы других программ.
- Д-20: менеджер данных «как ESRI ArcGIS — управление данными проекта как файлами, импорт и экспорт прямо из его области». Хранилище проекта — неизменяемые `blobs` с именами SHA-256 и описания в SQLite (ADR 0002 §5, 17.3.10): настоящих «файлов объектов» в папке проекта нет и быть не должно.
- Писатели форматов появляются на Э4 (DAT/CSV/XLSX скважин), Э7 (STR, DXF, GeoTIFF), Э8 (TRIDB, DXF, DWG, OBJ, STL, DTM), Э11 (OMF), Э17 (блоки). DWG — через ODA File Converter (ADR 0009, вариант А).

## Решение

### 1. Экспорт проекта по типам объектов (Д-17)

| Тема | Решение |
|---|---|
| Окно | Модальное «Экспорт проекта» (7.0.12) в части «Объекты проекта в файлы»: таблица «тип объекта → формат» (выбор на тип; по умолчанию — самый распространённый), папка назначения, подпапки по типам, флажки типов. `.bfggis` — прежняя команда (7.4), в это окно не входит |
| Форматы по типам | Блочные модели — DAT (Micromine) или CSV; каркасы — DXF или DWG; скважины (наборы: устья, инклинометрия, интервальные таблицы) — CSV или XLSX (и DAT, если писатель есть); линии и стринги — STR или DXF; ЦТМ — DXF или другие форматы каркасов; растры — исходный файл (GeoTIFF или изображение с привязкой); прочее — по реестру |
| Реестр писателей | `core/bf_core/exporting/registry.py`: `(kind, format) → writer(object, path, progress)`; каждый модуль регистрирует свои писатели явным импортом (как обработчики заданий, 17.3.9). Окно, менеджер данных (Д-20) и отдельные команды экспорта зовут один реестр |
| Задание | `export.objects` (очередь `heavy`): пишет во временную папку рядом с целью, затем переименование; отмена и сбой не оставляют частичных файлов; журнал операции (7.9); итог — отчёт со списком файлов, «Показать в папке» |
| Состав по этапам | Окно и реестр — Э11 (к нему есть писатели скважин Э4, линий Э7, каркасов Э8; OMF — тот же этап); линии и растры — Э7, каркасы и DWG — Э8, блочные модели — Э17. Формат или тип без писателя в окне недоступен с причиной («Экспорт блочных моделей — этап Э17») |
| Ограничения | Режим «только просмотр» (5.7) — экспорт недоступен; водяной знак лицензии (5.7) в файлах данных не ставится (только в печати, Э22) |
| Команда | `project.export {formats: {<тип>: <формат>}, folder, types?}`; вызов без параметров — `.bfggis`, как раньше |

### 2. Менеджер данных (Д-20)

| Тема | Решение |
|---|---|
| Что это | Логический каталог над `objects` (тип, папка `objects.folder`, имя, `meta`, размеры blobs через `blob_owners`), а не файловая система. Хранилище не меняется |
| Окно | Плавающее «Менеджер данных · \<проект\>» (размер «обычный»): папки слева, таблица справа (виртуальная прокрутка), выбор нескольких, сортировка, поиск; строки дерева — общий `TreeRow` (ADR 0008) |
| Действия | Импорт в папку (системный диалог или перетаскивание из Проводника → мастер 7.8 с папкой назначения); экспорт выбранного (форматы — из реестра писателей, п. 1); переименование; перенос между папками перетаскиванием (`dataset.move`); удаление (`askConfirm`, `danger`); «Показать в 3D»; «Свойства»; «Исходный файл → Сохранить копию как…» (копия blob исходника) |
| API | `GET /api/v1/catalog?folder=&q=&sort=&offset=&limit=` — страница строк каталога; остальное — существующие API импорта, экспорта, объектов |
| Команда | `data.manager` (uiOnly), кнопка «Настройки проекта → Данные → Менеджер данных» |

## Варианты

| Вариант | Плюсы | Минусы | Выбор |
|---|---|---|---|
| **А. Экспорт объектов по типам в выбранные форматы через реестр писателей** | Ровно то, что просит владелец; без новых зависимостей; один реестр для окна, менеджера и команд | Состав растёт по этапам типов | **Выбрано** (ответ № 10) |
| Б. Пакет-папка/ZIP с манифестом и README | Самодостаточная передача | Владелец отказался (№ 10) | Нет |
| В. «Паспорт проекта PDF» со снимками видов | Обзор проекта | Владелец отказался (№ 10); печать — Э22 | Нет |
| Г. Отдельная команда помимо окна «Экспорт проекта» | Не трогает 7.4 | Две похожие кнопки — владелец убирает дубли (Д-05, Д-08) | Нет |
| Менеджер: настоящие файлы объектов в папке проекта | «Как в ArcGIS» буквально | Ломает ADR 0002 (неизменяемые blobs SHA-256, транзакции, сборщик) | Нет |
| Менеджер данных — «желательно», возможен перенос на Э26 | Меньше Э11 | Владелец поднял до «обязательно» (№ 11) | Нет |

## Риски

| Риск | Мера |
|---|---|
| Экспорт большого проекта долгий и тяжёлый | Потоковые писатели, прогресс по объектам, отмена; бюджет — на Э11 (`bench/scenarios/project_export.py`, ориентир 1 ГБ ≤ 3 мин) |
| Формат без писателя на момент Э11 | В окне недоступен с причиной; в отчёте задания — список пропущенного |
| DWG без установленного ODA File Converter | Формат DWG в окне недоступен с подсказкой по установке и предложением DXF |
| Имена файлов из имён объектов | Очистка запрещённых символов Windows, длина пути ≤ 260 (17.2.3), имена не различаются только регистром (17.2.1) — уникализация «(2)» |
| Менеджер дублирует дерево | Общие команды и `TreeRow`; одна модель каталога в чистом модуле |

## Последствия

- ТЗ 7.4 и 7.0.4 (подсказка «Экспорт проекта»), 9.12 (экспорт по типам) правятся в docx v1.1 через ТЗ 7.35.
- Ориентир Э11 растёт с 1 до 2–3 окон 5 ч (OMF + экспорт по типам + менеджер); менеджер входит в готовность (10.5), на Э26 не переносится.
- Э7, Э8, Э17 добавляют писатели своих типов в реестр.

## Проверка

| Что | Как |
|---|---|
| Экспорт демо-проекта | pytest: по файлу на объект; каждый файл импортируется обратно (счётчики, координаты побитно для STR/DXF/OBJ/TRIDB) |
| Отмена и сбой | pytest: снятие исполнителя посреди записи — ни частичных файлов |
| Недоступное | pytest/vitest: тип без писателя и DWG без конвертера — причина по-русски |
| Менеджер | vitest: модель каталога; E2E: перетаскивание `.str` в папку, экспорт двух каркасов в DXF |
| Скорость | `project_export` в `bench` (`ci` — демо); список 1000 объектов ≤ 200 мс |
