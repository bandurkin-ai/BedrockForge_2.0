# ADR 0021. Истинная мощность и рудные пересечения (Э15)

**Статус:** Предложен 2026-11-21 (проект — architect, fable / xhigh; решения 1–24 — в конце; вопросы заказчику № 44–51 неблокирующие, до ответа — «По умолчанию»). Исполняет ТЗ 8.5 (Т8.5-1…13; CHECKLIST № 163), 8.0 (общие правила новых модулей), 7.35 Д-26 «Связь» и ответ № 19 (истинная мощность — полем), 10.5. Опирается на ADR 0001 (версии), 0002 (задания), 0003 (таблицы наборов), 0007 (отображения по стволу), 0013 (`geo/intersect.py`, дерево коробок), 0014 (потоки над ядрами `nogil`), 0018 (`dh_results`, движок интервалов, запись полей и таблиц, рамка окна инструмента). Их не пересматривает; ядро Д-26 (`composites/ore_*`) не меняется.

Геометрия — `core/bf_core/geo/nearest.py` |

### 2. Формулы и точность (`formulas.py`; numpy, float64)

| Что | Решение |
|---|---|
| Расчёт | Всегда векторный: m = l·abs(n·d); n и d — по 8.0.1. Развёрнутая запись и запись Леонтовского — функции для теста Т8.5-6 и подсказки окна |
| Нормаль → углы | n_z < 0 → −n; α = arccos(n_z) с обрезкой аргумента в [−1; 1]; Aп = atan2(n_x, n_y) mod 360; α < 1e−6° → Aп = 0. Вертикальная плоскость (abs(n_z) ≤ 1e−12): из двух азимутов берётся Aп ∈ [0°; 180°) — результат не зависит от обхода треугольника |
| Углы ствола | θ = arccos(−d_z) ∈ [0°; 180°] (больше 90° — восстающая); Aс = atan2(d_x, d_y) mod 360; горизонтальная часть < 1e−12 → Aс = 0 |
| Вход | α ∈ [0; 90], Aп ∈ [0; 360] (360 → 0); вне диапазона — 422 `bad_param`; пусто — у строки нет ориентировки (не ноль) |
| Допуски | Формулы — 1e−12 при l = 1; Т8.5-5 — 1e−6; керн — 1e−4°; дуги — 1e−4·l; каркас — 1e−6 м; допуск записан в тесте. Сравнения правила 8.5.3 — относительный допуск 1e−9 в сторону равенства, суммы — прямые по фрагменту (как решение 5 ADR 0018) |
| Опорная точка | Вершины каркаса и точки запроса — относительно центра охвата каркаса (8.0.1); глубины и направления от неё не зависят |

### 3. Направление ствола и сумма по интервалу (`directions.py`)

| Что | Решение |
|---|---|
| Направление на глубине | Касательная к той кривой, которую строит метод траектории набора. Минимальная кривизна — формула 8.5.1 (ψ через atan2; sin ψ < 1e−9 — t1; разворот направления — t1 в верхней половине, t2 в нижней, как `desurvey._delta`); касательный — t1; сбалансированный касательный — t1 и t2 по половинам; средний угол — направление метода; между станциями с координатами (канава) — единичный вектор хорды; ниже последней станции — её направление |
| Части | k = ⌈(TO − FROM) / шаг⌉ равных частей, d_j — в середине части; TT = Σ l_j·abs(n·d_j), попарная сумма в порядке частей; для прямого участка равно l·abs(n·d) с точностью 1e−12·l |
| Нормаль | Одна на интервал (п. 4–6): в таблице у интервала одни ALPHA и DIPDIR |
| Вырождение | TT / l < ε_в → бит 1 в TT_FLAG; TT записывается как получилась (Т8.5-3: 0 и флаг) |
| HOLE_THETA, HOLE_AZ | По направлению в середине интервала |
| Потоки | `from bf_core.jit import njit`, `cache=True, nogil=True`, без `prange` и `fastmath`; полосы по 4096 скважин (`composites/strips`), полоса пишет только свой участок; итоговые суммы — в одном потоке. Результат побитно одинаков при 1, 2, 4, 8 потоках |

### 4. Ориентировка: источники и признаки (`orient.py`)

| Что | Решение |
|---|---|
| Запрос | `orientation` — список из 1–3 источников по приоритету; интервал получает нормаль первого источника, который её дал. В окне — основной источник и «если не найдена — глобальная» |
| Глобальная | α, Aп на весь расчёт (ручной ввод; плоскость) |
| По домену | Таблица «код → α, Aп» (до 1000 строк) — в параметрах расчёта. Код интервала — поле той же таблицы, другой интервальной таблицы или каркасы-домены (`composites/domains`, как в Э12). Интервал с несколькими кодами берёт код наибольшей длины (`intervals.mode_by_length`). Кода нет в таблице — источник не дал |
| Каркас или поверхность | До 16 каркасов и ЦТМ, замкнутых и незамкнутых (тело; отдельные поверхности висячего и лежачего бока) — п. 5 |
| Ориентированный керн | Таблица замеров и поля α_к, β_к, линия BOH или TOH — п. 6 |
| TT_SRC (текст) | «глобальная», «домен», «каркас: пересечение», «каркас: ближайшая», «керн: замер», «керн: ближайший», «нет» |
| TT_FLAG (сумма битов) | 1 — скважина почти параллельна телу (ТЗ); 2 — ориентировка не найдена, TT пусто; 4 — замер керна не пересчитан в мировую нормаль (θ < 1°), ALPHA и DIPDIR пусты; 8 — у скважины нет траектории, TT пусто (кроме «керн: замер») |

### 5. Ориентировка по каркасу (`orient_mesh.py`, `geo/nearest.py`)

| Что | Решение |
|---|---|
| Пересечения внутри интервала | `hole_crossings` по всем стволам один раз на каркас; берутся глубины в [FROM − 1e−6; TO + 1e−6] м. Нормаль каждого пересечения поворачивается навстречу стволу (−`side`·n треугольника), сумма нормируется. Одно пересечение — нормаль треугольника; вход и выход из тела — норм(n_вх − n_вых) по внешним нормалям (запись ТЗ); висячий и лежачий бок двумя поверхностями — средняя плоскость; складки и несколько тел — тем же правилом. Сумма короче 1e−9 — переход к «ближайшей» |
| Ближайшая | Точка — середина интервала (`positions`). `geo/nearest`: ближайший треугольник всех каркасов списка не дальше d_max, расстояние точное; при равных расстояниях — меньший номер треугольника, затем каркаса; треугольник без площади ближайшим не считается. d_max = 0 — только пересечения |
| Радиус r_n > 0 | Сумма «площадь × нормаль» по треугольникам не дальше r_n от найденной точки; нормали приводятся к стороне ближайшего треугольника (тонкое тело даёт среднюю плоскость, а не ноль); сумма короче 1e−9 — нормаль ближайшего |
| Обход дерева | Стек, ближний потомок первым, коробки дальше текущего лучшего отсекаются; начальная граница — min(d_max, расстояние до треугольника, найденного для предыдущего интервала той же скважины); внутри серии сначала проверяется коробка треугольника |
| Память (10 млн треугольников) | Вершины 120 МБ и треугольники int32 120 МБ (отображение файлов blobs), коробки ≤ 100 МБ; каркасы обрабатываются по одному; колонки 5 млн интервалов ≈ 0,5 ГБ. Оценка пика — ≤ 1,5 ГБ при цели ≤ 3 ГБ; проверяется замером (подшаги 15.5, 15.13) |
| Предпросмотр | Одна скважина на деревьях кеша `wireframes/exact`; если в списке больше 2 млн треугольников — ориентировка по каркасу в предпросмотре не считается, окно об этом сообщает |

### 6. Ориентированный керн (`core_orient.py`)

| Что | Решение |
|---|---|
| Данные | Любая таблица набора вида «события» (глубина) или интервальная (глубина замера — середина) с двумя числовыми полями; линия отсчёта — одна на расчёт |
| Пересчёт | Формулы 8.5.2 дословно; d — направление на глубине замера (п. 3); TOH — e1 = −e1; β_к приводится по модулю 360; α_к пусто или вне [0; 90] — замер не участвует и считается в журнале задания |
| Интервал с замерами | Глубина замера в [FROM; TO] с допуском 1e−6 м. Один замер — TT = l·sin α_к (ТЗ), ALPHA и DIPDIR — из мировой нормали. Несколько — главный собственный вектор Σ n·nᵀ (`numpy.linalg.eigh`, знак — n_z ≥ 0), TT — суммой п. 3 |
| Интервал без замера | Ближайший пересчитанный замер той же скважины не дальше d_к по стволу от ближайшего конца интервала (равные расстояния — верхний); TT — суммой п. 3 |
| θ < 1° | Замер в мировую нормаль не пересчитывается (бит 4): своему интервалу даёт TT = l·sin α_к без ALPHA и DIPDIR; «ближайшим» для других интервалов не служит |

### 7. Правило рудных пересечений 8.5.3 (`rule.py`)

| Что | Решение |
|---|---|
| Линии | Пробы или композиты по (скважина, FROM), движок `composites/intervals`; строки с TO ≤ FROM и перекрытия с предыдущей не участвуют и считаются в журнале (как Э12) |
| Пропуски | `missing = waste` (умолчание ТЗ): проба с g = NaN и промежуток без проб — пустая порода с g = 0, их длина копится в MISS_LEN; `missing = break`: разрывают линию |
| Шаги 1–2 | Дословно: серии рудных проб (g ≥ c); слева направо присоединение следующей серии, если пустая порода между ними ≤ L_п и среднее объединения ≥ c. Кандидаты строятся без L_min |
| Шаг 3, приёмка | `min_by = length`: LENGTH ≥ L_min; `min_by = tt`: TT ≥ m_min, TT кандидата — по п. 3–6; TT пусто — проверка по длине тем же числом и бит 2 |
| Шаг 4, «в том числе» | Один борт c2 > c: те же шаги и приёмка по пробам внутри принятого пересечения; строки KIND = «в том числе», INCL — номер основного пересечения |
| Среднее | Σ l·g / Σ l; с плотностью — Σ l·ρ·g / Σ l·ρ (проба без плотности берёт средний вес фрагмента, как `intervals.aggregate`) |
| Домены | Правило границ доменов не знает (в 8.5.3 их нет); расчёт внутри доменов — у Д-26 |

### 8. Результаты и хранение

| Что | Решение |
|---|---|
| «Истинная мощность» (`tt`) | Поля в таблице источника одной транзакцией (`sink.write_columns`, запись журнала правок `column`): TT, TT_FLAG, TT_SRC; при `angles = true` (умолчание) — ALPHA, DIPDIR, HOLE_THETA, HOLE_AZ. Источник — любая интервальная таблица набора: пробы, композиты, «Рудные интервалы» (поля в таблице-результате живут по правилам Э12: её перестроение предупреждает об их потере — 409 `dependents_lost`). Повтор перезаписывает свои поля и свою запись |
| «Рудные пересечения» (`intercepts`) | Новая таблица вида `interval` «Рудные пересечения» (занято — « (2)»; «Заменить» — из окна): HOLE, FROM, TO, LENGTH, TT, TT_FLAG, TT_SRC, ALPHA, DIPDIR, HOLE_THETA, HOLE_AZ, содержания (поле расчёта и прочие числовые — средневзвешенные, у прочих NaN не участвует), LEN_G (LENGTH·g — метропроцент, для г/т — метрограмм), TT_G (TT·g), WASTE_LEN, N_INT, X, Y, Z середины, INCL, LABEL; сверх ТЗ — ID (номер в скважине), KIND («основное», «в том числе»), MISS_LEN |
| LABEL | «12,0 м @ 2,10 г/т (ИМ 9,8 м)»; «в том числе» — с приставкой «в т. ч. »; TT пусто — без скобок; бит 1 — «(ИМ 0,3 м, вдоль тела)»; единица — из поля; округление — как подписи Э12 (`ore_set`) |

### 12. Крайние случаи

| Случай | Поведение |
|---|---|
| Скважина почти параллельна телу | Бит 1, TT записана как получилась, подпись с пометкой «вдоль тела». Само ничего не исключается; при `min_by = tt` такое пересечение отсеивается по m_min как тонкое — причина видна в предпросмотре |
| Пропуски | Пустые α, Aп, α_к, β_к, FROM, TO — строка без ориентировки (бит 2) или вне расчёта, с подсчётом в журнале; TT пусто, не 0. g = NaN — параметр `missing` |
| Нет траектории | Бит 8, TT и углы ствола пусты |
| Ствол целиком в теле, каркас не пересечён | «Ближайшая» в пределах d_max; дальше — бит 2 либо следующий источник списка |
| Несколько пересечений каркаса в интервале | Общее правило п. 5 (сумма нормалей навстречу стволу) |
| Многоствольные скважины | Боковые стволы в BF2 — отдельные скважины набора (связи «родитель — боковой» в данных нет): считаются независимо. Общий участок, занесённый в обе скважины, даст два пересечения: модуль их не склеивает, это правка данных |
| Канавы, горизонтальные и восстающие стволы | Направление — по хорде между вершинами или по методу траектории; θ до 180°; формулы те же (в них модуль) |
| Интервал ниже забоя | Направление последней станции (траектория продлена до забоя, 7.11) |
| Вертикальная плоскость; горизонтальный пласт | α = 90° — Aп ∈ [0°; 180°); α < 1e−6° — Aп = 0 |
| Очень длинное пересечение | Частей не больше 100 000 на интервал: шаг для него увеличивается, запись в журнале |

### 13. Что Э15 не берёт

Горизонтальная и вертикальная мощность (вопрос № 49); диски ориентировки в 3D (№ 50); тренд как источник ориентировки (Д-15, Э16 / Э19); правила Д-26 в окне пересечений и расчёт 8.5.3 внутри доменов; линии и стринги как источник ориентировки; элемент макета (Э22); пересечения в демо-проекте; правки `viz`, схемы БД, `geo/intersect.py`, `drillholes/desurvey.py`, `composites/ore_*`; новые зависимости.

## Последствия
