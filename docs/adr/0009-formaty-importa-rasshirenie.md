# ADR 0009. Расширение импорта: Datamine, Surpac, Vulcan, DWG, SHP, MapInfo (Д-13)

**Статус:** Принято, 2026-11-17 (ответы владельца на вопросы ТЗ 7.35.6 № 2–4; № 4 — открыт: образцы позже). Зависимости вводятся дополнениями ADR 0001 на этапах, где появляются их читатели.

## Ответы владельца (2026-11-17)

| № | Ответ | Что учтено |
|---|---|---|
| 2 | «удали» | DNG исключён: строка, rawpy и вопрос убраны |
| 3 | «A» | DWG — вариант А (выбран); импорт и экспорт каркасов в DWG через DXF; приоритет «обязательно» |
| 4 | «пришлю позже, напомни, да нужны»; 2026-11-18: блочные модели DM/FBM/DAT (`Для BF.zip`), каркасы Datamine (`Datamine_wireframe.zip`, `Datamine_block_model.zip`), Surpac (`Surpac string.zip`); «Vulcan и GeoTIFF — отмена»; другие форматы Micromine — «не нужны»; векторный TAB — «не нужно» | **Почти закрыт.** Получено: блоки DM/FBM/DAT (проверены — совпадают построчно), пара Surpac STR двоичный + текстовый одной линии, каркас Datamine `FXDRIVES` в формате `.dmx` (`_tr` + `_pt`) и треугольники `optimizedpits_2tr.dm` **без** файла точек `*pt`. ## Контекст

- ТЗ 9.12, последняя строка: «Datamine DM, DWG, Shapefile — нет в v1; DWG — «сохраните в DXF»; DM — после образцов от заказчика». Владелец (Д-13) просит импорт Datamine, Micromine, Surpac, Maptek Vulcan, DWG, DXF, GeoTIFF, SHP и MapInfo («DNG» — снят ответом № 2) — это меняет принятый состав форматов.
- Уже в плане: Micromine DAT/STR/TRIDB (Э3, Э7, Э8), Surpac STR и DTM текстом (Э7, Э8), DXF (Э7, Э8), растры с привязкой world/TAB/GRF и GeoTIFF (Э7, tifffile).
- Правила: лицензии только MIT/BSD/Apache-2.0/MPL-2.0/ISC/PSF; GPL/LGPL/AGPL запрещены (5, 8.0.3, 17); готовые колёса `cp312-win_amd64`, сборка из исходников запрещена (ADR 0001, П4); дистрибутив ≤ 400 МБ при оценке 330–370 МБ (ADR 0001, «Последствия»).
- `tools/ci/check_licenses_py.py` проверяет лицензию в метаданных пакетов замыкания `[project].dependencies`; `check_licenses_npm.mjs` — поле `license` в `package.json` продуктового замыкания. Библиотеки DLL внутри колёс ни один из них не видит.

## Решение

| Формат | Описание | Решение | Зависимость | Этап | Приоритет |
|---|---|---|---|---|---|
| ESRI Shapefile `.shp/.shx/.dbf/.prj/.cpg` | Открыт (ESRI Shapefile Technical Description, 1998) | Читатель на pyshp: Point/MultiPoint → точки, PolyLine → линии, Polygon → замкнутые линии (кольца — отдельные линии с атрибутом «кольцо»); Z и M сохраняются; атрибуты DBF; кодировка `.cpg`, иначе cp1251 с предупреждением; СК — `.prj` (pyproj есть) | pyshp (MIT), дополнение ADR 0001 на Э7 | Э7 | обязательно |
| MapInfo MIF/MID | Открыт (MapInfo Interchange Format) | Свой разбор текста: Point, Line, Pline (в т. ч. Multiple), Region, Text; `CoordSys Earth Projection …` → EPSG/WKT через pyproj; `Delimiter`, `Charset` | — | Э7 | обязательно |
| MapInfo TAB (вектор) | — | **Не нужен** (владелец, 2026-11-18): MIF/MID; растровый TAB (привязка) — как есть | — | — | — |
| GeoTIFF | Открыт (OGC 19-008r4) | tifffile: `geotiff_metadata` (ModelPixelScale, ModelTiepoint, ModelTransformation, GeoKeys → EPSG); без сжатия и Deflate/PackBits — без новых пакетов; LZW, JPEG, LERC — **не поддерживаются** (образцов сжатых GeoTIFF не будет — владелец, 2026-11-18): понятное сообщение «Сжатие … не поддерживается: сохраните GeoTIFF без сжатия или с Deflate» | — | Э7 | обязательно |
| DXF | Открыт | Без изменений плана (9.12) | ezdxf (есть) | Э7, Э8 | обязательно |
| DWG | Закрыт (ODA, Autodesk); LibreDWG — GPL-3.0 | **Вариант А — выбран владельцем (№ 3):** ODA File Converter — бесплатная программа Open Design Alliance, пользователь ставит её сам; путь — в «Настройке»; ядро вызывает её как внешний процесс через `ezdxf.addons.odafc` (MIT, есть в ezdxf 1.4.5): импорт — DWG → временный DXF → наш читатель; экспорт каркасов (Д-17) — наш писатель DXF → DWG. BF2 программу не распространяет и не связывается с ней как с библиотекой. Без конвертера — сообщение по-русски («Не найден ODA File Converter: установите его и укажите путь в «Настройке»; или сохраните чертёж в DXF») и предложение «Сохраните в DXF». Б (коммерческий ODA SDK) и В (только DXF) — не выбраны | — | Э8 | обязательно |
| Datamine `.dm`, `.fbm`, `.dmx` | **Описан для блочных моделей** (разбор владельца 2026-11-18 по экспорту из Micromine — `tests/data/real/blockmodels-dm-fbm-dat.md`): страницы 4096 байт (extended, слово 8 байт, 4 символа на слово с добивкой пробелами) или 2048 (single); страница 0 — имя, описание, число полей, номер последней страницы, записей на последней; описатель поля — 7 слов (имя 8 символов, тип N/A, номер хранимого слова, 0 — поле-константа со значением в слове 6, номер слова внутри A-поля); записи подряд, хвост страницы — нули. `.fbm` — то же, маркер 42 в служебном слове, сетка NX/NY/NZ может быть шире. Имена — cp1251. Каркасы (`*tr` + `*pt`) и стринги — не описаны | Свой читатель (без новых пакетов): детект single/extended по странице 0 и кратности размера; хранимые поля и константы; A-поля по словам; последняя страница. Блочная модель: центр, размер, атрибуты; **IJK пересчитывается** из центра, начала и шага (`I·NY + J)·NZ + K`, Z быстрее), из файла не берётся (у `.fbm` сетка другая); допускаются субблоки (меньшие XINC… и повторный IJK); параметры сетки (начало — угол модели, шаг, NX/NY/NZ, поворот) — отдельный объект; код пустого значения (−99 и др.) — настраивается в мастере. Каркасы: `.dm` — та же страничная структура (проверено на `optimizedpits_2tr.dm`: поля PID1, PID2, PID3, TRIANGLE и атрибуты, пустое −1e30); `.dmx` (`FXDRIVES_tr/_pt.dmx`) — другой, сжатый двоичный формат без описания: реверс только с парой `.dm` того же каркаса | — | Э17 (блоки); Э8 (каркасы `.dm` — нужен файл точек; `.dmx` — после пары `.dm`) | обязательно (блоки); желательно (каркасы) |
| Micromine `.DAT` (Extended Data File) | **Описан** (тот же разбор): сигнатура `THIS IS MICROMINE EXTENDED DATA FILE!`, XML-метаданные UTF-8 до 8192 байт (кодировка, классы полей), с 0x2000 — «N VARIABLES» и строки полей (имя 10, тип R/C/…, ширина, знаки), записи фиксированной длины + CRLF, R8 — double LE; имена и тексты — **BOCU-1**. Параметров сетки в файле нет | Расширение читателя DAT Э3 (скважины) на таблицы любых полей и блочные модели. BOCU-1 — **свой декодер** по Unicode TN #6 (PyICU — лицензия Unicode/ICU, нет в списке разрешённых ТЗ 5.x; ASCII-случай тривиален, кириллица нужна в русских проектах); сетка восстанавливается как min(центр) − размер/2 и шаг по уникальным координатам, либо из сопутствующего файла; EAST/NORTH/RL ↔ XC/YC/ZC, _EAST/_NORTH/_RL ↔ XINC… Открыто: C-поля, XML длиннее 8 КБ, поворот модели — по образцам | — | Э17 (блоки); Э7 (таблицы) | обязательно |
| Surpac двоичный STR | Не описан; **образец владельца** (2026-11-18): одна линия в двоичном и текстовом STR (`tests/data/real/Surpac string.zip`) — пара для реверса (заголовок текстом, координаты — double) | Свой читатель по паре образцов: сверка двоичного с текстовым точно; DTM и `.mdl` — нет (не просили) | — | Э8 | желательно |
| Maptek Vulcan | **Исключён владельцем** (2026-11-18, «Vulcan — отмена») | Не поддерживается; данные Vulcan — через DXF, OMF, CSV | — | — | — |
| Micromine прочие (`.PIT`, `.GRD`, `.DHDB`…) | — | **Не нужны** (владелец, 2026-11-18); `.PIT` по-прежнему читается как STR, если подан (9.3) | — | — | — |

Общие правила читателей — 9.12 (потоково, прогресс, отмена, негативные тесты, «бомбы», журнал операции, цикл «импорт → экспорт → импорт» для форматов с экспортом). Мастер «Импорт файлов» (7.8) узнаёт новые расширения: `.shp .dbf .shx .prj .cpg .mif .mid .dm .fbm .dwg .pit`; DAT Micromine определяется по сигнатуре (скважины или блочная модель). DNG не поддерживается (ответ № 2).

## Причины

- SHP и MIF/MID открыто описаны и малы: pyshp — 73 КБ, чистый Python; MIF — текст, свой разбор короче и надёжнее, чем зависимость.
- DWG по варианту А не добавляет ни зависимости, ни лицензионного риска: программа пользователя, внешний процесс, обёртка уже в стеке (ezdxf MIT).
- Закрытые форматы (DM, Vulcan, двоичный Surpac) нельзя «угадывать» (17.1.3): только описание + образцы владельца + тесты на них.

## Последствия

- ТЗ 9.12: строка «Datamine DM, DWG, Shapefile — нет в v1» заменяется ссылкой на ТЗ 7.35 Д-13 (в docx v1.1).
- Новое правило проверки зависимостей: для колёс с вложенными DLL (`*.libs`, `*.dylibs`) — ручной разбор лицензий вложенных библиотек в ADR-дополнении; желательно — расширить `check_licenses_py.py` списком известных библиотек (GEOS, iconv, LibRaw, spatialite).
- Образцы владельца — в `tests/data/real/` (только чтение); без образца формат не объявляется готовым.

## Проверка

| Что | Как |
|---|---|
| SHP: точки, линии, полигоны с Z, атрибуты, cp1251, `.prj` | pytest на синтетике (pyshp пишет эталоны в тесте); негативные: обрезанный `.shp`, нет `.shx`, битый `.dbf` |
| MIF/MID: все типы объектов, CoordSys | pytest на синтетике и образце владельца |
| GeoTIFF: привязка по tiepoint + scale и по ModelTransformation | pytest: координаты углов = эталон (1e−9); сжатый файл без imagecodecs → понятная ошибка |
| DWG (А) | pytest с подменой конвертера (фальшивый исполняемый файл), импорт и экспорт; цикл «каркас → DWG → каркас» — ручная на Windows с установленным ODA File Converter; без него — сообщение с подсказкой и «сохраните в DXF» |
| DM, FBM, DAT (блоки) | pytest на образцах владельца: три файла одной модели дают одинаковый набор блоков (число, центры 1e−6 м, атрибуты точно; контрольные значения — `tests/data/real/blockmodels-dm-fbm-dat.md` §4); IJK пересчитан и совпадает с `.dm`; BOCU-1 — тесты на ASCII и кириллице |
| DM (каркасы) | pytest на образцах владельца: объём каркаса = объёму из Datamine (1e−9 отн.) |
| Скорость | SHP и MIF 1 млн вершин ≤ 10 с; DM 20 млн блоков ≤ 8 мин (5.3); память — 5.3 |
| Лицензии | `check_licenses_py.py` после `uv lock`; запись версии и лицензии в ADR 0001 |
