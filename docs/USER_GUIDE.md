# BedrockForge 2 — руководство пользователя

Руководство дополняется на каждом этапе: разделы — по вкладкам ленты и модулям.

## Запуск
| Вариант | Как работает |
|---|---|
| `BedrockForge-x.y.z-portable.exe` | Без установки. При первом запуске распаковывается рядом с собой (папка `BedrockForge-x.y.z`), если папка только для чтения — в `%LOCALAPPDATA%\BedrockForge\portable\x.y.z`; дальше запуск сразу |
| `BedrockForge-x.y.z-setup.exe` | Установщик для текущего пользователя, права администратора не нужны |

- Без подписи кода Windows SmartScreen покажет «Неизвестный издатель»: «Подробнее» → «Выполнить в любом случае».
- При запуске показывается заставка, пока не будет готово вычислительное ядро; затем открывается главное окно.
  Если ядро не запустилось, заставка показывает причину и кнопки «Скопировать журнал», «Закрыть».
- Запускается один экземпляр программы.
- Журналы: `%LOCALAPPDATA%\BedrockForge\logs\` (`shell.log` — оболочка, `core.log` — ядро).
- Служебные клавиши окна: `F5` — перезагрузить окно, `F11` — полный экран, `Ctrl+Shift+I` — инструменты разработчика.

## Интерфейс
**Заголовок:** логотип «BedrockForge by Mikhail Bandurkin», выбор проекта ⚙, поиск команд `Ctrl+K`,
кнопка темы, значок ⓘ «О производителе» (справа от переключателя темы), кнопка «Claude».

**Лента** — 6 вкладок. `Ctrl+F1` сворачивает ленту. При узком окне группы справа ужимаются:
сначала малые кнопки, затем только значки.

| Вкладка | Назначение |
|---|---|
| «Главная» | Проект, импорт, настройка (в т. ч. «О производителе»), лицензия |
| «Вид» | Поворот вида («В план», «Сбоку», «Вписать», «Разрез»), окно, слои, стиль, панели |
| «Моделирование» | Построение моделей (по этапам); «Поверхности» › «Построить ЦТМ» |
| «Анализ» | Группа «Аудит и статистика», графики, отчёты (по этапам) |
| «Настройки проекта» | Группа «Обслуживание» › «Очистить выполненные задания» |
| «Claude» | Ассистент |

Кнопки будущих этапов видны, но серые, с причиной «Функция появится на этапе ЭN».

**Дерево данных** (слева) — 8 разделов: «Виды» (первым), «Скважины», «Каркасы», «ЦТМ», «Линии», «Растры», «Блочные модели», «Аудит и статистика».

| Действие | Как |
|---|---|
| Свернуть/развернуть раздел или узел | только стрелка ▸/▾ |
| Выбрать | щелчок по названию (по набору — активный набор, в строке состояния «Набор: …») |
| Действие по умолчанию | двойной щелчок (набор — таблица, отображение — форма) |
| Клавиши | `↑`/`↓`; `→` раскрыть / войти; `←` свернуть / к родителю; `Enter` — выбрать; пробел — галочка; `Home`/`End` |
| Изменить порядок разделов | перетащить заголовок |
| Добавить объект | «+» у раздела |
| Меню раздела | правая кнопка мыши |
| Импорт с заданным типом | перетащить файлы из Проводника на раздел |
| Пустое дерево | кнопка «Загрузить демо-проект» |

**Панели**

| Место | Вкладки |
|---|---|
| Справа | «Свойства», «Claude» |
| Снизу | «Таблица», «Аудит и статистика», «Статистика», «Swath plot», «Задания», «Журнал команд» (`Ctrl+Ё`) |
| Строка состояния | ядро, проект, набор, выбор, вид, Claude, аудит |

«Журнал команд»: время, кто («Вы» / «Claude»), команда, параметры, результат; последние 200.

**Палитра команд `Ctrl+K`:** поиск по названию, пути «вкладка › группа» и подсказке; до 60 результатов;
`↑`/`↓` — выбор, `Enter` — выполнить, `Esc` — закрыть. Запрос «скв » ищет скважины (с Э4).

**Окна и диалоги** — собственные: плавающие окна (перетаскивание, размер, развернуть, закрыть;
щёлкнутое выходит наверх), подтверждения, сообщения с кнопками «Скопировать» и «Сохранить .txt».

**Темы:** тёмная (по умолчанию) и светлая; выбор запоминается.

**Фирменный стиль:** палитра Anthracite / Cobalt / Copper Orange / Light Stone / Slate; шрифты Montserrat (заголовки) и Inter (текст) встроены, интернет не нужен; знак-куб в заголовке и на заставке; иконка у приложения.

### Горячие клавиши по умолчанию
Работают в русской и английской раскладке. Одиночные клавиши не срабатывают в поле ввода.

| Клавиша | Действие |
|---|---|
| `T` | «В план» — вид сверху на то, что на экране |
| `X` | «Сбоку Z/X» — вид на север |
| `Y` | «Сбоку Z/Y» — вид на запад |
| `F` | «Вписать» — показать всё, не поворачивая вид |
| `S` | «Разрез» — провести линию разреза |
| `C` | «Отсечение» по окну разреза |
| `[` / `]` | Предыдущий / следующий профиль разреза |
| `Esc` | Снять выбор скважины |
| `Ctrl+Shift+F` | Счётчик кадров 3D («Счётчик кадров») |
| `Ctrl+Shift+H` | «Очистить окно» — скрыть все объекты в 3D |
| `Ctrl+Z` / `Ctrl+Y` | В форме отображения: отменить / повторить правку |
| `Ctrl+K` | Палитра команд |
| `Ctrl+J` | Панель «Claude» |
| `Ctrl+B` | Дерево данных |
| `Ctrl+Ё` | Нижняя панель (клавиша над Tab) |
| `Ctrl+F1` | Свернуть/развернуть ленту |

## Проекты
Окно «Проекты»: кнопка с названием проекта в заголовке (или «Проект не открыт»), «Главная» › «Проекты», `Ctrl+K` → «Проекты».

| Блок | Что в нём |
|---|---|
| «Открытый проект» | Название, «Переименовать», «Экспорт»; поля «Месторождение», «Лицензия», «Стадия работ» (сохраняются при уходе из поля); даты создания и изменения; состав: наборы скважин, скважины, замеры, пробы, интервалы таблиц, каркасы, линии, растры, блочные модели, графики, диалоги Claude |
| «Все проекты» | Поиск по названию и описанию; у строки — число скважин и объектов, дата изменения; «Открыть» (или двойной щелчок), значки «Переименовать», «Экспорт», «Удалить» |
| Внизу | «Новый проект», «Демо-проект», «Импорт…» |

- Названия уникальны без учёта регистра: занятое название отклоняется сообщением.
- При запуске открывается последний проект. Каждое изменение записывается сразу; если ядро аварийно завершилось, подтверждённые правки сохранены.
- «Удалить» — с подтверждением; вся папка проекта удаляется.
- Проект, открытый в другом окне BedrockForge, открывается «только чтение».

**Где хранятся.** Папка `<Название>.bfproj` в `Документы\BedrockForge\Проекты` (меняется в «Настройка» › «Общие», действует после перезапуска).

| Внутри папки | Назначение |
|---|---|
| `project.bfproj`, `project.sqlite` | Описание и данные проекта |
| `blobs`, `cache` | Хранилище файлов и кеш |
| `backups` | Автокопия раз в сутки, хранятся 5 последних |
| `logs`, `project.lock` | Журналы; отметка «проект открыт» |

Сетевые диски не поддерживаются; путь к проекту — не длиннее 180 символов.

## Перенос проекта (`.bfggis`)
Весь проект — один сжатый файл для другого компьютера.

**Экспорт:** «Главная» › «Экспорт проекта», «Экспорт» в окне «Проекты» или значок в строке проекта.

| Элемент окна | Назначение |
|---|---|
| Состав | Что войдёт в файл |
| «Сохранить как…» | Имя по умолчанию «<Название>_ГГГГ-ММ-ДД.bfggis» |
| «Пароль», «Повтор пароля» | Необязательно: шифрование AES-256; пароль нигде не сохраняется — без него файл не открыть |
| «Настройки вида» | Видимость слоёв, стили, порядок дерева |

Экспорт идёт заданием `export.project` во вкладке «Задания»; у готового — «Показать в папке».

**Импорт:** «Главная» › «Импорт проекта», «Импорт…» или перетащить `.bfggis` на окно.

| Шаг | Что происходит |
|---|---|
| Проверка | Название, описание, дата экспорта, версии программы и схемы, состав; для зашифрованного файла — пароль («Неверный пароль» — импорт не начинается) |
| Название занято | «Создать копию «Имя (2)»», «Другое название» или «Заменить существующий» (старый проект удаляется только после успешного импорта) |
| «Применить настройки вида из файла» | Если они есть в файле |
| Импорт | Задание `import.project`; у готового — «Открыть проект» |

- Оборванный или повреждённый файл не оставляет ничего; заменяемый проект остаётся целым.
- Файл новее программы отклоняется: «обновите программу».
- Файлы BedrockForge 1 распознаются (название, состав), но перенос их данных появится на следующих этапах: кнопка «Импортировать» серая.

## Импорт скважин
«Главная» › «Скважины» (`import.open`) открывает мастер «Импорт скважин». Файлы можно перетащить из Проводника на окно (DAT, CSV, TXT, Excel) — мастер откроется с ними.

| Шаг | Что загружается |
|---|---|
| «1. Устья» | Collar |
| «2. Инклинометрия» | Survey |
| «3. Интервалы и события» | Пробы, интервальные таблицы, события |
| «4. Импорт» | Набор, система координат, запуск |

Заголовок показывает «Шаг N из 4». «Добавить файлы…» принимает несколько файлов сразу: каждый попадает на шаг по определённому типу таблицы.

**«Главная» › «Импорт файлов»** (`import.files`): выбор файлов и передача в нужный мастер.

| Файлы | Куда |
|---|---|
| Таблицы | «Импорт скважин» |
| `.bfggis` | Импорт проекта |
| Линии, точки, растры (и файлы привязки) | Окно «Импорт файлов», см. «Линии, растры, ЦТМ» |
| Каркасы, OMF | Сообщение, на каком этапе появятся: каркасы — Э8, OMF — Э11 |

**Форматы:** Micromine DAT (в том числе кодовая страница BOCU-1), CSV/TXT/TSV/PRN, Excel `.xlsx`/`.xlsm` и `.xls` (чтение).

### Карточка файла
| Элемент | Назначение |
|---|---|
| Сводка | Как прочитан файл |
| «Кодировка» | Авто, UTF-8, UTF-16, cp1251, cp866, KOI8-R, latin-1 |
| «Разделитель» | Авто, `;`, `,`, табуляция, `\|`, пробелы |
| «Лист» | Для книг Excel |
| «Строка заголовка» | Номер строки с названиями; 0 — без заголовка |
| «Строки файла» | Первые строки как в файле |
| «Тип таблицы» | «Устья», «Инклинометрия», «Пробы», «Интервальная таблица», «События» |
| «Название таблицы» | Для интервальных таблиц |

- Обязательные поля помечены `*`.
- Колонки назначаются сами по словарям Micromine, Datamine, Surpac, Vulcan, Leapfrog, acQuire и русским названиям; регистр, разделители и единицы не важны, названия, обрезанные до 8–10 символов, узнаются.
- Для проб: флажок «компонент» и единица (из названия: ppm, г/т, %, ppb). Остальные колонки можно сохранить как «атрибут».

### Числа и пропуски
| В файле | В проекте |
|---|---|
| Запятая или точка; пробелы между разрядами («4 584 699,70») | Число |
| «<0,005» | 0,0025 (половина); счётчик замен на экране |
| «>1000» | 1000; счётчик замен на экране |
| «-», «н/д», «н.о.», «NA», «N/A» | Пусто (не 0) |

### Замечания
- Список замечаний: текст в числовой колонке останавливает импорт.
- Флажок «Загрузить с ошибками — исправлю в BedrockForge»: значение становится пустым, исходный текст — в атрибуте «<колонка> (исходное)». Строка без номера скважины получает «БЕЗ НОМЕРА (строка N)», повторное устье — «<номер> (повтор k)».
- Ошибки назначения колонок так не загружаются.
- Предпросмотр показывает первые нормализованные строки.

### Шаг «4. Импорт»
| Элемент | Назначение |
|---|---|
| «Новый набор» | Название нового набора |
| «В существующий» | Выбор набора; заменяется только в нём («Заменить»): пробы — таблица проб набора (она одна), интервальные таблицы и события — таблица того же типа и названия |
| «Система координат» | «Из файла .prj…» |
| «Состав» | Что будет загружено и что заменится («заменит таблицу «…»») |
| «Импортировать» | Запускает задание «Импорт скважин» (вкладка «Задания») |

- Загружаются все файлы или ни одного.
- Несколько файлов устьев или инклинометрии объединяются; скважина в двух таких файлах — ошибка.
- Два файла в одну таблицу (например, два файла проб) не загружаются вместе: уберите лишний или переименуйте таблицу.
- Исходные файлы и назначение колонок хранятся в проекте (история импорта).
- Ориентир по скорости: 5 млн проб с номером пробы — около 40 с, около 1,8 ГБ памяти (тестовый компьютер).

### Журнал операции
Значок журнала в заголовке мастера (красный, если были ошибки) открывает журнал.

| В журнале | Содержимое |
|---|---|
| Среда | Время, версии, система, размер окна, проект |
| Файлы | Как прочитаны, назначение колонок, проверки |
| Запросы к ядру | Статус и время; пароли скрыты |
| Задание | Состояние, результат или ошибка и журнал задания — до его окончания, даже после закрытия мастера |
| Ошибки | `detail` и `trace` ядра |

Кнопки: «Копировать», «Сохранить .txt» (имя `bedrockforge-import-ГГГГ-ММ-ДД_чч-мм-сс.txt`), «Обновить». «OMF» › «Журналы» (`logs.open`) — последние 30 журналов сеанса. Во вкладке «Задания» у задания мастера — ссылка «журнал операции».

## Наборы скважин
Наборы лежат в дереве данных в разделе «Скважины».

| Действие | Как |
|---|---|
| Сделать набор активным и открыть его таблицу | щелчок по набору |
| Открыть «Устья» / «Инклинометрия» / «Пробы» | правая кнопка › одноимённый пункт |
| «Переименовать…» | правая кнопка |
| «Удалить…» | правая кнопка; с подтверждением; удаляются скважины, таблицы и история импорта набора |
| «Новый набор…» (`set.create`) | создаёт пустой набор; скважины добавляются вручную |

## Таблица
Вкладка «Таблица» нижней панели: выбор набора и вкладки таблиц с числом строк — «Устья», «Инклинометрия», «Пробы», остальные интервальные таблицы, события.

| Действие | Как |
|---|---|
| Прокрутка | Строки грузятся страницами: таблица на 5 млн строк не загружается целиком |
| Сортировка | Щелчок по заголовку: по возрастанию → по убыванию → выключена; пустые значения — в конце |
| Одна скважина | Щелчок по номеру скважины (кроме таблицы «Устья»); метка «Скважина … ✕» снимает отбор |
| Фильтр | Поле выражения: `Enter` — применить, `Esc` — очистить |
| Статистика колонки | Кнопка Σ в заголовке |

**Фильтр-выражение.** Пример: `AU > 0,5 и [Литология] = "гранит"`.

| Элемент | Правила |
|---|---|
| Связки | `и`, `или`, `не` |
| Имена | Если в имени пробел — в квадратных скобках: `[Литология]` |
| Аргументы функций | Через `;` |
| Проверка значений | `isnull(x)`, `notnull(x)`, `between(x; a; b)`, `inlist(x; a; b…)` |
| Числа | `abs`, `sqrt`, `log`, `log10`, `exp`, `round`, `floor`, `ceil`, `min`, `max` |
| Текст | `upper`, `lower`, `trim`, `contains` |

**Σ — статистика колонки:** заполнено, пусто, min, max, среднее, медиана, std; для текста — число уникальных и частые значения. Учитывается выбранная скважина и фильтр.

### Правка
| Действие | Как |
|---|---|
| Править ячейку | Щелчок по ячейке |
| Сохранить / следующая колонка / отмена | `Enter` / `Tab` / `Esc` |
| Очистить значение | Стереть текст и `Enter` |
| Числа | «12,5» и «12.5» — одно и то же, 12,5 |
| Новая строка | «+ Строка» (форма) |
| Удалить строку | 🗑 в начале строки |

Проверки при сохранении (нарушение — сообщение, правка не записывается):

| Проверка |
|---|
| Обязательные поля (помечены `*`) заполнены |
| «До» не меньше «От» |
| Второе устье с тем же номером скважины отклоняется |
| Переименование скважины в уже существующий номер отклоняется |

### Журнал правок
Кнопка «Журнал правок»: время, пользователь, таблица, скважина, что изменено (было → стало).

| Действие | Результат |
|---|---|
| «Отменить» у записи | Возвращает прежнее значение |
| Отмена удаления строки | Строка возвращается как новая |
| Отмена действия инструмента (замена, вычисляемое поле, объединение…) | Отменяется целиком сразу |

### Инструменты ▾
| Инструмент | Что делает |
|---|---|

## 3D-окно
Центральная область. Показывает устья и стволы всех видимых наборов; траектории рисуются с точностью до 1 см, координаты не округляются. Открытие проекта — до первого кадра не более 5 с (устья появляются первыми, затем стволы).

**Мышью:** вращение, сдвиг, масштаб. Проекция по умолчанию ортогональная. Положение камеры в проекте не хранится: при открытии проекта выполняется «Вписать».

**Панель над окном** (подсказки на кнопках; каждая кнопка — команда, есть в ленте и `Ctrl+K`). Кнопки крупные: 42×39 px, значки 24 px. В ленте те же кнопки — на вкладке «Вид» (с «Главной» группы «Вид» и «Разрез» убраны).

| Группа | Кнопки |
|---|---|
| Поворот вида | «В план» (`T`), «Сбоку Z/X» (`X`), «Сбоку Z/Y» (`Y`), «Вписать» (`F`), «Разрез» |
| Разрез | «Разрез» (`S`), «Разрез через скважину», «Авто-разрез» (пока линии нет); при линии — «Отсечение» (`C`), «Предыдущий профиль» (`[`), «Следующий профиль» (`]`), «В плоскость разреза», «План», «Сбросить разрез» |
| Окно разреза | Поля «От», «До» (м) и «Аз.» (азимут линии, градусы) — при заданной линии |
| Вид | «Вертикальное преувеличение» ×1, ×2, ×3, ×5; «Непрозрачность каркасов» 0,1–1 (по умолчанию 0,7); «Перспектива»; «Сетка» («Координатная сетка с подписями») |
| Просмотр | «Данные по скважинам» (нужен активный набор) |

| Вид | Что делает |
|---|---|
| «В план» | Сверху (Y вверх, X вправо): поворот вокруг центра вида, масштаб и центр сохраняются |
| «Сбоку Z/X» / «Сбоку Z/Y» | На север: Z вверх, X вправо / на запад: Z вверх, Y вправо |
| «Вписать» | Все видимые объекты без поворота; при отсечении — только то, что в окне разреза |
| «В плоскость разреза» | Z вверх, линия слева направо |

**Гизмо осей** (левый нижний угол): X красная, Y зелёная, Z синяя, поворачивается вместе с камерой. Щелчок по головке оси — вид вдоль оси с её положительной стороны (головка Z — сверху), по кружку напротив — с отрицательной (кружок Z — снизу). Поворот плавный; новый щелчок прерывает начатый.

**Выбор.** Щелчок по устью (в пределах 8 px) или стволу (6 px) выбирает скважину: карточка в «Свойствах», строка в таблице. `Esc` или «Выделение» › «Снять выбор» — снять. «Найти скважину» — `Ctrl+K`, запрос «скв ».

**Цвет устьев по аудиту**

| Цвет | Значение |
|---|---|
| Красный | Есть критичные замечания |
| Жёлтый | Есть предупреждения |
| Синий | Только информация |
| Зелёный | Находок нет |
| Серый | Аудит не запускался |

Если аудит устарел, в легенде плашка «устарел», цвета остаются. Проектные скважины рисуются пунктиром; у канав свой цвет.

**Видимость и сохранение.** Слои (набор, устья, стволы, отображения) включаются и выключаются галочками; команда `layer.show`. В проекте запоминаются: перспектива, сетка, преувеличение, видимость слоёв, линия разреза и отсечение, стили устьев и стволов набора, включённые отображения. Правка данных, импорт и удаление набора обновляют окно сами: удалённый набор сразу исчезает.

**Если графика остановилась.** Нет WebGL2 — окно «3D-окно недоступно» с причиной и вариантом «Программная отрисовка (медленно)». Потеря контекста — плашка «Графика перезапускается…», затем кадр восстанавливается. Три потери за минуту — нагрузка снижается, в углу пометка.

**Счётчик кадров (`Ctrl+Shift+F`).** Показывает кадры/с (текущее, минимум, среднее), мс на кадр, число треугольников и вызовов отрисовки, оценку памяти видеокарты, класс и название видеокарты, долю «упрощено». Итог замера можно скопировать. Цель на встроенной графике ПК приёмки — не менее 20 кадров/с на 50 000 стволов. Окно в углу «Программная отрисовка» — видеокарта не используется, 3D медленнее.

**Очистить окно.** «Вид» › «Окно» › «Очистить окно» (`Ctrl+Shift+H`, `Ctrl+K`, ассистент) скрывает все объекты (наборы, устья, стволы, отображения…) при любом их числе и снимает выбор скважины. Камера, разрез, сетка и сохранённые виды не меняются. Галочка показывает объект снова; набор, импортированный после очистки, показывается. Состояние сохраняется в проекте.

Будет позже: пересечения стволов с каркасами и блочными моделями, подсказка при наведении на устье, показ каркасов, линий, растров и блочных моделей, наклонные разрезы.

### Разрезы
| Действие | Как |
|---|---|
| Линия двумя щелчками | `S` (или «Разрез»), щелчок — начало, второй щелчок — конец, в виде сверху, сбоку или на мини-плане. Затем включается отсечение, вид разворачивается в плоскость разреза, линия вписывается от края до края данных |
| Через скважину | Выбрать скважину → «Разрез через скважину»: линия через устье по азимуту скважины в плане, вся скважина в плоскости разреза; у вертикальной азимут прежний |
| Авто-разрез | «Авто-разрез»: поперёк простирания устьев видимых наборов, через их центр |
| Окно | «От» (к наблюдателю) и «До» (от наблюдателя), по умолчанию 25 и 25 м; «Аз.» — азимут линии |
| Профили | `[` и `]` сдвигают линию ровно на «От» + «До» |

## Отображения по стволу
Данные любых таблиц набора вдоль стволов в 3D: содержания, литология, события.

**Открыть:** «Вид» › «По стволу» › «Содержания…», «Литология…», «События…» (нужен активный набор; пункт задаёт первое поле). Для Claude — `holes.show_data` (таблица и поле).

**Как работает**
- Изменения сразу видны на скважинах как черновик. В дерево (строкой под «Стволами» набора) отображение попадает только по «Сохранить».
- Сохранённые отображения: галочка — показать на скважинах, щелчок — показать или скрыть, двойной щелчок — настройки. Включённые встают рядом: колонки подряд от ствола, трубки одна в другой.
- Закрытие формы с несохранённым спрашивает подтверждение.
- Легенда в окне вида: слои и число интервалов в классах; щелчок по слою открывает его настройки.
- При удалении отображения (с подтверждением) стили библиотеки остаются.

| Зона формы | Что в ней |
|---|---|
| Шаблон | Весь набор слоёв как стиль из библиотеки: выбрать, связать 🔗, сохранить, сохранить как, применить к другим таблицам, экспорт, импорт, удалить |
| Слои | Поля любых таблиц набора; «+ Добавить» (поиск, несколько полей); порядок перетаскиванием; глаз; ⋯ — дублировать, стиль, применить к другим полям, удалить; «Разложить» — трубка на стволе, остальные по сторонам; несколько слоёв выбираются Shift/Ctrl и правятся вместе |
| Стиль слоя | Выбрать, связать, сохранить, сделать умолчанием для поля |
| Данные | Таблица и поле; скважины — все или выбранные; глубины «от — до» |
| Вид | Столбцы, ступени, линия, точки, трубка, лента, текст (у событий — значок); сторона слева / справа / обе; ширина и отступ; прозрачность, зазор, заливка; трубка постоянной толщины или по значению |
| Шкала | От — до (пусто — по данным), «мин — макс», «P2 — P98», «0 — P99»; логарифмическая; выше максимума — обрезать, с пометкой или как есть |
| Цвет | Один цвет; градации на гистограмме (границы мышью и стрелками; авто — квантили, равные, логарифмические и др.; число и доля проб в классе); непрерывная шкала и градиенты; цвет по другому полю; для текстовых полей — значения с поиском, глазом, порядком и цветом |
| Фильтр | Все / от борта / диапазон; пустые — пропуск или цветом; ноль и отрицательные; коды вроде −999 — как пустые |
| Подписи | Шаблон (`{AU} г/т`, `{from}`, `{to}`, `{len}`), знаки, только ≥ X, размер, цвет, не больше N (самые высокие) |
| Низ | «Сохранить», «Отменить изменения» (к сохранённому), `Ctrl+Z` / `Ctrl+Y` |

Пропуски не превращаются в ноль: пустое значение остаётся пустым и рисуется по настройке фильтра.

**Библиотека стилей проекта** (раскраска, стиль слоя, шаблон)
- Выбранный стиль копируется в слой. Со связью 🔗 правка стиля («Изменить стиль» в предупреждении над разделами) перестраивает все связанные отображения; «Только здесь» оставляет изменение в слое.
- «Где используется» — список отображений со стилем.
- Удаление используемого стиля оставляет слоям копию настроек: вид не меняется.
- Умолчание по полю: маска `AU` или `AU*` без учёта регистра; применяется само при добавлении такого поля (в том числе `AU_CUT` из другой таблицы); побеждает самая точная маска.
- Встроенные стили (только чтение): столбцы, градации, ступени, линия, трубка по шкале, лента по градациям, литология, события.
- Обмен: «Вид» › «По стволу» › «Экспорт стилей» / «Импорт стилей» — файл `.bfstyle.json` (до 1000 стилей и 4 МБ; файлы BedrockForge 1 читаются). При совпадении названий: «заменить», «оставить оба» (к имени добавляется «(2)»), «пропустить».

## Данные по скважинам
Каротажная диаграмма нескольких скважин рядом. «Вид» › «Просмотр» › «Данные по скважинам» или кнопка на панели 3D (`holes.data_window`); нужен активный набор. Только просмотр и экспорт, ничего не сохраняется. Для Claude — `chart.striplog` (текст CSV).

| Блок | Что делает |
|---|---|
| «Скважины» | До 30 рядом, поле «поиск»; 31-ю отметить нельзя; открытая из 3D выбранная скважина идёт первой |
| «Глубина» | «от, м», «до, м» (пусто — устье и забой); «Масштаб»: вписать, 1:2000, 1:1000, 1:500, 1:250, 1:125, 1:50; «общая шкала глубин» |
| «Таблица» | Таблица набора; её поля становятся колонками |
| «Колонки» | «Левее» / «Правее» / «Убрать»; «Вид»: столбцы, линия, цвет, текст, цвет + текст (у событий — значки); «Ширина»; шкала «от» / «до» (пусто — авто), «лог.»; «Раскраска»: один цвет, по градациям, непрерывная шкала, раскраска проекта; «границы интервалов»; поля других таблиц — «+ колонка…» |
| Экспорт | «PNG», «SVG», «CSV» через окно «Сохранить как» |

- Подсказка при наведении: скважина, глубины, значение; под колонками легенда категорий.
- SVG и PNG содержат фирменные шрифты; PNG — в двойном размере.
- CSV: строки `Скважина;От;До;<колонки…>`, на каждой скважине объединены границы всех колонок; пустое остаётся пустым; разделитель «;», кодировка UTF-8 с BOM.
- Не больше 20 000 строк на скважину и таблицу; при обрезке окно сообщает об этом.

## Аудит данных
«Анализ» › «Аудит данных» или «Запустить аудит» (`audit.run`) проверяет активный набор 27 правилами; идёт заданием в фоне. Результат — на вкладке «Аудит и статистика» нижней панели.

| Элемент | Что делает |
|---|---|
| «Таблица проб» | Какую таблицу проверять: по умолчанию «Пробы», иначе первая таблица проб; отчёт помнит, какая проверена |
| «Пороги» | Допуск глубины 0,01 м; изгиб 10° на 30 м; изоляция устья 10× медианного расстояния до ближайшего; скачок Z 50 м от медианы соседних; выброс 8 робастных σ от log10 значения; маркеры плановых: `project`, `planned`, `plan`, `проект`, `план` |
| «Отчёт Excel…» | Файл (`audit.export`) с листами «Сводка», «По правилам», «Находки» |

- Список правил показывает все 27, в том числе пройденные (✓), важность К / П / И (Критично, Предупреждение, Информация), число строк и скважин. Щелчок по правилу отбирает его находки.
- Находки можно отобрать по важности, таблице и скважине. У находки: скважина, правило, строки, до 20 примеров с русскими названиями полей.
- Новый запуск заменяет прежний результат. После импорта или правки результат помечается «устарел».
- Строка состояния: «Аудит: N критично, N предупр., N инф.» (при устаревшем — «(устарел)»); щелчок открывает вкладку.
- Карточка скважины в «Свойствах» перечисляет замечания по ней.

### Правила
Важность: К — критично, П — предупреждение, И — информация.

**Устья**

| Код | Важн. | Смысл |
|---|---|---|
| `COLLAR_MISSING_COORDS` | К | Не заданы координаты X/Y/Z |
| `COLLAR_INVALID_TD` | К | Глубина скважины не задана или не положительна |
| `COLLAR_ANGLE_RANGE` | К | Азимут или наклон вне допустимого диапазона |
| `COLLAR_ISOLATED` | П | Устье далеко от всех остальных |
| `COLLAR_Z_JUMP` | П | Отметка Z резко отличается от соседних устьев |
| `COLLAR_PLANNED_WITH_DATA` | П | Плановая скважина с данными |
| `COLLAR_EMPTY_STATUS` | И | Пустой статус устья |
| `COLLAR_WITHOUT_SURVEY` | П | Скважина без инклинометрии |
| `COLLAR_WITHOUT_ASSAY` | И | Скважина без проб |

**Инклинометрия**

| Код | Важн. | Смысл |
|---|---|---|
| `SURVEY_ORPHAN_HOLE` | К | Инклинометрия по скважине, которой нет в устьях |
| `SURVEY_EMPTY_VALUES` | П | Пустые значения глубины, азимута или наклона |
| `SURVEY_ANGLE_RANGE` | К | Азимут или наклон вне допустимого диапазона |
| `SURVEY_BEYOND_TD` | К | Замер глубже забоя |
| `SURVEY_DUPLICATE_DEPTH` | К | Повторяющаяся глубина замера |
| `SURVEY_NOT_ASCENDING` | П | Замеры идут не по возрастанию глубины |
| `SURVEY_FIRST_NOT_ZERO` | И | Первый замер не на устье |
| `SURVEY_DOGLEG` | П | Слишком резкий изгиб ствола |
| `SURVEY_COLLAR_MISMATCH` | П | Первый замер расходится с наклоном или азимутом устья |

**Пробы**

| Код | Важн. | Смысл |
|---|---|---|
| `ASSAY_ORPHAN_HOLE` | К | Пробы по скважине, которой нет в устьях |
| `ASSAY_INVALID_INTERVAL` | К | Некорректный интервал |
| `ASSAY_BEYOND_TD` | К | Интервал глубже забоя |
| `ASSAY_OVERLAP` | К | Перекрытие интервалов |
| `ASSAY_GAP` | П | Разрыв между интервалами |
| `ASSAY_DUPLICATE_SAMPLE` | К | Повторяющийся номер пробы |
| `ASSAY_NEGATIVE_VALUE` | К | Отрицательное содержание |
| `ASSAY_EMPTY_VALUE` | П | Пустое содержание компонента |
| `ASSAY_OUTLIER` | И | Экстремально высокое содержание |

Скорость (тестовый компьютер): 50 000 скважин и 5 млн проб — около 23 с вместе с чтением из проекта, 1,3 ГБ памяти.

## Линии, растры, ЦТМ
Линии и точки, растры и цифровые модели рельефа (ЦТМ) в проекте и в 3D.

### Импорт
«Главная» › «Импорт файлов» (или перетащить файлы на окно); отдельно — «Линии» и «Растры» в той же группе.

| Что | Форматы |
|---|---|
| Линии и точки | Micromine STR и `.PIT`, Surpac STR, DXF (линии, точки, текст, дуги и сплайны — ломаными), ESRI Shapefile, MapInfo MIF/MID, точки XYZ (CSV, TXT, DAT) |
| Растры | JPG, PNG, TIFF, BMP + world-файл; GeoTIFF; MapInfo TAB; Micromine GRF; вертикальные растры |

- Окно «Состав загрузки» до импорта показывает слои, линии, вершины, растры с привязкой и то, что не загрузится, с причиной. Нечитаемый файл пропускается, запись остаётся в «Журнале операции». Повтор имени — «имя (2)».
- Файлы привязки растра (world, TAB, GRF) подхватываются рядом с изображением.
- «Уровень растров по Z»: высота загружаемых растров и сдвиг; числа с запятой или точкой (`250,5`). Потом меняется в «Свойствах» растра.
- Слой линий — код стринга, номер Surpac, слой DXF, файл SHP или MIF; у MIF — до трёх слоёв «(линии)», «(точки)», «(текст)». Пустое значение остаётся пустым.
- Отмена импорта не оставляет объектов.

### Канавы по полилиниям
«Главная» › «Канавы» (или «+» у «Скважин» › «Импорт канав…»; первый шаг мастера скважин).

| Элемент | Назначение |
|---|---|
| Файл | STR, DXF или таблица вершин «канава, X, Y, Z» (CSV, TXT, DAT) |
| «Имя канавы» | Из стринга (слоя) или из «Поля с именем канавы»; несколько линий стринга — «имя-1», «имя-2» |
| «Обратить» | Меняет направление: устье — первая вершина |
| «Предпросмотр» | «Канава», «Вершин», «Длина по 3D, м», «Устье X / Y / Z» |

Длина и «от — до» проб считаются по 3D-длине вдоль полилинии; траектория проходит ровно через вершины. Пробы загружаются как в мастере скважин. «Заменить» инклинометрию станции канав не трогает.

### Дерево и «Свойства»
| Раздел дерева | Что внутри и что в «Свойствах» |
|---|---|
| «Линии» | Файл → слои, галочка у файла и у слоя (у файла > 200 слоёв общей галочки нет). Слой: цвет, длина, замкнутость, «Атрибуты слоя» по страницам |
| «Растры» | Высота (пусто — под самым низким объектом), «Сдвиг по Z» и «Сдвинуть» (плюс — вверх), «Вертикальный растр», «Непрозрачность растра», края X/Y и «Верх Z», «На текущий разрез» (в плоскость линии разреза), отклонения по опорным точкам |
| «Каркасы» | Видимость, цвет; «Перенести в ЦТМ» |
| «ЦТМ» | У строк нет кнопок: щелчок открывает «Настройки ЦТМ» вверху «Свойств»; в меню — «Настройки ЦТМ…» и «Вернуть в каркасы» |

«Настройки ЦТМ»: «Растр на рельефе» (вертикальные не предлагаются), «Скрыть данные за ЦТМ», «Цвет растра», «Непрозрачность растра», «Тени рельефа», «Вернуть в каркасы» (с подтверждением: настройки сбросятся, растр снимется). Растр, лежащий на ЦТМ, удалить нельзя — сообщение называет ЦТМ.

Объект переименовывается и удаляется из меню дерева или кнопками «Переименовать объект», «Цвет объекта», «Удалить объект» («Главная»); удаляется растр, каркас или ЦТМ, слой линий — только вместе с файлом.

### Построить ЦТМ
«Моделирование» › «Поверхности» › «Построить ЦТМ» (`model.dtm`) — заданием в фоне, ход и журнал на вкладке «Задания»; результат сразу в разделе «ЦТМ».

| Элемент | Назначение |
|---|---|
| Источники | Слои точек и линий, устья скважин; «Название ЦТМ» |
| Отрезки линий | Становятся рёбрами поверхности: бровки и подошвы не срезаются |
| «Слой границы», «Номер линии границы» | Замкнутая линия; высоты границы по умолчанию не берутся (контур часто на Z = 0); без точек внутри — отказ с подсказкой |
| «Наибольшая длина ребра, м» | Пусто — без ограничения |

«В ЦТМ» переносит выбранный каркас в раздел «ЦТМ». Изолинии, объём и обрезка — позже. Каркасы из файлов — в разделе «Каркасы».

### Экспорт
| Команда | Что делает |
|---|---|
| «Моделирование» › «Стринги» › «В STR», «В DXF» | Окно «Формат»: Micromine STR, Surpac STR, DXF, CSV («Запись CSV»: разделитель, десятичный знак), Micromine DAT; «Слои»; «Файл» |
| «Моделирование» › «Растры» › «Экспорт растра» | Исходный файл с привязкой (world-файл, `.prj`) или GeoTIFF |

Существующие файлы без подтверждения не перезаписываются. Слои точек в STR не пишутся (предупреждение). Команды экспорта не принимают путь: файл выбирает человек.

### В 3D
- Линии, точки и подписи текста (до 1000 подписей на часть); на дальнем плане линии упрощаются, помета «упрощено».
- Растры в плане и вертикальные (при разрезе — подложкой, скважины видны поверх); на ЦТМ — драпировка, одинаковая на любом уровне детализации.
- Щелчок по линии, точке, растру или поверхности выбирает объект (`object.select`), карточка — в «Свойствах»; `Esc` снимает выбор объекта и скважины (`selection.clear`). Линия под курсором выигрывает у растра.
- «Очистить окно» (`Ctrl+Shift+H`) скрывает и эти объекты.
- Пустая высота вершины рисуется на нижней высоте части.

### Ограничения
- SHP, MIF/MID и растры проверены на синтетических файлах; реальные образцы владельца ожидаются.
- Без imagecodecs 16-бит LZW читается с потерей до 8 бит; float LZW и JPEG — отказ. EXIF-поворот изображений не учитывается.
- MIF: Arc, Ellipse и Roundrect пропускаются с предупреждением; пользовательские датумы (МСК) — без системы координат.
- Растр больше 400 Мпикс — отказ; не JPEG — до 2,2 ГБ памяти.
- Писателей SHP и MIF нет; сдвига по Z у слоёв линий нет; выбрать отдельные слои при импорте нельзя.
- Редактор линий и версии слоя — в разделе «Редактор стрингов» ниже. Каркасы, DWG и Datamine — в разделе «Каркасы».

## Каркасы
Объёмные и поверхностные каркасы из файлов: загрузка, проверка, показ в 3D, точный выбор, сечения, пересечения со стволами, экспорт.

### Импорт
«Главная» › «Импорт файлов» (или перетащить файлы на окно); отдельно — «Каркасы» в той же группе.

| Формат | Что читается |
|---|---|
| Micromine TRIDB | Все каркасы файла: имена, цвета, атрибуты |
| DXF | Сетки (polyface, mesh, `3DFACE`, `MESH`) — каркасом на слой; линии и точки того же файла грузятся вместе с ними |
| DWG | Через ODA File Converter («Настройка › Внешние программы»); без него — подсказка с кнопкой «Настройка › Внешние программы…» и «Прочитать снова» |
| OBJ | Каркас на `o`/`g`; цвет — из комментария `# color` |
| STL | Двоичный и текстовый; координаты float32 — помечено в «Свойствах» |
| Surpac DTM + STR | Каркас из `.dtm`; одноимённый `.str` рядом подхватывается как спутник |
| Datamine | Пары «треугольники + точки» (`tr` + `pt`), каркасы и стринги; пара ищется по имени, иначе по содержимому |

- Каждый каркас — отдельный объект в разделе «Каркасы»; повтор имени — «имя (2)».
- Окно «Состав загрузки» показывает таблицу «Каркас / Треугольников / Вершин / Атрибуты»; что не загрузится — с причиной и подсказкой. Битый каркас пропускается, остальные грузятся, запись остаётся в «Журнале операции».
- Datamine: «Делить на каркасы по полю» (пусто — «не делить: один каркас») и «Слои по полю» (пусто — «один слой»). Формат помечен «Предварительно»: он прочитан по описанию и проверен на синтетических файлах — сверьте число треугольников, положение и объём с исходной программой.
- После импорта каркасы автоматически проверяются заданием в фоне; ход — на вкладке «Задания».
- Отмена импорта не оставляет объектов.

### «Свойства» каркаса
| Блок | Что показывает |
|---|---|
| Цвет, «показан в 3D» | Цвет поверхности («Без цвета» — умолчание), видимость |
| Общее | «Площадь», «Площадь в плане», «Объём» (только у замкнутого; иначе «нет: каркас не замкнут»), «Замкнутость», «Открытых рёбер», «Неманифолдных рёбер», «Вырожденных треугольников» |
| «Проверки» | «Нормали», «Самопересечения», «Проверено»; кнопка «Проверить» запускает проверку заново (идёт заданием, пока она работает, кнопка ждёт) |
| «Источник» | «Файл», «Формат», «Имя в файле», «Слой», «Точность» |
| «Треугольник по клику» | Точка, «Угол падения», «Азимут падения», «Площадь треугольника», «Треугольник №» |
| «Атрибуты» | Свои атрибуты: «Добавить», изменить, переименовать, удалить |

«Самопересечения» показываются красным в 3D-окне; число пар — в «Проверках». Проверка также доступна из ленты («Моделирование» › «Правка каркасов» › «Проверить», «Самопересечения»). «Перенести в ЦТМ» — как раньше.

### В 3D
- Точный выбор: щелчок по каркасу находит треугольник по настоящей геометрии (не по упрощённой копии показа); «Свойства» показывают азимут и угол падения. Пока точный треугольник уточняется, там написано «точка — по копии для показа».
- Разрез с «Отсечением» рисует линии сечения каркаса плоскостью разреза.
- Метки пересечений стволов с каркасами: в «Устья и стволы: стили» › «Пересечения» — «отмечать точки пересечения», «с каркасами», «только с видимыми объектами». Галочка «с ЦТМ» по умолчанию выключена: рельеф, построенный через устья, дал бы метку «0,000 м» у каждой скважины.
- «Очистить окно» скрывает и каркасы.

### Экспорт каркасов
«Моделирование» › «Экспорт каркасов» («В TRIDB», «В DXF», «В DWG», «В OBJ», «В STL», «В Surpac DTM») или «Экспорт каркасов…» в меню раздела «Каркасы» (у ЦТМ — «Экспорт ЦТМ…»). Все кнопки открывают окно «Экспорт каркасов» с выбранным форматом.

| Элемент | Назначение |
|---|---|
| «Формат» | Micromine TRIDB, DXF, DWG, OBJ, STL, Surpac DTM (`.dtm` + `.str`) |
| «Версия DWG» | AutoCAD-версия файла (только для DWG; нужен ODA File Converter) |
| «Запись STL» | «двоичный (float32, файл меньше)» — с предупреждением о потере точности координат; «текстовый (координаты без потерь)» |
| «Каркасы» | Галочки по разделам и папкам дерева, итог «треугольников и каркасов» |
| «Файл» | «Сохранить как…» |

Экспорт идёт заданием: ход и журнал — на вкладке «Задания». Если файл уже существует, окно спросит о замене («Отмена» оставляет окно открытым). DXF пишется всегда в формате R2004; DWG без конвертера — отказ с кнопкой «Внешние программы…».

### Настройка › Внешние программы
«Главная» › «Настройка» › «Внешние программы»: путь к `ODAFileConverter.exe` (или к его папке).

| Кнопка | Что делает |
|---|---|
| «Выбрать…» | Диалог выбора файла (только в приложении) |
| «Найти» | Поиск в стандартных местах: переменная `BF_ODA_CONVERTER`, `PATH`, `Program Files\ODA` |
| «Проверить» | Проверяет введённый путь и запоминает его; программа при этом не запускается, версия — из имени папки |
| «Очистить» | Убирает путь, поиск — в стандартных местах |

BedrockForge не распространяет ODA File Converter (установите его отдельно, подсказка — в окне); он запускается только для преобразования DWG в DXF и обратно.

### Ограничения
- Datamine: проверено на синтетических файлах («предварительно»); писателя Datamine нет. Surpac DTM — по описанию формата; Vulcan и двоичный Surpac — позже.
- DWG на Windows — только через ODA File Converter; файл с кириллицей в имени пользователя и повреждённый чертёж проверяются вручную (см. CHECKLIST).
- Очень много мелких каркасов грузятся медленнее (около 6 мс на каркас: 3000 каркасов в DXF — около 19 с).
- Показ крупных карьеров с рельефом упрощается сильнее (отклонение до 2–5 м на дальних уровнях детализации); точный выбор и сечения работают по полной геометрии.
- Порядок треугольников после импорта не сохраняется, DXF при повторном экспорте совпадает по составу (не по рамке файла с датой).
- Изолинии, объём, обрезка, исправление, упрощение и булевы операции — в разделе «Операции с линиями и каркасами».

## Облака точек и фильтр земли
Облако точек (лидар, съёмка с дрона) → классы «земля / растительность / шум» → ЦТМ из земли. Рассчитано на 10–50 млн точек; облако хранится как слой раздела «Линии» (значок облака).

### Загрузка
«Главная» › «Загрузка» › «Облако точек» (`points.import`) — окно «Импорт файлов» в режиме облака; файл `.las` из «Импорта файлов» тоже грузится облаком.

| Формат | Что читается |
|---|---|
| LAS 1.2–1.4 | Форматы точек 0–10; координаты с масштабом и смещением (float64); класс ASPRS, номер возврата и число возвратов; система координат из файла — как метка, без пересчёта |
| XYZ, CSV, TXT | Колонки «Колонка X», «Колонка Y», «Колонка Z», «Колонка класса» (необязательно); разделитель и десятичный знак определяются по началу файла; остальные колонки не грузятся (предупреждение); строка без Z пропускается и считается |

- «Каждая k-я запись» — прореживание при загрузке (пусто или 1 — все точки); для файла больше 50 млн записей окно предлагает значение с кнопкой «Применить». Карточка файла показывает версию, формат точек, число записей, охват, масштаб, систему координат и классы по выборке.
- LAZ не поддерживается: окно отвечает «Сжатые облака LAZ не читаются» и подсказывает сохранить как LAS (CloudCompare: «Сохранить как» › LAS; LAStools: `laszip -i облако.laz -o облако.las`).
- Цвета RGB, интенсивность и время GPS не загружаются (в карточке они в списке «не загружается»); при экспорте LAS «по исходному файлу» они сохраняются.
- Облако больше 2 млн точек через обычный «Импорт файлов» (слой точек) — предупреждение «загрузите как облако».

### В 3D и «Свойства» облака
Точки по 2 px; при отдалении облако редеет, помета «упрощено». Щелчок по точке — «Точка № …» в «Свойствах»: X, Y, Z, «Класс: 2 — земля», «Возврат», «Высота над землёй», «Отклонение от ЦТМ».

| Элемент «Свойств» | Что делает |
|---|---|
| «Цвет точек» › «Режим» | «Класс»; «Цвет слоя»; «Высота над землёй (h)» — после «Фильтра земли»; «Отклонение от ЦТМ (dz)» — разность Z точки и ЦТМ, после «Карты разностей» или «Построить ЦТМ из облака» |
| «Классы» | Таблица «Класс / Точек» с цветом и галочкой видимости; «Показать все», «Скрыть все». Видимость действует в режимах «Класс» и «Цвет слоя»; скрытые точки не рисуются и не выбираются |
| «Земля и ЦТМ» | Параметры последнего фильтра; кнопки «Фильтр земли…», «Построить ЦТМ из облака…», «Карта разностей…»; сводка карты разностей: с какой поверхностью сравнивали, когда, СКО, P95, наибольшее отклонение и число точек вне поверхности |
| «Точки облака» | Таблица X, Y, Z и поля по страницам |

Названия классов — по ASPRS: 0 «создана, не классифицирована», 1 «не классифицирована», 2 «земля», 3–5 «низкая / средняя / высокая растительность», 6 «здание», 7 «низкая точка (шум)», 9 «вода», 10 «железная дорога», 11 «дорожное покрытие», 17 «настил моста», 18 «высокий шум»; 19–63 «резерв ASPRS», 64–255 «пользовательский».

### Фильтр земли
«Моделирование» › «Поверхности» › «Фильтр земли» (`ground.classify`; также меню облака в дереве и кнопка в «Свойствах»). Идёт заданием, ход и журнал — на вкладке «Задания».

Принцип: облако мысленно переворачивают и опускают на него «ткань» с шагом CR; ткань не гнётся и ложится на самые нижние точки. Точка ближе к ткани, чем CT, — земля.

| Параметр | Простыми словами | Диапазон (умолчание) |
|---|---|---|
| «Шаг ткани CR, м» | Размер ячейки поверхности земли: меньше — подробнее рельеф и дольше расчёт | 0,1–50 (1) |
| «Жёсткость ткани RI» | Насколько ткань «перекрывает» пропуски в данных: 3 — жёсткая (равнина), 1 — мягкая (крутые склоны) | 1–3 (2) |
| «Порог земли CT, м» | Точка не выше поверхности земли более чем на CT (по нормали к ней) — земля | 0,05–5 (0,5) |
| «Искать землю у вертикальных граней», «Радиус R_б, м» | Уступ с вертикальной или нависающей стенкой: точки стенки — земля, если выше и ниже неё в пределах R_б (в плане) есть земля; стена здания такого не имеет | 1–20 (5) |
| «Искать шум (класс 7)», «Радиус шума, м», «Соседей не меньше» | Точка, у которой в радиусе меньше заданного числа соседей, — шум и дальше не участвует | 0,5–20 (2); 1–20 (3) |

| Профиль | Для чего |
|---|---|
| «Карьер» (по умолчанию) | Уступы, бермы, откосы, бровки: ткань мягче, рост по склону до 55°, грани включены |
| «Равнина» | Пологий рельеф: жёсткая ткань, рост по склону до 30°, грани не ищутся |
| «Свой» | Числа профиля («На основе профиля») можно менять; поля вводятся с запятой или точкой |

Результат: классы облака заменяются — 2 «земля», 3–5 растительность и постройки по высоте над землёй (пороги 0,5 и 2 м), 1 «не классифицирована», 7 «шум»; здания отдельно не выделяются (класс 6 не ставится). Появляется режим цвета «Высота над землёй». Журнал задания: профиль, CR, RI, CT, R_б, шум, число точек по классам до и после, время. Повторный фильтр заменяет классы заново; прежних классов из файла вернуть нельзя (кроме повторной загрузки). Команда спрашивает подтверждение.

### Построить ЦТМ из облака
«Моделирование» › «Поверхности» › «Построить ЦТМ из облака» (`terrain.from_points`) — окно «Построение ЦТМ» с блоком «Источники: облака точек»; облако можно сочетать с другими источниками.

| Элемент | Назначение |
|---|---|
| Галочка облака, «Классы» | Какие классы брать; по умолчанию 2 «земля». Нет точек земли — подсказка и кнопка «Фильтр земли…» |
| «Шаг прореживания, м» | В ячейке остаётся одна точка — с нижней медианой высоты над землёй; пусто — шаг подбирается так, чтобы вершин было не больше 2 млн (шаг пишется в журнал) |
| «Слой границы» | Замкнутая линия, как у обычного «Построить ЦТМ» |
| «Наибольшая длина ребра, м» | Пусто — 5 шагов ткани последнего фильтра (иначе 5 м) |
| «Карта разностей для облаков» | Включено по умолчанию: облака-источники сразу получают отклонение от построенной ЦТМ (см. «Карта разностей») |

Вершины ЦТМ — исходные точки облака без изменения координат.

### Карта разностей
Насколько точки облака отстоят от поверхности: dz = Z точки − высота ЦТМ или каркаса под ней (над ней). Считается сама после «Построить ЦТМ из облака» (галочка «Карта разностей для облаков») или по команде «Моделирование» › «Поверхности» › «Карта разностей» (`cloud.dz`; также «Карта разностей…» в меню облака в дереве и в «Свойствах» облака, блок «Земля и ЦТМ»).

| Элемент окна «Карта разностей» | Назначение |
|---|---|
| «Облако точек» | Выбранное облако или единственное в проекте |
| «Поверхность» | Любая ЦТМ или каркас проекта; по умолчанию — та, с которой сравнивали в прошлый раз, иначе последняя ЦТМ, построенная из этого облака |
| «Рассчитать» | Задание «Карта разностей» (ход — на вкладке «Задания»); окно показывает «Итог»: СКО, P95, наибольшее по модулю, по каким точкам мерено, «Точек с отклонением», «Вне поверхности» |

- Меры считаются по точкам земли (класс 2); если земли под поверхностью нет — по всем точкам. У точки вне поверхности в плане отклонения нет (пусто, не ноль); такие точки считаются отдельно.
- После расчёта у облака появляется режим цвета «Отклонение от ЦТМ (dz)» (шкала ±2,5 м), в «Свойствах» точки — «Отклонение от ЦТМ», в таблице точек — столбец «Отклонение от ЦТМ, м». Новый расчёт заменяет прежние отклонения.
- Отказы: «Под точками облака … нет поверхности» — поверхность лежит в стороне от облака; «Облако точек изменилось, пока шёл расчёт» — облако отфильтровали заново (повторите команду); каркас удалён — обновите дерево. Удалённая поверхность остаётся в сводке с пометкой «(удалена)».

### Экспорт облака
Щёлкните облако в дереве правой кнопкой → «Экспорт…» (или «Экспорт линий» с отмеченным облаком): откроется окно «Экспорт линий» с форматом LAS. Для облака доступны только «LAS» и «CSV (X;Y;Z;класс;h)»; остальные форматы скрыты, а LAS для обычных слоёв недоступен. Облако экспортируется одно: если вместе с ним отмечены другие слои, окно сразу скажет «Облако точек экспортируется отдельным файлом…», и кнопка «Экспортировать» будет недоступна.

Для LAS выберите «Запись LAS»: «По исходному файлу (меняются только классы)» — по умолчанию для облака из LAS; для облака из таблицы XYZ этот вариант недоступен (подсказка объясняет почему), и пишется «Новый файл». Для CSV можно выбрать разделитель столбцов и десятичный знак. Экспорт идёт как задание, ход и журнал — на вкладке «Задания».

| Формат | Что в файле |
|---|---|
| LAS «по исходному файлу» (для облака из LAS) | Копия исходного файла, в записях меняются только классы: цвет, время GPS, система координат — как были |
| LAS «новый файл» | LAS 1.2 формат 0 (при кодах класса больше 31 — 1.4 формат 6); масштаб и смещение исходника, если облако из LAS; координаты без потерь |
| CSV | X; Y; Z; класс (и h после фильтра), порядок хранения |

Существующий файл без подтверждения не перезаписывается.

### Ограничения
- Проверено на синтетических облаках (равнина со зданиями и деревьями, воронка с бортом 50°, уступы со стенками 15 м); реальное облако карьера ждём от владельца. Числа профилей предварительные.
- Останец круче угла профиля вне края съёмки (узкий отвал, скала) может остаться растительностью; профиль «Карьер» поднимается по откосу до 55°.
- Растительность над бортом, под которой нет ни одной точки земли, может быть принята за землю в пределах CT.
- Облако в градусах: фильтр считает в метрах — предупреждение при загрузке.
- Больше 200 млн точек после прореживания — отказ («каждая k-я запись»). Точки с NaN и значениями больше 1e9 по модулю пропускаются и считаются.
- Облако не редактируется: отмены фильтра нет, только повторный фильтр или загрузка; ручной правки классов, обрезки по контуру, LAZ, E57, PLY нет.
- Диск: на 50 млн точек около 1,5 ГБ данных плюс исходный LAS; расход памяти — 10 млн: фильтр около 0,7 ГБ, ЦТМ около 1,1 ГБ.

## Редактор стрингов
Оцифровка и правка линий и полигонов в 3D-окне с версиями слоя. Лента «Моделирование» › группа «Стринги»; те же команды — в `Ctrl+K`. Правка идёт над рабочей копией в окне, в проект она попадает только по «Сохранить».

### Начало работы
| Что | Как |
|---|---|
| Новый слой | «Моделирование» › «Стринги» › «Новый слой» или «Новый слой…» в меню раздела «Линии» (`lines.new_layer`): пустой слой в новом файле линий и сразу правка; название — код стринга в STR; занято — «имя (2)» |
| Правка готового слоя | «Редактировать» (`lines.edit`) для выбранного слоя; открытая правка другого слоя сначала завершается (с вопросом о несохранённом) |
| Сохранить | «Сохранить» (`Ctrl+S`, с подтверждением): новая версия слоя |
| Выйти | «Завершить» (в панели — «Завершить правку»); при несохранённом — окно «Завершить правку»: «Сохранить», «Не сохранять», «Отмена» |

Панель «Редактор стрингов» над 3D-окном: у каждой кнопки подсказка — название, действие, клавиши и, если кнопка недоступна, причина. Сохранённый слой на время правки скрыт, слой правки рисуется поверх.

### Инструменты (`lines.tool`)
| Инструмент | Клавиша | Что делает |
|---|---|---|
| «Выбор и перемещение» | `V` | Щелчок — выбрать, тянуть — переместить вершину или линию; `Ctrl` + тянуть — рамка; `Shift` — добавить к выбору; двойной щелчок по отрезку — вставить вершину |
| «Линия» | `L` (при активной серии разрезов — `Shift+L`: `L` там фиксирует вид) | Щелчок — точка; щелчок по концу готовой линии продолжает её |
| «Полигон» | `P` | Щелчок — вершина; при завершении полигон замыкается |
| «Точка» | `T` | Щелчок — отдельная точка |
| «Тай-линия» | `Y` | Две точки на вершинах контуров соседних разрезов; линия получает метку `ROLE = TIE` и служит связью для сшивки контуров |
| «Вставить вершину» | `I` | Щелчок по отрезку — новая вершина на нём |

Куда ложится точка: в плане — на уровень `Z` из панели (запятая и точка равноправны); при разрезе с отсечением — в вертикальную плоскость середины окна разреза; при привязке — в точку цели (или в её проекцию на плоскость разреза).

| Клавиша | Действие |
|---|---|
| `Enter`, двойной щелчок, правая кнопка (щелчок без перетаскивания) | Закончить линию; полигон замыкается |
| `Backspace` | Убрать последнюю точку |
| `Esc` | Снять выбор |
| `Delete` | Удалить выбранные вершины или линии |
| `Ctrl+Z`, `Ctrl+Y` (или `Ctrl+Shift+Z`) | «Отменить», «Повторить» (до 200 шагов и 256 МБ заменённых линий) |
| `Ctrl+S` | «Сохранить» |

Клавиши действуют при фокусе 3D-окна в режиме правки и не срабатывают в полях ввода.

### Ввод координат
Поле «Координаты точки» в панели (`Enter` — поставить точку или перенести выбранную вершину, `Esc` — выйти из поля):

| Запись | Смысл |
|---|---|
| `X Y Z` | Абсолютные координаты проекта; `X Y` — высота с панели |
| `@азимут расстояние [наклон]` | От предыдущей точки; азимут — от севера по часовой стрелке, наклон — от горизонта, вверх — плюс. `@90 100` от (0, 0, 0) даёт (100, 0, 0) |
| `@@dX dY [dZ]` | Приращения от предыдущей точки |

Для ассистента — команда `lines.add_line {points, closed}` (без правки — отказ с подсказкой «Новый слой» или «Редактировать»).

### Привязка
Кнопка «Привязка» включает и выключает её; «Цели привязки» (кнопка рядом) — что ловить. Каждое изменение — команда `lines.snap`.

| Цель | Что ловит |
|---|---|
| «вершина», «середина», «на линии» | Вершины, середины и ближайшая точка сегментов рабочей копии и других видимых слоёв линий |
| «вершина каркаса», «ребро каркаса» | Вершина и ребро треугольника под курсором (точный выбор по настоящей геометрии) |
| «сечение каркаса» | Линия сечения каркаса на разрезе |
| «устье», «траектория», «граница интервала» | Устья, стволы и границы интервалов скважин (рассчитывает ядро) |
| «узел сетки» | Узел сетки с шагом «Шаг сетки, м» |

Остальное в панели целей: «Радиус, px» (2–60) и «проецировать в плоскость разреза» — на разрезе точки скважин и каркасов ложатся в плоскость разреза; привязка к устью на разрезе даёт точку в этой плоскости. Слои больше 500 тыс. вершин и облака точек в привязке не участвуют — панель целей пишет об этом.

### Правка линий (`lines.modify`)
Кнопки группы «Правка линий»; действия с числами открывают окно «Правка выбранного» (числа с запятой и точкой; «Применить», «Отмена»). Выбирайте линии инструментом «Выбор» (`Shift` — добавить).

| Кнопка | Что делает | Поля окна |
|---|---|---|
| «Закончить линию» | Закончить рисуемую линию (`Enter`) | — |
| «Замкнуть» / «Разомкнуть» | Линия ↔ полигон | — |
| «Разорвать» | Разорвать линию в выбранной вершине | — |
| «Соединить» | Соединить две выбранные линии ближайшими концами | — |
| «Развернуть» | Обратить направление | — |
| «Сдвинуть…» | Сдвинуть на вектор, в том числе по Z | «ΔX, м», «ΔY, м», «ΔZ, м» |
| «Копия на вектор…» | Копия, сдвинутая на вектор | «ΔX, м», «ΔY, м», «ΔZ, м» |
| «Копия со смещением…» | Параллельная копия; у полигона больше нуля — наружу, меньше — внутрь | «Смещение, м» |
| «Проредить…» | Убрать вершины ближе допуска к линии (Дуглас–Пекер) | «Допуск, м» (больше 0) |
| «Сгустить…» | Отрезки не длиннее шага | «Шаг, м» (больше 0) |
| «Сгладить…» | Срезание углов | «Проходов» (1–10) |
| «Удалить» | Удалить выбранные вершины или линии (`Delete`) | — |

Вершина без высоты остаётся без высоты: в 3D-длину и площадь она не входит, нулём не становится. Действие, не изменившее слой, истории не добавляет.

### Измерения
«Измерить» (`lines.measure`) и строка под панелью: вершины, длина 3D и в плане, периметр, площадь полигона в его плоскости и в плане — для выбранного и для всего слоя, с несохранёнными правками. Площадь квадрата 10 × 10 в плане — 100.

### Версии
Каждое «Сохранить» — новая версия слоя; ничего не стирается. «Версии…» (`lines.versions`) открывает окно «Версии»:

| Колонка | Что показывает |
|---|---|
| «Версия», «Когда», «Кто», «Действие» | Номер, время, автор и действие (импорт, создание, сохранение, возврат, перенос, операция) |
| «Линии», «Вершины» | «было → стало» |
| «Заметка» | Заметка к версии |
| «Вернуть» | Создаёт версию N + 1 с геометрией выбранной (с подтверждением, `lines.restore`); текущая помечена «текущая» |

Если слой сохранён кем-то после начала вашей правки, «Сохранить» ничего не записывает и открывает окно «Слой изменён»: «Слой «имя» сохранён после начала правки (версия N, кто, когда). Ничего не записано.» Кнопки: «Сохранить как новый слой» (правка пишется отдельным слоем «имя (правка)» в том же файле), «Перечитать слой» (несохранённые правки пропадут), «Отмена». Смена цвета или названия слоя сохранение не блокирует.

«Перенести в другой слой…» (`lines.move_selected`, с подтверждением): окно «Перенести в другой слой» — поле «Найти слой», список слоёв, «Перенести». Выбранные линии уходят в выбранный слой, оба слоя получают новую версию; новые несохранённые линии сначала сохраните.

### Ограничения
- Правится слой до 1 млн вершин. Облака точек не правятся (отказ «not_editable»). В проекте «только чтение» сохранение недоступно.
- Автоматической очистки журнала версий нет: каждая версия хранит полную копию геометрии слоя; размер журнала растёт.
- Привязка не берёт слои больше 500 тыс. вершин и облака точек.

## Операции с линиями и каркасами
Построение и правка тел и поверхностей из линий и каркасов. Лента «Моделирование»: группы «Каркас из контуров», «Правка каркасов», «Операции», «Поверхности»; те же команды — `model.*`, `Ctrl+K` и ассистент (`model.operation`, с подтверждением).

### Общие правила
- Операция идёт заданием (`geometry.operation`) с ходом и отменой на вкладке «Задания»; результат — новый объект в папке первого исходного, исходные не меняются. Занятое имя — «имя (2)».
- Входы до 2 млн треугольников идут в быструю очередь, больше — в общую; долгий импорт не задерживает быструю операцию. Отмена и сбой не оставляют ни объектов, ни временных файлов.
- Предусловия проверяются до запуска, окно показывает исходные, число треугольников на входе и очередь. Пример отказа: «Каркас «Тело 2» не замкнут: открытых рёбер — 14.» с подсказкой и кнопкой «Исправить каркас».
- После операции каркасы результата проверяются автоматически (`wireframe.check`); отчёт открывается окном «Отчёт операции».

### Окно операции
Одно окно на операцию; «Обрезать» — одно окно трёх операций (переключатель «Операция»). Поля ставит ядро (список операций — `GET /operations`).

| Элемент | Назначение |
|---|---|
| Поля параметров | По таблице ниже; поля, зависящие от других, появляются по месту |
| «Название результата» | Пусто — имя по операции и исходным |
| Строка проверки | «Исходные: …», число треугольников, очередь; или причина отказа |
| «Выполнить», «Отмена» | Запуск через `model.operation` / закрыть |
| После запуска | Состояние и ход задания, «Отменить», «К параметрам» (при ошибке или отмене), «Отчёт», «Закрыть» |

### Операции

| «Править треугольники» | каркас; «Удалить треугольники», «Добавить треугольники (по три вершины)» | Новый каркас (панель режима правки, см. ниже) |

| «Обрезать полигоном» | «Полигон в плане», «Оставить» (внутри, снаружи, обе части) | Новые каркасы |

Правила: булева работает только с замкнутыми телами (замкнутость видна в «Свойствах»; для незамкнутого — «Исправить каркас»). «Самопересечения» только отмечаются красным, не исправляются. Вершины исходных контуров попадают в результат сшивки без изменений.

### Сшивка контуров
- Контуры группируются в разрезы по положению вдоль общей нормали; соседние разрезы связываются лентой по кратчайшему пути между вершинами (алгоритм Фукса–Кедема–Юзелтона, перенесён из BedrockForge 1): разное число вершин не мешает, лента без перекрута.
- Тай-линия закрепляет пару вершин: линия из двух вершин с атрибутом `ROLE = TIE` (инструмент «Тай-линия») либо линия без метки, концы которой стоят на вершинах контуров (до 1 мм). Каждая тай-линия становится ребром результата.
- Разветвление: один контур на разрезе против нескольких на соседнем; родительский контур режется одной прямой хордой.
- Торцы: «Плоская крышка», «В точку», «В линию (гребень)», «Продолжение контура», «Открыто».
- Два контура 10 × 10 через 10 м с плоскими торцами дают замкнутое тело объёмом 1000.

### «Собрать из контуров»
«Моделирование» › «Каркас из контуров» › «Собрать из контуров» (`model.assemble`): как связывание стрингов в Micromine. Откройте слой в редакторе и щёлкайте замкнутые контуры по порядку — каркас растёт в окне; повторный щелчок по контуру убирает его. Контуры берутся из рабочей копии, сохранять слой заранее не нужно.

| Элемент панели «Сборка каркаса» | Назначение |
|---|---|
| «контуров N · тай-линий M» | Сколько выбрано; тай-линии считаются только с концами на вершинах выбранных контуров |
| «Убрать последний контур» | Каркас становится на контур короче |
| «Замкнуть торцы» | Плоские крышки по первому и последнему контуру — замкнутое тело с объёмом; повторное нажатие открывает торцы |
| «треугольников N · объём V м³» | Предпросмотр; при ошибке — причина («Каркас строится…», «Щёлкните следующий контур») |
| «Создать каркас» | Недоступна при меньше чем двух контурах или ошибке; сохраняет слой (если изменён) и строит объект операцией «Сшить контуры» в фоне |
| «Отмена» (`Esc`) | Выход; контуры не меняются |

- Тай-линии ставит инструмент «Тай-линия» (`Y`); затем вернитесь к «Выбору» (`V`).
- Предпросмотр ограничен 500 контурами и 50 тыс. вершин; больше — создайте каркас операцией «Сшить контуры».

### «Править треугольники»
«Моделирование» › «Каркас из контуров» › «Треугольники» (`model.triangles`): панель «Треугольники: <имя каркаса>» над 3D-окном. Результат — новый каркас, исходный не меняется.

| Элемент | Назначение |
|---|---|
| «Отметить к удалению» | Щелчок по треугольнику (точный выбор) отмечает его; повторный щелчок снимает отметку |
| «Добавить по трём вершинам» | Три щелчка; щелчок берёт ближайшую к нему вершину треугольника под курсором. Щелчок в пустое отверстие — отказ с подсказкой |
| «Убрать последнее» (правый щелчок — то же) | Выбранная вершина, новый треугольник или отметка |
| «к удалению N · новых M · вершин K из 3» | Счётчики |
| «Применить» | Недоступна, пока нет правок; операция «Править треугольники» строит новый каркас в фоне |
| «Отмена» | Выход, каркас не меняется |

Панель не открывается, пока открыт редактор стрингов: оба занимают инструмент 3D-окна.

### Отчёт и «Свойства» результата
Окно «Отчёт операции»: «Создано» (каркасы с объёмом, слои), таблица «Показатель / Было / Стало» (исправление, упрощение, сглаживание: объём, треугольники, проверки), числа операции (изменение объёма, отклонение, выемка и насыпь), шаги и предупреждения; «Скопировать» кладёт отчёт в буфер.

В «Свойствах» результата — блок «Операция»: операция и время, «Исходные объекты» (удалённый исходный остаётся по имени), «Параметры», «Допуски», кнопки «Перестроить» и «Отчёт». Связь с исходными — по номерам: удалить контуры после построения тела можно.

### Перестроить (`model.rebuild`)
Повторяет операцию на текущих исходных с теми же параметрами и тай-линиями (контуры берутся по устойчивому номеру линии: вставки и удаления линий их не сбивают); результат — новый объект с пометкой «Перестроено: прежний объект №N не изменён». Исходный удалён или линии нет — отказ с именем. ЦТМ перестраивается заданием «Построить ЦТМ» с прежними параметрами. Команда спрашивает подтверждение.

### Ограничения
- Самопересечения не исправляются автоматически.
- Разветвление режет контур одной прямой хордой; неразделимые ветви — отказ с номерами разрезов (помогают тай-линии или промежуточный контур). Контур не должен быть повёрнут больше чем на 60° от плоскости разрезов.
- Полигон обрезки и «Полигон в плане» — один простой замкнутый контур без отверстий.
- Оболочки (shell) нет.
- Булева: отмены внутри одной булевой нет — только между этапами; незамкнутый каркас — отказ с числом открытых рёбер.
- Поверхность, не перекрывающая тело, — отказ при обрезке поверхностью; крутой разлом — подсказка выбрать «По нормали поверхности».
- Номера линий в параметрах окна — с 1; «Перестроить» ЦТМ читает границу по позиции в слое, после правки слоя она может не совпасть.

### Ориентир по скорости
Тестовый компьютер; у вас время зависит от процессора и памяти.

| «Исправить каркас», 1 млн треугольников | около 4 с |
| «Сшить контуры», 500 разрезов × 500 вершин | около 3 с |
| Предпросмотр «Собрать из контуров» | около 50 мс |
| «Объём», 2 поверхности × 1 млн треугольников | около 7 с |

## Серии разрезов
Серия — набор параллельных разрезов с одним шагом: по ним оцифровывают контуры и строят тело («Каркас по серии»). Вкладка ленты «Разрезы»; раздел «Серии разрезов» в дереве; те же команды `series.*` — в `Ctrl+K` и у ассистента (создание, копия, удаление, переименование — с подтверждением). Серия хранится в проекте и переносится в `.bfggis`; текущий разрез — в виде проекта (`]` серию не меняет).

### Типы и параметры
Окно «Новая серия» (`series.new`): параметры подставляются по линии разреза и видимым данным; «По видимым данным» ставит пределы кратно шагу.

| Тип | Что задать | Замечание |
|---|---|---|
| «Вертикальная» | «X P1», «Y P1», «P1 → P2» или «P1 и азимут» («Азимут A, °»), «Начало s0, м», «Конец s1, м», «Шаг Δ, м» | Разрезы сдвигаются поперёк линии |
| «План» | «Верхняя отметка, м», «Нижняя отметка, м», шаг по Z | Горизонтальные срезы сверху вниз |
| «Наклонная» | то же и «Наклон φ, °» (0–90) | Пока серия активна, преувеличение ×1: кнопки ×2…×5 недоступны с причиной |
| «Ломаная» | «Вершины ломаной» («X; Y» по строке, до 1 000), «Ширина коридора, м» (25) | Одна развёртка: серия из одного разреза; в 3D — текущий сегмент, `]` / `[` переключают сегменты |

| Поле | Правило |
|---|---|
| «Окно «к себе», м» и «Окно «от себя», м» | 0,01–10 000 (по умолчанию 25 и 25); окно полуоткрытое: точка ровно на грани уходит в следующий разрез. При Δ = сумме окон окна соседних разрезов смыкаются |
| «Шаг Δ, м» | 0,01–10 000; разрезов не больше 5 000; серий в проекте — до 1 000 |
| «Шаблон имён» | Только `{k}` (с 1), `{s}`, `{X}`, `{Y}`, `{Z}` и формат числа; пусто — по азимуту: `{Y:.0f}N`, `{X:.0f}E`, для плана `{Z:.0f}`, иначе `{s:+.0f}`. Повтор имени — ошибка «добавьте {k}» |
| «Тень» | «Нет», «Предыдущий» (по умолчанию), «Следующий», «Оба» |

- Быстрые способы: «Из линии разреза» (`series.from_line`), «Через скважину» (`series.through_hole`), «Из одного разреза» (`series.from_section`).
- Числа вводятся с запятой или точкой; ошибка называет поле и даёт подсказку.
- Изменить P1, азимут, φ, шаг или пределы можно и при готовых контурах: их атрибуты не пересчитываются; для новой геометрии рядом — «Копировать».
- Предупреждение при правке серии: перед сохранением «Параметры…» программа считает контуры слоя серии вне новых окон (без сохранения). Если они выпадут, появится окно «Контуры вне окон»: «N из M контуров слоя «…» выпадут из окон разрезов». Контуры не удаляются; «Сохранить» — применить, «Отмена» — оставить как было (для новой геометрии сделайте «Копировать серию»). Серия без контуров — без вопроса. Своё окно отдельного разреза правится без вопроса.

### «Менеджер серий»
«Разрезы» › «Серия» › «Менеджер серий» (`series.manager`). Список серий; кнопки «Создать…», «Копировать», «Удалить» (с вопросом), «Параметры…», «Сделать активной»; таблица разрезов (номер, «Имя», «s, м», «к себе, м», «от себя, м»); линии серии на плане. Свои окна разреза правятся в таблице, «Вернуть окно серии» убирает их; двойной щелчок по строке — переход к разрезу. Если серию изменили в другом окне, программа просит повторить правку (таблица уже обновлена). Удаление серии контуры не трогает.

### Переходы
Строка состояния: «Серия «Профили» · разрез 3 из 12 · 5050N». Клавиши работают при фокусе 3D-окна, не в полях ввода.

| Действие | Клавиша / кнопка |
|---|---|
| Следующий, предыдущий | `]`, `[` — «Следующий», «Предыдущий» (без серии — сдвиг линии разреза на ширину окна) |
| Первый, последний | `Home`, `End` — «Первый», «Последний» |
| По имени или номеру | `Ctrl+G` — «Перейти…»: «Имя или номер разреза (1–N)» с подсказками |
| Из дерева | Щелчок по разрезу в разделе «Серии разрезов» (до 1 000 строк, дальше — «Перейти…»); меню серии: «Сделать активной», «Копировать», «Переименовать», «Удалить» |

- На краю серии разрез не меняется, в строке состояния — сообщение.
- Свободный разрез (`S`, «Через скважину», «Авто-разрез») снимает активную серию, сама серия остаётся.
- «Зафиксировать вид» (`L`): камера по нормали к разрезу, вращение выключено, сдвиг и масштаб работают; при переходе точка остаётся на месте экрана. Во время правки на разрезе серии инструмент «Линия» — `Shift+L`.
- Если сменить разрез во время рисования, линия завершается (как по `Enter`, полигон замыкается) и остаётся на своём разрезе.
- «Отсечение» (`C`) работает и для наклонной серии и плана. «Часть каркаса в окне» (по умолчанию включена): кроме линий сечения — сам каркас, обрезанный окном; сечения каркасов считаются точно, соседние разрезы готовятся заранее и в фоне.
- «Тень»: контуры соседних разрезов серым пунктиром; не выбираются и не являются целями привязки.

### Контур на разрезе
«Оцифровка» › «Контур на разрезе» (`series.digitize`): включается отсечение, открывается правка слоя контуров серии (нет слоя — новый «Контуры <серия>» в файле «Серии разрезов»), инструмент «Полигон». Вершины ложатся в плоскость разреза (точность до 1e−9 м на координатах UTM); `Enter` — замкнуть, `]` / `[` — соседний разрез, `Ctrl+S` — сохранить. Линии получают атрибуты `SECTION_SET` (номер серии), `SECTION` (номер разреза с 1), `SECTION_NAME`; они справочные: контур относится к разрезу по положению (все вершины в окне), контуры из STR без атрибутов тоже годятся. Линии вне текущего разреза видны, но не правятся.

### «Каркас по серии»
«Оцифровка» › «Каркас по серии» (`series.stitch`): окно со списком контуров по разрезам («Разрез», «Контур», «Площадь, м²», «Связи»).
- Связи строятся сами: проекции контуров соседних разрезов перекрываются, иначе центры не дальше Δ. Щелчок по контуру выбирает его, щелчок по контуру соседнего разреза связывает или развязывает; выбранный остаётся, поэтому возможно разветвление 1 → N. «Автосвязи» возвращает автоматические связи, линии связей видны в 3D.
- Связи N : M в одной паре разрезов — отказ «разделите связи». Связь через пустой разрез не строится: он заканчивает тело торцом.
- «Начальный торец» и «Конечный торец»: «Продолжение на Δ/2, плоская крышка» (по умолчанию), «Плоская крышка на крайнем разрезе», «Выклинивание в точку на Δ/2», «Выклинивание в линию (гребень) на Δ/2».
- Связная группа контуров — отдельный каркас «<серия> — тело N»; «Одним каркасом» собирает тела в один объект.
- «Создать каркас» — задание (подтверждение, ход и «Отменить» в окне и на вкладке «Задания»), затем «Отчёт» (объём, треугольники, замкнутость). Ошибка называет разрезы: «между 5050N и 5075N: самопересечение». Контуры дальше 1e−3 м от плоскости — предупреждение, незамкнутые и вне окон — пропускаются со счётом. «Перестроить» в «Свойствах» тела работает как для других операций.

### Демо
Серия № 1 «Разрезы рудного тела 3» (Y 8000…8250, шаг 50, окна 25 / 25) с контурами; «Каркас по серии» даёт одно замкнутое тело около 0,86 млн м³ (8 связей, тай-линии пропускаются). Серия № 2 «Планы по рельефу» (через 2 м).

### Ограничения
- «Печать серии»: кнопка недоступна («Печать серии — этап Э22»); печать и листы — Э22.
- Ломаный разрез — одна развёртка; серий параллельных ломаных нет.
- Наклонная серия — преувеличение ×1.
- Блоки в разрезе — «Срез по разрезу» (раздел «Блочные модели»): подложка под скважинами в 3D, отдельного окна разреза нет; самопересечения тела не исправляются.
- Окно разреза на экране замкнутое: точка ровно на грани видна в обоих соседних разрезах.

## OMF (Leapfrog)
Формат OMF v1 (в Leapfrog — «OMF 0.9») — обмен с Leapfrog. Лента «Главная», группа «OMF»: «Импорт OMF» (`omf.import`), «Экспорт OMF» (`omf.export`), «Журналы».

### Импорт
«Импорт OMF» открывает мастер «Импорт файлов» (файл `.omf` можно перетащить на окно). Мастер разбирает файл без загрузки данных и показывает каждый элемент: во что он превратится, размер, что не переносится и почему.

| В OMF | В проекте | Не переносится (видно в мастере и в журнале) |
|---|---|---|
| Поверхности | Каркасы (ЦТМ — если файл написан BedrockForge); все поверхности файла — в папке дерева по имени файла | Данные на вершинах и гранях, текстуры |
| Линии | Один файл линий, слой на элемент | Данные на вершинах; данные сегментов, постоянные вдоль линии, становятся атрибутами линии |
| Объёмы | Блочные модели; числа и категории — поля; поворот вокруг Z сохраняется | Данные на узлах; поворот вокруг X/Y, зеркало, перекос — «Поворот вокруг X/Y в v1 не поддерживается» |
| Точки, текстуры | — | Целиком: в мастере «не загрузится», по именам элементов |

- Пропуск значения остаётся пропуском: ячейки, у которых пусты все поля, не загружаются.
- OMF 2 (ZIP) не поддерживается: ошибка «OMF 2 (ZIP) не поддерживается» в карточке файла; в Leapfrog сохраните как OMF v1 («OMF 0.9»).
- Повреждённый, обрезанный или слишком большой файл — ошибка с подсказкой, в проекте ничего не остаётся. Нехватка памяти или диска — ошибка задания, две попытки; отмена ничего не оставляет.
- Предел — 200 млн ячеек в модели.

### Экспорт
«Экспорт OMF» — окно «Экспорт OMF»; то же — «Экспорт OMF…» в меню каркаса, ЦТМ, файла линий и блочной модели (объект уже отмечен).

| Элемент окна | Назначение |
|---|---|
| «Каркасы и ЦТМ» | Поверхности; цвет сохраняется, ЦТМ помечается в описании |
| «Файлы линий» | Набор линий на слой; замкнутая линия — сегмент к первой вершине; атрибуты линии — на сегментах |
| «Блочные модели» | Объёмы с полями в ячейках; единица поля — в описании |
| «Сохранить как…» | Файл `.omf`; в имени по умолчанию — проект или объект |
| «Экспортировать» | Задание `export.omf`: ход в окне и на вкладке «Задания», «Отменить», затем «Показать в папке» |

- Недоступный объект отмечен причиной: модель с субблоками — «только после регуляризации»; поворот вокруг X/Y; модели больше 100 млн ячеек; слои точек не пишутся (предупреждение); линии с вершинами без Z не пишутся — пропуск не превращается в 0.
- Файл уже есть — окно «Заменить файлы?» («Заменить»); без согласия файл не меняется. Отмена или сбой — файла нет.
- Ассистент: `omf.export` с `dataset_ids` после подтверждения сразу ставит задание и пишет файл в папку «Экспорт» рядом с папкой проектов; путь ассистент не задаёт. Без `dataset_ids` — окно.
- Координаты — двойной точности, вершины записываются без изменений.

## Обработка проб
Лента «Анализ», группа «Обработка проб»: «Композиты», «Кодировать каркасами», «Объединить таблицы», «Координаты проб», «Урезка», «Эквивалент металла», «Декластеризация» (команды `composite.*`). Окно операции: источник (набор, таблица, поля), параметры, предпросмотр на выбранной скважине (пробы и результат рядом) и сводка «до/после» (число, длина, среднее и металл Σ l·g). «Применить» — задание. Без обязательных параметров команда открывает окно; с параметрами у ассистента ставит задание сразу.

| Операция | Что делает | Результат |
|---|---|---|
| «Композиты» › «По длине» | Длина L (0,1–100 м; 2), правило остатка («присоединить», «отбросить», «равные части»; f_min 0,5), отсчёт «от начала участка», «от устья», «от кровли первой пробы» | Таблица «Композиты 2 м» |
| «Композиты» › «По доменам» | Композит не пересекает смену кода: домен — поле интервальной таблицы или каркасы | Таблица «Композиты по доменам» |
| «Композиты» › «По уступам» | Высота H (1–50 м; 10), «Отметка верха Z» (пусто — максимум Z устьев, вверх до H); флаг «пологая» | Таблица «Композиты по уступам 10 м» |
| «Кодировать каркасами» | Код тела у каждой пробы; «Делить пробы на границе каркаса» (по умолчанию да; без деления — код по середине и доля длины внутри, `INSIDE_FRAC`); перекрытие тел — по порядку списка | Таблица «‹Таблица› — коды» |
| «Объединить таблицы» | Все границы FROM/TO выбранных таблиц; значения покрывающих интервалов; нет покрытия — пусто | Таблица «Объединение: …» |
| «Урезка» | Порог: «перцентиль» P (90–99,99 %; 99, с весом длины, по доменам), «значение» T или «по доменам»; кривые «порог → среднее, CV, потеря металла, число урезанных», доли металла по децилям с пометками (верхний дециль > 40 %, верхний процентиль > 10 %); порог сам не применяется — только «Применить» | Поля `‹F›_CUT`, `‹F›_CUT_F` в таблице источника, результат «Урезка · ‹F›» с отчётом «до/после» |
| «Эквивалент металла» | Цены, извлечение, единицы полей; «Пустое содержание считать нулём» — только галочкой | Поле `‹основной›EQ` (имя можно задать) |
| «Координаты проб» | Начало, середина и конец проб по траекториям | Таблица «‹Таблица› — координаты» (XB…ZE) |
| «Декластеризация» | «ячейки в плане», «полигоны в плане», «ячейки в 3D» (анизотропия Y, Z); «Критерий» — «минимум среднего» или «максимум среднего»; кривая «размер → среднее» | Поле `DECL_W` в таблице источника |

Композиты: колонки LENGTH, X, Y, Z, поля источника, DENSITY, SAMPLED_LEN, N_SAMPLES, DOMAIN, FLAG («мало проб», если опробованная доля < p_min, 0,5). Непробованные участки — пусто (или число по выбору); пропуск не становится нулём. Вес по плотности — по выбору.

### Результаты в дереве
- Под набором — строка «Обработка проб» со всеми результатами; двойной щелчок открывает таблицу (результат без таблицы — «Свойства»).
- Меню результата: «Открыть таблицу», «Параметры…» (окно с прежними значениями), «Перестроить», «Свойства» (источник, параметры, SHA-256 входов, версия алгоритма, время, сводка), «Удалить…» (у полей на месте убирает колонки).
- «устарел» — после правки источника (таблицы, устьев и инклинометрии, каркаса); причина — в подсказке. «Перестроить» с теми же входами расчёт не повторяет и снимает отметку; повторяет урезку, эквивалент и `DECL_W` на новой таблице. «Перестроить» всегда спрашивает: окно «Перестроить результат» перечисляет, что пропадёт (зависимые результаты и колонки пользователя).
- Таблицы-результаты — только для чтения: правка ячеек и строк отклоняется («Таблица — результат расчёта; правьте источник и перестройте»). Колонки добавлять можно. Исключение — «Ручная правка» рудных интервалов.
- Имя занято — « (2)»; из окна можно «Заменить» одноимённую таблицу после подтверждения.
- Результат хранится в проекте и переносится в `.bfggis`; расчёт отменяется без следов.

### Ограничения
- Кодирование — только замкнутыми каркасами: иначе ошибка «Проверьте и исправьте каркас».
- Скважина без траектории — координаты и коды пустые, запись в журнале задания.
- Пробы с TO ≤ FROM и перекрытия не участвуют (число — в журнале); совет — запустить «Аудит данных».
- Первое задание после установки компилирует ядра (до 30 с).

## Рудные интервалы (ГКЗ)
Лента «Анализ» › «Обработка проб» › «Рудные интервалы (ГКЗ)» (`composite.ore_intervals`): кондиционные интервалы по методике ГКЗ по одному полю содержания.

| Параметр | Смысл |
|---|---|
| «Бортовое содержание Сб» | Проба с C ≥ Сб — рудная; равенство — руда (допуск 1e−9) |
| «Мин. мощность Мрт» | Наименьшая мощность рудного интервала |
| «Макс. мощность прослоя Мпп» | Пустой прослой не больше Мпп присоединяется; M = Мпп — присоединяется |
| «Мин. метропроцент МС» | Пусто — Сб·Мрт |
| «Мин. содержание Смин» | Пусто — выключено (= Сб) |
| «Мощность пробы» | Пусто — длина по стволу; или числовое поле базы (истинная мощность — через поле). Углы встречи и флаг < 30° в расчёт не входят |
| «Пропуски» | «разрывают интервал» (по умолчанию) или «пустая порода до длины» (до «Наибольшего пропуска», с флагом) |

Режимы:

| «Режим» | Особенность |
|---|---|
| «строгий, исключить пустую породу» | По умолчанию; прослои с C < Сб и M > Мпп исключаются |
| «строгий» | Прослой разрывает интервал |
| «смягчённый» | Без поиска пустого прослоя (шаг 3): в интервале могут остаться прослои мощнее Мпп; сближенные объединяются |
| «упрощённый» | Наращивание парами «безрудный + рудный» |
| «по контактам» | Участки домена («Коды тела» — пусто, все непустые); кондиционность по МС. Коды домена — текстом: литология «QZ», имена тел каркасов |

Результат:
- Таблица «Рудные интервалы»: LENGTH, M, содержания (поле расчёта и прочие числовые — средневзвешенные), MC, CLASS, BASIS, NESTED, N_SAMPLES, WASTE_LEN, MODE, MANUAL, ORE_ID, X, Y, Z, LABEL («8,0 м @ 2,84 г/т (МС 22,7)»). В таблице проб — поля `ORE_ID`, `ORE_CLS`. Два расчёта рудных интервалов по одной таблице допустимы; поля `ORE_ID`/`ORE_CLS` принадлежат последнему.
- Классы CLASS: «кондиционный рудный», «некондиционный рудный», «включённый прослой», «исключённый прослой», «безрудный», «обрамление» (пробы по обе стороны, пока M не достигнет Мпп). Вложенные строки (прослои внутри интервала, обрамление) в суммы мощности не входят.
- Отображение по стволу «Рудные интервалы»: цвет по классу, подпись LABEL — в 3D и на разрезах; обрамление скрыто фильтром.
- Окно: вкладки «Столбец» (пробы, классы, прирезки, итог), «Протокол», «Сводка» (число, Σ M, средняя M, C = Σ MC / Σ M, Σ MC — по классам и доменам; по набору — после расчёта, если проб больше 200 тыс.).

### Протокол и экспорт в Excel
- «Протокол» — форма И1: пробы строками; столбцы N / IN₀, C₁…, IN₁…, «Прослои», «Сближенные», «Итог»; каждое решение с причиной («отклонён — C < Сб», «прослой исключён»…). Не хранится, пересчитывается; у устаревшего результата — «Перестройте результат».
- «Сохранить как…» — книга XLSX: «Параметры», «Интервалы», «Сводка», «Протокол» и листы «Скв. ‹имя›» (до 50 скважин) в форме И1; или CSV (`;`, UTF-8) — два файла: протокол и «… · интервалы.csv». Листы «Скв. …» — не более 50 скважин. Лист больше 1 048 575 строк уходит в CSV рядом.

### Анализ кондиций
«Анализ кондиций» (`composite.conditions_analysis`; желательная функция): списки Сб, Мрт, Мпп через «;» — до 200 вариантов тем же расчётом. Таблица: число интервалов, среднее содержание, Σ M, ср. M, Σ MC, «Изменение Σ M, %» (пометка, если соседние варианты различаются не на 10–15 %), содержание прирезки между соседними бортами. «Исключить пробы по полю» — например, CODE после кодирования каркасами (внутри карьера). Сохранить CSV, копировать.

### Ручная правка
В окне результата «Рудные интервалы (ГКЗ)», вкладка «Ручная правка» (желательная): скважина, «Разделить», «Объединить», «Сдвинуть границу» — по границам проб; нарушения К, Мпп и прирезки показываются, MANUAL = 1, `ORE_*` обновляются. «Перестроить» результат с правками предупреждает, что они будут потеряны. У устаревшего результата и в проекте «только просмотр» правка недоступна.

### Правила (выведены из примеров ГКЗ)
- Скважина обходится от устья вниз; пропуск разрывает линию опробования.
- Прирезка остаётся у вышележащего интервала; этапы идут по единицам предыдущего этапа.
- Сближенные интервалы — последним проходом и дальше Мпп от прочих; действует и в «смягчённом».
- На примере с прослоем 2 × 10,6 м строгие режимы дают два интервала, «смягчённый» — 35,5 м.
- Правила проверены на числах примеров; Т8.2-18 (сл. 17 первого примера) не применяется. Крайний случай: «строгий, исключить пустую породу» может дать пустой итог, если нигде выше нет кондиционного.

## Истинная мощность и рудные пересечения
Лента «Анализ» › «Пересечения» (ТЗ 8.5, ADR 0021): «Истинная мощность» (`intercept.tt`) и «Рудные пересечения» (`intercept.run`); те же команды — в `Ctrl+K` и у ассистента. Без обязательных параметров команда открывает окно с предпросмотром по выбранной скважине (выбор — «Скважина»); с параметрами ассистент ставит задание сразу. Нужен открытый проект и набор скважин с траекториями.

### «Истинная мощность»
Для каждого интервала таблицы (пробы, композиты) считает мощность поперёк тела: `m = l·|n·d|` (n — нормаль тела, d — направление ствола; искривлённый ствол — частями). Результат — поля `TT`, `TT_FLAG`, `TT_SRC` (и углы) в таблице источника; повтор перезаписывает их. Нет данных — поле пусто, не ноль.

### Ориентировка
Блок «Ориентировка» — один из четырёх источников:

| Источник | Что задаётся | Как берётся ориентировка |
|---|---|---|
| «Глобальная» | «Угол падения α» (0–90°), «Азимут падения Aп» (0–360°); «Взять с каркаса» — средняя плоскость отмеченных каркасов | Одна для всего расчёта |
| «По домену» | «Код домена» — «поле интервальной таблицы» («Таблица кода», «Поле кода») или «каркасы-домены»; таблица «код → α, Aп» (до 1000 кодов; вставка из Excel и CSV, «Заполнить кодами») | По коду домена интервала |
| «По каркасу» | Каркасы и ЦТМ (до 16), «Поиск ближайшего d_max», «Радиус осреднения нормали r_n» | Ствол пересекает каркас внутри интервала — нормаль в точке пересечения (вход и выход из тела — по обеим нормалям); иначе ближайший треугольник не дальше d_max |
| «Ориентированный керн» | «Таблица замеров», «Поле α_к (к оси керна)», «Поле β_к (от линии отсчёта)», «Линия отсчёта» («низ керна (BOH)» или «верх керна (TOH)»), «Ближайший замер d_к» | Интервал с замером — по нему (`m = l·sin α_к`); без замера — ближайший по стволу не дальше d_к |

«Если не найдена — глобальная α, Aп» — запасной источник: ориентировка не найдена у интервала (нет домена, каркаса, замера) — берётся глобальная. Цепочка: основной источник → глобальная → пусто (бит 2). Источник записан у каждого интервала в `TT_SRC`.

### Поля результата
`TT_SRC`: «глобальная», «домен», «каркас: пересечение», «каркас: ближайшая», «керн: замер», «керн: ближайший», «нет».
`TT_FLAG` — сумма битов; 0 — всё в порядке:

| Бит | Подпись | Смысл |
|---|---|---|
| 1 | «вдоль тела» | Скважина почти параллельна телу: `TT / LENGTH` < ε_в — только пометка, мощность не «исправляется» |
| 2 | «нет ориентировки» | Ориентировка не найдена, строка вне расчёта (нет глубины, TO ≤ FROM) — TT пусто |
| 4 | «керн не пересчитан» | Замер керна не пересчитан в мировую нормаль (наклон ствола < 1°) |
| 8 | «нет траектории» | У скважины нет траектории — TT пусто |

Дополнительно, если «Записать углы» включено (по умолчанию): `ALPHA`, `DIPDIR` (ориентировка), `HOLE_THETA`, `HOLE_AZ` (ствол), °.

### Параметры

| Параметр | Диапазон | По умолчанию |
|---|---|---|
| «Порог вырождения ε_в» | 0,01–0,5 | 0,1 |
| «Часть ствола», м | 0,1–10 | 1 |
| «Поиск ближайшего d_max», м | 0–1000 (0 — только пересечения) | 50 |
| «Радиус осреднения нормали r_n», м | 0–200 (0 — ближайший треугольник) | 0 |
| «Ближайший замер d_к», м | 0–1000 | 10 |
| «Угол падения α» / «Азимут падения Aп», ° | 0–90 / 0–360 | — |

Значение вне диапазона подсвечивается и не отправляется; пустое не становится нулём.

### «Рудные пересечения»
Правило 8.5.3 по таблице проб или композитов и одному полю содержания; результат — новая таблица набора «Рудные пересечения» (имя занято — « (2)» или «Заменить?»), исходная таблица не меняется.
1. Рудный интервал — содержание g ≥ борта c; подряд идущие рудные интервалы образуют серию.
2. Слева направо: следующая серия присоединяется, если пустая порода между ними ≤ L_п и среднее объединения (с пустой породой) ≥ c; иначе пересечение закрывается.
3. Принимается при длине ≥ L_min — или при истинной мощности ≥ m_min («Критерий приёмки»: «по длине (L_min)» / «по истинной мощности (m_min)»; без ориентировки проверка идёт по длине).
4. «В том числе» — то же внутри принятого по борту c2 > c («Борт «в том числе» c2»; пусто — без него).

Среднее — взвешенное по длине; с «Полем плотности» — по длине × плотность.

| Параметр | Диапазон | По умолчанию |
|---|---|---|
| «Бортовое содержание c» | любое число больше 0 | — |
| «Мин. длина пересечения L_min» (или «Мин. истинная мощность m_min»), м | 0–100 | 2 |
| «Макс. пустая порода внутри L_п», м | 0–50 | 2 |
| «Борт «в том числе» c2» | больше c | нет |
| «Пропуски» | «пустая порода (g = 0)» / «разрыв пересечения» | пустая порода |

«Поля содержаний сверх основного» — «все числовые (кроме плотности и полей истинной мощности)» или «только отмеченные». Блок «Ориентировка» можно выключить («Считать истинную мощность» — без галочки TT пусто, `TT_SRC` «нет»).

Колонки таблицы: HOLE, FROM, TO, LENGTH, TT, TT_FLAG, TT_SRC, ALPHA, DIPDIR, HOLE_THETA, HOLE_AZ, содержания, LEN_G (длина × содержание: метропроцент; для г/т и ppm — метрограмм), TT_G (TT × содержание), WASTE_LEN (пустая порода внутри), MISS_LEN (из неё — без проб), N_INT, X, Y, Z (середина), INCL, LABEL, ID, KIND («основное», «в том числе»). LABEL — подпись, например «12,0 м @ 2,10 г/т (ИМ 9,8 м)» (ИМ — истинная мощность); показывается по стволу в 3D. Строки «в том числе» ссылаются на основное пересечение через INCL.

### Результаты в «Обработка проб»
Под набором в строке «Обработка проб» появляются «Истинная мощность · ‹Таблица›» и «Рудные пересечения». Меню и правила — как у результатов Э12 (раздел «Обработка проб»):
- «Открыть таблицу» (у «Истинной мощности» — «Открыть таблицу с полями»), «Параметры…» (окно с прежними значениями), «Свойства» (ориентировка по-русски, число строк по `TT_SRC` и по битам `TT_FLAG`, Σ LENGTH, Σ TT), «Перестроить», «Удалить…».
- «устарел» — после правки таблицы источника, траекторий, каркасов или таблицы домена; причина — в подсказке. «Перестроить» повторяет расчёт; «Удалить…» у «Истинной мощности» убирает поля TT, TT_FLAG, TT_SRC и углы.
- «Истинная мощность» — не зависимая операция: если «Перестроить» таблицу-результат (например, композиты), поля TT в ней пропадут — окно «Перестроить результат» перечислит их; повторите «Истинную мощность».
- Таблица «Рудные пересечения» — результат расчёта, только для чтения.

### Какой инструмент выбрать: 8.5.3 или рудные интервалы Д-26

| | «Рудные пересечения» (8.5.3) | «Рудные интервалы (ГКЗ)» (Д-26) |
|---|---|---|
| Правило | Борт c, L_min или m_min, L_п, «в том числе» по c2 | Сб, Мрт, Мпп, МС, Смин, пять режимов |
| Истинная мощность | Считается в самом расчёте (ориентировка), можно взять как критерий m_min | Не считается: «Мощность пробы» — длина по стволу или числовое поле базы, в т. ч. `TT` после «Истинной мощности» |
| Когда брать | Подсчёт подсечений с истинной мощностью и подписями «ИМ» | Кондиционные интервалы по методике ГКЗ с протоколом И1 и Excel |

Для Д-26 с истинной мощностью: сначала «Истинная мощность» по таблице проб, затем в окне Д-26 «Мощность пробы» = `TT` (в списке поле первым; строка «Взять TT»).

### Ограничения
- Почти параллельная скважина (бит 1) — только пометка: мощность и результат считаются как есть; решение за геологом.
- Каркас без нормали (канава «туда-обратно») и нет траектории — TT пусто, не ноль.
- Первое задание после установки компилирует ядра (21–22,5 с).
- Предпросмотр: каркасы в сумме больше 2 млн треугольников не считаются (`mesh_skipped`; в окне — одна фраза, цепочка идёт к следующему источнику). «Взять с каркаса» — тот же предел (2 млн в сумме); само задание берёт каркасы по одному.
- Большой «d_max» на плотном теле — предупреждение в журнале задания (поиск ближайшего медленнее).
- На одном потоке расчёт по каркасу 10 млн треугольников заметно медленнее (около 48 с вместо 26 с на 4 потоках).
- «Заполнить кодами поля» — до 1000 кодов, текстовые и числовые поля; при большем числе окно пишет «показаны 1 000 из N».
- Бит 2 `TT_FLAG` — нет ориентировки или строка вне расчёта (нет глубины или TO ≤ FROM).
- «Удалить…» у результата «Истинная мощность» убирает её поля (`TT`, `TT_FLAG`, `TT_SRC`, углы); «Отменить» вернёт.
- Цели времени — замеры ниже; окончательная проверка на ПК приёмки.

| Замер (full) | Цель | Результат |
|---|---|---|
| «Истинная мощность», 5 млн интервалов | ≤ 10 с | 14,1 с (запись полей 10,8–11 с, расчёт 2,5–2,9 с) |
| По каркасу 10 млн треугольников | ≤ 60 с, ≤ 3 ГБ | 26 с, 2,03 ГБ |
| «Рудные пересечения» | ≤ 20 с | 6,6–6,9 с |

## Графики
Лента «Анализ», группа «Графики» (команды `chart.*`; нужен активный набор скважин). Каждый график — плавающее окно: перетаскивание, размер, положение запоминаются; график считается по текущим данным и пересчитывается после правки проб.

| Кнопка | Что показывает |
|---|---|
| «Гистограмма» | Распределение поля; вес «по длине» (по умолчанию), «по полю», «без веса»; верхняя и нижняя отсечки («заменить» или «исключить»); логарифмическая шкала; число бинов или ширина; таблица статистики (среднее, CV, процентили) |
| «Q-Q график» | Квантили против нормального или логнормального распределения (PPCC) либо против другой выборки (другое поле или набор; D Колмогорова–Смирнова, таблица X / Y / отношение) |
| «Дендрограмма» | Кластеры полей по корреляции (Пирсон, Спирмен; по умолчанию логарифмы), связи average, complete, single, weighted (Ward нет); нужно 2 и больше компонента |
| «Рассеяние» | Два поля: регрессии МНК, RMA, взвешенная, r Пирсона и Спирмена, лог-оси, цвет по полю; больше 200 000 точек — плотность 100 × 100 |
| «Ящики с усами» | Q1, медиана, Q3, усы 1,5·IQR, выбросы и среднее по доменам; лог-шкала |
| «Лог-вероятностный» | Содержание против вероятности по доменам; щелчок по линии открывает «Урезку» с этим порогом (порог сам не применяется) |
| «Контактный анализ» | Средние по шагам с обеих сторон контакта доменов вдоль ствола (контакт — поле домена или каркас); до 500 шагов на сторону |
| «Тернарная» | Доли трёх полей в треугольнике, цвет по полю; больше 200 000 строк — прореживание |
| «По доменам» | Таблица статистики по доменам, экспорт; пробы без домена — отдельной строкой |

Домен — текстовое поле той же или другой интервальной таблицы набора; для каркасов сначала «Кодировать каркасами» (Э12). Кнопки окна: PNG (вдвое больше окна), SVG, CSV.

### Сохранённые графики
График сохраняется в дереве набора («Графики») сразу при открытии; настройки правятся и сохраняются с задержкой. Имя строится из настроек («Гистограмма · AU · по длине»); после ручного переименования больше не меняется. Двойной щелчок — окно (одно на график); меню: «Открыть», «Переименовать», «Удалить» (данные проб не меняются). Проект «только чтение» — окно работает без сохранения, с пометкой.

### Выделение проб
- Рассеяние: рамка или лассо; ящики — рамка по ящикам; лог-вероятностный — рамка по диапазону. Выбранные пробы — слоем в 3D (в окне разреза — с отсечением) и фильтром таблицы («Показать» открывает таблицу выделения). Выделение одно на приложение.
- «Выделить на графиках» в панели «Таблица» — строки текущего фильтра; выбранная в 3D скважина — её пробы; открытые графики отмечают эти точки.
- `Esc` в окне графика снимает выделение (то же — «Снять выделение проб»). Правка таблицы делает выделение устаревшим — оно снимается с причиной в строке состояния. Не больше 200 000 строк. Выбор проб рамкой в 3D не предусмотрен.

## Статистика
Нижняя вкладка «Статистика» (лента «Анализ» → «Статистика»): компонент и таблица — выбор вверху.

| Анализ | Что делает |
|---|---|
| «Декластеризация» | Ячейки или полигоны; критерий «минимум» или «максимум среднего»; кривая «размер → среднее»; по умолчанию 20 размеров и 8 сдвигов. Веса — поле `DECL_W` через «Анализ → Обработка проб → Декластеризация» |
| «Нормальные оценки» | Преобразование в нормальные оценки (nscore), график и таблица; вес 0 в таблицу не входит |
| «Бутстрап» | Шесть статистик за проход (по умолчанию 1000 выборок, доверие 95 %); зерно показывается, «Повторить с этим зерном» воспроизводит результат |

- Предел — 20 000 интервалов; больше — отказ с кнопками «Композиты…» и «Декластеризация всей таблицы…».
- Панели Э16 (предел тот же — 20 000 интервалов; больше — отказ с подсказкой «композиты или окно «Вариография»»):

| Панель | Что показывает |
|---|---|
| «Вариограмма» | Экспериментальная вариограмма и кривая модели; лаг без пар — «—», не ноль |
| «Карта вариограммы» | Карта в плане: север вверх, восток вправо, один масштаб осей; пустая клетка — штриховка «пусто», в CSV пусто |
| «Карта неопределённости» (`local`) | IDW-оценка по скважинам, не меньше 3 скважин; север вверх; при отказе на 20 001 интервал кнопки окна нет |

- Кнопка «Открыть в окне «Вариография»» (у вариограммы и карты) — те же данные в окне без предела 20 000 и с любой плоскостью. Карта вкладки — в осях X/Y (u = ΔX), в окне — по осям модели (a1 вверх).
- Результаты не хранятся: правка данных, смена набора, таблицы или компонента их сбрасывает.

## Swath plot
Лента «Анализ» → «Статистика» → «SWATH PLOT» (`stats.swath`) — плавающее немодальное окно, по одному на swath; 3D, `T`, щелчок по устью и `Ctrl+K` работают при открытом окне. Swath сохраняется в дереве («Swath plot»), имя — «Swath plot · X · 25 м».

| Область окна | Что задаёт |
|---|---|
| «Направление полос» | X, Y, Z или «по углам»: «Азимут, °» (0–360 от севера), «Наклон, °» (−90…+90, минус — вниз), «Поворот, °» (вокруг оси полос, −180…+180) |
| Ряды | До 12: блочные модели («Поле модели», «Вес блоков»: объём, тоннаж, без веса; плотность; отбор блоков по полю; «Фильтр» — фильтр библиотеки блочных моделей) и «Скважины (пробы)» («Поле проб», «Вес проб», «Отрицательные значения», «Урезка ураганных значений», «Отбор проб», «внутри блоков»); цвет, «Убрать ряд» |
| «Ширина полосы» | «авто»: с моделью — кратна родительскому блоку, полос не больше 50; без — около 1/25 габарита. Больше 2000 полос — отказ |
| «Привязка полос» | «от края» или от значения |
| «Диапазон полос» | «Первая полоса», «Последняя полоса» (ползунки; с 1) |
| «Высота графика в 3D» | График над коробом |

График: линии средних, столбики числа проб или блоков; таблица под графиком — средние по полосам и отклонение от ряда 1, %; порядок рядов — кнопки «Выше», «Ниже» в списке рядов; наведение на полосу подсвечивает её в 3D.

### Короб и ручки в 3D
- «Полосы в 3D» показывает кубоид на полосах и над ним график, повёрнутый к наблюдателю; кубоид — по габаритам ячеек рядов-моделей (без моделей — по пробам).
- У выбранного swath три ручки: кольцо в горизонтальной плоскости — азимут; дуга в вертикальной плоскости оси полос — наклон; круг вокруг оси — поворот. Шаг 1°, `Shift` — 5°. Во время перетаскивания короб поворачивается, график скрыт; после отпускания — один пересчёт (до 2 с на 20 млн ячеек). Углы можно ввести числами в окне; поворот осей X и Y переводит направление в «по углам».
- Ручки граней и сдвига, «Взять из серии…» — не сделаны.

### Ограничения
- Swath по блочным моделям: с Э17 — и модели с субблоками и поворотом вокруг Z, и «Фильтр» ряда (раздел «Блочные модели»); пробы «внутри блоков» у таких рядов не поддерживаются.
- Графики и вкладка «Статистика» считают по текущим данным и не хранят результатов; цели времени (5 млн проб, 20 млн ячеек) — на ПК приёмки.
- Список из 10 000 скважин не вмещается в 64 КБ настроек графика.

## QAQC
Контроль качества анализов (ТЗ 8.4, ADR 0020): стандарты (CRM), бланки, дубликаты, внешний контроль, партии, отчёт. Лента «Анализ → QAQC»: «Настройка» и шесть разделов; те же команды `qaqc.*` — в `Ctrl+K`. Нужен открытый проект. Нижняя вкладка «QAQC» считает по загруженным данным без заданий; цель — все разделы одного элемента ≤ 3 с на 1 млн записей.

### Данные и сопоставление колонок
«Настройка» → «Данные» → «Загрузить из файла…» (CSV, TXT, DAT, XLSX, XLS) или «…из таблицы набора…». Форма сопоставления с автоподбором по именам и предпросмотром 50 строк.

| Поле | Смысл |
|---|---|
| `SAMPLE_ID`, `TYPE` | Обязательны; без них импорт отклоняется |
| `HOLE`, `PARENT_ID`, `CRM_ID`, `LAB`, `BATCH`, `DATE`, `SEQ` | По необходимости: исходная проба дубликата, стандарт, лаборатория, партия, порядок |
| Остальные числовые колонки | Элементы; единица — из имени («AU_ppm», «Cu, %») или вручную |

- Раскладка «длинная»: дубликат — отдельная строка с `PARENT_ID` исходной пробы. Без `PARENT_ID` пара не образуется («нет исходной» в счётчиках). «Широкая» раскладка (исходное значение в колонке той же строки) — через колонку исходного значения в сопоставлении.
- «<0,01» читается как половина предела с признаком «ниже DL»; пропуск остаётся пропуском, не нулём. Даты: `ГГГГ-ММ-ДД`, `ДД.ММ.ГГГГ`, `ДД/ММ/ГГГГ`, дата Excel; неразобранные — пусто и в счётчик.
- Итог импорта показывает счётчики: нет исходной, повторы `SAMPLE_ID`, неразобранные даты и числа, ниже и выше DL. Предел — 5 млн строк и 60 элементов.
- Из таблицы набора данные берутся снимком: после правки таблицы они помечены «устарели», «Обновить» повторяет импорт с тем же сопоставлением. Данные неизменяемы; исправление — повторный импорт («Заменить?»).

### Типы
«Настройка» → «Типы»: код TYPE из файла → тип ORIG, CRM, BLANK, DUP_F (полевой), DUP_C (дроблёный), DUP_P (пульповый), UMP (внешний контроль). По умолчанию «STD», «STANDARD» → CRM, «BLK» → BLANK; **пустой код — ORIG**. Нераспознанный код выделен, с числом записей; в расчёт не идёт и в ORIG не превращается. Правка соответствия действует сразу, без повторного импорта.

### Справочник CRM
«Настройка» → «CRM»: строки «CRM_ID, элемент, среднее μ, σ, единица, источник»; ключ — пара CRM_ID и элемент, регистр не важен; μ и σ больше 0, иначе строка отклоняется с номером. «Загрузить из файла…» (CSV, XLSX) заполняет таблицу, запись — после проверки. Единицы: г/т = ppm, ppb, % пересчитываются; иное несовпадение — группа «единицы не совпадают» без оценки. CRM нет в справочнике — группа «нет справочного значения».

### DL и пороги
- «DL»: предел по (элемент, лаборатория) или по элементу; приоритет — поле DL записи, затем лаборатория, затем элемент. Без DL бланк — «не оценён» (не «норма»), у дубликатов отсев по DL не применяется, с примечанием.
- «Пороги» (кнопка «По умолчанию»); вне диапазона — отказ `bad_param`:

| Порог | По умолчанию | Диапазон |
|---|---|---|
| σ предупреждения / отказа | 2 / 3 | 1–5, первое меньше второго |
| Длина серии | 9 | 5–20 |
| k для бланка | 5 | 1–50 |
| k для дубликатов (отсев по DL) | 5 | 0–50 |
| Группа Томпсона–Ховарта, пар | 11 | 5–51, нечётное |
| HARD: полевые / дроблёные / пульповые / внешний, % | 10 / 20 / 30 / 10 | 1–100 |
| Доля пар в критерии, % | 90 | 50–100 |
| Бутстрап: реализаций; зерно | 1000; 12345 | 100–5000 |

Правка настроек и справочника делает готовые отчёты «устаревшими». Значение ровно на границе порога относится к мягкой стороне (1,10 при μ = 1,00, σ = 0,05 — «норма»).

### Вкладка «QAQC»
Слева: данные, элемент и фильтры со счётчиком «записей N из M» и «Сбросить». Справа: «Стандарты», «Бланки», «Дубликаты», «Внешний контроль», «Партии», «Отчёт».

| Фильтр | Действие |
|---|---|
| Лаборатории, партии, даты (с — по), типы, скважина (начало имени) | Построчные условия по полям записи |
| CRM | **Только записи типа CRM**; бланки, дубликаты и ORIG им не отсекаются |
| «Любое поле» | До 20 условий «И» по прочим полям файла |

Один фильтр действует на все разделы, графики и отчёт. Расчёт по фильтру равен расчёту по заранее отобранным записям. Графики — до 100 тыс. точек: все не «нормальные» и равномерная выборка остальных, число показано; числа считаются по всем. Графики: PNG (вдвое больше окна), SVG, CSV.

### Стандарты и контрольная карта
Группа — CRM × элемент × лаборатория; порядок — дата, `SEQ`, строка файла. z = (x − μ) / σ.

| Статус | Условие |
|---|---|
| норма | \|z\| ≤ 2σ |
| предупреждение | 2σ < \|z\| ≤ 3σ |
| отказ | \|z\| > 3σ; **две подряд** в 2–3σ по одну сторону μ (вторая и далее) |
| не оценён | нет справочного значения или единицы не совпадают |

- Серия: 9 подряд (порог настраивается) по одну сторону μ — признак «смещение» с 9-й пробы, статус не ниже «предупреждение»; z = 0 серию обрывает. Партию серия не бракует.
- Подмена: \|z\| > 3σ, но значение в пределах 2σ другого CRM того же элемента — пометка «возможна подмена: ‹CRM›».
- Смещение группы = 100·(x̄ − μ) / μ по всем значениям (отказные тоже): до 5 % — норма, до 10 % — внимание, больше — недопустимо.
- Карта выбранной группы: значения по дате или по порядку (`SEQ`), линии μ, ±2σ, ±3σ, среднее и скользящее среднее по 10, цвет по статусу. Щелчок по точке — карточка пробы и подсветка её партии.

### Бланки и перенос загрязнения
Отказ, если значение > k·DL (по умолчанию 5·DL); «ниже DL» — норма; без DL — «не оценён». График по лабораториям с линией k·DL. Перенос загрязнения: рассеяние «предыдущая проба партии — бланк», r Пирсона, n.

### Партии
Партия — пара «лаборатория, партия». Отказ, если в ней есть отказ CRM (в том числе «две подряд») или бланка. Во вкладке — по активному элементу, в отчёте — по каждому элементу и «по любому». Записи без партии считаются отдельно. Щелчок по партии ставит фильтр по ней.

### Дубликаты
Переключатель типа: полевые, дроблёные, пульповые — считаются порознь. Пара: x1 — исходная проба, x2 — контрольная.

| Мера | Формула |
|---|---|
| HARD, % | 100·\|x1 − x2\| / (x1 + x2) |
| HRD, % | 100·(x1 − x2) / (x1 + x2) |
| AMPD, % | 2·HARD |

- В расчёт идут пары без пропусков, без отрицательных, с x1 + x2 > 0 и средним ≥ k·DL; отброшенные считаются по причинам: нет исходной, пропуск, отрицательное, ноль, ниже DL.
- Критерий выполнен, если доля пар с HARD ≤ порога типа (10 / 20 / 30 %) не меньше 90 %. Показаны доли при 10, 20, 30 %.
- Рассеяние x1 — x2: линии 1:1, ±10 %, ±20 %, RMA, r. «Ранжированный HARD»: HARD по возрастанию против процента пар, с порогом; в ответе до 2000 точек, доли — по всем парам.

### Томпсон–Ховарт
Нужно не менее 50 пар, иначе «мало пар» без графика. Пары по возрастанию среднего делятся на группы по 11 (остаток — к последней); медиана \|x1 − x2\| по группе против среднего группы — прямая a + b·c. Точность P(c) = 200·σ(c) / c, %, где σ(c) = K·(a + b·c); показана для P10, P50, P90 и заданных c. Если a + b·c ≤ 0 — «нет наклона», значение пусто.

### Внешний контроль
Тип UMP: x1 — основная лаборатория (из исходной пробы), x2 — контрольная; группа — элемент × пара лабораторий. Отбор пар и критерий — как у дубликатов (10 %). Таблица групп: смещение = 100·(x̄₁ − x̄₂) / x̄₂, парный t-критерий (t, p, степени свободы), RMA y = a + b·x с интервалами 95 % (бутстрап по зерну). При n·B > 10⁸ число реализаций уменьшается (не ниже 100) и показано. Если все разности равны, t и p пусты с примечанием.

### Отчёт
«Отчёт» → «Сформировать»: имя, элементы, графики `all` (все группы), `flagged` (только с предупреждениями и отказами и сводные), `none`; не больше 200. Ход: расчёт → графики «37 из 120» → XLSX; отмена доступна. Отчёт — объект раздела «Отчёты» в дереве: «Открыть», «Сохранить XLSX…», «Перестроить», «Переименовать», «Удалить». Он хранит копию записей, фильтр, настройку, CRM, зерно, SHA-256 данных и входов, поэтому воспроизводим после замены или удаления данных; размер удержанных записей показан в окне.

- XLSX: листы «Сводка», «Стандарты», «Бланки», «Дубликаты», «Внешний контроль», «Партии», «Параметры»; таблица по группам, ниже — по пробам или парам; графики — столбиком справа; числа полной точности, пропуск — пустая ячейка; длинный лист продолжается на «‹имя› (2)». Один и тот же отчёт даёт побайтно один файл.
- «устарел» с причиной: данные заменены, изменились настройка или справочник, данные удалены. «Перестроить» повторяет расчёт с сохранёнными фильтром и параметрами на текущих данных (при удалённых данных недоступно).
- «PDF» недоступен: «Появится на этапе Э22».

### Ограничения
- PDF отчёта — Э22; связи контрольных записей с 3D и таблицей нет; ручное исключение записей и сохранение графиков QAQC в «Графики» не предусмотрены.
- Проект «только просмотр»: расчёты и сохранение файла работают; импорт, настройка, создание и удаление — нет.
- Реальных файлов QAQC для приёмки не было — проверено на синтетике; цели времени и 30 кадров/с — на ПК приёмки.

## Вариография и тренды
Лента «Геостатистика» → «Вариография» (ТЗ 8.6, Д-14, Д-15, ADR 0022): «Вариограммы», «Вдоль скважин», «Веер», «Карта вариограмм», «Нормальные оценки», «Модели»; те же команды `variography.*`, `trend.*` — в `Ctrl+K` и у ассистента. Нужен открытый проект и интервальная таблица (пробы, композиты) с траекториями. Расчёты работают и в проекте «только просмотр»; сохранение, замена и удаление моделей и трендов — нет.

### Окно «Вариография · ‹поле›»
Плавающее окно, можно открыть несколько. Слева — данные и параметры, в центре — графики, справа — модель; внизу «Рассчитать», «Подобрать», «Эллипсоид в 3D», «Сохранить», «Сохранить как тренд».

| Область | Что задаёт |
|---|---|
| «Данные» | «Набор скважин», «Таблица», «Поле» (числовое), «Домен» («все точки» или «по полю домена»: таблица, поле, значения — до 1000), «Веса» («DECL_W, если есть», «без весов» или поле), «Преобразование» («без преобразования», «нормальные оценки»). Под формой: «Точек: N из M (пропуск значения …, нет положения …, вне домена …)», σ², медиана длин |
| «Лаги и допуски» | «Лаг L» (по умолчанию 5 × медиана длин, 2 значащие цифры), «Число лагов» (15; 1–100), «Допуск лага» (L / 2), «Допуск азимута» и «Допуск погружения» (22,5°; 90° — без проверки), «Горизонтальная полоса» (3L), «Вертикальная полоса» (2L), «Наименьшее число пар» (30), «Зерно выборки»; «Вдоль скважин» — свои лаг, число лагов, допуск |
| Графики | Три оси модели (a1, a2, a3) и «Вдоль скважин» (самородок); у каждой точки — число пар; точка с числом пар меньше порога — полый знак, в подбор не входит; лаг без пар — пусто, не ноль |

- Типы (список «Тип» в модели): «полувариограмма», «коррелограмма (1 − ρ)», «парная относительная» (пары с z_i + z_j ≤ 0 не входят, окно предупреждает), «нормальные оценки» (при преобразовании «нормальные оценки»; σ² = 1, веса — только в таблицу оценок).
- Пока меняются данные и параметры, виден предпросмотр по выборке до 20 000 точек; итог — по «Рассчитать» как задание (вкладка «Задания», отмена). После первого расчёта правка параметров запускает задание заново, прежнее незаконченное отменяется. Те же данные и параметры — «Итог из кеша».
- Оценка числа проверок пар больше 2·10⁹ — расчёт по выборке: «Расчёт по выборке n′ из n проб» (воспроизводима по зерну). Вдоль скважин считается по всем пробам.
- Результат при 1 и 4 потоках побитно одинаков.
- Отказы с подсказкой: «нет значений», «одна проба», «все значения равны», «медиана длин не определена — задайте лаг».

| Вкладка | Что показывает |
|---|---|
| «Веер» | Вариограммы по лучам плоскости (по умолчанию 12 направлений; плоскость — оси первой структуры) и роза дальностей: дальность луча — где кривая достигает заданной доли порога; луч без дальности — пунктир «> h». Вид сверху: a1 вверх, a2 влево. Щелчок по лучу поворачивает ось a1 модели на это направление (при «общих осях» — всех структур; у модели без структур добавляется сферическая) |
| «Карта» | Карта вариограммы в плоскости a1–a2, вид сверху (a1 вверх, a2 влево); клетка без достаточного числа пар — штриховка «пусто». Линия уровня — σ² (для коррелограммы — 1). Щелчок по клетке поворачивает a1 к ней |
| «Нормальные оценки» | График нормальных оценок и блок «Обратное преобразование» (ниже) |

- Веер и карта считаются заданием `variography.map` (выборка одна на оба) и берут точки расчёта.
- Нормальные оценки: после подбора модели в Y блок «Обратное преобразование (Эрмит)» даёт модель для исходных значений: показывает «Доля Σφ² / Var(Z)». Доля меньше 0,95 — предупреждение: модель передаёт не всю дисперсию, обратное преобразование приблизительно. «Перестроить» пересчитывает его по новой таблице модели.

### Модель
Таблица «Модель»: «Самородок C0», до трёх структур («сферическая», «экспоненциальная», «гауссова») с вкладом c, дальностями a1–a3 (0 < a ≤ 100 000 м) и углами ang1–ang3 по GSLIB: ang1 — азимут оси a1 от севера по часовой (0–360°), ang2 = −погружение a1 (−90…90°), ang3 — поворот вокруг a1 (−180…180°). Значение вне диапазона отмечается, модель сохраняет последнее верное. «Общие оси» (по умолчанию) — углы всех структур равны углам первой; без флажка у каждой структуры свои. Флажок у ячейки — «Закрепить при подборе». Под таблицей «Порог …; σ² = …»; порог больше 1,2·σ² — предупреждение (допускается).

### Правка кривых и подбор
- Правка мышью на графиках осей: самородок — точка у h = 0, вклад (порог) — горизонтальная линия, дальность — вертикальная линия на графике своей оси. Значение при перетаскивании — 3 значащие цифры, дальность не меньше L/2; таблица и кривые следуют сразу (отклик ≤ 50 мс). Любая ручная правка сбрасывает сведения подбора и Эрмита.
- «Подобрать» — по осям последнего расчёта: взвешенные наименьшие квадраты, 8 стартов, веса N / h̄ (также N и N / γ²); типы структур и углы задаёт пользователь, закреплённые параметры не меняются. Начальный C0 — по первым трём лагам вдоль скважин. Предупреждения: дальность на границе 2·h_max, точек меньше, чем неизвестных, ось без точек.
- «Подобрать» учитывает закрепления (флажки у ячеек таблицы) и выбранное правило весов; в ответе — порядок структур, закреплённое, невязка. Устаревший ответ (модель правили, пока шёл подбор) отбрасывается.
- Эрмит для нормальных оценок — на вкладке «Нормальные оценки» (доля Σφ² / Var(Z) < 0,95 — предупреждение).

### Эллипсоид в 3D
«Эллипсоид в 3D» показывает эллипсоид выбранной структуры в 3D с центром в середине охвата точек расчёта: полупрозрачная поверхность, три сечения, диск a1–a2; пробы в допуске лага — цветом, без значения — цветом «нет значения». Шесть ручек (Cobalt, под курсором — Copper Orange):

| Ручка | Меняет |
|---|---|
| Кольцо в горизонтальной плоскости | ang1 (азимут) |
| Дуга в вертикальной плоскости оси a1 | ang2 (погружение) |
| Дуга вокруг оси a1 | ang3 (поворот) |
| Три конца осей | a1, a2, a3 |

Шаг угла 1°, `Shift` — 5°; дальность — 3 значащие цифры; `Ctrl` — все три дальности в одном отношении. Каждая ручка меняет только свой параметр; при «общих осях» поворачиваются все структуры. Таблица модели и кривые на графиках следуют за ручкой сразу; перетаскивание не пересчитывает пары. Плоскость ручки почти ребром к лучу — значение остаётся прежним.

### Обмен, сохранение, «устарел»
| Действие | Что делает |
|---|---|
| «Сохранить» (`variography.save`) | Модель — объект проекта «Геостатистика → Модели вариограмм» вместе с точками последнего расчёта, параметрами, невязкой и SHA-256. Имя по умолчанию «‹поле› · ‹таблица›», занятое — с « (2)»; замена сохранённой — после подтверждения |
| Экспорт (`variography.export`) | JSON (все поля модели) или параметры GSLIB (`nst c0`, `it cc ang1 ang2 ang3`, `a1 a2 a3`); путь абсолютный, кириллица допустима; повторный экспорт — тот же текст |
| Импорт (`variography.import`) | JSON или GSLIB (формат определяется по содержимому); модель — рабочая в новом окне, не сохраняется до «Сохранить»; битый файл — ошибка с номером строки |
| «устарел» | Таблица или траектории изменились после расчёта: у модели причина («изменена таблица «…»»); «Перестроить» пересчитывает точки на текущих данных с прежними параметрами, модель не меняется. Источник удалён — «источник удалён», «Перестроить» недоступно |

Проект переносится в `.bfggis` вместе с моделями и трендами.

Раздел дерева «Модели вариограмм» (в «Геостатистике»): меню строки — «Открыть», «Показать эллипсоид», «Перестроить», «Экспорт», «Свойства», «Удалить». «устарел» показан у строки с причиной; «Перестроить» не меняет C0, структуры, углы и тип, а пересчитывает точки, невязку и обратное преобразование.

| Действие | Подробности |
|---|---|
| «Экспорт», «Импорт» (кнопки окна) | Файлы `.json` и `.par` (GSLIB); экспорт — только у сохранённой модели; расширение по формату; существующий файл заменяется только после вопроса «Заменить?»; путь в папке проекта — отказ; импорт определяет формат по расширению; работают и в «только просмотр» |
| Конфликт версий | Модель сохранена в другом окне: вопрос «Сохранить как новую» (следующее свободное имя) или «Перечитать» (сохранённая заменяет модель окна) |
| Замена, имя | Замена сохранённой — с вопросом; явное занятое имя — вопрос «Заменить?», имя по умолчанию получает « (2)» |
| «Удалить» | Модель удаляется; тренды, созданные из неё, остаются копией (`model_id` пуст) |

### Тренды
Раздел дерева «Тренды» (после «Блочных моделей»; «+» создаёт тренд); «Настройки проекта → Геостатистика → Новый тренд…». Тренд — глобальный (структурные — Э19): имя, «Азимут ang1, °», ang2, «Поворот ang3, °», отношения средней и малой осей к большой (> 0; a1 : a2 : a3 = 1 : a2/a1 : a3/a1), «Размер показа a1, м», центр показа (пусто — центр вида), цвет. Ядро считает матрицу анизотропии A = diag(1, a1/a2, a1/a3)·R.

| Действие | Как |
|---|---|
| Создать, изменить | Окно «Тренд»: числа и эллипсоид в 3D с теми же ручками (кольцо азимута, дуги погружения и поворота, концы осей) |
| «Из модели вариограммы» | «Модель» и «Структура» → «Взять оси модели»: копия углов и отношений (по умолчанию структура с наибольшей a1); правка модели тренд не меняет; «Обновить из модели» — копирует заново |
| «Сохранить как тренд» | Кнопка окна «Вариография»: оси выбранной структуры рабочей модели (или сохранённой) — в «Тренды» |
| Показать | Галочка или «Показать в 3D» / «Скрыть в 3D»; хранится в сохранённом виде |
| «Где используется» | Объекты, которые ссылаются на тренд (мастера оценки и RBF, Э18–Э19): имя, вид, роль |
| «Удалить…» | Тренд, на который есть ссылки, не удаляется: ответ называет до 5 потребителей |

### Ограничения
- Тренды — глобальные; структурные (замеры, опорный каркас) — Э19; выбор тренда в RBF и оценке блочных моделей — Э18–Э19.
- Выборка при оценке больше 2·10⁹ проверок пар (200 тыс. точек — 179 979 проб); вдоль скважин — всё. Ручки эллипсоида при виде ребром к плоскости ручки держат прежнее значение: поверните вид.
- Время (200 тыс. проб; замер `bench`, профиль `full`): 3 оси + вдоль скважин 5,7 с (≤ 15), веер и карта 11,0 с (≤ 20), подбор 3 структур 0,05 с (≤ 3), предпросмотр 0,60 с (≤ 1), первая компиляция ядер 7,05 с (≤ 30), вкладка «Статистика» ≤ 2,2 с. 30 кадров/с ручек — на ПК приёмки.

## Блочные модели
ТЗ 7.31, 8.7, Д-02, Д-13; ADR 0023. Блочная модель — объект проекта: сетка родительских блоков, у каждого блока — поля (содержания, плотность, домен, категория…). Поддерживаются субблоки и поворот вокруг Z; модели до 20 млн блоков. Раздел «Блочные модели» в дереве, подраздел «Фильтры» в нём; модель переносится в `.bfggis`; проект «только просмотр» не даёт писать (создание, расчёты, правка и удаление полей — отказ), показ, срез, отчёт и экспорт работают.

Кнопки — на вкладке «Настройки проекта»:

| Группа | Кнопки (команды) |
|---|---|
| «Блочные модели» | «Фильтры» (`filters.manage`) |
| «Вид» | «Оболочка», «Все блоки», «Скрыть» (`blocks.show`), «Фильтр» (`blocks.filter`), «Срез», «Срез по разрезу», «Срез выше», «Срез ниже», «Убрать срез» (`blocks.slice`), «Настройки» (`blocks.settings`) |
| «Обмен» | «Импорт модели» (`import.files {kind: "blocks"}`), «Экспорт модели» (`blocks.export`) |
| «Создание» | «Прототип» (`blocks.prototype`), «Заполнить каркасами» (`blocks.fill`), «Кодировать каркасами» (`blocks.code`) |
| «Поля» | «Калькулятор» (`blocks.calc`), «Плотность» (`blocks.density`), «Категории» (`blocks.classify`), «Свойства полей» (`blocks.field.props`), «Регуляризация» (`blocks.regularize`), «Содержание–тоннаж» (`blocks.report`) |

- Меню строки модели в дереве: «Свойства», «Показать в 3D», «Скрыть в 3D», «Настройки…», «Экспорт OMF…», «Экспорт…», «Переименовать…», «Удалить…». Меню фильтра: «Изменить», «Где используется», «Удалить…».
- Те же команды — в `Ctrl+K` и у ассистента; горячих клавиш по умолчанию нет. Команда без обязательных параметров открывает своё окно. Ассистент окна «Блочная модель · …» не открывает — правки показа он делает командами `blocks.show`, `blocks.filter`, `blocks.quick`, `blocks.style`. Команды, которые создают или меняют данные (`blocks.prototype`, `.fill`, `.code`, `.regularize`, `.calc`, `.density`, `.classify`, `.rebuild`, `filter.save`, `filter.delete`, удаление и пересчёт поля), у ассистента идут с подтверждением. Блок в точке — `blocks.pick {model_id, x, y, z}`.

### Импорт
«Импорт модели» (или «+» у раздела, или перетаскивание файла на окно) открывает мастер «Импорт файлов»; блочный файл узнаётся по содержимому. Импорт идёт заданием: ход и «Отменить» — на вкладке «Задания»; отмена и сбой ничего не оставляют. Дисковое место проверяется заранее.

| Формат | Что читается |
|---|---|
| Micromine DAT | Типы C, N, R; кодировки cp1251 и BOCU-1; заголовок 4096 или 8192 байта. Блочный файл отличается от таблицы скважин полями центра и размера |
| CSV Micromine | Три строки заголовка: имена, типы, сетка (`x0, dx, y0, dy, z0, dz, CENTRE\|CORNER`) |
| Обычный CSV | Разделитель выбирается в мастере; десятичный знак определяется сам; `<x` читается как x/2 (с предупреждением) |
| Datamine `.dm`, `.fbm` | Блочные модели (Д-13): сетка из заголовка, неявные поля (`XINC`…) — столбцы-константы; IJK из файла не берётся, считается заново; `.fbm` и `.dm` одной модели дают одни и те же блоки. Файл, который не блочная модель, отвергается |
| OMF v1 | Регулярные модели, в том числе повёрнутые вокруг Z (раздел «OMF (Leapfrog)») |

Шаг «Блочная модель» мастера показывает заголовок («формат · блоков N · родителей N · с субблоками»), «Название модели» и «Разделитель» (для текстовых файлов), затем:

- Таблица «Столбец / Тип / Роль / Единица / Найденное». Роль подбирается по названию (центр: `X/Y/Z`, `XC/YC/ZC`, `EAST/NORTH/RL`, `X_CENTRE`, `Centroid X`…; размер: `DX…`, `XINC`, `_EAST`, `DIM_X`, `Size X`…) и правится списком: «Центр X/Y/Z», «Размер DX/DY/DZ», «Поле», «Содержание», «Плотность», «FRAC (доля)», «Код (категория)», «Класс», «Пропустить». Текстовый столбец — категория; число с ролью «Код» или «Класс» тоже становится категорией (до 32 767 подписей). «Единица» (г/т, %, ppm, ppb…) правится, пустая единица остаётся пустой. Столбец «Найденное» говорит, что нашло ядро, и называет коды пустого в этом столбце.
- «Коды "пусто"» — числа вроде −99, которые в файле означают «нет значения» (через «;»). Код, который встречается в файле, предлагается кнопкой «Принять как «пусто»». Пустое значение становится пропуском, а не нулём; в Datamine −1e30 — пропуск сам, −99 предлагается.
- «Сетка модели»: «Начало сетки, м», «Размер родителя, м», «Число ячеек», «Деление на субблоки» (степени двойки 1…128 по оси; поле появляется, если в файле есть субблоки), «Поворот вокруг Z, °» (против часовой стрелки при виде сверху, от −180 не включая до 180) и «Оси центров в файле» («оси проекта» или «оси повёрнутой модели»). Пустое поле — «как в файле»; если сетку по файлу определить нельзя, её задают здесь. Без подсказки начало берётся по минимальным углам блоков и кратно размеру родителя, размер родителя — по самому большому блоку (с предупреждением), число ячеек и деление — по данным.
- «Проверка трёх центров»: центры первой, средней и последней строк файла сверяются с вычисленными по сетке и повороту (допуск 1e−6 м). Не совпали — импорт отклоняется с подсказкой «проверьте начало, размер родителя и угол поворота». Соглашение о повороте — Micromine (угол вокруг Z) или Datamine (`ANGLE1` вокруг оси 3); в мастере оно помечено «предварительно»: повёрнутых образцов пока нет (вопрос № 64), решает проверка трёх центров.
- Отказ со строками: блок за началом сетки, субблок через границу родителя, субблок не по подъячейкам 2^L (в том числе «целые метры» Micromine — вопрос № 63) — «Строки данных (с 1): …» (до 20 строк). Поворот вокруг X или Y — «Поворот вокруг X/Y в v1 не поддерживается».
- Дубликаты (остаётся первая строка) и перекрытия (строки остаются) считаются при импорте и попадают в «Проверки» модели.

### Проверки и «Свойства»
Вкладка «Свойства» окна «Блочная модель · …» (и «Свойства» в дереве) показывает: «Сетка» (число ячеек, шаг или «переменный», начало, охват, поворот, деление, уровни, строк и родителей), «Поля» (тип, единица, роль, значений, пусто, мин., макс., среднее; пропуск — «—»), «Проверки», «Выбранный блок», «Источник» (импорт, «Создана: Заполнение каркасами / Кодирование каркасами / Прототип / Регуляризация / Калькулятор»), «Не перенесено при импорте». Если модель «устарела» (изменились каркасы или модель, из которых она получена), вверху — предупреждение с причиной.

Проверки (7.31): блоки за началом сетки, субблоки через границу родителя, дубликаты, перекрытия, пустые поля (ни одного значения), постоянные поля (все значения равны), объём. Перекрытия считаются точно на сетке наименьшего блока, а если в родителе больше 6·10⁷ подъячеек — по сумме объёмов в родительской ячейке (метод «по объёму»). Примеры строк — до 20.

Проверки пересчитывает только задание `blocks.check` (`POST /blocks/{id}/check`; версия модели не меняется). Кнопки «Перепроверить» в окне нет, а после заполнения, регуляризации, калькулятора и кодирования проверки сами не пересчитываются — см. «Ограничения».

### Прототип
«Прототип» — окно «Прототип модели»: пустая сетка по охвату объектов.

| Область | Что задаёт |
|---|---|
| «Охват» | «Объекты охвата» (каркасы, слои линий, блочные модели) или границы вручную; «Отступ от охвата, м» |
| «Блок» | «Размер X/Y/Z, м» (одно число или `X; Y; Z`); «Поворот вокруг Z, °»; начало сетки кратно размеру блока |
| «Субблоки» | «Уровни L по X/Y/Z» (0 — без дробления, не больше 7; уровень делит блок пополам по оси) |
| флажок | «Все родители заняты» — в модели будет строка на каждого родителя, даже пока в ней нет данных (вопрос № 66) |
| «Имя» | Имя модели |

«Предпросмотр» показывает «Родителей» (nx·ny·nz, не больше 2·10⁹), «Субблоки», объём на диске и «Занято …»; в 3D-окне рисуется рамка сетки с линиями родителей. «Создать» — модель без строк в разделе «Блочные модели».

### Заполнение и кодирование каркасами
«Заполнить каркасами» — окно «Заполнить каркасами»: из прототипа получается новая модель с полями кода и доли объёма. «Кодировать каркасами» — то же на готовой модели.

| Область | Что задаёт |
|---|---|
| «Прототип» / «Модель» | Источник |
| «Каркасы» | Список замкнутых каркасов: код (по умолчанию — имя каркаса) и приоритет (больше — главнее; пусто — по порядку списка; при равных главнее верхний). Незамкнутый каркас — отказ с причиной |
| «Режим» | «Внутри каркасов», «Снаружи каркасов» (код «вне» — «Код снаружи»), «Внутри и снаружи» |
| «Дробление» (заполнение) | «Уровни» L по осям (по умолчанию — уровни прототипа) и «Точек подсетки» m (1–16): доля объёма FRAC — доля из m × m × m точек внутри тела |
| «Способ» (кодирование) | «Поля той же модели; субблоки не меняются» (по центру блока) или «Новая модель: граничные блоки делятся на субблоки» («‹имя› (кодирование)») |
| «Поля и имя» | «Поле кода», «Поле доли объёма», имя новой модели |

- Блок, пересекаемый поверхностью каркаса, получает код и FRAC по m³ точкам подсетки, а не по одному центру (отклонение от дословного текста 8.7.3 п. 3, иначе объём граничных блоков занижается — вопрос № 72); не пересекаемые блоки — по центру. Сумма «внутри» и «снаружи» равна объёму сетки.
- Несколько каркасов: точка принадлежит телу с наибольшим приоритетом. Результат не зависит от числа потоков.
- Ход — по стадиям «Каркасы», «Столбцы», «Граничные родители», «Дробление», «Слияние», «Запись»; итог: строк, кодов, объёмов. «Отменить» ничего не оставляет.
- Результат заполнения запоминает каркасы, из которых он получен. Изменился каркас — модель «устарела»; «Перестроить» (см. «Свойства полей») пересчитывает её. Перестройка «на месте» удаляет поля других операций — окно спрашивает об этом до запуска.

### Регуляризация
«Регуляризация» — окно «Регуляризация»: новая регулярная модель с другим размером блока в тех же осях (начало кратно новому размеру, поворот прежний). Нужна, чтобы получить модель без субблоков (например, для OMF и Leapfrog).

- «Новый блок» — размер X/Y/Z (по умолчанию удвоенный). «Поля и содержания» — какие числовые поля переносить («Выбранные») и «по объёму» или «по тоннажу» для каждого; «Плотность» — поле или постоянная т/м³ (нужна для весов по тоннажу и металла). «Категории» — категорийные поля: категория нового блока — мода по объёму, доля каждого кода — поля `P_<КОД>` (блоки без категории дают пропуск).
- Объём, тоннаж и металл сохраняются (допуск 1e−9). В результате всегда есть поле `FRAC` — доля покрытого объёма; пропуск не превращается в ноль. Итог показывает суммы «до» и «после». Слишком большой накопительный слой (> 3 ГБ) — отказ с подсказкой (`block_model_too_large`).

### Фильтры (библиотека, Д-02)
«Фильтры» (`filters.manage`) — окно «Фильтры»: библиотека фильтров проекта. Фильтр — именованный объект (раздел «Блочные модели» → «Фильтры» в дереве); один фильтр применим к любой модели, у которой есть нужные поля. Модель без поля — ошибка по-русски с подсказкой («Читает поля: …»).

- Слева список («Новый», «Копировать», «Удалить…»), справа: «Имя», «Примечание», правила в двух видах — «Конструктор» и текст выражения 8.7.4 (переключение без потерь). Правила: группы «И», «ИЛИ», «НЕ»; условие «поле — оператор — значение» (`=`, `<>`, `>`, `>=`, `<`, `<=`, «пусто», «не пусто», «в списке»; для категорий — подпись); «Выражение» языка калькулятора; «Каркас» («внутри каркаса» / «снаружи каркаса», «по центру» или «по доле» с «Подсеткой доли m»); «Поверхность» («выше поверхности» / «ниже поверхности», ЦТМ первыми в списке; «по центру» или «по доле»). У фильтра с каркасом или поверхностью текста выражения нет — только конструктор.
- «Проверить на модели» — сколько блоков модели проходит фильтр. «Где используется» — объекты и виды, которые используют фильтр. Используемый фильтр не удаляется: отказ со списком потребителей. Если фильтр изменили в другом месте, сохранение отклоняется (409 `version_conflict`) — перечитайте фильтр. Несохранённые правки в окне при открытии другого фильтра — вопрос «Заменить?».
- Блок проходит фильтр, если его доля больше нуля: условие даёт 0 или 1; каркас и поверхность «по доле» — долю блока; «И» — произведение, «ИЛИ» — максимум, «НЕ» — 1 − доля (вопрос № 65). Блок, частично попавший в ограничитель, проходит; в отчёте «Содержание–тоннаж» он входит с весом, равным доле.
- Фильтр используется в показе, калькуляторе, плотности, категориях, отчёте, экспорте и в swath; в таблицах скважин фильтры остаются на движке Э4 (вопрос № 67). Лист с каркасом или поверхностью, которых нет (удалены или не попали в `.bfggis`), — «недоступен»: доля 0 с предупреждением.
- Фильтр переносится в `.bfggis`; идентификаторы каркасов в нём перенумеровываются при импорте.

### Показ в 3D
«Оболочка» (`blocks.show`) показывает внешнюю оболочку блоков, прошедших фильтр; «Все блоки» — каждую ячейку с рёбрами (до лимита граней); «Скрыть» убирает модель из 3D. Первый показ идёт без раскраски — одним цветом; поле раскраски задаёт окно или `blocks.style`.

- Оболочку считает ядро: грань видна, если сосед за ней — не «полный и прошедший» родитель; одноцветные соседние грани сливаются в прямоугольники. Цель — показ не дольше 3 с; повтор — из кеша. Если запрос обогнал новый (двигаете границы), прежний отменяется молча; старый слой остаётся до нового.
- Лимит граней — 5 млн (в «Показе» «Лимит граней, млн» 0,5–10). Больше лимита — модель показана укрупнённо (родители 2×2×2, 4×4×4…; среднее по объёму, для категорий — мода): в строке состояния «упрощено», в окне — предупреждение. Увеличьте лимит или ограничьте показ фильтром.
- Щелчок по блоку в 3D — «Выбранный блок» (ячейка, центр, размер, значения полей; «скрыт фильтром», если блок не проходит фильтр; пропуск — «—»); то же — в «Свойствах» и в строке состояния. Блок ищется по точке щелчка, в том числе на укрупнённой модели.
- Срез: «Срез» (`blocks.slice`) — плоскость (по умолчанию горизонтальная в середине модели, либо по разрезу, если он нарисован); «Срез выше» / «Срез ниже» сдвигают плоскость на ячейку; «Срез по разрезу» ставит плоскость текущего разреза; «Убрать срез». Срез — значения поля в плоскости цветом (регулярная модель — по ячейкам, с субблоками — растр по подъячейкам до 4096 × 4096); в 3D это подложка под остальными слоями; смена палитры не запрашивает ядро. Многоугольники сечения нужны для печати (Э22) — на экране их нет.

#### Окно «Блочная модель · ‹модель›»
«Настройки» (`blocks.settings`, «Настройки…» в меню модели) — плавающее окно, по одному на модель. Всё применяется сразу и запоминается в виде проекта для этой модели (`block_styles`).

| Вкладка | Что в ней |
|---|---|
| «Показ» | «Показать в 3D» / «Скрыть»; «Режим показа» («Только грани блоков, видимые снаружи» или «Каждая ячейка с рёбрами, до лимита граней»); «Раскраска»: «Поле раскраски» и «Вид раскраски» — «Шкала» (границы «от» и «до», «Логарифмическая шкала», «Взять границы, которые ядро выбрало по данным поля»), «Градации» (границы через «;») или «Категории» (цвет у каждой подписи; снять флажок — скрыть блоки категории); «Палитра»; «Рёбра» (цвет, толщина) и «Непрозрачность»; «Лимит граней, млн». Пустые границы — ядро берёт минимум и максимум поля |
| «Фильтр» | «Фильтр из библиотеки» (список), «Фильтры…» (окно библиотеки), «Быстрый ограничитель → фильтр» (сохранить условия вкладки в библиотеку под именем) |
| «Быстрый ограничитель» | Свои строки «поле — оператор — значение» без библиотеки; «Как объединить» — «И» (все условия) или «ИЛИ» (любое); «Показать блоки, которые условия не пропускают (НЕ)» — обратный фильтр. Значение с ошибкой не записывается (до ≤ от, логарифм от ≤ 0, не возрастающие границы — сообщение у поля) |
| «Легенда» | Что означают цвета сейчас: шкала с границами, градации, категории с кодами и скрытыми подписями |
| «Свойства» | См. раздел «Проверки и «Свойства»» |

- Вкладки переключаются стрелками, `Home` и `End`.
- Быстрый ограничитель и фильтр работают вместе: блок показан, если проходит оба. Полное дерево (группы, каркасы, поверхности) в быстрый ограничитель не записать — для него фильтр библиотеки.
- У поля с пропусками блоки без значения рисуются цветом «нет значения» (его легенда называет отдельно), а не цветом нуля.

### Калькулятор
«Калькулятор» — вкладка «Калькулятор» окна «Поля блочной модели · ‹модель›» (в окне ещё «Плотность», «Категории», «Свойства полей»; те же вкладки открывают кнопки группы «Поля»). Новое поле считается по выражению; вычисление идёт заданием, поле записывается целиком или не записывается («Отменить»).

- Форма: «Модель», «Имя» нового поля, «Выражение» (с подсказкой функций и вставкой полей модели), «Тип» («по выражению» — число, «условие (0 или 1)» или «категория», если `IF` даёт текст; можно задать «число», «условие» или «категорию» явно), «Единица», «Описание», «Фильтр библиотеки» и быстрый ограничитель, «Вне ограничителя»: «оставить прежнее значение (у нового поля — пусто)» или «пусто (NaN)». «Проверить» показывает тип результата, прочитанные поля и место ошибки.
- Язык (8.7.4): операторы `+ − * / ^ ( )`; сравнения `= <> < <= > >=`; `AND`, `OR`, `NOT` (без учёта регистра; русских «И/ИЛИ/НЕ» нет); `IN ('A', 'B')`; функции `ABS SQRT LN LOG10 EXP MIN MAX ROUND(x, n) FLOOR CEIL CLIP(x, a, b) IF(усл, a, b) ISNULL(x) COALESCE(x, y)`. Поле — имя или `[имя с пробелами]`; строки — в одинарных кавычках. Выражение — не длиннее 4000 символов и глубиной не больше 64. `__import__('os')` и подобное — синтаксическая ошибка, ничего не выполняется.
- Место ошибки показано строкой, столбцом и кареткой под символом. Модели не хватает поля — ошибка с названием поля.
- Правила пропусков: арифметика с пропуском — пропуск; сравнение с пропуском — «ложь» (поэтому обратный фильтр — дополнение прошедших); `IF`, у которого в условии пропуск, даёт пропуск; `x/0`, `LN(0)`, `SQRT(−1)` и переполнение — пропуск, а не ∞; `ROUND` — от нуля (2,5 → 3). Результат с пропуском в целом поле — пусто (null), не 0. Категория сравнивается с текстом по подписи, с числом — по числу в подписи.
- Условие, записанное в поле «условие (0 или 1)», при пропуске даёт 0, а `IF` в той же ситуации — пропуск (вопрос № 75): пропуск в условии лучше проверять `ISNULL`.
- Имя занято — «Заменить поле»: окно спрашивает, прежние значения пропадут, единица и описание не переносятся; роль сохраняется, если подходит новому типу. Выражение может читать заменяемое поле (`AU = AU + 1`). Ассистент без `replace: true` заменить поле не может — отказ с подсказкой.
- Поле запоминает выражение, фильтр и входные поля; когда они изменились, оно «устарело» (см. «Свойства полей»).

### Плотность
Вкладка «Плотность»: «Способ задания плотности» — «Постоянная» (т/м³), «Поле модели» (числовое поле), «Таблица по домену» (строка на каждую подпись категории или число поля домена; «Плотность домена вне таблицы»), «Формула» (выражение 8.7.4). Блок без значения получает «Плотность «по умолчанию», т/м³» и пометку в поле источника: пишутся два поля — плотность (роль «плотность», т/м³) и источник (по умолчанию `DENS_SRC`: 0 — своё значение, 1 — по умолчанию); без значения по умолчанию пропуск остаётся пропуском. Плотность ≤ 0 или бесконечная внутри ограничителя — отказ `density_invalid` с подсказкой. Вне ограничителя оба поля остаются пустыми.

### Категории (JORC, ГКЗ)
Вкладка «Категории»: «Схема в справочнике проекта», «Поле оценки» и правила по порядку — первое выполненное правило задаёт категорию блока.

- Схемы: «JORC» (пример 8.7.5: «Измеренные» — `PASS = 1 AND SLOPE >= 0.8 AND NH >= 3 AND AD <= 25`; «Выявленные» — `PASS <= 2 AND SLOPE >= 0.5 AND NH >= 2`; «Предполагаемые» — `1 = 1`, то есть любой блок с оценкой), «ГКЗ» (категории A, B, C1, C2 — шаблон без порогов: пороги задаёт пользователь, иначе «схема не заполнена»), свои схемы. Правила редактируются стрелками «Выше» / «Ниже», «Удалить правило»; «Сохранить схему» записывает их в справочник проекта (код — латиница, цифры, `_`, `-`, до 40 знаков; до 64 правил; нетронутые JORC и ГКЗ в базе не хранятся); «Проверить правила» проверяет условия на модели; изменённая и не сохранённая схема помечена «Свои правила (не сохранены)».
- Имена полей в схемах JORC (`PASS`, `SLOPE`, `NH`, `AD`) — без префикса. Оценка блоков (Э18) пишет поля с префиксом, заданным пользователем; до Э18 схему правят под имена полей или заводят нужные поля калькулятором.
- «Поле оценки»: блок без оценки категории не получает («без оценки — без категории»). Пусто — оценка есть у всех блоков.
- «Каркасы категорий»: блок с оценкой внутри каркаса получает категорию каркаса вместо правила (при нескольких каркасах — первый).
- «Проходов мажоритарного фильтра» (0 — не применять): сглаживание по 27 родителям, равенство голосов — своя категория, иначе меньший код.
- Результат — поле категорий (по умолчанию `CLASS`); итог — число блоков по категориям, «без категории» и «без оценки».

### Свойства полей
«Свойства полей» — вкладка окна «Поля блочной модели»: таблица полей выбранной модели.

| Что | Как |
|---|---|
| «Единица», «Описание», «Роль» | Правятся и записываются кнопкой «Сохранить» (пустое значение очищает). Роли: число — «содержание», «плотность», «FRAC (доля)»; категория — «код», «класс». Доля (FRAC) допускается при значениях в [0; 1], плотность — при значениях > 0; второе поле с ролью «FRAC» — отказ |
| «Откуда» | Операция, которая создала поле, и её параметры |
| «устарел» | Поле «устарело», если изменились данные, из которых оно получено: входные поля, каркасы, правила фильтра. Причина названа в «Свойствах поля» |
| «Перестроить» | Пересчёт поля по тем же параметрам (калькулятор, плотность, категории, заполнение, кодирование с дроблением, регуляризация). Поле из файла импорта перестроить нельзя |
| «Где используется» | Другие поля модели, чьё правило читает это поле, виды проекта и сохранённые виды (раскраска, быстрый ограничитель, фильтр) |
| «Удалить» | Поле, которое используется, и обязательное поле (с ролью «FRAC») не удаляются: отказ со списком «Где используется». |

Переименование поля недоступно: имя — ключ колонки, ссылок в фильтрах, видах и выражениях (вопрос № 74); «создайте поле калькулятором и удалите старое». Единицу металла в отчёте определяет единица поля содержания.

### Содержание–тоннаж
«Содержание–тоннаж» — окно «Содержание–тоннаж · ‹модель›» (ТЗ 7.31): отчёт по бортам. Слева запрос, справа результат.

| Поле запроса | Назначение |
|---|---|
| «Модель», «Содержания» | До 20 содержаний; по умолчанию — поля `*_CUT` или поля с ролью «содержание» |
| «Плотность» | Поле или постоянная, т/м³; по умолчанию — меняющееся поле `SG`; постоянное `DENSITY` = 2,6 пропускается |
| «Борта», «Поле борта» | Борта через «;», например `0; 0,5; 1` (до 200); блок проходит борт «≥» (поле борта — по умолчанию первое из содержаний). **Борт 0 даёт полный тоннаж блоков, у которых есть значение поля борта** |
| «Фильтр библиотеки», быстрый ограничитель | Отбор блоков; вес блока — его доля |
| «Категории и группы» | «Поле категорий» и отбор подписей; «Группы по полю» — отдельные строки таблицы для каждой категории (до 1000 подписей; «(пусто)» — блоки без категории) |
| «Точек кривой» | 0 — без кривой, иначе 2…500 |

Тоннаж = объём × FRAC × доля фильтра × плотность. Содержание — среднее, взвешенное тоннажем блоков, у которых оно есть (в таблице отмечены блоки строки, в которых нет значения этого содержания). Блок без значения поля борта не проходит ни один борт. «Не вошли в расчёт» называет блоки, отсечённые фильтром, без плотности, без объёма, без значения борта. Нет содержания ни у одного блока — «—», не 0.

Металл: г/т и ppm — в тыс. унций (31,1034768 г в унции), % — в тоннах; другая единица — «Металл не считается: единица содержания не распознана». ppb пересчитывается по контракту ядра (в кг); единица металла для ppb — на подтверждении (вопрос № 73).

Справа: таблица (борт, блоков, объём, тоннаж, содержания, металл), «Кривая» «содержание–тоннаж» (переключатель «Содержание» / «Металл»; пропуск рвёт линию, а не рисуется нулём), «Копировать CSV» и «Сохранить CSV…». CSV таблицы — «;», десятичная запятая, CRLF, без BOM (для Excel); CSV кривой — с десятичной точкой («CSV кривой» в панели графика). Суммирование идёт в порядке строк: результат побитно повторяется при любом числе потоков. Отчёт работает и в проекте «только просмотр».

### Swath plot по блокам
В окне «SWATH PLOT» у ряда блочной модели есть «Фильтр» — фильтр библиотеки («без фильтра» — все блоки); потерянный фильтр помечен «Фильтр № N (не найден)», ошибки фильтра показаны в карточке ряда. Счётчик «отфильтровано N» — блоки, не прошедшие отбор или фильтр. Модели с субблоками и поворотом вокруг Z поддерживаются: блок делится между полосами пропорционально пересечению (поворот, субблоки, FRAC), в ответе — примечание; результат не зависит от числа потоков. Пробы «внутри блоков» для рядов с поворотом или субблоками не поддерживаются.

### Экспорт
«Экспорт модели» (`blocks.export`; «Экспорт…» в меню модели) — окно «Экспорт блочной модели»: «Модель», «Формат», «Поля», «Отбор блоков», «Запись», «Файл» («Сохранить как…»), «Экспортировать». Ход — на вкладке «Задания», «Отменить».

| Формат | Что пишется |
|---|---|
| Micromine DAT | Столбцы `X, Y, Z` (центр в осях проекта), `DX, DY, DZ` (размер по осям модели) и поля; сетка (начало, число ячеек, размер, поворот, деление) — в XML-шапке файла; имена полей режутся до 10 знаков (предупреждение); кодировка cp1251, BOCU-1 или UTF-8 |
| CSV | Те же столбцы; «Заголовок» — простой или Micromine (три строки: имена, типы, сетка); у повёрнутой модели и модели с переменным шагом строки сетки нет (предупреждение); «Разделитель» (`;`, `,`, табуляция, `|`), «Десятичный знак», кодировка (utf-8-sig, utf-8, cp1251, cp866, koi8-r, utf-16) |
| Apache Parquet | `idx` (номер родителя), у модели с субблоками — `sx…wz`, затем `X, Y, Z, DX, DY, DZ` и поля; сетка и поля — в метаданных `bf2.block_model`; пропуск — пустое значение |
| OMF v1 (Leapfrog OMF 0.9) | Регулярные модели; повёрнутая вокруг Z — через оси `axis_u/v`; нужно хотя бы одно поле; модель с субблоками — **только после регуляризации**; поворот вокруг X/Y — «Поворот вокруг X/Y в v1 не поддерживается» |

- «Отбор блоков»: фильтр библиотеки и быстрый ограничитель вместе; записываются блоки, чья доля больше нуля. Поле, имя которого совпало с `X, Y, Z, DX, DY, DZ` (в Parquet ещё `idx`, `sx…`), пишется как `имя_2` с предупреждением. Пропуск пишется пустым значением, не нулём; для DAT и CSV флажок «Писать пропуск числом» задаёт число вместо пропуска (например −99; число, уже занятое значением поля, — отказ).
- Файл уже есть — окно «Заменить?»; без согласия файл не меняется. Путь внутри папки проекта — отказ. Отмена и сбой файла не оставляют.
- Экспорт идёт заданием и работает в проекте «только просмотр». Цикл «экспорт → импорт» DAT, CSV, Parquet возвращает координаты и значения побитно (OMF — с точностью до формата).
- «Экспорт проекта» → «Объекты в файлы» (Д-17) пишет модель целиком, с перезаписью одноимённого файла, в DAT, CSV, Parquet или OMF. Datamine DM не экспортируется.
- У ассистента `blocks.export` перезаписывает файл при `overwrite: true` без отдельного подтверждения (как прочие экспорты).

### Время (синтетика, 20 млн блоков)
Замеры по ходу этапа (Linux, 4 ядра, синтетика `tools/gen`; сводная таблица `bench` — «см. таблицу замеров 17.39» в ADR 0023): калькулятор над 5 полями — 2,5 с (цель ≤ 5); фильтр + оболочка — 2,1–2,4 с (≤ 3); срез ⟂Z — 0,02 с, ⟂X — 0,2 с, косой — 0,45 с (≤ 1); блок по точке из кеша — 26–51 мс (≤ 100); регуляризация 20 → 2,67 млн — 5,3–6,4 с (≤ 60); категории — 1,8 с (≤ 10); плотность — 0,8–1,5 с; отчёт — 2,85–3,6 с; заполнение каркасом 10⁶ треугольников — 19,7 с (4 потока), 46,4 с (1 поток) (≤ 180 с, ≤ 3 ГБ; память 0,96 ГБ); прототип 37 млн родителей — 15 мс; импорт DAT 20 млн × 20 полей — 58,8 с, 1,86 ГБ (≤ 8 мин, ≤ 4 ГБ), DM 20 млн — 58 с; экспорт CSV 20 × 20 — 77 с, DAT 20 млн × 10 полей — 9,8 с; первая компиляция ядер блоков ≈ 23 с (≤ 30), из кеша 1,7 с. Частота кадров на встроенной графике (Т8.7-10) и реальные файлы — на ПК приёмки.

### Ограничения
- Только поворот вокруг Z (8.7.1); вокруг X/Y — отказ при импорте и экспорте. Субблоки — степени двойки по оси (до 2⁷); «целые метры» Micromine (№ 63) отвергаются со строками.
- Соглашение о повороте Datamine и Micromine — «предварительно» (вопрос № 64): образцов повёрнутых и субблочных файлов нет, ориентир — проверка трёх центров.
- Порядок строк модели — по номеру родителя и субблоку (как в Э11), а не по коду Мортона (вопрос № 62).
- Не уложились в цель на синтетике 20 млн: мажоритарный фильтр, один проход — 13,75 с (цель 10 с; сам фильтр необязателен, по умолчанию 0 проходов); показ модели с субблоками при первом запросе — 3,8 с (> 3 с, разовое чтение Parquet; повтор — из кеша); фильтр с ≈ 3 млн граней — 3,6–3,8 с; «все блоки» при укрупнении (≈ 120 млн граней) — 4,9 с; блок по точке на холодном пути (кеш столбцов не создан) — 106–173 мс (> 100 мс; по кешу — 26–51 мс); swath с поворотом — 2,6 с (без поворота — 0,3 с, как в Э13).
- Нет автоматического пересчёта проверок после операций над моделью; кнопки «Перепроверить» в окне нет (задание `blocks.check` есть в ядре).
- Переименование поля недоступно (вопрос № 74); число в условии i1-поля при пропуске даёт 0 (вопрос № 75); единица металла для ppb — вопрос № 73.
- Фильтры и вычисляемые колонки таблиц скважин остаются на движке Э4 (вопрос № 67); экспорта Datamine DM нет; печать срезов — Э22; оценка содержаний — Э18.
- Окно «Блочная модель · …»: цвета палитр — для данных (не из фирменной палитры), «Взять раскраску» и «Сохранить…» в библиотеку стилей в окне пока нет (раскраска хранится в виде проекта).
- Файлы заказчика (повёрнутые и субблочные DM и DAT, модель 10–20 млн блоков — вопросы № 64, 70), реальная Windows 11 и встроенная графика не проверялись.

## Экспорт проекта: объекты в файлы

Окно: таблица «Тип объектов» — «Объектов» — «Формат» (галочка типа, список форматов; недоступный формат — с причиной), «Папка» («Выбрать папку…»), «Экспортировать». Из менеджера данных «Экспорт…» открывает окно с выбранными объектами («Только выбранные объекты: N»).

| Тип | Форматы (первый — по умолчанию) |
|---|---|

| Каркасы | DXF, DWG (нужен ODA), TRIDB, OBJ, STL, Surpac DTM, OMF |

| Облака точек | LAS, CSV |
| Растры | «Исходный файл» с привязкой, GeoTIFF |
| Блочные модели | OMF, DAT, CSV, Parquet (модель целиком) |

Для всего, что загружено из файла, есть «Исходный файл» — копия байт в байт.

- Результат — папка «‹Проект› — экспорт ГГГГ-ММ-ДД» (при повторе в тот же день — « (2)») в выбранной папке; внутри «Скважины», «Каркасы», «ЦТМ», «Линии», «Облака точек», «Растры», «Блочные модели» и папки пользователя. Существующие файлы не меняются.

- Что пропускается, видно в отчёте с причиной: объект без исходного файла при формате «Исходный файл»; формат, который не записывается (DWG без ODA); объект, который писатель отклонил.
- Имена приводятся к допустимым для Windows: запрещённые символы и `CON`, `AUX`, `COM1` и т. п. заменяются, точки и пробелы в конце убираются, длинный путь (до 259) сокращается, повторы без учёта регистра получают « (2)».
- Проект открыт только для чтения — экспорт недоступен.
- Команда `project.export {formats, folder, types?}` у ассистента — с подтверждением; без параметров — окно `.bfggis`.

## Задания
Вкладка «Задания» нижней панели (`Ctrl+K` → «Задания») — долгие операции (экспорт, импорт) идут в фоне.

| Колонка | Что показывает |
|---|---|
| № | Номер задания |
| Задание | Название; щелчок открывает журнал («Скопировать», «Сохранить .txt») |
| Состояние | «В очереди», «Выполняется», «Готово», «Ошибка», «Отменено»; после запроса отмены — «Отмена…» |
| Ход | Процент, сообщение, полоса |

| Кнопка | Когда |
|---|---|
| «Отменить» | В очереди или выполняется; в очереди — сразу, выполняется — на ближайшем шаге; ничего неполного не остаётся |
| «Повторить» | Задание в состоянии «Ошибка» |
| «Показать в папке» | Готовый экспорт |
| «Открыть проект» | Готовый импорт |
| «Очистить выполненные» | Есть готовые или отменённые задания (флажок «и с ошибкой» добавляет «Ошибка») |

«Очистить выполненные» после подтверждения «Убрать N заданий из списка?» убирает готовые и отменённые задания с их журналами; задания в очереди и выполняемые не трогаются, файлы экспортов остаются. Нет выполненных — кнопка недоступна («Нет выполненных заданий»). В проекте «только чтение» — понятная ошибка. Та же команда: «Настройки проекта» › «Обслуживание» › «Очистить выполненные задания».

**Почему задание ждёт** (под названием): «Нет работающего исполнителя…» с кнопкой «Перезапустить исполнителей»; «Впереди заданий: N, №… выполняется M мин»; нехватка памяти.
Если исполнитель прервался посреди задания, оно возвращается в очередь; после 3 неудач (для импорта — 2) — «Ошибка».
