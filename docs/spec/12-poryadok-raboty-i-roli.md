## 12. Порядок работы и роли

### 12.1. Общая схема

| **Уровень**   | **Единица**                                    | **Правило**                                                                      |
|---------------|------------------------------------------------|----------------------------------------------------------------------------------|
| Веха (В1–В6)  | Одна облачная сессия Claude Code               | Новая веха — новая сессия с чистым контекстом; модель выбирается в начале сессии |
| Этап (Э0–Э26) | Один PR                                        | PR из ветки сессии в `main`; этап закрыт, когда выполнена готовность 10.5        |
| Подшаг этапа  | 30–45 минут работы, один проверяемый результат | Заканчивается чекпойнтом (15.2)                                                  |

### 12.2. Цикл этапа

1.  Прочитать `CLAUDE.md`, `PROGRESS.md` и **только** файлы `docs/spec/`, указанные для этапа в `docs/spec/00-index.md`.

2.  Записать план этапа в `PROGRESS.md`: 4–10 подшагов, у каждого — результат и способ проверки.

3.  Открыть черновой PR этапа (CI начнёт проверять каждый пуш).

4.  Для каждого подшага: выполнить сам или поручить субагенту (12.3) → тесты через `test-runner` → чекпойнт.

5.  В конце этапа: полный набор тестов, замеры, ревью субагентом `reviewer`, документация (10.5), описание PR по шаблону (Приложение Ж).

6.  Дождаться зелёного CI (подписка на события PR, без опроса), слить PR (16.5), обновить ветку от `main`.

7.  Перейти к следующему этапу. На последнем этапе вехи — отчёт вехи и остановка.

### 12.3. Роли

| **Роль**          | **Кто**         | **Модель / усилия**                               | **Инструменты**                     | **Возвращает**                                                    |
|-------------------|-----------------|---------------------------------------------------|-------------------------------------|-------------------------------------------------------------------|
| Оркестратор       | Основная сессия | Opus 5.5 / high                                   | Все                                 | —                                                                 |
| `architect`       | Субагент        | Fable 5.2 / xhigh                                 | Чтение, поиск                       | Проект решения ≤ 150 строк: варианты, выбор, риски, план подшагов |
| `kernel-engineer` | Субагент        | Fable 5.2 / xhigh (запасной — Opus 5.5 / xhigh)   | Все                                 | Отчёт ≤ 40 строк: файлы, тесты, точность, замеры, нерешённое      |
| `reviewer`        | Субагент        | Opus 5.5 / high (Э24 безопасность — Fable / high) | Чтение, поиск, Bash (только тесты)  | Список находок по важности с `файл:строка`, ≤ 40 строк            |
| `test-runner`     | Субагент        | Haiku 5.5 / low                                   | Bash, чтение                        | Итог: прошло/упало; для упавших — имя теста, 10 строк трассы      |
| `explorer`        | Субагент        | Haiku 5.5 / low                                   | Чтение, поиск, Bash (только чтение) | Пути, номера строк, выдержки ≤ 40 строк                           |
| `docs-writer`     | Субагент        | Sonnet 5.5 / medium                               | Чтение, запись `docs/`              | Изменённые файлы, ≤ 10 строк                                      |

### 12.4. Правила делегирования

- Не больше **2 субагентов одновременно** (в BF Fable + 6 фоновых субагентов выбрали 5-часовой лимит за 73 минуты).

- Субагент получает полный бриф: цель, файлы, ограничения, критерии готовности, формат и предельный размер отчёта.

- Поиск по коду BF, чтение длинных файлов, логов и вывода тестов — всегда через `explorer` или `test-runner`, чтобы шум не попадал в контекст оркестратора.

- Оркестратор не повторяет работу субагента и не перечитывает файлы, которые тот уже изучил, — пользуется его отчётом.

- Отчёт субагента проверяется выборочно: тест запускается, ключевой фрагмент кода просматривается.

### 12.5. Вопросы и блокеры

- Исполнитель не останавливается из-за вопроса, если есть разумное решение по умолчанию: принимает его, записывает в `docs/adr/` и в `PROGRESS.md` («Допущения»), выносит в отчёт вехи.

- Блокер, который не обойти (нужен файл заказчика, сертификат, доступ), — в `PROGRESS.md` «Блокеры», переход к независимому этапу.

- Остановка до вехи — только если блокеры не дают продолжить ни один этап. Сообщение — короткая таблица и нумерованные варианты ответа.
