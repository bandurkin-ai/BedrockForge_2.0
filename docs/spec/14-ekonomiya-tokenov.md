### 14.2. Правила

1.  **Одна веха — одна сессия.** Не возвращаться в старую длинную сессию после перерыва — начинать новую с промтом возобновления.

2.  **Модель основной сессии не меняется внутри вехи**; другие модели — только через субагентов (13.3).

3.  **Контекст оркестратора — не больше 300–400 тыс. токенов**: `/autocompact 400k` при старте; шум (поиск, логи, тесты) — в субагентах; отчёты субагентов — короткие.

4.  **ТЗ читается частями**: на Э0 документ разбивается на `docs/spec/NN-*.md` и `docs/spec/00-index.md` («этап → файлы»); на этапе читаются только нужные файлы. Целиком ТЗ читается один раз — на Э0.

5.  **CLAUDE.md ≤ 200 строк**: правила, команды, структура, ссылки. Подробности — в `docs/`; редкие процедуры — в `.claude/agents/` и `docs/`.

6.  **PROGRESS.md ≤ 150 строк**: только текущая веха; история — в `docs/progress/history.md` (не читается без нужды).

7.  **Не читать большие файлы целиком**: поиск `rg`, чтение диапазонами; файлы \> 600 строк делить при разработке.

8.  **Вывод команд — коротко**: `pytest -q -x --tb=short`, `vitest run --reporter=dot`, сборка — только ошибки; длинный вывод — через `test-runner`, который возвращает только упавшее.

9.  **Во время разработки — целевые тесты** (изменённый модуль); полный набор — перед слиянием этапа (и в CI).

10. **Не опрашивать CI**: подписка на события PR; ждать события, а не спрашивать статус.

11. **Переносить проверенный код BF**, а не писать заново (Приложение Е): `explorer` находит файл, оркестратор читает только его и переносит с тестами.

12. **Решения — один раз**: принятое решение записывается в `docs/adr/` и не обсуждается заново; при сомнении — прочитать ADR, а не рассуждать с нуля.

13. **Генерировать, а не дублировать**: типы фронта — из OpenAPI; инструменты ассистента — из реестра команд; таблицы документации — скриптами, где возможно.

14. **Не больше 2 субагентов одновременно**; Fable — только для ядер и проектирования.

15. **Один подшаг — одна задача**: не объединять несколько функций в одном большом ходе.

16. **Не повторять неудачную попытку тем же способом**: после двух неудач — записать в `PROGRESS.md` и сменить подход или вынести в блокер.

17. **Сжатие — на границе этапа**, пока кэш тёплый: если контекст \> 300 тыс. и этап завершён, заказчик (или автосжатие) делает `/compact` с фокусом из раздела «Compact instructions» `CLAUDE.md`.

18. **Простые вопросы заказчик задаёт в отдельной короткой сессии** (на Haiku или Sonnet), а не в сессии вехи.

19. **Ответы заказчику — короткие**: таблица, итог, нумерованные варианты.
