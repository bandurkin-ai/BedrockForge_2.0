### 9.2. Micromine DAT

| **Часть**      | **Устройство**                                                                                                                                                                                                                                                                                                    |
|----------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Начало         | `THIS IS MICROMINE EXTENDED DATA FILE` (по справке — 42 символа; заголовки Standard и Extended)                                                                                                                                                                                                                   |
| Заголовок      | XML: `title`, `encoding` (`codepage`), `field-class` на поле. Страница 4096 байт; у экспорта моделей — до 8192, кодовую страницу искать по всему заголовку                                                                                                                                                        |
| Поля           | С 4096 (8192): `N VARIABLES`, N строк `ИМЯ ТИП ШИРИНА ДЕСЯТИЧНЫЕ`. Имя из 10 символов — тип вплотную (`RUN_AU_CUTN 12 8`); новые версии пишут `ИМЯ C 1 0|описание`                                                                                                                                                |
| Записи         | Фиксированной длины + `CRLF`; чтение столбцами через `memmap` порциями                                                                                                                                                                                                                                            |
| Типы           | `C` текст с пробелами; `R` double LE; `N` число текстом; по размеру (в файлах не встречались) `F` float32, `L` int32, `S` int16, `B` byte                                                                                                                                                                         |
| Кодировки      | `ibm-5347` = cp1251 (в файлах `ibm-5347_P100-1998`, суффикс ICU отбрасывается), `ibm-1251`, `windows-1251`, `ibm-5348`/`windows-1252`, `utf-8`, `ascii`. `BOCU-1`: каждое имя и значение C/N кодируется отдельно (ASCII = байт + 0x50); свой декодер сверен с ICU 74; без кодовой страницы распознаётся по байтам |
| Блочная модель | Micromine `X, Y, Z` + `_X, _Y, _Z` (и `_EAST, _NORTH, _RL`), Datamine `XC, YC, ZC` + `XINC, YINC, ZINC`. Субблоки — целые метры, не степени двойки. Начало родительской сетки — где стоят блоки полного размера. Без размеров — регулярная (шаг центров или строка сетки)                                         |
| Micromine CSV  | 3 строки: имена; типы (`DOUBLE`, `NUMERIC`, `CHARACTER`); сетка `x0, dx, y0, dy, z0, dz, CENTRE` или `CORNER`                                                                                                                                                                                                     |
| По справке     | Центроиды назначает пользователь, `_`-поля — размеры, метаданные в заголовке или `.metax`, индексы в `METADATA`                                                                                                                                                                                                   |

Ловушки из коммитов: заголовок \> 4096 (`314394c`), 10-символьное имя и суффикс ICU (`a1147b9`), `|описание` (`a84fec7`), `_EAST` (`b90365d`), pandas 3 читает текст как `str`, а не `object` (`8b3c33d`/`0096576`).

### 9.3. Micromine STR

Тот же формат, что DAT. Поля: `EAST`, `NORTH`, `RL` — `R 8`; `JOIN` — `N 12` (число текстом, смена значения = новая линия); `STRING` — `C 20`; свои поля `C` (например, «Участок»); cp1251 в именах и значениях. Замкнута, если первая и последняя точки совпадают. Запись (`write_micromine_str`): магическая строка, XML (title, `ibm-5347_P100-1998`, `field-class` на поле), NUL до 4096, `N   VARIABLES`, строки `NAME(10)T WW DD`, координаты — двоичные double, `JOIN` — `N 12 0` влево, `STRING` — `C 20 0`, атрибуты — текстовые или десятичные столбцы; цикл побитный, реальные STR после экспорта совпадают байт в байт. По справке: STR — Data-файл со STRING и необязательным JOIN; `.PIT` — STR + поле Road.

### 9.4. Micromine TRIDB

SQLite, текст UTF-16; несколько каркасов в файле; `.TDB` до v14 (2013), `.TRIDB` с v15 (2014). Таблицы: `GeneralInformation` (`ID`, `Name`, `Colour` BGR, даты Unix, охват `XMinimum…ZMaximum`, `Volume`, `SurfaceArea` и др. — 27 столбцов в реальных файлах), `Geometry` (`ID`, BLOB), `GeometryProperties` (`PointCount`, `TriangleCount`, `Volume`, `SurfaceArea`, `PlanSilhouetteArea`), `UserAttributeDefinition`/`Value`, `PointAttribute*`, `TriangleAttribute*`; в реальных файлах есть ещё `DatabaseInformation`, `DisplayProperties`. В файлах `real_data` `GeometryProperties` — таблица «ключ–значение» (`TriangulationID`, `GUID`, `Property`, `TextValue`, `RealValue`), свойства могут повторяться (до 3 строк) или отсутствовать (`Volume` у 41 из 55 каркасов `Rock Model`).

BLOB (LE): 0 — `FF FF FF FF 00 00 05 00` (признак, версия 5); 8 — int64 36 (длина GUID); 16 — int64 9; 24 — GUID 36 байт ASCII (= `GeometryProperties.GUID`); с 60 — блоки «int64 длина, int64 номер, данные»: 1 — X double × N, 2 — Y, 3 — Z, 4 — треугольники int32 × 3 × M (индексы с 0). Проверка: N, M = `PointCount`, `TriangleCount`, индексы в `0…N−1`, охват = `GeneralInformation`. Чтение BLOB частями (`read_tridb_geometry`, `sqlite3.Blob`). Экспорт TRIDB и обменная пара `*_MMpt.dat` + `*_MMtr.dat` не сделаны.

### 9.5. DXF

Образец `TST-FAULTS.DXF`: AC1018, `ANSI_1251`, одна `POLYLINE` флаг 64 (polyface), слой `FLT-Combined_TST`, 7 443 вершины, 7 417 треуг., Z 182–588 м, 2 723 самопересечения. `VERTEX` флаг 192 — вершина (10/20/30), флаг 128 — грань: 71–74 — номера с 1, отрицательный — невидимое ребро. Каркасы читаются своим потоковым разбором ASCII DXF блоками; линии — через ezdxf. Запись: AC1018, `ANSI_1251`, `CRLF`; заголовок, таблицы, блоки, объекты — из ezdxf, сущности текстом порциями со своими хендлами; координаты `repr()` (побитно); цвет — ближайший ACI; каркас — polyface (как пишет Micromine).

### 9.6. Surpac STR, CSV/TXT/Excel

Surpac STR: заголовок и строка осей, затем `string, Y, X, Z, описания…`; строка 0 заканчивает сегмент; `0, …, END` — конец; cp1251.

Таблицы скважин: кодировки UTF-8, UTF-8 BOM, UTF-16, cp1251, cp866, KOI8-R (запасная latin-1); разделители `;` `,` табуляция `|` пробелы; Excel — выбор листа, даты ISO-текстом; номер строки заголовка, пустые строки и столбцы убираются, повторы имён исправляются; десятичная запятая, разряды, «н/д», NA, «-»; `<x` → x/2, `>x` → x с сообщением; имена с единицами («X, м», «Au, г/т»), русские псевдонимы, словари Micromine/Datamine/Surpac/Vulcan/Leapfrog/acQuire (`importing/names.py`); тип таблицы (устья, инклинометрия, пробы, интервалы, события; «от–до» без номера пробы и содержаний — интервальная); режим только «заменить»; флажок «Загрузить с ошибками — исправлю в BedrockForge».

### 9.7. Растры и привязка

World-файл: 6 чисел A, D, B, E, C, F; `X = A·col + B·row + C`, `Y = D·col + E·row + F`; C, F — **центр** левого верхнего пикселя. MapInfo `.TAB` (`Type "RASTER"`): опорные точки `(X, Y) (col, row) Label`, `CoordSys`. Micromine `.grf`: строки 1–3 — X, Y, Z **угла**; 4–5 — размер пикселя; 6–11 — матрица поворота 2×3; далее `col row X Y Z флаг`. Образец «Восточный_TS» (Восточный Цители-Сопели, 1:10 000): пиксель ≈ 2,02 м, поворот ≈ 0,2°, GRF смещён от JGW на полпикселя, world-файл — аффинное приближение по 7 точкам TAB с отклонениями 0,5–4,6 м. Порядок выбора: world → TAB → GRF, отклонения по каждой точке. GRF с разными Z, изображение без привязки при линии разреза или ручные края — вертикальный растр (подложка без глубины); Z плоского растра — при импорте и в свойствах; растр на ЦТМ — координаты изображения в шейдере. Образцы FORMATS.md — WGS 84 / UTM 38N.

### 9.8. OMF v1

Leapfrog Geo 2026.1 пишет и читает только OMF 0.9 = файловая v1; поддержка в обе стороны. Библиотека `omf` не используется (numpy \< 2, пакет `properties` не собирается на Python 3.12+). Эталон — `omf/compat/omf_v1.py` (omf-python), образец `api/tests/fixtures/omf_v1_test_file.omf` (93 КБ, MIT). v2 из `bandurkin-ai/omf-python` — альфа-диалект, не равный OMF 2.0-beta (`gmggroup/omf-rust`); не поддерживается.

Файл: 0 — `84 83 82 81`; 4 — 32 байта `OMF-v0.9.0` + нули; 36 — UUID 16 байт; 52 — uint64 LE смещение JSON; с 60 — блоки, каждый отдельный поток zlib; JSON до конца — `uid → объект` с `__class__`. Массивы `ScalarArray`, `Vector2/3Array`, `Int2/3Array` (обычно `<i8`) — блок `{start, length, dtype}`; `StringArray`, `DateTimeArray`, `ColorArray` — в JSON; изображения — `image/png`. Порядок узлов и ячеек — Фортран (u, затем v, затем w; проверено на сетке 2 × 3 × 4).

| **OMF v1 → BF**                                           | **Результат**                                                                           | **Теряется**                                                |
|-----------------------------------------------------------|-----------------------------------------------------------------------------------------|-------------------------------------------------------------|
| `SurfaceElement` (треугольники)                           | Каркас                                                                                  | Данные на вершинах и гранях                                 |
| `SurfaceElement` (грид)                                   | Каркас: `origin + u·axis_u + v·axis_v + offset_w·(axis_u × axis_v)`, 2 треуг. на ячейку | То же                                                       |
| `LineSetElement`                                          | Слой линий: смежные сегменты склеиваются, возврат в первую вершину = замкнута           | Данные на вершинах; постоянные вдоль линии → атрибуты линии |
| `VolumeElement`                                           | Блочная модель (пустые ячейки не грузятся; оси до перестановки и знака)                 | Повёрнутые модели, данные на узлах                          |
| `ScalarData` / `MappedData`, `StringData`, `DateTimeData` | Число / категория (первая легенда)                                                      | Цвета легенды                                               |
| `PointSetElement`, `ImageTexture`                         | —                                                                                       | Целиком                                                     |
| `origin`, `color [r, g, b]`                               | Прибавляется / `#rrggbb`                                                                | —                                                           |

Пропущенное — в журнале задания и `meta.warnings`. Один файл → набор каркасов + набор линий + по набору блоков на Volume; исходный файл в хранилище последним шагом, один хеш в `source`. Большие регулярные сетки: без проверок дубликатов, оболочка по маске занятости, координаты порциями (47 млн ячеек — 47 с, 4,5 ГБ). Экспорт: каркас → `SurfaceElement` (float64, `origin` = 0); линии → `LineSetElement` (замкнутая — петля, атрибуты на сегментах: числа `ScalarData`, текст `MappedData`); регулярная модель → `VolumeElement` по `meta.grid`, пустые NaN или −1, единица в описании («Единицы: g/t»); субблочные, повёрнутые и \> 100 млн ячеек не пишутся. Задание `export.omf`, файл `DATA_DIR/exports/<id>.omf` на 48 ч, `POST /api/projects/{id}/exports`, `GET /api/jobs/{id}/download`. Проверки: побитный цикл (`tests/test_omf.py`), `omf.load` + `validate()` в Python 3.11 разово; Leapfrog не проверялся. Мастер: нет сигнатуры — «файл повреждён»; `PK` — «OMF 2 (ZIP) не поддерживается: сохраните в OMF 1 (Leapfrog: OMF 0.9)»; иная версия — «читается OMF v1».

### 9.9. `.bfggis` и `.bfstyle.json`

`.bfggis`: сигнатура `BFGGIS\r\n` (8 байт), версия `u16` (1), длина заголовка `u32` LE; заголовок JSON — `app_version`, `schema_revision` (ревизия Alembic), `created_at`, `encrypted`, `compression: "zstd"`, без пароля `summary`, с паролем `cipher`, `kdf` (scrypt n = 2¹⁵, r = 8, p = 1, соль), `nonce_prefix`, `chunk`; тело — `tar` (PAX) → `zstd` (уровень 3, сумма кадра) → AES-256-GCM блоками по 4 МиБ (`u32 длина | шифротекст+тег`; nonce = 7 байт префикса + 4 номера + 1 «последний»; заголовок — AAD: ловятся перестановка, потеря, обрезка, правка). Внутри: `manifest.json` (первым), `db/<таблица>.csv` (`COPY … CSV HEADER`, список — `archive/spec.py`), `blobs.json`, `blobs/<sha256>`, `browser.json` (вид браузера), `checksums.json` (последним). Совместимость: временные таблицы текущего вида, недостающие столбцы по умолчанию, лишние — текстом, шаги `UPGRADES` (`archive/versions.py`); более новый файл отклоняется; тест-сторож требует запись в `UPGRADES` и `TABLES`/`SKIPPED`. Импорт одной транзакцией, новые id, пересчёт ссылок в JSON (операции, ЦТМ, графики, стили, журнал правок, Swath plot); режимы копия «Имя (2)» / другое имя / замена. Загрузка без проекта (0016) до 256 ГБ, скачивание с Range. Не переносятся задания, незавершённые загрузки, расходы Claude.

`.bfstyle.json`: `{ "format": "bedrockforge-styles", "version": 1, "styles": [...] }`; экспорт одного, выбранных или всех (связанные раскраски вкладываются); импорт с конфликтами по имени (заменить / оставить оба / пропустить); неизвестные поля не теряются.

### 9.10. Каталог Micromine (`docs/Форматы-ММ.MD`)

По справке Micromine (v18, v21–25.5); побайтовой спецификации нет. Нативные: `.DAT` (таблицы; блочные модели + `.metax`), `.DHDB` (база скважин: Collar и Survey в БД, Interval и Event — внешние ссылки), `.TDB`/`.TRIDB`, `*_MMpt.dat` + `*_MMtr.dat`, `.STR`, `.PIT`, `.SVY`, `.SEC`/`.STP` (номер профиля, X, Y), `.OUT` (полигоны, свой формат), `.GRD` (double по строкам с левого верхнего угла, пусто `-100000000`, заголовок 592 байта), `.LDT`/`.LBN`/`.LK` (справочники), `.MCR`, `.BDB`/`.mmsetx`/`.set`/`.xpm` (`FLDVAL125.bdb`), Plot Editor (`.PEX`, `.PTX`, `.PEL`, `.PED`, `.PEP`, `.PLS`, `.PGL`, `.PRN`), Vizex (`.VFLY`, `.FLY`, `.GRF`), `.RDF`, `.RPT`/`.REP`. Проект — папка (`SECTIONS`, `METADATA`, `SchedulerDataFiles`, `RingDesignDATFiles`); смена расширения ломает поиск. Обмен Micromine: каркасы — DWG, DXF, DXB, DGN, Vulcan `.00t`, Surpac `.dtm`, Datamine `.tr`, PLY, RAW, OMF, OBJ, DAE, BLEND, 3DS, ASE, FBX, STL, Leapfrog `.msh`, GOCAD `.ts`; блоки — Vulcan `.bmf`, Surpac `.mdl`/`.fbm`, Datamine `.dm`, OMF, UBC Mesh, `.txt`; стринги — Datamine, Surpac `.str`, текст. Не найдено в справке: побайтовые DAT, BLOB TRIDB (оба потом разобраны по образцам), `.DHDB`, `.OUT`; открытых парсеров нет. Рекомендации: нейтральный обмен OMF, CSV, DXF; реверс начинать с DAT. Правила для всех читателей:

- Потоковое чтение с прогрессом и отменой; память ограничена бюджетом раздела 5.3.

- Негативные тесты на каждый формат: обрезанный файл, неизвестная версия, битая кодировка, пустой файл, «бомба».

- Неизвестное поле или кодировка — предупреждение в журнале операции, а не тихая потеря данных.

- Каждый читатель и писатель — тест «импорт → экспорт → импорт» с побитным или численным (1e-12) совпадением.
