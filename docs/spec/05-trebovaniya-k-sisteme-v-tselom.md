## 5. Требования к системе в целом

### 5.1. Платформа и окружение

| **Требование** | **Значение**                                                                                                                    |
|----------------|---------------------------------------------------------------------------------------------------------------------------------|
| ОС             | Windows 11 x64 (22H2+); Windows 10 x64 22H2 — без гарантии                                                                      |
| ОЗУ            | Минимум 16 ГБ (целевой ПК приёмки); работа на 8 ГБ — с упрощённым 3D и предупреждением                                          |
| Графика        | WebGL2; встроенная графика Intel Iris Xe / AMD Radeon Vega — обязательный целевой уровень; дискретная — используется, если есть |
| Процессор      | 4–8 ядер x64                                                                                                                    |
| Диск           | Дистрибутив ≤ 400 МБ; проект — на любом локальном диске; кеш — в профиле пользователя                                           |
| Права          | Работа без прав администратора (portable и установщик «для текущего пользователя»)                                              |
| Сеть           | Не нужна; ассистент Claude и проверка обновлений — только при наличии интернета                                                 |
| Экран          | Минимальная ширина окна 1024 px; масштаб Windows 100–200 %                                                                      |
| Язык           | Только русский интерфейс; числа — с запятой и точкой при вводе, вывод по настройке                                              |

Правила:

- Замеры — в `bench/` с бюджетами `bench/budgets.json` (профили `ci` и `full`); CI проверяет `ci` на каждом PR (раздел 10.4).

- Бюджеты для встроенной графики проверяются заказчиком на вехах (дымовой сценарий с счётчиком кадров, встроенным в приложение: `Ctrl+Shift+F`).

- Нарушение бюджета — ошибка этапа; исключение оформляется записью в `docs/adr/` с замером и причиной.

### 5.4. Точность

| **Область**              | **Правило**                                                                                                                                                                 |
|--------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Координаты               | Только float64 без округления; импорт → экспорт побитно совпадает для STR/DXF/OBJ/TRIDB                                                                                     |
| Видеокарта               | float32 относительно целочисленного начала у центра охвата объекта; до 16 км — погрешность ≤ 0,5 мм (тест: 200 тыс. точек на 16 км в UTM); крупнее — части со своим началом |
| Измерения, клик, сечения | По float64 в ядре, не по буферам видеокарты                                                                                                                                 |
| Объём и площадь          | Знаковые тетраэдры от центра охвата, попарное суммирование; сверка с `Volume`/`SurfaceArea` TRIDB с допуском 1e-9 (отн.)                                                    |
| Траектории               | Минимальная кривизна; сверка с Micromine — расхождение ≤ 5 см (как в BF на 21 145 интервалах)                                                                               |
| Блочная модель           | Объём = сумма объёмов блоков; субблоки не перекрываются                                                                                                                     |
| Булевы операции          | V(A∪B) = V(A) + V(B) − V(A∩B) с допуском 1e-9 × (V(A)+V(B)); перенос к целочисленному началу перед операцией                                                                |
| Геостатистика            | Эталоны GSLIB/GeostatsPy (допуск 1e-6 отн.), аналитические случаи; результаты Micromine — когда заказчик их предоставит                                                     |
| Системы координат        | Код EPSG или WKT `.prj` у объекта; пересчёт только явной командой                                                                                                           |
| Пропуски                 | `NaN`, пусто, `-999`, `<0.01`, `>N` — по правилам импорта с отчётом; молча в ноль — запрещено                                                                               |
| Воспроизводимость        | В результате расчёта хранятся параметры, версия алгоритма, хеш входа, зерно генератора                                                                                      |
| Упрощение                | LOD и прореживание — только для показа, с пометкой «упрощено»; расчёты — по исходным данным                                                                                 |

### 5.5. Надёжность

- Каждое изменение данных — транзакция SQLite (WAL); при сбое питания проект открывается в последнем согласованном состоянии.

- Автосохранение не требуется: изменения записываются сразу; черновики (отображения, стили, макеты) — только по кнопке «Сохранить».

- Отмена (Ctrl+Z / Ctrl+Y) — для правок таблиц, редактора стрингов, атрибутов объектов; журнал правок хранится в проекте и переносится в `.bfggis`.

- Ежедневная автокопия `project.sqlite` (`VACUUM INTO`), хранить 5 последних; при открытии — `PRAGMA quick_check`, при ошибке — предложение восстановить из копии.

- Задания переживают перезапуск приложения: незавершённые возвращаются в очередь (попытка +1, максимум 2 для импорта).

- Падение ядра: оболочка перезапускает его, показывает сообщение «Вычислительное ядро перезапущено» с ссылкой на журнал; данные не теряются.

- Нехватка памяти: задание завершается с понятным сообщением («Не хватило памяти: нужно ~N ГБ, доступно M ГБ; закройте…»), очередь продолжает работу.

- Журналы: `%LOCALAPPDATA%\BedrockForge\logs\` (оболочка, ядро, задания), ротация 10 × 10 МБ; кнопка «Скопировать журнал» в любом окне ошибки.

### 5.6. Безопасность

| **№** | **Требование**                                                                                                                                                                           |
|-------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| S1    | Ядро слушает только `127.0.0.1`, случайный порт; каждый запрос — с токеном запуска (`X-BF-Token`), без токена — 401                                                                      |
| S2    | Проверка `Host` и `Origin`; сторонняя страница или процесс без токена не читает проект                                                                                                   |
| S3    | Electron: `contextIsolation`, `sandbox`, без `nodeIntegration`, CSP по хешам, запрет навигации и новых окон, собственный протокол `app://bedrockforge`                                   |
| S4    | Пределы разбора: изображения ≤ 400 млн пикселей; распаковка архивов с пределом размера и коэффициента сжатия; XLSX/DXF/OMF — потоково с пределом памяти; «бомбы» отклоняются без падения |
| S5    | Ключ Claude — в хранилище Windows через `safeStorage` (DPAPI); в проект и `.bfggis` не попадает                                                                                          |
| S6    | Шифрование `.bfggis` паролем: AES-256-GCM, ключ из пароля через scrypt; пароль нигде не сохраняется                                                                                      |
| S7    | Обновления — только по HTTPS, проверка SHA-512 из `latest.yml` и подписи (если есть сертификат)                                                                                          |
| S8    | Зависимости: `uv.lock` и `package-lock.json` с хешами; SBOM (CycloneDX) в каждом выпуске                                                                                                 |
| S9    | Нет `eval`, `new Function`, `dangerouslySetInnerHTML` (кроме проверенного рендера Markdown с санитайзером) — закреплено тестом                                                           |
| S10   | Разрушающие команды ассистента Claude требуют подтверждения пользователя                                                                                                                 |
| S11   | Сервер ЛВС (Э25): HTTPS, пароли argon2id, роли, журнал действий, ограничение частоты входа                                                                                               |

### 5.7. Лицензирование и защита от копирования (Э24)

| **Элемент**           | **Требование**                                                                                                                                                                                                                                     |
|-----------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Файл лицензии         | `license.bflic`: JSON `{id, customer, hwid, features[], issued, expires, version_max}` + подпись Ed25519 (base64)                                                                                                                                  |
| Открытый ключ         | Встроен в ядро и оболочку; закрытый — только у заказчика, в репозиторий не попадает                                                                                                                                                                |
| Привязка к ПК (HWID)  | SHA-256 от трёх компонентов: `MachineGuid` (реестр), серийный номер системного тома, идентификатор процессора; лицензия действительна при совпадении ≥ 2 из 3                                                                                      |
| Пробный период        | 30 дней с первого запуска; отметка в трёх местах (HKCU, `%APPDATA%`, `%LOCALAPPDATA%`) с HMAC; перевод часов назад обнаруживается по монотонной отметке «последний запуск»                                                                         |
| После окончания срока | Режим «только просмотр»: открытие и просмотр проектов, без изменения и экспорта; данные не блокируются и не удаляются                                                                                                                              |
| Окно «Лицензия»       | Код ПК (HWID) с кнопкой «Скопировать», загрузка файла лицензии, срок, владелец, функции                                                                                                                                                            |
| Утилита выпуска       | `tools/bf-license` (Python CLI): `keygen`, `issue --hwid … --customer … --expires … --features …`, `verify`; инструкция в `docs/LICENSING.md`                                                                                                      |
| Функции по лицензии   | Флаги модулей (`geostat`, `pit`, `rbf`, `server`) — для будущих редакций; в v1 все включены                                                                                                                                                        |
| Защита кода           | Ядро: модули Python компилируются Nuitka или Cython в `.pyd` (лицензионный модуль — обязательно); оболочка: `asar` + Electron Fuses (`onlyLoadAppFromAsar`, `EnableEmbeddedAsarIntegrityValidation`), минификация и обфускация JS-модулей лицензии |
| Водяной знак          | Идентификатор лицензии в метаданных `.bfggis`, PDF и экспортируемых файлов, где формат это позволяет                                                                                                                                               |
| Честность             | В `docs/LICENSING.md` указано: клиентская защита повышает стоимость обхода, но не исключает его                                                                                                                                                    |
