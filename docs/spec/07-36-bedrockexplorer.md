# 7.36. BedrockExplorer 0.5.0 [Э25а]

> Источник: промпт заказчика (2026-11-27), помещён без изменений. Этап Э25а стоит после Э25 и перед Э26; в В6. Начинать только по команде заказчика (см. PROGRESS.md, порядок В6).


Ты разрабатываешь настольное приложение **BedrockExplorer** для горно-геологической системы BedrockForge 2 (далее BF). Воспроизведи существующий BedrockExplorer **0.5.0** с его интерфейсом, поведением, форматом данных и сборкой. Результат нужен в двух вариантах: самостоятельное приложение Windows x64 и тот же Explorer, открываемый из **«Главная → BedrockExplorer»** в BF.

- Эталон самостоятельной сборки — [BedrockExplorer 0.5.0 для Windows](https://github.com/aeromikeuz-gif/BedrockForge_2.0_fork2/actions/runs/45867636430#artifacts). При наличии приложенных снимков интерфейса сверяй с ними размеры, расположение и внешний вид.
- При доступе к эталонному исходнику используй его как источник точных подписей, CSS, форматов и контрактов. Если текст промпта и исходник расходятся, для точного воспроизведения приоритет у закреплённого коммита. Избегай заимствования оформления ESRI. От ArcCatalog здесь взят принцип «дерево → содержимое → свойства».

## Рабочее окно

1. **Оформление и размеры.** Интерфейс на русском. Шрифт Segoe UI, базовый размер 13 px. Стартовое окно 1320 × 850, минимальное 960 × 620. Верхняя графитовая строка 55 px с существующей иконкой BF, надписью BedrockExplorer, путём подключённого каталога и кнопкой «Меню». Нижняя строка состояния 32 px. Используй графит `#1b1f23` и `#282c30`, бумажный фон `#fcfaf6`, фон области поиска `#f3f0e9`, границы `#ded8cd`, медный акцент `#85471e` и выделение `#f3e5d4`. Таблица плотная, с чередованием строк, тонкими разделителями, липким заголовком и метками типов объектов.
2. **Левое дерево «Проекты».** Подключается локальный каталог, содержащий папки проектов BF с расширением `.bfproj`. Проект показывает «Все объекты», реальные папки с вложенностью, объекты без папок и группировку «По типам». Закреплённые проекты выше остальных. Кнопка `+` создаёт проект. Для папки можно открыть её содержимое или раскрыть ветку.
3. **Центральная таблица.** Вверху компактный путь и название текущего проекта или раздела. Далее строка поиска, переключатель области, кнопки «Колонки» и «Инспектор», счётчик результатов и выделения. Колонки в порядке эталона: флажок, «Название», «Тип», «Папка», «Формат», «Размер». Названия сортируются с учётом русской локали. Есть одиночное и множественное выделение, `Ctrl+клик` и флажок выбора всех видимых строк. Пользователь может скрыть колонки типа, папки, формата и размера.
4. **Области поиска.** «Текущий раздел», «Весь проект», «Все проекты». Ищи по названию, папке, формату и отображаемому типу без учёта регистра. В глобальной выдаче показывай объект, проект и папку. Клик открывает найденное место и выделяет объект. При большом результате показывай до 250 строк и общий счётчик.
5. **Правый «Инспектор».** Вкладки «Свойства» и «Связи». Свойства включают имя, тип, папку, формат, размер, число строк, CRS, состояние и дату изменения, где данные доступны. Для каркасов и ЦТМ показывай миниатюру реальной сетки, вершины, треугольники и габариты при наличии. Для растров — миниатюру, разрешение и источник геопривязки. Для наборов скважин — число скважин и таблицы. Во вкладке «Связи» показывай оба направления: «Использует» и «Используется в». Отсутствующая миниатюра не скрывает метаданные.
6. **Размеры и профиль.** Разделители дерева и инспектора перетаскиваются мышью и двигаются клавишами. Начальные ширины около 208 и 243 px соответственно. При ширине окна до 1050 px инспектор сворачивается, сохраняя возможность раскрыть его кнопкой. Сохраняй профиль интерфейса, закрепления, раскрытие дерева, последний проект и раздел, ширины и скрытые колонки между запусками.
7. **Статус.** Показывай готовность ядра, текущие операции, ошибки и прогресс фоновых заданий. Кнопка «Отменить задание» появляется во время выполнения задания.

## Контекстные команды

Верхней ленты операций в Explorer нет. Все основные действия живут в контекстных меню, как в версии 0.5.0. Верхняя кнопка «Меню» управляет каталогом.

| Место вызова | Команды |
| --- | --- |
| Строка объекта | «Копировать…», «В буфер объектов», «Перенести…», «Дублировать», «Переименовать…», «Удалить…», «Экспорт…», «Импорт…» |
| Папка или свободное место таблицы | «Вставить объекты…», «Импорт…», «Экспорт проекта BF…», «Обновить» |
| Проект | «Открыть», «Закрепить проект» или «Открепить проект», «Вставить объекты…», «Импорт…», «Экспорт проекта BF…» |
| Меню рабочего пространства | «Подключить каталог…», «Создать проект», «Импорт проекта BF…», «Обновить» |

ПКМ по невыделенной строке выбирает её. ПКМ внутри выделенной группы сохраняет группу. Опасное действие выделено красным и требует подтверждения со списком объектов. Недоступные команды блокируются по контексту. Поддержи клавиатурное управление меню и `Shift+F10` на строке, стрелки и `Esc` внутри меню, `Ctrl+K` для фокуса поиска, `F2` для переименования, `Delete` для удаления. `Ctrl+C` и `Ctrl+V` работают с внутренним буфером объектов BF. Для вставки можно выбрать другой проект и папку, после чего открывается окно копирования.

## Двухпанельная операция «Откуда → Куда»

- Один диалог для копирования, переноса и дублирования. Слева исходный проект и выбранные объекты с папками. Справа проект назначения, путь папки с подсказками по существующим папкам, список объектов выбранной папки и статус возможности записи.
- Для одного копируемого объекта можно задать новое имя. Пустое поле оставляет исходное имя с автоматическим подбором свободного суффикса при конфликте. Явно заданное занятое имя требует исправления. Дублирование использует текущий проект. Внутрипроектный перенос меняет папку.
- «Проверить перенос» запрашивает состав связанных объектов и конфликты имён. В том же диалоге отображается сводка. Доступны возврат к редактированию параметров, отмена и явное подтверждение. После успеха открой назначение и выдели результат.
- Копирование между проектами использует нативный механизм BF с переносом связанных записей и файлов. При переносе снимай исходники только после проверенной фиксации назначения. Связанные объекты, включённые как зависимости, копируются, а удаляются только выбранные исходные объекты и их штатные дочерние записи. Если оставшиеся в источнике данные ссылаются на удаляемые объекты, операция должна завершиться понятным отказом. Эталонный предел выбора — 500 объектов, предел плана с зависимостями — 5000.

## Работа с проектом BF

- Поддерживаемые типы каталога соответствуют BF: наборы скважин, каркасы, ЦТМ, файлы линий, облака точек, растры и блочные модели. Используй фактическую схему BF, каталог, блокировки проекта, штатное хранилище бинарных данных, журнал и механизмы перенумерации.
- Различай исходный ID объекта и ID в назначении. Перенумеровывай поддерживаемые внешние ключи, зависимости, владельцев файлов, ссылки в метаданных, журналы правок скважин и их группы. Сохраняй те же правила для ссылок, которые применяет BF. Проверяй SHA‑256 и размер файлов. Закрывай доступ к записи, когда проект занят другим процессом BF. Разрешай чтение и допустимое копирование из такого источника.
- Не доверяй одному числовому ID при изменении данных. В запросах записи используй идентификатор состояния из эталона `created_at:updated_at:version`. Повторно проверяй выбранные записи и подтверждённый состав зависимостей внутри операции записи. При устаревшем выборе, повреждённых файлах, неоднозначном UID проекта или блокировке покажи ошибку без изменения исходных данных.
- Межпроектный перенос сначала фиксирует назначение с гарантией долговечности записи, затем фиксирует удаление исходника. При исключительной ошибке второй фиксации сообщай, что копия сохранена и требуется проверить оба проекта. Не заявляй, что две независимые базы фиксируются одной атомарной транзакцией.
- Импорт и экспорт используют существующие команды BF и фоновые задания. Импорт внешних файлов включает определение состава и ошибок до запуска. Для таблиц скважин используй распознавание типа и столбцов штатным ядром. Экспорт показывает доступные форматы по типу объекта. Импорт и экспорт **проекта целиком** используют штатный `.bfggis`, включая пароль для поддерживаемых архивов.

## Архитектура и поставка

- Explorer — Electron 45, TypeScript, HTML и CSS, сборка esbuild. Храни реализацию оболочки в `app/src/explorer/`, сборку в `app/build-explorer.mjs`, конфигурацию NSIS в `app/explorer-builder.yml`. Повторно используй `CoreProcess` и существующие ассеты BF.
- Локальное ядро — Python 3.12 и FastAPI из BF. Нативные операции находятся в `core/bf_core/explorer/`, эндпоинты подключаются под `/api/v1/explorer`. Переиспользуй штатные маршруты BF для проектов, импорта, экспорта и заданий. Renderer работает через узкий типизированный preload, изолирован и не имеет прямого доступа к Node.js. Main проверяет источник IPC и проксирует только разрешённые вызовы по loopback с токеном BF.
- Встроенный режим использует тот же код и ту же сборку Explorer. Команда BF `data.explorer` отображается кнопкой «BedrockExplorer» на вкладке «Главная» и названием «Открыть BedrockExplorer» в поиске команд. Оболочка запускает отдельное окно в режиме `--bedrock-explorer`, передаёт папку проектов BF и использует отдельный профиль Explorer. Режим доступен в обычном и переносимом выпуске BF. Установщик BF включает Explorer и ядро без отдельной установки.
- Самостоятельный Windows x64 выпуск собирается через `.github/workflows/bedrockexplorer.yml`: `BedrockExplorer-0.5.0-setup.exe`, артефакт `BedrockExplorer-Windows-x64`, контрольные суммы в `SHA256SUMS.txt`. Встроенный вариант собирается в стандартном Windows workflow выпуска BF вместе с установщиком и переносимым пакетом. Создание новых тегов, слияние в `main` и публикация на GitHub выполняются только если текущая задача их разрешает.

## Приёмка

1. Собери проект из существующих lock-файлов. Прогони `npm run typecheck`, `npm run build` и тесты ядра `core/tests/test_explorer.py`, архива и структуры. Проверь, что новые маршруты попали в замороженное ядро.
2. На временных проектах проверь меню ПКМ, полный сценарий копирования, переименование и удаление, все три области поиска, буфер `Ctrl+C`/`Ctrl+V`, импорт CSV и экспорт DXF. Эталонный сценарий находится в `app/explorer-e2e/catalog.spec.ts` и запускается с `app/playwright.explorer.config.ts`.
3. Проверь целостность после переноса в проект с занятыми ID, совпадение имён, заблокированное назначение, устаревший выбор, повреждённый файл и сохранение журнала. При ошибке источник остаётся доступен согласно описанному порядку фиксации.
4. Проверь демопроект BF с реальными каркасом и растром, две вкладки инспектора, компактное окно 960 × 620 и восстановление настроек после перезапуска. Сопоставь внешний вид с эталонным исходником или приложенными снимками.
5. Собери и запусти упакованное приложение Windows x64. Для встроенного режима проверь кнопку «BedrockExplorer» с реальной «Главной» BF, старт отдельного окна и готовность его собственного ядра. Эталон — `app/e2e/smoke.spec.ts`.
6. В результате перечисли выполненные проверки, то, что осталось непроверенным, и дай ссылки на сборки при наличии. Успех сборки, запуск приложения и публикацию подтверждай отдельно.

Начни со сверки доступного репозитория с закреплённым эталоном. Затем реализуй и проверь рабочее приложение, сохраняя согласованные русские подписи, поведение и форматы BF.
