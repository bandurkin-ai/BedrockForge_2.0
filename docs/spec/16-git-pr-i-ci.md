## 16. Git, PR и CI

### 16.1. Ветки

| **Ветка**                   | **Правило**                                                                                                                |
|-----------------------------|----------------------------------------------------------------------------------------------------------------------------|
| `main`                      | Защищена: только через PR, обязательные проверки `ci` и `windows`                                                          |
| Ветка сессии `claude/<имя>` | Облачная сессия пушит в свою ветку; веха = сессия = ветка                                                                  |
| PR этапа                    | Из ветки сессии в `main`; после слияния — `git fetch origin main && git merge origin/main` в ветку сессии и следующий этап |
| Другие ветки                | Можно создавать (`stage/eNN-*`), если окружение разрешает пуш; по умолчанию не требуются                                   |

### 16.2. Коммиты

- Маленькие логические шаги; сообщение по-русски: `Э<N>: <что сделано>`; незавершённое — `wip(Э<N>): …`.

- Каждый коммит пушится сразу (15.2).

- Подписи соавторства — по правилам окружения сессии.

### 16.3. PR

- Заголовок: `Э<N>. <Название этапа>`; описание — шаблон Приложения Ж.

- Черновой PR открывается в начале этапа; готов к слиянию — после выполнения 10.5.

- Ожидание CI — подпиской на события PR; во время ожидания — чтение спецификации следующего этапа и план (без кода, зависящего от текущего PR).

### 16.4. Слияние

- Заказчик разрешает исполнителю **сливать PR своего этапа после зелёного CI** (merge commit) — это разрешение записывается в мастер-промте.

- Если слияние недоступно (нет прав или запрещено окружением) — следующий этап продолжается в той же ветке (PR накапливаются по порядку); на вехе — список PR для слияния заказчиком по порядку.

- Конфликты: влить свежий `main`, взять обе стороны для независимых добавлений, прогнать тесты, повторить CI.

### 16.5. Выпуски

| **Веха** | **Тег**             | **Артефакты**                                                                      |
|----------|---------------------|------------------------------------------------------------------------------------|
| В1–В5    | `v0.1.0` … `v0.5.0` | Черновик GitHub Release: portable `.exe`, установщик, `SHA256SUMS.txt`, отчёт вехи |
| В6       | `v1.0.0`            | То же + `latest.yml` автообновления, SBOM, `bf-license`, документация              |

- Артефакты Actions и Releases приватного репозитория скачиваются после входа в GitHub; срок хранения артефактов Actions — 30 дней (выпуски — бессрочно).

- Автообновление: из приватного репозитория без токена не работает — для обновлений используется отдельный публичный репозиторий только с выпусками (`BedrockForge2-releases`) или свой сервер (решение — ADR на Э24).

### 16.6. Запрещено

- Принудительный пуш в `main`, переписывание чужой истории.

- Пропуск, отключение или ослабление тестов ради зелёного CI.

- Коммит секретов: ключи API, закрытый ключ лицензий, пароли, сертификаты.

- Коммит данных заказчика, кроме набора `tests/data/real/` из ветки `real_data`.

- Зависимости под GPL/LGPL/AGPL.
