##### Д-01. Swath plot в плавающем окне \[Э13\]

| **Что** | **Требование** |
|---|---|
| Требование | Swath plot (7.30) открывается в плавающем окне «Swath plot · \<название\>» (7.0.12), а не во вкладке нижней панели. Окно не модальное: лента, дерево, 3D и другие окна работают, пока оно открыто; можно открыть несколько swath; положение и размер запоминаются. Короб (кубоид полос) в 3D вращается мышью **во всех плоскостях** (ответ № 8): ручки на коробе — кольцо вокруг вертикальной оси через центр (азимут), дуга наклона (dip) и дуга поворота вокруг оси полос (roll); шаг 1°, с `Shift` — 5°. Три угла видны в окне и вводятся числами (синхронно с ручками). Полосы и статистика считаются в повёрнутой системе координат короба (оси — по трём углам). При перетаскивании кубоид и границы полос рисуются каждый кадр, график пересчитывается после отпускания; направление X или Y при повороте становится «азимут». Вращение сцены мышью при открытом окне работает как обычно |
| Место | «Анализ → Статистика → SWATH PLOT»; «+» у раздела «Аудит и статистика»; двойной щелчок по swath в дереве; ручка — в 3D у выбранного swath. Вкладка «Swath plot» нижней панели удаляется |
| Команды | `stats.swath {swath_id, azimuth, dip, roll, …}` (есть; `dip`, `roll` — новые, по умолчанию 0) открывает окно; поворот мышью вызывает её же с углами |
| Готовность | vitest: ручки → азимут, наклон, поворот; матрица поворота ↔ углы, номер полосы по проекции центра (1e−9); E2E: при открытом окне `T`, щелчок по устью и `Ctrl+K` работают; перетаскивание каждой ручки меняет свой угол в окне, ввод числом поворачивает короб; pytest: swath по азимуту 90° (dip = roll = 0) побитно равен swath по X; swath с dip и roll = swath по точкам, заранее повёрнутым в систему короба (1e−9); замер: пересчёт после отпускания ≤ 2 с на 20 млн блоков (5.3, «Статистика») |
| Модули | ui: `modules/swath` (новый), `viz/swath` (кубоид, ручка), `shell/workspace.ts` (вкладка `swath` убирается, старое значение нормализуется к «Таблица»); core: `stats` (swath) |
| Приоритет | Обязательно: меняет принятое размещение (7.0.3, 7.30); при создании swath на Э13 почти бесплатно, переделка после — дороже |

##### Д-24. Разломы, эрозия и налегание в неявной модели \[Э19\]

| **Что** | **Требование** |
|---|---|
| Требование | В 8.9 домены строятся по хронологии (тело D = {f_D < 0} минус тела доменов с меньшим номером) — это обрезка тел, но не отношения между данными и не разломы. |---|---|
| Требование | В 8.9.2 сглаживание η = s·h̄ (линейное), s·h̄³ (кубическое), s (конечный радиус) задаётся вручную (по умолчанию s = 0 для контактов). Добавить режим **«Авто»**: η подбирается так, чтобы число обусловленности системы участка [Φ + η·I, P; Pᵀ, 0] не превышало заданную цель; близкие и дублирующие точки не ломают решение |
| Алгоритм | Оценка cond₂ участка: наибольшее и наименьшее по модулю собственное значение блока Φ + η·I на подпространстве, ортогональном P (`scipy.sparse.linalg.eigsh`, не более 30 итераций Ланцоша); поиск η — деление отрезка (двоичный поиск по log η) от η_0 = s·h̄^k до η_max = 1e−2·max abs(Φ) до cond ≤ цель·(1 ± 5 %); детерминировано (без градиентного спуска и случайности). Цель — cond ≤ 1e8 (по умолчанию), диапазон 1e4–1e12; η на участок записывается в проект. Необязательно: свой η по типу данных (контакты, замеры нормалей) |
| Приёмка | **Т8.9-14** облако из 2000 контактов с 5 % дублей (расстояние 1e−6·h): режим «Авто» даёт cond ≤ 1,05·цель; без «Авто» (η = 0) — система вырождена (cond > 1e12) или решение с невязкой > 1e−3·max abs(f) — контраст проверяется; **Т8.9-15** η «Авто» для данных Т8.9-1: форма сферы сохраняется (abs(‖x‖ − R) ≤ 0,25·h), η ≤ 1e−6·max abs(Φ) там, где cond и без η ≤ цель (η не вносится без нужды); **Т8.9-16** результат одинаков при 1, 2, 4, 8 потоках (побитно); накладные расходы на 100 тыс. точек ≤ 10 % времени решения |
| Место | Мастер неявной модели, шаг «Интерполяция»: «Сглаживание: Вручную / Авто (цель cond)»; свойства модели — η по участкам, cond |
| Команды | параметр `smoothing: {mode: "auto", cond_target}` команд `implicit.*` (отдельной команды нет) |
| Модули | ui: `modules/implicit`; core: `model` (RBF), `jobs` |
| Идея / лицензия | Идея — `optimize_nuggets` GemPy (EUPL-1.2): подбор нагета до целевого cond градиентным спуском; код и зависимость (PyTorch) не берутся, подбор — детерминированный, на SciPy |
| Зависит от | Э19; ориентир 0,5 окна 5 ч; ведущий — kernel-engineer |
| Приоритет | Желательно: ручное s уже работает; «Авто» убирает подбор на данных с дублями и густыми контактами. При нехватке времени — в Э19 только ручное s, «Авто» — после |
