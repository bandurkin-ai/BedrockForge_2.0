### 10.3. Замеры скорости

- `bench/budgets.json` — бюджеты по сценариям в профилях `ci` (объёмы ~1/10 целевых) и `full` (раздел 5.3).

- CI сравнивает с базовой веткой на том же runner: ошибка, если сценарий медленнее на \> 20 % **и** на ≥ 0,25 с; при провале — 3 повтора, берётся медиана (защита от шума).

- Отчёт замеров — артефакт `bench-ci.json` в каждом PR и таблица в описании PR.

- На вехах исполнитель запускает профиль `full` в облаке; заказчик — дымовой сценарий на своём ПК (счётчик кадров `Ctrl+Shift+F`, время операций в журнале заданий).

### 10.4. CI (GitHub Actions)

| **Workflow**  | **Когда**                 | **Шаги**                                                                                                                                                                                                                                                                                                          |
|---------------|---------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `ci.yml`      | Каждый push и PR          | ruff + mypy (ядро); pytest на SQLite; pytest слоя БД на PostgreSQL 16 (service); vitest; `tsc --noEmit`; сборка интерфейса; bench `ci` против базы; проверка лицензий зависимостей; проверка имён файлов, различающихся регистром; проверка, что изменённый модуль отражён в `docs/CHECKLIST.md` (предупреждение) |
| `windows.yml` | Каждый PR и push в `main` | Python + uv; pytest (подмножество `-m windows` и `tests/data/real`); PyInstaller `onedir`; electron-builder portable и NSIS; дымовой E2E на собранном `.exe` (запуск, демо-проект, кадр 3D, выход); артефакты `.exe` + `SHA256SUMS.txt` (хранение 30 дней)                                                        |
| `release.yml` | Тег `v*`                  | Полная сборка, подпись (если заданы секреты сертификата), SBOM, `latest.yml` для автообновления, черновик GitHub Release                                                                                                                                                                                          |

### 10.5. Готовность этапа (Definition of Done)

Этап считается выполненным, когда **все** пункты выполнены:

1.  Код ядра с тестами на синтетике; тест точности против эталона с допуском (если есть расчёт).

2.  Замер в бюджете (если операция есть в 5.3 или в разделе 8); `bench/budgets.json` обновлён.

3.  Проверка на файлах `tests/data/real/` (если формат или операция их касается).

4.  Команды в реестре (лента, `Ctrl+K`, горячие клавиши, ассистент); окна и объекты в дереве по разделу 7/8.

5.  Обратимая миграция БД (если менялась схема); тест цикла `.bfggis` для новых типов данных.

6.  Документация: раздел в `docs/USER_GUIDE.md`, строки `docs/CHECKLIST.md` отмечены, `CHANGELOG.md`, при необходимости `docs/adr/`.

7.  `PROGRESS.md` обновлён; PR с отчётом по шаблону Приложения Ж; CI зелёный (Linux и Windows).
