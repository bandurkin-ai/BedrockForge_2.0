## 8. Новые модули

Раздел задаёт двенадцать модулей, которых в BedrockForge (BF) нет или которые есть частично. Где модуль опирается на код BF (`api/app/stats`, `api/app/blocks`, `app/geo/stitch.py`, swath plot, редактор стрингов), код переносится с сохранением поведения и тестов. «Как в Micromine» (Leapfrog) — функциональный аналог: требования ниже относятся к BF2. Соответствие этапам `docs/ROADMAP.md` BF: Э10 — 14 и 16; Э12 — 18; Э13 — 17; Э14 — 19; Э16 — 20; Э17 — 12; Э18 — 21 и 22; Э19 — 26; Э20 — 23; Э21 — вне плана BF; Э22 — 16.

### 8.0. Общие положения

#### 8.0.1. Соглашения

| **Что**                 | **Правило**                                                                                                                                                                                                          |
|-------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Оси и координаты        | X — восток, Y — север, Z — вверх; float64. Перед расчётом вычитается опорная точка (центр охвата входных данных), результат возвращается в координаты проекта                                                        |
| Азимуты                 | По часовой стрелке от севера, \[0°; 360°)                                                                                                                                                                            |
| Плоскость (пласт, борт) | Угол падения α ∈ \[0°; 90°\], азимут падения Aп; верхняя нормаль n = (sin α·sin Aп, sin α·cos Aп, cos α)                                                                                                             |
| Скважина                | Зенитный угол θ (0° — вниз, 90° — горизонтально), азимут Aс; вектор вниз по стволу d = (sin θ·sin Aс, sin θ·cos Aс, −cos θ). Угол наклона δ из инклинометрии (−90° — вниз): θ = 90° + δ; знак δ задаётся при импорте |
| Анизотропия             | Углы GSLIB: ang1 — азимут большой оси; ang2 — её наклон, отрицательный вниз (в интерфейсе «погружение» p \> 0 вниз, ang2 = −p); ang3 — поворот вокруг большой оси; радиусы a1, a2, a3. Матрица — 8.6.3               |
| Пропуски                | NaN; в ноль — только явным параметром операции                                                                                                                                                                       |
| Единицы                 | м, т, т/м³; содержания г/т, %, ppm, ppb — единица хранится у поля; металл — как BF `blocks/report.py` (унция 31,1034768 г)                                                                                           |
| Суммы, случайные числа  | float64, попарное суммирование в фиксированном порядке; `numpy.random.Generator(PCG64(seed))`, зерно — параметр, по умолчанию 12345                                                                                  |

#### 8.0.2. Задания, воспроизводимость, хранение

- Операция дольше 1 с — фоновое задание по 6.7 (очередь `heavy` или `quick`, прогресс с названием стадии, кооперативная отмена, журнал). Результат пишется во временный каталог и переносится атомарно: прерванное задание не оставляет объектов.

- Расчётный объект хранит параметры (JSON), версию алгоритма, SHA-256 входов, зерно, версии библиотек, время. При смене входов объект помечается «устарел»; «Перестроить» повторяет расчёт.

- Параллельные ядра numba (`prange`) обрабатывают независимые элементы без атомарных операций над float; BLAS внутри параллельных участков — в один поток (`threadpoolctl`). Результат побитно одинаков при 1, 2, 4, 8 потоках.

- Хранение — по 6.5: описание объектов и таблицы наборов скважин (композиты, пересечения) — в `project.sqlite`; массивы — неизменяемые файлы в `blobs` (Parquet zstd, `.npy`); производные — в `cache\`. Состав сохраняемого задают подразделы ниже.

- Пиковая память вычислительного ядра ≤ 4 ГБ, если не сказано иное; обработка чанками.

- Бюджеты 5.3 действуют; здесь — цели операций модулей. Время — на ПК приёмки: 4 ядра / 8 потоков, 16 ГБ, NVMe SSD, встроенная графика уровня Intel Iris Xe или AMD Radeon 680M, Windows 11, 1920×1080; от «Запустить» до объекта в дереве; без первичной компиляции numba (`cache=True`; первая компиляция ядер модуля ≤ 30 с, в фоне после запуска).

- Тесты — pytest, данные — `tests/fixtures`, допуск записан в тесте. «Ручной» тест выполняется на ПК приёмки с записью в протокол.

#### 8.0.3. Лента, дерево, библиотеки

Новые вкладки ленты — «Разрезы», «Геостатистика», «Блочные модели», «Карьер», «Вывод»; новые группы — на вкладках «Анализ» и «Моделирование»; состав групп — в подразделах. Кнопка — команда реестра команд (лента, палитра, клавиши). Новые разделы дерева: «Серии разрезов», «Геостатистика», «Неявные модели», «Карьер», «Макеты», «Отчёты»; композиты, урезка и пересечения — таблицы набора скважин. Если раздел интерфейса называет вкладки иначе, действует он, состав групп — отсюда.

Библиотеки — стека 6.3 (numpy, scipy, pandas, numba, duckdb, pyarrow, manifold3d, PythonCDT, mapbox-earcut, pyfqmr, scikit-image, OR-Tools, openpyxl). Добавляются: numexpr (MIT) — калькулятор полей; threadpoolctl (BSD-3) — потоки BLAS; pdf-lib (MIT, Node) — склейка PDF. Только в тестах: geostatspy (MIT), statsmodels (BSD-3), pdfminer.six (MIT), omf (MIT, сверка). GPL, LGPL, AGPL запрещены (например, PyMaxflow, CGAL).
