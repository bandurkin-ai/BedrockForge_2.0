### 7.6. Фоновые задания, хранилище и исполнители \[Э2\]

**Назначение.** Долгие операции идут в исполнителях из очередей, не блокируя окно.

| **Что**              | **Требование**                                                                                                                                                                                           |
|----------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Хранилище            | Геометрия, изображения, массивы, исходные файлы — файлами в папке проекта (имя — SHA-256), в SQLite только описание и ссылки                                                                             |
| Передача в интерфейс | Сырые массивы с `ETag` и частичным чтением (`Range`); разбор в фоновом потоке интерфейса без копирования                                                                                                 |
| Задания              | Прогресс, журнал, отмена: в очереди — сразу, выполняющееся — на ближайшем шаге, частичный результат не сохраняется (`jobs.cancel`). Задание упавшего процесса возвращается в очередь, до **3** попыток   |
| Виды                 | `import.objects`, `import.project`, `export.project`, `export.omf`, `geometry.operation`, проверка каркасов; задания модулей раздела 8                                                                   |
| Очереди              | Общая (все виды) и быстрая (`geometry.operation`) со своим исполнителем: долгий импорт не задерживает операции с каркасами. Число исполнителей общей очереди — в «Настройке», по умолчанию 1 + 1 быстрый |
| Почему ждёт          | Исполнитель раз в **5 с** отмечает, что жив. «Задания» и журнал объясняют ожидание: «Нет работающего исполнителя…» (с кнопкой перезапуска) или «Впереди заданий: N, №… выполняется 12 мин»               |
| Память               | Нехватка памяти — ошибка задания с понятным текстом, исполнитель перезапускается                                                                                                                         |
| Очистка              | Раз в час — файлы без ссылок; \[сервер\] — и брошенные загрузки старше **48 ч**; вне расписания — по команде                                                                                             |
| \[сервер\] Загрузка  | Частями по **16 МБ** с SHA-256 части; объекты до **4 ГБ**, `.bfggis` до **256 ГБ**; докачка                                                                                                              |

**Вкладка «Задания»:** название (ссылка на журнал), состояние («В очереди», «Выполняется», «Готово», «Ошибка», «Отменено»), ход, причина ожидания; «Отменить» («Отмена…» после запроса), «Повторить» у упавших (те же файлы), «Показать в папке» у экспортов. \[сервер\] Секция «Передача файлов» («Прервать», «Очистить»), «Скачать».

**Хранение.** Задания с журналами — в проекте (в `.bfggis` не входят); файлы — в хранилище проекта.

**Приёмка**

- При остановленном исполнителе задание показывает «Нет работающего исполнителя…», исполнитель перезапускается.

- Снятие исполнителя посреди задания возвращает его в очередь; после 3 неудач — «Ошибка».

- Файлы без ссылок удаляются не позже чем через час.

- Массив отдаётся с `ETag` и `Range` (206).

- Отменённое задание не оставляет частичного результата.
