## Приложение Ж. Шаблоны отчётов

### Ж.1. Описание PR этапа

    ## Э<N>. <Название>
    Задание: docs/spec/<файлы> · Веха: В<n>
     
    ### Что сделано
    | Часть | Состав | Состояние |
     
    ### Не сделано
    | Пункт | Причина | Куда перенесено |
     
    ### Библиотеки и алгоритмы
    | Задача | Выбор | Лицензия | Чем проверена устойчивость |
     
    ### Тесты
    pytest: N passed (было M) · vitest: N · E2E: N
    | Что | Эталон | Допуск |
     
    ### Скорость и память
    | Сценарий | Объём | Время | Память | Бюджет |
     
    ### Допущения и решения
    - ADR: docs/adr/NNNN-*.md
     
    ### Проверить вручную
    - [ ] …

### Ж.2. Отчёт вехи

    # Веха В<n> «<название>» — готова к приёмке
     
    | Пункт | Значение |
    |---|---|
    | Этапы | Э… (PR #…, слиты) |
    | Выпуск | v0.<n>.0 — <ссылка на черновик выпуска>, SHA-256: … |
    | Тесты | pytest N, vitest N, E2E N — зелёные (Linux, Windows) |
    | Замеры full | <в бюджетах / исключения> |
    | Расход | окон 5 ч: оценка … / факт … |
     
    ## Сценарий приёмки (отметьте)
    - [ ] …
     
    ## Не проверено в облаке
    - Встроенная графика, реальная Windows 11, файлы заказчика вне real_data
     
    ## Допущения
    | Вопрос | Решение | ADR |
     
    ## Дальше
    1. Принять веху
    2. Принять с замечаниями: <список>
    3. Не принимать: <список>
