## Т1. Схема

Было:

```
Браузер (Chrome, localhost:5173)
        │
       web ──► api (localhost:8000) ──► db (PostgreSQL + PostGIS)
                 │                         ▲
                 ├──► том store (файлы) ◄──┤
                 └──► очередь заданий ──► worker, worker-quick
```

Стало:

```
BedrockForge.exe (Electron)
 ├── окно: собранный web/ (статика внутри exe)
 └── главный процесс: отдаёт статику и пересылает /api/*
        │
        ▼
      api (localhost:8000) ──► db (PostgreSQL + PostGIS)
        │                         ▲
        ├──► том store (файлы) ◄──┤
        └──► очередь заданий ──► worker, worker-quick
```

- Контейнер `web` клиенту не нужен. В `docker-compose.yml` он остаётся для браузерной версии.
- Порт 8000 уже опубликован на хост: в Docker ничего менять не надо.
- Новый код — в папке `desktop/`.

## Т2. Как окно обращается к API

Сейчас фронтенд ходит на относительный адрес `/api/...`, который Vite пересылает в `api`. В клиенте эту роль берёт главный процесс Electron.

| Вариант | Правки в `web/` | Правки в `api/` | Оценка |
|---|---|---|---|
| **Свой протокол `app://` с пересылкой `/api/*`** (выбран) | Одна строка (Т3, п. 1) | Нет | Адрес окна постоянный, настройки в `localStorage` сохраняются |
| Настраиваемый адрес API во фронтенде | Все вызовы `fetch` и `EventSource`, Web Worker | Нужен CORS для нового источника | Больше правок в обеих версиях |
| Открыть в окне `http://localhost:5173` | Нет | Нет | Самый быстрый, но `web` из Docker не уходит |

Риск выбранного варианта: потоковые ответы через протокол (события заданий, загрузка частями, чтение `Range`). Проверяется на этапе K0. Запасной вариант — маленький HTTP-сервер внутри главного процесса с той же логикой.

# Часть 2. Полная версия без Docker

## 0. Принятые решения

| Вопрос | Решение | Следствие |
|---|---|---|
| Оболочка | Electron | Тот же движок Chromium, что и у браузерной версии |
| Браузерная версия | Развивается параллельно | Один фронтенд, один API, одна схема БД; различия только в запуске |
| База данных | PostgreSQL 16, встроенный в portable `.exe` | Следствие параллельной разработки, см. раздел 2 |

| WebGPU | Не входит в первый выпуск | Вернуться после вехи M2 из `docs/ROADMAP.md` |

Открытый вопрос: нужен ли MCP в десктопе с первого выпуска. В плане он есть, но выключен по умолчанию.

## 2. База данных: встроенный PostgreSQL вместо SQLite

Код привязан к PostgreSQL сильнее, чем к одной колонке:

| Конструкция | Число вхождений в `api/app` и миграциях |
|---|---|
| `JSONB` | 66 |
| `::jsonb` | 22 |
| Функции `jsonb_*` | 15 |
| `on_conflict` | 6 |
| `pg_advisory` | 3 |
| `FOR UPDATE`, `SKIP LOCKED` | 2 + 2 |
| Функции PostGIS (`ST_*`), геотипы | 0 |

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Встроенный PostgreSQL** (выбран) | Один диалект SQL в обеих версиях; миграции и очередь заданий без изменений; результаты расчётов совпадают по построению | Файл программы больше примерно на 50–100 МБ; ещё один дочерний процесс; первый запуск дольше на `initdb` |
| SQLite | Один файл, нет сервера | Два диалекта при параллельной разработке: каждая миграция и каждый JSON-запрос пишутся и тестируются дважды; 8–12 дней на перенос |

Правила для встроенного PostgreSQL:

- **Состав:** официальные двоичные файлы PostgreSQL 16 для Windows без PostGIS (он не используется).
- **Данные:** `%LOCALAPPDATA%\BedrockForge\pg`, создаются `initdb` при первом запуске.
- **Сеть:** только `127.0.0.1`, свободный порт выбирается при запуске.
- **Доступ:** случайный пароль на установку (SCRAM), хранится в Credential Manager.
- **Жизненный цикл:** Electron запускает и останавливает сервер (`pg_ctl stop -m fast`); после сбоя — проверка и запуск заново.
- **Версия:** основная версия закреплена; переход на следующую — отдельная задача с `pg_upgrade`.
- **Резервная копия проекта:** `pg_dump` плюс файлы хранилища в один архив.

## 3. Целевая архитектура

```
BedrockForge.exe (Electron, portable)
 ├── окно Chromium: собранный web/ как статика
 ├── postgres.exe            127.0.0.1:<порт 1>
 ├── bedrockforge-api.exe    127.0.0.1:<порт 2>, токен запуска
 └── bedrockforge-worker.exe тяжёлые задания и разбор файлов
```

| Что | Где |
|---|---|
| Программа | Один файл `BedrockForge-<версия>-portable.exe` в любой папке; при запуске распаковывается во временную папку |
| Хранилище файлов (`DATA_DIR`) | `%APPDATA%\BedrockForge\data` |
| База | `%LOCALAPPDATA%\BedrockForge\pg` |
| Журналы, кеш numba | `%LOCALAPPDATA%\BedrockForge\logs`, `...\cache` |
| Ключ Claude, пароль БД | Windows Credential Manager |

Различия версий сводятся к режиму запуска:

| Тема | Браузерная версия | Десктоп |
|---|---|---|
| Запуск | Docker Compose | Electron запускает три процесса |
| Адрес API | Прокси Vite, `/api` | Адрес и токен передаются окну при запуске |
| Авторизация API | Нет (локальная установка) | Токен запуска обязателен |
| Выбор файлов | Диалог браузера | Системный диалог Electron |
| MCP | Включён | Выключен по умолчанию |

Режим задаётся переменной окружения (`BF_MODE=desktop`); ветвлений по режиму в коде расчётов и форматов быть не должно.

## 4. Безопасность

Главная угроза: локальный HTTP-сервер без авторизации доступен любой программе на машине и любой странице в браузере пользователя.

| # | Находка | Где | Мера | Версия |
|---|---|---|---|---|
| S1 | API без авторизации; CORS не останавливает простые запросы | `api/app/main.py` | Токен на запуск: Electron генерирует его, передаёт API и окну; без токена ответ 401 | Десктоп |
| S2 | Привязка к `0.0.0.0`, база с паролем `geo/geo` открыта в сеть | `docker-compose.yml` | Только `127.0.0.1`; проверка `Host` и `Origin` на всех маршрутах | Обе |
| S3 | MCP управляет интерфейсом и читает данные | `api/app/mcp_server.py` | Выключен по умолчанию; включение в настройках, отдельный токен | Десктоп |
| S4 | `Image.MAX_IMAGE_PIXELS = None` снимает защиту от «бомб» | `api/app/formats/inspect.py:133` | Предел 400 млн пикселей, как в `rasters.py` | Обе |
| S5 | Разбор недоверенных файлов в процессе API | `api/app/formats/` | Пределы на размер после распаковки и число объектов; разбор в рабочем процессе с ограничением памяти (Job Object) | Обе, Job Object — десктоп |
| S6 | Ключ Claude в файле | `api/app/assistant/connection.py:124` | Credential Manager (DPAPI); профиль `ant` в папке с доступом только пользователю | Десктоп |
| S7 | Запуск `ant` через `subprocess` | `connection.py:343` | Абсолютный путь внутри установки, проверка SHA-256 при сборке, без поиска по `PATH` | Десктоп |
| S8 | Настройки Electron | новый код | `contextIsolation`, `sandbox`, без `nodeIntegration`; запрет навигации и новых окон; узкий IPC через preload | Десктоп |
| S9 | Ответы Claude показываются как разметка | `web/src/shell/markdown.tsx` | `dangerouslySetInnerHTML` и `eval` в коде нет: закрепить тестом и строгим CSP | Обе |
| S10 | Цепочка поставки | сборка | Закреплённые версии с хешами (`pip --require-hashes`, `npm ci`), SBOM к каждому выпуску | Обе |
| S11 | Запуск | portable `.exe` | Без прав администратора; данные только в папках пользователя | Десктоп |
| S12 | Команды интерфейса от Claude и MCP | `api/app/ui_bridge.py` | Подтверждение разрушающих команд (удаление, перезапись) | Обе |

## 5. Выпуск без сертификата подписи

| Последствие | Что делаем |
|---|---|
| SmartScreen показывает «Неизвестный издатель» при каждой новой версии | Инструкция в README: «Подробнее → Выполнить в любом случае» |
| Антивирусы чаще срабатывают на PyInstaller | Сборка `onedir`, без UPX; при ложном срабатывании — заявка в Microsoft на пересмотр |
| Обновление нельзя проверить по подписи издателя | Проверка новой версии только по HTTPS с GitHub Releases; SHA-256 нового файла сверяется с `SHA256SUMS.txt` выпуска |
| Пользователь не может проверить происхождение файла | SHA-256 в описании выпуска; аттестация сборки GitHub (`gh attestation verify`), сборка только в GitHub Actions |
| Целостность держится на аккаунте GitHub | Двухфакторная авторизация, защита ветки выпуска, выпуск только из тега |

Остаточный риск: тот, кто получит доступ к репозиторию, может выпустить обновление. Без сертификата он не закрывается полностью.

## 9. Критерии приёмки

| Область | Критерий |
|---|---|
| Безопасность | Запрос к API без токена получает 401 |

| Безопасность | Порты API и базы недоступны из локальной сети |

## 11. Что не проверено
