### Допущения Э2 (были в отчёте В1)
- Э2: переименование проекта не меняет имя папки `<Имя>.bfproj` (папка открыта ядром; пользователю не показывается).
- Э2: удаление проекта — сразу (переименование папки в `.del-…` и удаление), не заданием; занятый другим окном — 423.
- Э2: `quick_check` при открытии — всегда синхронно; фоновая проверка баз > 200 МБ — когда появятся большие таблицы (Э3).
- Э2: `.bfggis` из BF распознаётся (шаг 2 показывает название и состав), перенос его данных — с этапами их типов;
  приёмка «демо из BF с теми же счётчиками и итогом аудита» — после Э5.
- Э2: исполнителей общей очереди по умолчанию 1 (ТЗ 7.6 «по умолчанию 1 + 1 быстрый»), а не min(ядра−1, ОЗУ/3 ГБ) из 6.7;
  число меняется в «Настройке». Лимит памяти через вложенный Job Object — на Э24 (сейчас: оценка памяти до старта и MemoryError → понятная ошибка).
- Э2: импорт проекта — не больше 2 попыток (ТЗ 6.7 «импорт — не больше 2 попыток»), остальные задания — 3 (7.6).
- Э2: задания с паролем (зашифрованные экспорт и импорт) после сбоя исполнителя не повторяются без пароля:
  «Ошибка: пароль не сохраняется», «Повторить» недоступно — запуск заново с паролем. Пароль заданий закрытого
  проекта стирается при их запуске или отмене (secure_delete включён).
- Э2: сборщик blobs — каждые 30 мин (ADR 0002), файл без строки старше 15 мин; итог «не позже чем через час» выполняется.
