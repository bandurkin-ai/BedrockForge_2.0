# Форматы файлов: результаты разбора образцов

Разбор образцов, присланных к этапам 9–11 плана (`docs/ROADMAP.md`). Образцы в git не хранятся.
Все образцы в одной системе координат: WGS 84 / UTM 38N (по подписи на карте).

| Образец | Формат | Содержимое | К этапу |
|---|---|---|---|
| Контуры участков `.STR` | Micromine STR | 6 замкнутых контуров участков ГРР, 101 точка | 9 |
| `TST-FAULTS.DXF` | DXF 2004 (AC1018), polyface | Каркас разломов: 7 443 вершины, 7 417 треугольников | 10 |
| `Pit.tridb` | Micromine TRIDB | 2 каркаса: «выемка» (47 625 точек, 95 246 треуг.) и «насыпь» (2 964 / 5 856) | 10 |
| Восточный_TS `.jpg` + `.jgw` / `.TAB` / `.grf` | Растр и три файла привязки | Карта участков Восточный Цители-Сопели, 1:10 000 | 11 |

## Micromine STR

Тот же формат, что DAT: XML-заголовок 4096 байт, блок `N VARIABLES`, записи фиксированной длины с `CRLF`.

| Поле | Тип | Смысл |
|---|---|---|
| `EAST`, `NORTH`, `RL` | `R 8` — double | Координаты точки |
| `JOIN` | `N 12` — **число, записанное текстом** | Номер линии: смена значения = новая линия |
| `STRING` | `C 20` | Код линии (в образце пустой) |
| Свои поля | `C` | Атрибуты, например «Участок» |

Доработано в `api/app/formats/micromine.py` (читатель линий — `api/app/formats/lines.py`):

| Проблема | Сейчас | Нужно |
|---|---|---|
| Тип поля `N` | Было: ошибка «unknown field type» | Сделано: текст переводится в число |
| Кириллица | Было: только ASCII и BOCU-1 | Сделано: `ibm-5347` = cp1251 (имена полей и значения) |

Линия замкнута, если первая и последняя точки совпадают (так во всех 6 контурах). В образце `RL = 1000` у всех точек — контуры плоские.

## Micromine TRIDB

База SQLite (текст в UTF-16). Один файл хранит несколько каркасов.

| Таблица | Содержимое |
|---|---|
| `GeneralInformation` | Каркас: `ID`, `Name`, `Colour` (BGR), охват, `Volume`, `SurfaceArea`, автор и даты (Unix-время) |
| `Geometry` | Двоичная геометрия: `ID`, `Geometry` BLOB |
| `GeometryProperties` | `PointCount`, `TriangleCount`, `Volume`, `SurfaceArea`, `PlanSilhouetteArea` |
| `UserAttributeDefinition` / `Value` | Атрибуты каркаса (в образце — параметры карьера: углы откоса, ширина бермы, высота уступа) |
| `PointAttribute*`, `TriangleAttribute*` | Атрибуты вершин и треугольников (в образце пусто) |

Структура BLOB `Geometry` (little-endian), проверена на обоих каркасах:

| Смещение | Размер | Содержимое |
|---|---|---|
| 0 | 8 | `FF FF FF FF 00 00 05 00` — признак и версия (5) |
| 8 | 8 | int64 = 36 — длина GUID |
| 16 | 8 | int64 = 9 |
| 24 | 36 | GUID каркаса (ASCII), совпадает с `GeometryProperties.GUID` |
| 60 | далее | Блоки: int64 длина в байтах, int64 номер блока, данные |

| Блок | Данные |
|---|---|
| 1 | X вершин, double × N |
| 2 | Y вершин, double × N |
| 3 | Z вершин, double × N |
| 4 | Треугольники, int32 × 3 × M, индексы вершин с 0 |

Проверка: N и M совпадают с `PointCount` и `TriangleCount`, индексы в диапазоне `0…N−1`, охват — с `GeneralInformation`.

## DXF: каркас polyface

Образец: одна сущность `POLYLINE` с флагом 64 (polyface mesh), слой `FLT-Combined_TST`, кодовая страница `ANSI_1251`.

| Сущность | Флаг 70 | Смысл |
|---|---|---|
| `VERTEX` | 192 | Вершина сетки (коды 10/20/30) |
| `VERTEX` | 128 | Грань: коды 71–74 — номера вершин с 1; отрицательный номер — невидимое ребро |

Четырёхугольных граней в образце нет. Для чтения нужна библиотека `ezdxf` (в зависимостях пока отсутствует).
Z разломов: 182–588 м — каркас пересекается с областью карьера из `Pit.tridb`.

## Привязка растров

Три файла привязки описывают одно изображение и согласованы между собой.

| Файл | Формат | Содержимое |
|---|---|---|
| `.jgw` (`.pgw`, `.tfw`) | World-файл ESRI | 6 чисел: A, D, B, E, C, F; `X = A·col + B·row + C`, `Y = D·col + E·row + F`; C, F — **центр** левого верхнего пикселя |
| `.TAB` | MapInfo, `Type "RASTER"` | Опорные точки `(X, Y) (col, row) Label`; `CoordSys`, единицы |
| `.grf` | Привязка Micromine | Строки 1–3: X, Y, Z **угла** изображения; 4–5: размер пикселя; 6–11: матрица поворота 2×3; далее опорные точки `col row X Y Z флаг` |

Проверка на образце:

- размер пикселя ≈ 2,02 м, поворот ≈ 0,2°;
- начало в `.grf` смещено от `.jgw` на полпикселя — разница между углом и центром пикселя;
- world-файл — аффинное приближение по 7 опорным точкам TAB, отклонения 0,5–4,6 м (до двух пикселей).

Порядок выбора привязки при импорте: world-файл → TAB → GRF; если есть опорные точки, показывать отклонения по каждой.

## OMF v1 (Open Mining Format)

Формат обмена горных ГГИС (Global Mining Guidelines Group). Leapfrog Geo 2026.1 читает и пишет только OMF 0.9 — это файловая версия v1; её и поддерживаем в обе стороны. OMF 2 (ZIP с `project.json`) не читается: мастер импорта так и сообщает. Код — `api/app/formats/omf.py`, библиотека `omf` не используется (нужен numpy < 2 и пакет `properties`, который не собирается на Python 3.12+). Эталон разбора — читатель v1 из omf-python (`omf/compat/omf_v1.py`), образец — `api/tests/fixtures/omf_v1_test_file.omf`.

| Смещение | Размер | Содержимое |
|---|---|---|
| 0 | 4 | `84 83 82 81` — сигнатура |
| 4 | 32 | Версия: `OMF-v0.9.0`, дополнена нулями |
| 36 | 16 | UUID проекта |
| 52 | 8 | uint64 — смещение JSON |
| 60 | … | Двоичные блоки, каждый — отдельный поток zlib |
| JSON | до конца | Словарь `uid → объект` с полем `__class__`; объекты ссылаются друг на друга по uid |

| Массив | Где значения | Форма |
|---|---|---|
| `ScalarArray` | Блок `{start, length, dtype}` | (n) |
| `Vector2Array`, `Vector3Array` | Блок | (n, 2), (n, 3) |
| `Int2Array`, `Int3Array` | Блок, обычно `<i8` | (n, 2), (n, 3) |
| `StringArray`, `DateTimeArray`, `ColorArray` | Список прямо в JSON | — |

Порядок узлов и ячеек сеток — Фортран: быстрее всех меняется u, затем v, затем w (проверено тестом на сетке 2 × 3 × 4 с разным шагом).

### Соответствие объектов

| OMF v1 | BedrockForge | Что не переносится |
|---|---|---|
| `SurfaceElement` + `SurfaceGeometry` | Каркас | Данные на вершинах и гранях |
| `SurfaceElement` + `SurfaceGridGeometry` | Каркас: узлы `origin + u·axis_u + v·axis_v + offset_w·(axis_u × axis_v)`, по два треугольника на ячейку | То же |
| `LineSetElement` | Слой линий: идущие подряд сегменты склеиваются в линию; линия, вернувшаяся в первую вершину, — замкнутая | Данные на вершинах и меняющиеся вдоль линии; постоянные вдоль линии становятся её атрибутами |
| `VolumeElement` | Блочная модель: центр и размер каждой ячейки; ячейки без значений не загружаются | Повёрнутая модель (оси не вдоль X, Y, Z) — не загружается; данные на узлах |
| `ScalarData` в ячейках | Числовое поле | — |
| `MappedData`, `StringData`, `DateTimeData` в ячейках | Категория; подписи — первая легенда, не цвета | Цвета легенды |
| `PointSetElement` | — (точек пока нет, этап 9) | Весь элемент |
| Текстуры `ImageTexture` | — | Изображения |
| `origin` проекта и геометрии | Прибавляется к координатам | — |
| `color` элемента `[r, g, b]` | `#rrggbb` | — |

Всё, что не перенесено, перечисляется в журнале задания и в `meta.warnings` наборов.

### Экспорт

| BedrockForge | OMF v1 |
|---|---|
| Каркас | `SurfaceElement`, координаты float64 как есть, `origin` = 0 |
| Слой линий | `LineSetElement`; замкнутая линия — петля на первую вершину; атрибуты линии — на её сегментах (числа — `ScalarData`, текст — `MappedData`) |
| Регулярная блочная модель | `VolumeElement` с полной сеткой по `meta.grid`; ячейки без блоков — NaN или −1; единица поля — в описании данных («Единицы: g/t», при импорте читается обратно) |
| Субблочная или повёрнутая модель, сетка > 100 млн ячеек | Не записывается, причина — в журнале |

Проверки: файл → чтение → запись → чтение совпадает побитно (`tests/test_omf.py`); экспортированный файл открывает `omf.load` из omf-python и проходит `validate()` (разовая проверка в Python 3.11). Открытие в Leapfrog не проверялось.
