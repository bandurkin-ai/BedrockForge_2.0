# BedrockForge

ГГИС в браузере: данные бурения, визуализация, аудит качества данных и ассистент Claude. Работает в Chrome на Windows и macOS.

## Структура

| Путь | Назначение |
|---|---|
| `api/` | Бэкенд на FastAPI: чтение файлов, аудит, работа с PostgreSQL |
| `api/app/formats/` | Форматы файлов. Сейчас: Micromine DAT (нативное чтение) |
| `web/` | Интерфейс на React + TypeScript + Vite |
| `docker-compose.yml` | PostgreSQL + PostGIS, API, веб-интерфейс |

## Интерфейс (этап 6): лента, окна видов, Claude

Компоновка «лента + вьюпорт» для компьютера (минимальная ширина 1024 px), тёмная тема по умолчанию.

| Область | Назначение |
|---|---|
| Заголовок | Выбор проекта, поиск команд и скважин (`Ctrl+K`), тема, кнопка Claude |
| Лента | Вкладки «Главная», «Вид», «Анализ», «Claude»; сворачивается (`Ctrl+F1`) |
| Рабочая область | 1, 2 или 4 окна; в каждом — 3D, План, Разрез, Колонка, Таблица, Аудит или Импорт. Выбор скважины общий для всех окон |
| Левая панель | Дерево проекта: таблицы данных и навигатор скважин с отметками аудита |
| Правая панель | «Свойства» (скважина или проект, раскраска по содержаниям) и чат «Claude» |
| Нижняя панель | Таблица данных и журнал команд (кто выполнил: вы, Claude, MCP) |
| Строка состояния | Сервер, проект, выбранная скважина, активное окно, состояние Claude и MCP, итог аудита |

Горячие клавиши: `3` / `P` / `S` / `L` / `T` — вид в активном окне, `Esc` — снять выбор, `Ctrl+K` — палитра команд,
`Ctrl+J` — Claude, `Ctrl+B` — дерево проекта, ``Ctrl+` `` — нижняя панель. Буквы работают в любой раскладке.

Адрес описывает активное окно: `#/3d?hole=BHTSE-1`. Компоновка, панели и тема запоминаются в браузере.

### Демо-проект

Лента **Главная → Демо-проект** (или кнопка «Загрузить демо-проект» в пустом дереве) создаёт учебный проект
«Демо: участок Северный»: 48 скважин, пробы AU и CU, результат аудита с несколькими намеренными ошибками.
Повторное нажатие открывает уже созданный проект. API: `POST /api/projects/demo`.

### Реестр команд

Все действия приложения описаны один раз в `web/src/shell/registry.ts`: идентификатор, описание, параметры, функция.
Один и тот же список используют лента, палитра, горячие клавиши, встроенный ассистент и MCP.

| Чтобы добавить | Где |
|---|---|
| Новое действие | команда в `web/src/shell/registry.ts` — Claude и MCP получают её автоматически |
| Кнопку на ленте, горячую клавишу | `web/src/shell/ribbon.ts` |
| Новый вид в окне | `VIEW_TITLES` в `web/src/shell/workspace.ts`, маршрут в `route.ts`, отрисовка в `App.tsx` |
| Инструмент чтения данных для Claude | `api/app/assistant/tools.py` (+ обёртка в `api/app/mcp_server.py`) |

Признаки команды: `uiOnly` — недоступна Claude, `confirm` — меняет данные, перед выполнением по запросу Claude
пользователь подтверждает действие в чате.

### Claude внутри приложения

Панель «Claude» отправляет сообщение на сервер вместе с контекстом экрана (проект, окна, выбранная скважина, шкала, разрез).
Сервер вызывает Claude API (`api/app/assistant/service.py`): инструменты `data_*` выполняются на сервере,
команды интерфейса `ui_*` возвращаются в браузер и выполняются там.

| Переменная окружения API | Назначение |
|---|---|
| `ANTHROPIC_API_KEY` | Ключ Claude API. Без него панель показывает «Claude не подключён» |
| `ASSISTANT_MODEL` | Модель, по умолчанию `claude-opus-5-5` |
| `ASSISTANT_EFFORT` | Глубина рассуждений: `low`, `medium` (по умолчанию), `high` |

```bash
ANTHROPIC_API_KEY=... docker compose up --build
```

| Эндпоинт | Назначение |
|---|---|
| `GET /api/assistant/status` | Подключён ли Claude и какая модель |
| `POST /api/projects/{id}/assistant/chat` | Ход диалога: текст или результаты команд интерфейса |

Диалоги хранятся в памяти сервера и теряются при перезапуске.

### MCP: управление из claude.ai, Claude Desktop, Claude Code

API публикует MCP-сервер (streamable HTTP) по адресу `http://localhost:8000/mcp`.

| Инструменты | Что делают |
|---|---|
| `list_projects`, `data_*` | Читают проекты, скважины, таблицы, аудит, статистику компонентов |
| `ui_list_commands`, `ui_run_command` | Выполняют команды реестра в открытой у пользователя вкладке BedrockForge |

Команды интерфейса работают, пока приложение открыто в браузере (в строке состояния «MCP: готов»).

```bash
claude mcp add --transport http bedrockforge http://localhost:8000/mcp
```

claude.ai подключается только к общедоступному HTTPS-адресу. У MCP-сервера и API **нет авторизации**:
публикуйте их только через туннель или прокси с собственной защитой и укажите внешний хост в `MCP_ALLOWED_HOSTS`.

| Эндпоинт | Назначение |
|---|---|
| `POST /mcp` | MCP-сервер |
| `GET /api/projects/{id}/ui/sessions/{sid}/events` | Поток команд для вкладки браузера (SSE) |
| `POST .../ui/sessions/{sid}/commands`, `.../results` | Список команд вкладки и результаты их выполнения |

| Эндпоинт | Назначение |
|---|---|
| `GET /api/projects/{id}/holes` | Список устьев со счётчиками замеров, проб и находок аудита |
| `GET /api/projects/{id}/holes/{hole_id}` | Карточка скважины и её находки |
| `GET /api/projects/{id}/tables/{kind}?hole_id=` | Таблица с фильтром по скважине |

Тесты веба: `cd web && npm test`.

## Импорт (этапы 2.1–2.2)

Экран импорта принимает **Micromine DAT**, **CSV/TXT** и **Excel (.xlsx, .xlsm)**: загрузка или перетаскивание файла,
автоопределение типа таблицы (Collar / Survey / Assay), назначение колонок, компоненты с единицами, проверка и предпросмотр.
Старый формат `.xls` не поддерживается: его нужно пересохранить в `.xlsx`.

| Возможность | Как работает |
|---|---|
| Кодировка текста | Определяется автоматически: UTF-8 (с BOM и без), UTF-16, cp1251, cp866, KOI8-R; можно выбрать вручную |
| Разделитель | `;` `,` табуляция `|` или пробелы; определяется по одинаковому числу полей в строках |
| Строка заголовка | Номер строки с названиями колонок (пустые строки не считаются), 0 — без заголовка; титульные строки пропускаются |
| Лист Excel | По умолчанию первый лист с данными; можно выбрать другой |
| Числа | Десятичная точка или запятая, пробелы между разрядами (`4 584 699,70`) |
| Предел обнаружения | `<0.005` записывается как половина предела (0.0025), `>1000` — как 1000; на экране показывается, сколько значений заменено |
| Пустые значения | `-`, `н/д`, `н.о.`, `NA`, `N/A` и т. п. считаются пустыми |
| Названия колонок | Русские и английские: «Скважина», «От», «До», «№ пробы», «Глубина (м)», «X, м», «Au, г/т» (единица берётся из названия) |
| Ошибки в числах | Текст в числовом поле показывается с примером значения и числом строк |

На образце проекта те же данные в CSV (cp1251, `;`, десятичная запятая) и в Excel дают тот же проект, что и DAT:
совпадают количества строк, значения и итог аудита.

| Эндпоинт | Назначение |
|---|---|
| `GET /api/import/schemas` | Целевые таблицы и поля |
| `POST /api/import/upload` | Загрузка файла, параметры чтения, предпросмотр, предложенное назначение колонок |
| `POST /api/import/{file_id}/options` | Перечитать файл с другой кодировкой, разделителем, строкой заголовка или листом |
| `POST /api/import/validate` | Проверка назначения, нормализованный предпросмотр |

## База данных (этап 3)

PostgreSQL 16 (в Docker с PostGIS). Схема создаётся миграциями Alembic: при старте контейнера API выполняется `alembic upgrade head`.

| Таблица | Содержимое |
|---|---|
| `project` | Проекты (данные разных проектов изолированы) |
| `collar`, `survey`, `assay` | Устья, инклинометрия, пробы; свободные колонки в `attributes` (JSONB) |
| `assay.analytes` | Значения компонентов по имени, например `{"AU": 0.007}` |
| `component` | Справочник компонентов с единицами измерения |
| `import_job` | История импорта: файл, назначение колонок, число строк |

Повторный импорт файла того же типа **заменяет** данные этого типа в проекте.

| Эндпоинт | Назначение |
|---|---|
| `GET/POST /api/projects`, `DELETE /api/projects/{id}` | Проекты |
| `GET /api/projects/{id}/summary` | Счётчики, компоненты, история импорта |
| `GET /api/projects/{id}/tables/{collar\|survey\|assay}` | Постраничный просмотр данных |
| `POST /api/import/commit` | Сохранение файла в проект |

Новая миграция после изменения `app/models.py`:

```bash
cd api
alembic revision --autogenerate -m "описание"
```

## Визуализация (этап 5)

Виды **План**, **Разрез**, **Колонка** и **3D**. Траектории считаются на сервере методом минимальной кривизны
(`api/app/geo/trajectory.py`). Азимут отсчитывается по часовой стрелке от севера, наклон отрицательный вниз.
На образце проекта траектории совпадают с координатами X/Y/Z, рассчитанными в Micromine, с точностью до 5 см
(21 145 интервалов, медиана отклонения 1 см).

| Вид | Что показывает |
|---|---|
| План | Устья и стволы в плане, цвет по замечаниям аудита, статусу или глубине; масштаб и сдвиг; инструмент «Линия разреза» (два клика) |
| Разрез | Вертикальный разрез по профилю с коридором (азимут, ширина, вертикальный масштаб ×1–5); стволы раскрашены по содержаниям |
| Колонка | Выбранная скважина по глубине: замеры (азимут/наклон), цветные интервалы проб, столбчатая диаграмма содержания |
| 3D | Стволы и интервалы в трёх измерениях, вращение, выбор скважины кликом, виды «Вписать / Сверху / Сбоку» |

Шкала цвета общая для разреза, колонки и 3D: компонент, диапазон (по умолчанию 5–95 перцентиль) и логарифмический режим настраиваются в панели «Свойства».
3D (three.js, ~130 КБ gzip) загружается только при открытии вида.

| Эндпоинт | Назначение |
|---|---|
| `GET /api/projects/{id}/trajectories` | Траектории: точки `[x, y, z, глубина]`, пропущенные устья без координат |
| `GET /api/projects/{id}/intervals?component=` | Интервалы компонента с 3D-координатами концов и статистикой значений |
| `GET /api/projects/{id}/holes/{hole_id}/log` | Данные колонки скважины |

## Аудит данных (этап 4)

Вид «Аудит»: запуск 27 правил по Collar, Survey и Assay, результаты по правилам (в том числе пройденным),
фильтруемый список находок и отчёт в Excel (листы «Сводка», «По правилам», «Находки»).
Находки сгруппированы по скважине и правилу: `count` — число строк, в `details.examples` — до 20 примеров.
Новый запуск заменяет предыдущий результат проекта; после нового импорта отчёт помечается устаревшим.

| Группа | Правила |
|---|---|
| Устья | нет координат, неверная глубина TD, углы вне диапазона, изолированное устье, скачок Z, плановая скважина с данными, пустой статус, нет инклинометрии, нет проб |
| Инклинометрия | скважины нет в устьях, пустые значения, углы вне диапазона, замер глубже забоя, дубли и нарушение порядка глубин, первый замер не на устье, резкий изгиб (°/30 м), расхождение с устьем |
| Пробы | скважины нет в устьях, некорректный интервал, глубже забоя, перекрытие, разрыв, дубли номеров проб, отрицательные и пустые содержания, экстремальные значения |

Пороги (допуск по глубине, изгиб, изоляция устья, скачок Z, выброс содержания) задаются в интерфейсе.
Добавить правило: описать в `app/audit/rules.py`, реализовать проверку в `app/audit/checks.py`, покрыть тестом в `tests/test_audit_checks.py`.

| Эндпоинт | Назначение |
|---|---|
| `POST /api/projects/{id}/audit` | Запуск аудита (необязательно: пороги в теле) |
| `GET /api/projects/{id}/audit` | Последний результат или `null` |
| `GET /api/projects/{id}/audit/findings` | Находки с фильтрами `severity`, `table`, `code`, `hole_id` |
| `GET /api/projects/{id}/audit/export.xlsx` | Отчёт в Excel |

## Запуск (Docker)

```bash
docker compose up --build
```

- Интерфейс: http://localhost:5173
- API: http://localhost:8000/api/health
- PostgreSQL: localhost:5432 (пользователь и база `geo`)

## Тесты API

```bash
cd api
python -m venv .venv && . .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
pytest
```

Тесты с базой используют `TEST_DATABASE_URL` (по умолчанию `postgresql+psycopg://geo:geo@localhost:5432/geo_test`);
без доступной PostgreSQL они пропускаются. Схема в тестах создаётся теми же миграциями.

Проверка на реальных файлах проекта (не хранятся в репозитории):

```bash
MICROMINE_SAMPLE_DIR=/путь/к/папке/с/DAT pytest
```
