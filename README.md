# Геологическая система: скважины и аудит данных

Веб-приложение для геолога и первичного аудита данных ГРР. Работает в Chrome на Windows и macOS.

## Структура

| Путь | Назначение |
|---|---|
| `api/` | Бэкенд на FastAPI: чтение файлов, аудит, работа с PostgreSQL |
| `api/app/formats/` | Форматы файлов. Сейчас: Micromine DAT (нативное чтение) |
| `web/` | Интерфейс на React + TypeScript + Vite |
| `docker-compose.yml` | PostgreSQL + PostGIS, API, веб-интерфейс |

## Интерфейс (этап 1)

| Область | Назначение |
|---|---|
| Верхняя панель | Выбор проекта, создание проекта, кнопка меню на узких экранах |
| Левая панель | Таблицы данных со счётчиками, поиск по списку скважин (с отметками аудита), карточка выбранной скважины |
| Вкладки | Таблица, План, Разрез, 3D (заглушки до этапа «Визуализация»), Аудит, Импорт |
| Строка состояния | Связь с сервером, проект, число скважин, выбранная скважина, итог последнего аудита |

Состояние хранится в адресе: `#/table/assay?hole=BHTSE-1`. Перезагрузка и кнопки браузера «Назад/Вперёд» сохраняют вкладку, таблицу и выбранную скважину.
Выбор скважины фильтрует таблицу и список находок аудита. Работает на экранах от 360 px.

| Эндпоинт | Назначение |
|---|---|
| `GET /api/projects/{id}/holes` | Список устьев со счётчиками замеров, проб и находок аудита |
| `GET /api/projects/{id}/holes/{hole_id}` | Карточка скважины и её находки |
| `GET /api/projects/{id}/tables/{kind}?hole_id=` | Таблица с фильтром по скважине |

Тесты веба: `cd web && npm test`.

## Импорт (этап 2.1)

Экран импорта: загрузка `.DAT` (Micromine), автоопределение типа таблицы (Collar / Survey / Assay),
назначение колонок, выбор компонентов с единицами, проверка и предпросмотр.

| Эндпоинт | Назначение |
|---|---|
| `GET /api/import/schemas` | Целевые таблицы и поля |
| `POST /api/import/upload` | Загрузка файла, предпросмотр, предложенное назначение колонок |
| `POST /api/import/validate` | Проверка назначения, нормализованный предпросмотр |

Форматы CSV и Excel появятся на этапе 2.2.

## База данных (этап 3)

PostgreSQL 16 (в Docker с PostGIS). Схема создаётся миграциями Alembic: при старте контейнера API выполняется `alembic upgrade head`.

| Таблица | Содержимое |
|---|---|
| `project` | Проекты (данные разных проектов изолированы) |
| `collar`, `survey`, `assay` | Устья, инклинометрия, пробы; свободные колонки в `attributes` (JSONB) |
| `assay.analytes` | Значения компонентов по имени, например `{"AU": 0.007}` |
| `component` | Справочник компонентов с единицами измерения |
| `import_job` | История импорта: файл, назначение колонок, число строк |

Повторный импорт файла того же типа **заменяет** данные этого типа в проекте.

| Эндпоинт | Назначение |
|---|---|
| `GET/POST /api/projects`, `DELETE /api/projects/{id}` | Проекты |
| `GET /api/projects/{id}/summary` | Счётчики, компоненты, история импорта |
| `GET /api/projects/{id}/tables/{collar\|survey\|assay}` | Постраничный просмотр данных |
| `POST /api/import/commit` | Сохранение файла в проект |

Новая миграция после изменения `app/models.py`:

```bash
cd api
alembic revision --autogenerate -m "описание"
```

## Визуализация (этап 5)

Вкладки **План**, **Разрез**, **Колонка** и **3D**. Траектории считаются на сервере методом минимальной кривизны
(`api/app/geo/trajectory.py`). Азимут отсчитывается по часовой стрелке от севера, наклон отрицательный вниз.
На образце проекта траектории совпадают с координатами X/Y/Z, рассчитанными в Micromine, с точностью до 5 см
(21 145 интервалов, медиана отклонения 1 см).

| Вкладка | Что показывает |
|---|---|
| План | Устья и стволы в плане, цвет по замечаниям аудита, статусу или глубине; масштаб и сдвиг; инструмент «Линия разреза» (два клика) |
| Разрез | Вертикальный разрез по профилю с коридором (азимут, ширина, вертикальный масштаб ×1–5); стволы раскрашены по содержаниям |
| Колонка | Выбранная скважина по глубине: замеры (азимут/наклон), цветные интервалы проб, столбчатая диаграмма содержания |
| 3D | Стволы и интервалы в трёх измерениях, вращение, выбор скважины кликом, виды «Вписать / Сверху / Сбоку» |

Шкала цвета общая для разреза, колонки и 3D: компонент, диапазон (по умолчанию 5–95 перцентиль) и логарифмический режим настраиваются на панели.
3D (three.js, ~130 КБ gzip) загружается только при открытии вкладки.

| Эндпоинт | Назначение |
|---|---|
| `GET /api/projects/{id}/trajectories` | Траектории: точки `[x, y, z, глубина]`, пропущенные устья без координат |
| `GET /api/projects/{id}/intervals?component=` | Интервалы компонента с 3D-координатами концов и статистикой значений |
| `GET /api/projects/{id}/holes/{hole_id}/log` | Данные колонки скважины |

## Аудит данных (этап 4)

Вкладка «Аудит»: запуск 27 правил по Collar, Survey и Assay, результаты по правилам (в том числе пройденным),
фильтруемый список находок и отчёт в Excel (листы «Сводка», «По правилам», «Находки»).
Находки сгруппированы по скважине и правилу: `count` — число строк, в `details.examples` — до 20 примеров.
Новый запуск заменяет предыдущий результат проекта; после нового импорта отчёт помечается устаревшим.

| Группа | Правила |
|---|---|
| Устья | нет координат, неверная глубина TD, углы вне диапазона, изолированное устье, скачок Z, плановая скважина с данными, пустой статус, нет инклинометрии, нет проб |
| Инклинометрия | скважины нет в устьях, пустые значения, углы вне диапазона, замер глубже забоя, дубли и нарушение порядка глубин, первый замер не на устье, резкий изгиб (°/30 м), расхождение с устьем |
| Пробы | скважины нет в устьях, некорректный интервал, глубже забоя, перекрытие, разрыв, дубли номеров проб, отрицательные и пустые содержания, экстремальные значения |

Пороги (допуск по глубине, изгиб, изоляция устья, скачок Z, выброс содержания) задаются в интерфейсе.
Добавить правило: описать в `app/audit/rules.py`, реализовать проверку в `app/audit/checks.py`, покрыть тестом в `tests/test_audit_checks.py`.

| Эндпоинт | Назначение |
|---|---|
| `POST /api/projects/{id}/audit` | Запуск аудита (необязательно: пороги в теле) |
| `GET /api/projects/{id}/audit` | Последний результат или `null` |
| `GET /api/projects/{id}/audit/findings` | Находки с фильтрами `severity`, `table`, `code`, `hole_id` |
| `GET /api/projects/{id}/audit/export.xlsx` | Отчёт в Excel |

## Запуск (Docker)

```bash
docker compose up --build
```

- Интерфейс: http://localhost:5173
- API: http://localhost:8000/api/health
- PostgreSQL: localhost:5432 (пользователь и база `geo`)

## Тесты API

```bash
cd api
python -m venv .venv && . .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
pytest
```

Тесты с базой используют `TEST_DATABASE_URL` (по умолчанию `postgresql+psycopg://geo:geo@localhost:5432/geo_test`);
без доступной PostgreSQL они пропускаются. Схема в тестах создаётся теми же миграциями.

Проверка на реальных файлах проекта (не хранятся в репозитории):

```bash
MICROMINE_SAMPLE_DIR=/путь/к/папке/с/DAT pytest
```
