# BedrockForge

ГГИС в браузере: данные бурения, визуализация, аудит качества данных и ассистент Claude. Работает в Chrome на Windows и macOS.

## Структура

| Путь | Назначение |
|---|---|
| `api/` | Бэкенд на FastAPI: чтение файлов, аудит, работа с PostgreSQL |
| `api/app/formats/` | Форматы файлов. Сейчас: Micromine DAT (нативное чтение) |
| `api/app/stats/` | Статистика: нормальные оценки, декластеризация, вариограммы (NumPy/SciPy, перенос из GeostatsPy) |
| `web/` | Интерфейс на React + TypeScript + Vite |
| `docker-compose.yml` | PostgreSQL + PostGIS, API, веб-интерфейс |

## Интерфейс

Компоновка «лента + одно 3D-окно» для компьютера (минимальная ширина 1024 px), тёмная тема по умолчанию.

| Область | Назначение |
|---|---|
| Заголовок | Выбор проекта, поиск команд и скважин (`Ctrl+K`), тема, кнопка Claude |
| Лента | «Главная», «Вид», «Анализ», «Claude»; сворачивается (`Ctrl+F1`) |
| Дерево данных (слева) | Скважины, Линии, Каркасы, Блочные модели, Растры; галочка — видимость в 3D |
| Главное окно | Одна 3D-сцена со всеми объектами; кнопки поворачивают вид и отсекают данные по разрезу |
| Правая панель | «Свойства» (набор, скважина или каркас; раскраска по содержаниям) и чат «Claude» |
| Нижняя панель | Таблица, аудит и статистика активного набора скважин, журнал команд |
| Строка состояния | Сервер, проект, активный набор, выбранная скважина, параметры разреза, Claude и MCP, итог аудита |

### Дерево данных

| Раздел | Что внутри | Состояние |
|---|---|---|
| Скважины | Наборы скважин; в наборе — слои (стволы, содержания, устья), таблицы, аудит, список скважин | Работает |
| Каркасы | Файлы и каркасы в них: цвет, видимость, площадь, объём, замкнутость | Работает: Micromine TRIDB, DXF |
| Линии | Файлы и слои линий (код стринга или слой DXF): цвет, видимость, длина, замкнутость | Работает: Micromine STR, Surpac STR, DXF |
| Растры | Изображения с привязкой: высота, прозрачность, отклонения опорных точек | Работает: JPG, PNG, TIFF, BMP |
| Блочные модели | Модели | Заглушка, этап 12 |

**Наборы скважин независимы**: у каждого свои устья, инклинометрия, пробы, компоненты и аудит, номера скважин
могут повторяться. Повторный импорт таблицы заменяет данные только в своём наборе. Импорт: «+» у раздела
«Скважины» (новый набор) или кнопка импорта у набора.

### Гистограмма проб

Правая кнопка мыши на наборе скважин, на «Пробы» или «Содержания» в дереве → «Гистограмма». Также лента «Анализ → Графики» и команда `chart.histogram` для Claude и MCP. Окно плавающее: перетаскивается, меняет размер, разворачивается; можно открыть несколько.

| Настройка | Варианты |
|---|---|
| Поле | Компоненты, числовые атрибуты таблицы проб, длина интервала |
| Вес | Без веса · длина интервала (по умолчанию) · другое поле · длина × поле (тоннаж, например с плотностью) |
| Значения < 0 | Оставить · половина предела (\|x\|/2, для «<0.01», записанных как −0.01) · исключить; отдельно — исключить нули |
| Отсечка снизу / сверху | Для каждой границы — «исключить» (пробы за порогом не учитываются, например только руда выше бортового) или «заменить значением» (урезка ураганных проб сверху, подъём до предела обнаружения снизу). По умолчанию снизу — исключить, сверху — урезать. Статистика — после отсечек. В API отсечки общие для гистограммы и Q-Q (`bottom_cut`, `bottom_mode`, `top_cut`, `top_mode`) |
| Бины | Линейная или логарифмическая шкала; авто, ширина (в log10 для логарифмической) или число; диапазон «от — до» |
| Вид | Ось Y: доля %, сумма весов, число проб; накопленная кривая; отметки среднего, медианы, P90, P97.5, отсечек; цвет |
| Экспорт | PNG (вдвое крупнее экрана), SVG, CSV бинов |

Статистика: число, сумма весов, минимум, максимум, среднее, медиана, σ, дисперсия, CV, асимметрия, P5–P99, геометрическое среднее, среднее и дисперсия логарифмов — с весом и без веса рядом. Процентили взвешенных данных — по GSLIB (середина накопленного веса); дисперсия генеральная. Эндпоинты: `GET /api/sets/{id}/stats/fields`, `POST /api/sets/{id}/stats/histogram`.

### Q-Q график

Правая кнопка на наборе скважин или «Пробы» → «Q-Q график»; лента «Анализ → Графики»; команда `chart.qq`.

| Режим | Что показывает |
|---|---|
| С распределением (по умолчанию — логнормальное, логарифмические оси) | Каждая проба в своём положении P = (C − w/2)/W против квантиля подобранного распределения (взвешенные среднее и σ, для логнормального — логарифмов). PPCC — корреляция точек: около 1 — распределение подходит. Больше 2000 точек прореживаются с сохранением крайних |
| Две выборки | Квантили X и Y при одинаковых вероятностях k/(n+1) (99 — каждый процент). Стороны — любой набор, поле, вес, фильтры, список скважин: домены, дубликаты, пробы и композиты. Линия 1:1, расстояние Колмогорова–Смирнова D, таблица X / Y / отношение |

Вид: логарифмические оси, одинаковый масштаб, линия 1:1, отметки P10 / P50 / P90, цвет; экспорт PNG, SVG, CSV точек. Эндпоинт: `POST /api/stats/qq`.

### Дендрограмма

Правая кнопка на наборе → «Дендрограмма»; лента «Анализ → Графики»; команда `chart.dendrogram`. Иерархическая кластеризация полей проб по корреляции (scipy) и матрица корреляций в порядке листьев.

| Настройка | Варианты |
|---|---|
| Поля | Любые числовые поля таблицы проб; по умолчанию все компоненты |
| Корреляция | Пирсон или Спирмен (ранговая); по логарифмам (по умолчанию); вес — длина интервала или без веса; пропуски — попарно или только полные строки; значения < 0 и нули — как в гистограмме |
| Кластеры | Расстояние 1 − r или 1 − \|r\|; связь средняя (UPGMA), полная, одиночная, взвешенная (Ward не предлагается: он требует евклидовых расстояний); порог отсечения — группы раскрашиваются |
| Экспорт | PNG, SVG, CSV матрицы корреляций |

### Сохранённые графики

Каждый созданный график (гистограмма, Q-Q, дендрограмма) сразу сохраняется в дереве: набор скважин → «Графики». Изменения настроек сохраняются автоматически; имя следует за настройками, пока график не переименован вручную. Клик по графику в дереве открывает его с сохранёнными настройками по текущим данным; правая кнопка — открыть, переименовать, удалить. Claude открывает сохранённый график командой `chart.open`. Эндпоинты: `GET/POST /api/sets/{id}/charts`, `GET/PATCH/DELETE /api/charts/{id}`.

### Статистика

Вкладка «Статистика» нижней панели (лента «Анализ → Статистика», команда `stats.open`, доступна и Claude).
Расчёт идёт по одному компоненту набора: каждый интервал опробования со значением становится точкой в середине
интервала на траектории скважины; декластеризация и вариограммы считаются в плане (X, Y).

| Анализ | Что показывает | Эндпоинт |
|---|---|---|
| Декластеризация | Среднее с весами и без, кривая «размер ячейки → среднее», лучший размер; метод ячеек или полигонов | `POST /api/sets/{id}/stats/declustering` |
| Нормальные оценки | Таблица нормального преобразования, можно с весами декластеризации | `…/stats/nscore`, `…/stats/backtr` |
| Вариограмма | Экспериментальная вариограмма: омни или 4 направления; модель поверх; число пар в лагах | `…/stats/variogram` |
| Карта вариограммы | γ по сдвигам (ΔX, ΔY); пустые ячейки — пар меньше порога | `…/stats/variogram-map` |
| Бутстрап | Доверительный интервал статистики (среднее, медиана, σ, CV, P10, P90); интервалы можно брать с весами декластеризации | `…/stats/bootstrap` |
| Карта неопределённости | Разброс оценки обратными расстояниями по плану: каждая реализация — выборка скважин с возвратом; карты среднего, σ, P10, P90, вероятности превысить порог | `…/stats/local-uncertainty` |

Кривая модели считается без данных: `POST /api/stats/variogram-model`. Больше 20 000 интервалов не считается
(расчёт по парам): сначала композитирование.

### Главное окно

Окно всегда 3D и всегда свободно вращается. Отдельных режимов «План» и «Разрез» нет: кнопки только
поворачивают камеру или отсекают данные.

| Кнопка | Клавиша | Что делает |
|---|---|---|
| В план | `T` | Вид сверху (Y вверх, X вправо) на то, что сейчас на экране: поворот вокруг центра вида с сохранением масштаба, всё не вписывается (для этого — «Вписать») |
| Z/X | `X` | Вид сбоку на север: Z вверх, X вправо |
| Z/Y | `Y` | Вид сбоку на запад: Z вверх, Y вправо |
| 3D | `3` | Изометрия |
| Вписать | `F` | Показать всё, не поворачивая вид |
| Разрез | `S` | Два клика — начало и конец линии разреза: прямо в текущем виде (вид не поворачивается и не вписывается) или на мини-плане. Между кликами линия тянется за курсором. Разрез показывает линию от края до края |
| План | — | В разрезе: маленький план с данными, линией разреза, окном просмотра «от / до» и стороной взгляда (оранжевый треугольник). Скрывается крестиком, открывается кнопкой «План» |
| Отсечение | `C` | Включить или выключить отсечение окном разреза |
| ◀ ▶ | `[` `]` | Соседний профиль: сдвиг линии на ширину окна |

**Разрез.** После второго клика включается отсечение и вид встаёт в плоскость разреза: Z вверх, линия слева
направо, наблюдатель справа от линии. Окно задаётся двумя числами в единицах карты: **От** — глубина к наблюдателю,
**До** — от наблюдателя. Каркасы в разрезе показаны линиями сечения. Вид можно вращать и с включённым отсечением;
«В плоскость» возвращает его обратно. «Авто-разрез» ставит линию поперёк простирания устьев.

**Разрез по скважине.** «Через скважину» ведёт линию через устье выбранной скважины **по её азимуту в плане**
(от устья к забою по траектории), так что скважина целиком лежит в плоскости разреза. У вертикальной скважины
азимут остаётся прежним.

Проекция по умолчанию ортогональная (как на планах и разрезах); флажок «перспектива» включает перспективу.

Другие клавиши: `Esc` — снять выбор, `Ctrl+K` — палитра команд, `Ctrl+J` — Claude, `Ctrl+B` — дерево,
``Ctrl+` `` — нижняя панель. Буквы работают в любой раскладке.

Адрес хранит активный набор, скважину и таблицу: `#/?set=3&hole=BHTSE-1&table=assay`.
Панели, видимость слоёв, проекция и тема запоминаются в браузере.

### Каркасы

| Формат | Что читается |
|---|---|
| Micromine TRIDB | Все каркасы файла, имена и цвета, пользовательские атрибуты (разбор формата — `docs/FORMATS.md`); геометрия читается из базы потоком |
| DXF | POLYFACE / POLYMESH, 3DFACE, MESH; один каркас на слой, совпадающие вершины сшиваются; текстовый DXF читается потоком (`formats/dxf_stream.py`), двоичный — через ezdxf |
| OBJ | Вершины и грани (`v`, `f`, отрицательные номера), один каркас на `o`/`g` |
| STL | Двоичный и текстовый; координаты в формате — float32, об этом пишется в свойствах |

При загрузке считаются площадь, объём (для замкнутых тел), ориентация нормалей, открытые и неманифолдные рёбра, вырожденные треугольники. Следом идёт задание «Проверка и копии для показа»: согласованность нормалей, самопересечения (numba, сетка ячеек), две упрощённые копии (1/8 и 1/64, pyfqmr) для дальних планов. Повторить — `POST /api/datasets/{id}/check` или «проверить» в свойствах.

Показ больших каркасов: треугольники хранятся в Z-порядке и делятся на части по 32 768; в 3D сначала грузится самая грубая копия, потом средняя, потом полная; невидимые части отсекаются, уровень выбирается по плотности треугольников на экране. Точные сечения считает сервер во float64 (`POST /api/sections`) — только по частям, которые задевает плоскость.

### Интервальные таблицы и данные по стволу

В наборе скважин может быть сколько угодно интервальных таблиц кроме проб: литология, изменения, выветривание, RQD, дополнительные анализы. Импорт — в мастере скважин, тип «Интервальная таблица»: назначаются скважина, «от» и «до», остальные отмеченные колонки сохраняются (числа — как числа, остальное — как текст). Таблица с тем же названием заменяется, пробы и другие таблицы не меняются. В дереве таблицы стоят под «Пробами»; правая кнопка — «Данные по стволу», переименовать, удалить.

**Данные по стволу** — колонки вдоль скважин, как каротажная диаграмма в Leapfrog / Micromine. Открываются правой кнопкой на «Пробах» или интервальной таблице (или кликом по таблице) и сразу сохраняются в узле набора «Данные по скважинам» (над «Аудитом»); настройки сохраняются сами, клик в дереве открывает колонку снова.

| Настройка | Варианты |
|---|---|
| Скважины | До 30 рядом, поиск; общая шкала глубин или каждая от своего устья |
| Глубина | Интервал «от–до», масштаб: вписать в окно, 1:2000 … 1:50 |
| Колонки | Поле любой таблицы набора; порядок, ширина |
| Вид колонки | График (ступенчатая линия), столбцы, цветная колонка (категории — своя палитра на все скважины, числа — цветовая шкала), текст, цвет + текст |
| Шкала | От / до (по умолчанию по данным), логарифмическая, цвет линии и столбцов, границы интервалов |
| Экспорт | PNG, SVG, CSV значений |

Подсказка у каждого интервала — скважина, глубины и значение; под колонками — легенда категорий. Claude открывает колонку командой `chart.striplog`.

### Блочные модели

Загрузка — «+» у группы «Блочные модели» или перетаскивание файла в окно: `.DAT` и `.CSV` с полями центра и размера блока мастер узнаёт по заголовку и отправляет в импорт объектов, а не в мастер скважин. Импорт идёт фоновым заданием.

| Что | Как |
|---|---|
| Форматы | Micromine DAT (типы C, N, R; кодировки cp1251 и BOCU-1; заголовок 4096 или 8192 байт), Micromine CSV (3 строки заголовка: имена, типы, сетка `x0, dx, y0, dy, z0, dz, CENTRE`), обычный CSV |
| Поля блока | Центр: `X/Y/Z`, `XC/YC/ZC`, `EAST/NORTH/RL`…; размер: `_X/_Y/_Z`, `XINC/YINC/ZINC`, `DX/DY/DZ`…. Без размеров — регулярная модель, размер по строке сетки или шагу центров |
| Субблоки | Хранятся как есть (центр и размер), плюс родительская сетка: угол начала, размер родителя, число ячеек, занятые ячейки |
| Проверки | Блоки за началом сетки, субблоки через границу родителя, дубликаты, перекрытия (точно — на сетке наименьшего блока; иначе по объёму в родительской ячейке), пустые и постоянные поля, объём |
| Свойства | Описание сетки, проверки, поля с единицами (г/т, %, ppm, ppb — меняются в таблице полей), выбранный кликом блок |
| Показ | Блоки — кубы с цветом по полю (шкала, лог.), «показать от / до» (например, бортовое), категории — флажками, непрозрачность; отсечение окном разреза работает и для блоков |
| Отчёт по бортам | Тоннаж = объём × плотность (поле или постоянная), содержания взвешены по тоннажу, металл: г/т → тыс. унц, % → т; отбор по категориям, группы, кривая содержание–тоннаж, CSV. По умолчанию плотность — меняющееся поле `SG` (постоянное `DENSITY` = 2,6 пропускается), содержания — поля `*_CUT` вместо исходных |

Скорость (синтетическая модель 363 517 блоков, 23 поля, 127 МБ BOCU-1): чтение 1,9 с, сетка и проверки 0,8 с.

### Линии

| Формат | Что читается |
|---|---|
| Micromine STR | Поля `EAST`, `NORTH`, `RL`; новая линия при смене `JOIN` или `STRING`; слой = код `STRING`; свои поля становятся атрибутами линии |
| Surpac STR | Текст `номер, Y, X, Z, описания`; сегменты разделены нулевой записью; слой = номер стринга |
| DXF | LINE, LWPOLYLINE, POLYLINE, SPLINE, ARC, CIRCLE, ELLIPSE; слой = слой DXF; кривые переводятся в ломаные |

Формат `.str` определяется по содержимому. Линия замкнута, если первая и последняя точки совпадают.
При отсечении видны части линий, попавшие в окно разреза.

### Растры

Изображение загружается **вместе с файлом привязки** с тем же именем (выделите оба файла в диалоге).

| Привязка | Файлы | Как используется |
|---|---|---|
| GeoTIFF | теги внутри `.tif` | Масштаб и точка привязки или матрица преобразования |
| World-файл | `.jgw`, `.pgw`, `.tfw`, `.wld` | Шесть чисел; координаты центра левого верхнего пикселя |
| MapInfo TAB | `.tab` | Аффинное преобразование по опорным точкам (не меньше трёх) |
| Micromine GRF | `.grf` | По опорным точкам; высота берётся из файла |

Порядок выбора: GeoTIFF → world-файл → TAB → GRF. Если есть несколько файлов, по опорным точкам остальных
считаются отклонения — они показаны в свойствах растра. Растр лежит в плане на заданной высоте
(пусто — под самым низким объектом сцены); отсечение по разрезу действует и на растры.

**Растры в вертикальной плоскости** (сканы разрезов) ставятся тремя способами:

| Способ | Как |
|---|---|
| GRF с отметками Z | Опорные точки `col row X Y Z` на разных высотах — растр встаёт в их плоскость |
| Загрузка без привязки | Если линия разреза проведена, изображение без файла привязки встаёт в её плоскость: края — по линии в пределах данных, верх и низ — по высотам данных |
| Свойства растра | Поля «Левый край X/Y», «Правый край X/Y», «Верх Z», «Низ Z» и кнопка «На текущий разрез» (работает и для растра, лежавшего в плане) |

При включённом отсечении вертикальный растр — подложка, как в Micromine: скважины, линии и сечения каркасов
рисуются поверх него. Без отсечения это обычный объект 3D-сцены.
Изображения больше 4096 пикселей по стороне уменьшаются для показа.

| Эндпоинт | Назначение |
|---|---|
| `POST /api/projects/{id}/lines` | Загрузка файла линий |
| `GET /api/lines/{id}/geometry` | Вершины и начала линий слоя для 3D |
| `PATCH`, `DELETE /api/lines/{id}` | Имя и цвет слоя, удаление |
| `POST /api/projects/{id}/rasters` | Загрузка изображений с файлами привязки (поле `files`, несколько файлов; `section` — плоскость для изображений без привязки) |
| `GET /api/rasters/{id}/image` | Изображение для показа |
| `PATCH /api/rasters/{id}` | Имя, высота, непрозрачность; `vertical` — поставить в вертикальную плоскость |
| `GET /api/projects/{id}/datasets` | Дерево проекта: наборы скважин, каркасы, линии, растры |
| `POST /api/projects/{id}/sets` | Пустой набор скважин |
| `PATCH`, `DELETE /api/datasets/{id}` | Переименование, удаление объекта со всеми данными |
| `POST /api/projects/{id}/wireframes` | Загрузка файла каркасов |

| `PATCH`, `DELETE /api/wireframes/{id}` | Имя и цвет, удаление |

### Claude внутри приложения

| `ASSISTANT_EFFORT` | Глубина рассуждений: `low`, `medium` (по умолчанию), `high` |


|---|---|

## Импорт (этапы 2.1–2.2)

Экран импорта принимает **Micromine DAT**, **CSV/TXT** и **Excel (.xlsx, .xlsm)**: загрузка или перетаскивание файла,
автоопределение типа таблицы (Collar / Survey / Assay), назначение колонок, компоненты с единицами, проверка и предпросмотр.
Старый формат `.xls` не поддерживается: его нужно пересохранить в `.xlsx`.

| Возможность | Как работает |
|---|---|
| Кодировка текста | Определяется автоматически: UTF-8 (с BOM и без), UTF-16, cp1251, cp866, KOI8-R; можно выбрать вручную |
| Разделитель | `;` `,` табуляция `|` или пробелы; определяется по одинаковому числу полей в строках |
| Строка заголовка | Номер строки с названиями колонок (пустые строки не считаются), 0 — без заголовка; титульные строки пропускаются |
| Лист Excel | По умолчанию первый лист с данными; можно выбрать другой |
| Числа | Десятичная точка или запятая, пробелы между разрядами (`4 584 699,70`) |
| Предел обнаружения | `<0.005` записывается как половина предела (0.0025), `>1000` — как 1000; на экране показывается, сколько значений заменено |
| Пустые значения | `-`, `н/д`, `н.о.`, `NA`, `N/A` и т. п. считаются пустыми |
| Названия колонок | Русские и английские: «Скважина», «От», «До», «№ пробы», «Глубина (м)», «X, м», «Au, г/т» (единица берётся из названия) |
| Ошибки в числах | Текст в числовом поле показывается с примером значения и числом строк |

На образце проекта те же данные в CSV (cp1251, `;`, десятичная запятая) и в Excel дают тот же проект, что и DAT:
совпадают количества строк, значения и итог аудита.

| Эндпоинт | Назначение |
|---|---|
| `GET /api/import/schemas` | Целевые таблицы и поля |
| `POST /api/import/upload` | Загрузка файла, параметры чтения, предпросмотр, предложенное назначение колонок |
| `POST /api/import/{file_id}/options` | Перечитать файл с другой кодировкой, разделителем, строкой заголовка или листом |
| `POST /api/import/validate` | Проверка назначения, нормализованный предпросмотр |

## Хранилище, загрузка и фоновые задания (этап 7)

Большие данные (геометрия, изображения, исходные файлы) лежат в файловом хранилище `DATA_DIR`, а не в PostgreSQL: имя файла — его SHA-256, в базе только описание (`blob`) и ссылки из объектов (колонки `blobs`). Миграция `0005` переносит данные старых проектов из `bytea` в файлы и обратно.

| Что | Как устроено |
|---|---|
| Точность | Исходные координаты — float64 без округления. Для показа — копия float32 относительно начала в центре объекта: до 16 км в поперечнике погрешность ≤ 0,5 мм. Расчёты идут по float64 |
| Передача в браузер | `GET /api/blobs/{sha256}`: сырые массивы, `ETag`, вечный кеш, частичное чтение (`Range`); разбор в Web Worker без копирования |
| Загрузка файлов | Частями по 16 МБ с SHA-256 каждой части, до 4 ГБ; после обрыва или перезагрузки страницы тот же файл продолжает с места остановки |
| Импорт | Фоновое задание: прогресс, журнал, отмена; результат и статус «готово» сохраняются в одной транзакции |
| Рабочие процессы | `python -m app.jobs.worker`; задание упавшего процесса возвращается в очередь (до 3 попыток) |
| Очистка | Раз в час: файлы без ссылок, брошенные загрузки (48 ч) |

| Эндпоинт | Назначение |
|---|---|
| `POST /api/projects/{id}/uploads` → `PUT /api/uploads/{id}?offset=N` | Загрузка частями; `X-Chunk-SHA256` — проверка части |
| `POST /api/projects/{id}/detect` | Тип объекта по файлам (каркасы, линии, растры, таблицы) |
| `POST /api/projects/{id}/imports` | Импорт загруженных файлов — задание |
| `GET /api/projects/{id}/jobs`, `GET /api/jobs/{id}` | Задания, журнал |
| `GET /api/projects/{id}/jobs/events`, `GET /api/jobs/{id}/events` | Ход заданий (SSE) |
| `POST /api/jobs/{id}/cancel` | Отмена |
| `PATCH /api/datasets/{id}` | Название и папка объекта в дереве |
| `POST /api/storage/gc` | Очистка хранилища вне расписания |

Прямые эндпоинты `POST /api/projects/{id}/wireframes | lines | rasters` остаются для небольших файлов и скриптов (до `MAX_UPLOAD_MB`, 200 МБ).

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `DATA_DIR` | `/tmp/bedrockforge-data` (в Docker — том `store`) | Файловое хранилище |
| `JOBS_IN_API` | `1` (в Docker — `0`) | Рабочие потоки заданий внутри API, для разработки без отдельного процесса |
| `MAX_CHUNKED_UPLOAD_MB` | `4096` | Предел загрузки частями |
| `UPLOAD_CHUNK_MB` | `16` | Размер части |

### Замеры скорости

```bash
cd api
python -m bench.run --profile ci --check      # 1 млн треугольников, пороги CI
python -m bench.run --profile full --check    # 10 млн треугольников, загрузка 2 ГБ
```

Каждый сценарий идёт в отдельном процессе; меряются время и пиковая память. Пороги — `api/bench/budgets.json`. В CI (`.github/workflows/ci.yml`) замер ветки сравнивается с замером базовой ветки на той же машине: замедление больше 20 % — ошибка.

## Визуализация (этап 5)

Траектории считаются на сервере методом минимальной кривизны
(`api/app/geo/trajectory.py`). Азимут отсчитывается по часовой стрелке от севера, наклон отрицательный вниз.
На образце проекта траектории совпадают с координатами X/Y/Z, рассчитанными в Micromine, с точностью до 5 см
(21 145 интервалов, медиана отклонения 1 см).

Стволы, интервалы проб и устья показываются в главном 3D-окне (см. «Интерфейс»).
Устья окрашены по замечаниям аудита. Шкала цвета содержаний общая для всех наборов: компонент, диапазон
(по умолчанию 5–95 перцентиль активного набора) и логарифмический режим настраиваются в панели «Свойства».
3D (three.js, ~140 КБ gzip) загружается отдельным файлом после оболочки.

| Эндпоинт | Назначение |
|---|---|
| `GET /api/sets/{id}/trajectories` | Траектории: точки `[x, y, z, глубина]`, пропущенные устья без координат |
| `GET /api/sets/{id}/intervals?component=` | Интервалы компонента с 3D-координатами концов и статистикой значений |

## Аудит данных (этап 4)

Вид «Аудит»: запуск 27 правил по Collar, Survey и Assay, результаты по правилам (в том числе пройденным),
фильтруемый список находок и отчёт в Excel (листы «Сводка», «По правилам», «Находки»).
Находки сгруппированы по скважине и правилу: `count` — число строк, в `details.examples` — до 20 примеров.
Новый запуск заменяет предыдущий результат проекта; после нового импорта отчёт помечается устаревшим.

| Группа | Правила |
|---|---|
| Устья | нет координат, неверная глубина TD, углы вне диапазона, изолированное устье, скачок Z, плановая скважина с данными, пустой статус, нет инклинометрии, нет проб |
| Инклинометрия | скважины нет в устьях, пустые значения, углы вне диапазона, замер глубже забоя, дубли и нарушение порядка глубин, первый замер не на устье, резкий изгиб (°/30 м), расхождение с устьем |
| Пробы | скважины нет в устьях, некорректный интервал, глубже забоя, перекрытие, разрыв, дубли номеров проб, отрицательные и пустые содержания, экстремальные значения |

Пороги (допуск по глубине, изгиб, изоляция устья, скачок Z, выброс содержания) задаются в интерфейсе.
Добавить правило: описать в `app/audit/rules.py`, реализовать проверку в `app/audit/checks.py`, покрыть тестом в `tests/test_audit_checks.py`.

| Эндпоинт | Назначение |
|---|---|
| `POST /api/sets/{id}/audit` | Запуск аудита (необязательно: пороги в теле) |
| `GET /api/sets/{id}/audit` | Последний результат или `null` |
| `GET /api/sets/{id}/audit/findings` | Находки с фильтрами `severity`, `table`, `code`, `hole_id` |
| `GET /api/sets/{id}/audit/export.xlsx` | Отчёт в Excel |
